# Карточка проекта FIB (числа Фибоначчи)

Паспорт файла: PROJECTS/fib/CARD.md | слой: L6 | роль: паспорт проекта.

| Поле | Значение |
|---|---|
| ID проекта | FIB |
| Слой | L6 (ПРОЕКТЫ, SPEC/06) — внешняя программа ядра |
| Назначение | Вычислительная программа: итеративно печатает первые 13 членов ряда Фибоначчи (1: 1 .. 13: 233). Второй проект-потребитель библиотеки L4 — ветви C+N с зависимостью N -> C и стеком |
| Вход | `fib.uva` (исходник: .mem + код + !include частей lib_c, lib_n) |
| Выход | Консоль: 13 строк «<i>: <fib(i)>» (CRLF); контейнер v1 — .data нет |
| Зависимости | Ядро kernel.exe (ISA v0+v1, .UP v1), ассемблер uva.exe, склейщик splice.exe; библиотека L4: lib_c + lib_n (print_u64 зовёт кирпичи C — ОБЯЗАТЕЛЬНЫ обе части, SPEC/14) |
| Ядро | Проект ядро не знает: kernel.exe исполняет байты .UP (правило R7); правка/удаление проекта не требует пересборки ядра |
| Свои кирпичи | НЕТ — только кирпичи библиотеки L4 по ссылке (правило R6, PROJECTS/README п. 3) |

## Сборка и запуск (Windows, из корня репозитория)

```
KERNEL\L1-SPLICE\splice.exe PROJECTS\fib\fib.uva PROJECTS\fib\fib.flat.uva
KERNEL\L3-UVA\uva.exe PROJECTS\fib\fib.flat.uva PROJECTS\fib\fib.up
KERNEL\L3-UNIVM\kernel.exe PROJECTS\fib\fib.up
```

Эталон вывода — TESTS/T-PROJECTS.md (T-P-02). Сборочные файлы
`fib.flat.uva` / `fib.up` — продукты сборки, в репозиторий не попадают
(.gitignore).

## Что демонстрирует

1. Зависимость ветвей N -> C по SPEC/14: программа обязана включить
   ОБЕ части (метки lib_buf_out_rev/lib_chr_out решаются в общем
   плоском тексте).
2. Собственное вычисление: цикл и шаг ряда на ALU (add/lt/jnz) —
   программа не только печатает, но и СЧИТАЕТ.
3. Состояние цикла в СОХРАНЯЕМЫХ регистрах r5..r10, переживающих
   вызовы кирпичей (ABI SPEC/14 п. 3 — проверяется фактом работы).
4. Стек-конвенция ветви N: r13 = 4000, слот [sp-8, sp).

## Тест

T-P-02 (TESTS/T-PROJECTS.md; батарея — секция 17, LAB/py/lab_t_prj.py):

LAB) — вывод байт-в-байт == якорю И оракулу (ряд Фибоначчи на Python).
