# Проверка модуля M0-SEED2

Паспорт файла: KERNEL/L0-SEED2/VERIFY.md | слой: L0 | роль: инструкция проверки.

## Паспорт артефакта

| Свойство | Значение |
|---|---|
| Файл | `KERNEL/L0-SEED2/seed2.exe` |
| Размер | 2048 байта (0x800) |
| SHA-256 | `190DE94E3F3227D421B6779B34985FD1762E127EC50EF864C4ED84814B05EE87` |
| Тип | PE32+ (консоль, x86-64), 1 секция, импорт kernel32.dll (4 функции) |
| Исходники | `seed2.hex` (тело секции, ATOM v1, телесная форма) + `seed2.peg` (обёртка, SPEC/07) |
| Команды | entry, image, align, sect, args (см. CARD.md) |

## Проверка 1: подлинность (хэш)

```
certutil -hashfile seed2.exe SHA256
```

Вывод должен совпасть с SHA-256 из таблицы выше (регистр не важен).

## Проверка 2: команды

```
seed2.exe entry     →  U-L0-SEED2 ENTRY=0x00001000
seed2.exe image     →  U-L0-SEED2 IMAGE=0x00002000
seed2.exe align     →  U-L0-SEED2 ALIGN=0x00001000
seed2.exe sect      →  U-L0-SEED2 SECT=0x00000001
seed2.exe args hello world  →  U-L0-SEED2 ARGS: hello world
seed2.exe           →  U-L0-SEED2 CMDS: ENTRY IMAGE ALIGN SECT ARGS
seed2.exe bogus     →  та же справка, код возврата 2
```

Каждая строка завершается CRLF. Числа читаются из собственного
заголовка образа — вывод сверяется с полями по смещениям 0xA8/0xD0/0xB8/0x86.

## Проверка 3: код возврата

```
seed2.exe entry
echo %errorlevel%        → 0
seed2.exe bogus
echo %errorlevel%        → 2
```

## Проверка 4: соответствие листингу

Контрольные байты (тест T-M2-12, `TESTS/T-L0-SEED2.md`).

## Сборка (с этапа E4)

```
hexgen.exe seed2.hex  t_body.bin
pegen.exe  t_body.bin  seed2.peg  t.exe
fc /b t.exe seed2.exe   ->  различий нет
```

Полный круг «текст → EXE» — `T-M5-03` в `TESTS/T-L0-PEGEN.md`
(заголовки генерирует pegen из `seed2.peg`; SHA-256 артефакта не изменился).

## Журнал верификации

| Дата | Кто | Уровни | Результат |
|---|---|---|---|
| Этап E1 | ИИ (GLM) | PE-разбор (38 полей) + дизассемблер (185 инструкций, objdump) + эмуляция (16 прогонов, 83–422 шага) | все зелёные |

Эмулятор подмножества x86-64 перед прогоном seed2 был сам валидирован
на `KERNEL/L0-SEED/seed.exe` (эталонный вывод E0 воспроизведён).

## Пойманные ошибки сборки (почему нужна трёхуровневая проверка)

Эмуляция уровня 3 поймала пять реальных дефектов ручной сборки,
прозеванных разбором и дизассемблированием:

1. Метки вызовов указывали на INT вместо IAT — на реальной Windows
   программа вызвала бы адрес данных (падение).
2. `mov rax,r8` был закодирован как `49 89 C0` (= `mov r8,rax`):
   перепутаны поля reg/rm; верно `4C 89 C0`.
3. `mov rdx,r11` вместо `add rdx,r11` — терялось смещение hex-поля
   (цифры писались в начало строки).
4. После закрывающей кавычки argv[0] не пропускался сам символ `"`
   — кавычка попадала в слово команды.
5. Длина хвоста хранилась в rcx (волатильном) — затиралась вызовом
   print_line; сохранена в неволатильном r14.

Каждая ошибка — класс, который ловится только исполнением. Вывод:
уровень 3 обязателен для каждого образа L0 (правило SPEC/02).

## Замечания

- Файл не подписан: SmartScreen/антивирус могут спросить подтверждение.
- Программа не трогает файлы и сеть: только командная строка, вывод
  в консоль и завершение.
- Работает на Windows 7+ x64 и под Wine.
