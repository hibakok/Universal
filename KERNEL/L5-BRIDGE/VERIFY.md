## 2. Уровни проверки (SPEC/02; батарея 234/234, группы 1/2/3/4/5)

1. Целостность: SHA-256 (лаборатория — реестр SHA lab_verify.py).
2. PE-инварианты SPEC/04 (вход 0x1200 — легальное отклонение
   SPEC/11 п. 6): hint-записи на чётных RVA, одна секция, обёртка
   PEG bridge.peg.
3. Фикс-пункт воспроизводимости (T-E9-17): сборка bridge.wall
   конвейером wall → enc → brick → pegen (эмуляция, ~305 млн шагов;
   шаг wall 247.7 млн — прямой lab_win с лимитом 2 млрд, прецедент
   T-E6-49a) == артефактам байт-в-байт; bridge.b2 == оракулу WALL.
4. Контракт CLI каркаса (T-E9-19): справка (нет аргументов / два /
   четвёртый), LONG NAME, OPEN EXE, BIG EXE (256 КиБ); семейные
   отказы — 21 мутант seed.exe (MZ/PE-сигнатура/Machine/
   NumberOfSections/Magic/ImageBase/Subsystem/имя секции/
   SizeOfImage/SizeOfHeaders/вход вне секции/файл короче raw/
   нулевой код/заглушка/игла/пробел в имени/DLL-имя/hint нечётный/
   терминатор IDT + срез E9.2-2: инструкция за vsize (vsize=0x3D —
   выжившая инструкция пересекает VirtualSize) и длина тела >
   vsize (vsize=0x40 — target за VirtualSize)) + мусор/пустой файл;
   ЛЕГАЛЬНЫЕ отклонения — вход 0x1100 (внутри секции) и регистр
   DLL-имени: успех с фактами == оракулу (диффтест семейства на
   мутантах).
5. Диффтест фактов с оракулом (T-E9-18): факт-строка
   MODULE/ENTRY/VSIZE/RAW/IMP/INS/TARGET/BSS == parse_family оракула
   LAB/py/lab_bridge.py на ВСЕХ 11 артефактах семейства + самом
   bridge.exe (12 прогонов под эмуляцией) — семантика каркаса
   (PE + семейство + импорты) и СПУСКА (декодер + тени + target/bss)
   равна оракулу на полном корпусе.
6. Синтетика спуска (T-E9-21): рукотворный образ (префикс импортов
   bridge + крафт): тень (цель jz ВНУТРИ соседней mov — младший
   адрес побеждает), нули — данные, терминал ret; факты ==
   оракулу (в реальных артефактах теней нет — правила закрыты
   синтетикой).
7. Круг оракула над bridge.exe (T-E9-20): мост над 12-м артефактом
   семейства воспроизводит bridge.exe байт-в-байт; M=19237 H=0 —
   100% M-строк (канон enc, как kernel/uva; массивы после скаляров,
   ПОСЛЕДНИЙ — w1: выравнивающий хвост !bss падает внутрь него —
   БЕЗУСЛОВНЫЙ инвариант E9.2-3b; сохранён и срезом E9.2-4 — массив
   ptplb[9] добавлен перед w1).
8. Диффтест raw-эмиссии с оракулом (T-E9-22, E9.2-3a): файл
   <выход>.b2 (шапка SPEC/15 + H-строки с примечаниями == _note +

## 3. Журнал срезов

### E9.2-1 (сессия 68) — каркас bridge.exe

Срез: CLI (3 аргумента) + чтение EXE (GlobalAlloc 262145, один
ReadFile, BIG EXE при got == 262145) + разбор PE по фиксированным
смещениям SPEC/04 + семейная проверка (ERR=FAMILY) + факт-строка.
26 кирпичей K5-* (8 C + 17 P + main); артефакты 15360 Б; батарея
224 → 230 (SHA +1, PE +1, T-E9-17..20 +4).

Дефекты (2, пойманы дымовыми прогонами до якорей):

1. Константа Machine 0x8664 записана как 34692 (правильно 34404) —
   все семейные образы отвергались ERR=FAMILY. Пойман маркерной
   отладкой (отладочная сборка моста с нумерованными отказами).
2. Разложение ImageBase 0x140000000 на dwords: низ = 0x40000000
   (= 1073741824), верх = 1 — проверка изначально ожидала низ 0.
   Заодно: длина «kernel32.dll» — 12 байт, не 11 (отказ по DLL-имени).
   Пойманы той же маркерной отладкой (маркеры 12 и 36).

Уроки (записаны в исходники):

1. Литерали WALL <= 2147483647 — 0xE0000020 выражается сдвигом
   (14 << 28) + 32.
2. Качество разложения моста (M/H) закладывается порядком глобалей:
   массивы после скаляров — 0 H-строк (иначе 114 rip-загрузок
   скаляров попадали в !bss-хвост без меток).
3. quirk оракула _read_cstr_rva (строка без NUL -> data[off:-1])
   воспроизведён в cstr_len — эквивалентность каркаса оракулу
   тотальна, включая краевые случаи.

### E9.2-2 (сессия 69) — спуск от входа: декодер + тени + target/bss

Срез: ветвь D (декодер x86-подмножества SPEC/05 — bridge_self_d.wall
+ bridge_self_d2.wall, 13 кирпичей: длины/классы/прямые цели ==
lab_x86.decode оракула; операнды/имена регистров — срезу не нужны,
это материал E9.2-3) + ветвь W (спуск — bridge_self_w.wall, 3
кирпича: стек целей в куче GlobalAlloc 1048584 (доказуемый предел
1 + rawlim/2), карты стартов/длин insmap/lenmap 262145, rawlim =
min(vsize, rawsize); тени — младший адрес побеждает; ВСЕ-НУЛЕВЫЕ
байты — данные; выжившие с концом за vsize — ERR=FAMILY; target:
max(последний ненулевой байт + 1, концы выживших, 1) с вилкой
raw-0x1FF; bss = vsize - target) + факт-строка расширена
INS/TARGET/BSS. 16 новых кирпичей K5-D*/K5-W*; модуль 42 кирпича;
артефакты 28672 Б; батарея 230 → 231 (T-E9-21 +1; T-E9-18/19
эволюционировали со срезом — прецедент E7.2-1). Ядро и другие
модули KERNEL/ не менялись (R7).

Дефекты (2, пойманы диффтестом/кругом ДО фиксации якорей):

1. **0xC6 = 198, записано 196 (= 0xC4)** — группа C6/C7 выпадала из
   диспетчера: путь обрывался на первом же `mov [rcx],0` — INS
   занижен на hexgen/pegen/brick/enc/splice (145/217/501/1843/318
   инструкций). Пойман T-E9-18 (факты != оракулу) + зеркальной
   симуляцией декодера; локализован первым потерянным адресом
   (0x31C hexgen — `C6 01 00`, переходов на него нет — fall-through).
2. **Инвариант «хвост !bss внутрь factbuf» нарушен ростом тела**:
   vsize mod 0x200 сместился с 0xBF на 0xE9 > 0xC1 — выравнивающий
   хвост (raw-0x1FF..vsize) начинался ДО базы factbuf, и 18 lea
   [rip+$factbuf] расширенной print_facts остались без меток —
   круг T-E9-20 дал H=18 (байто-точность круга сохранилась — H-фолбэк
   вопрос читаемости, не корректности). Фикс — w1[32] (0x100 Б)
   последним массивом вместо factbuf (инвариант держится при
   vsize mod 0x200 <= 0x101); H=0 восстановлен.

Уроки (записаны в исходники):

1. Шестнадцатеричные константы в WALL-коде писать с НОМЕРАМИ
   (`C6` — 198): перевод hex->dec проверять дважды; диффтест
   INS по 12 артефактам ловит выпавшую группу мгновенно.
2. Порядок массивов глобалей — не косметика: инвариант «хвост
   вилки внутри ПОСЛЕДНЕГО массива» зависит от vsize mod 0x200;
   при росте тела пересчитывать и выбирать последний массив
   достаточно большого размера (w1 0x100 >= 0x101-допуск).
3. Имя «end» занято терминатором блока WALL — локаль результата
   называется iend (урок грамматики, пойман компиляцией оракула).

### E9.2-3a (сессия 70) — raw-эмиссия b2: операнды декодера + H-строки

Срез: операндное расширение декодера (10 новых кирпичей K5-D014..D023
+ переработка D004..D013: modrm_read — полный разбор modrm+SIB+disp
вместо modrm_skip; u32/u64; setters операндов; alu_id) + ветвь E —
эмиссия (bridge_self_e.wall, 18 кирпичей K5-E001..E018: таблицы имён
мнемоник/условий/регистров, шапка SPEC/15 кириллицей через
HEX-литерал s_tpl (идиома wall_self_blob), форматтеры, примечания ==
_note оракула, H-строки, DZ/DB, запись <выход>.b2 — коды 8/9) +
дамп выживших sdump в sweep_ins; оракул получил режимы наращивания
emit_b2(mode=None/H/RAW — канон неизменен, якорь T-E9-02 зелёный).
Модуль 70 кирпичей; артефакты 48128 Б (тело 0xB8AE); батарея 231 →
233 (T-E9-22/23 +2). Ядро и другие модули KERNEL/ не менялись (R7).

Дефекты (3, все пойманы диффтестом T-E9-22 ДО фиксации якорей):

1. **Потерян байт шапки s_tpl** — 396 hex-символов вместо 398 (пробел
   между «.exe» и «(»): шапка смещалась на 1 байт, все тексты длиннее
   на 2-3 Б. Пойман первым прогоном (размер seed 1898 != 1896).
2. **Сдвиг id мнемоник** — карточки присваивали id 1..28, а таблица
   имён 0-базовая: o_mn[1] «add» печаталось как «or», «sub rsp, 28»
   как «xor rsp, 28». Фикс — ведущий пустое имя №0 в блобе s_mn.
3. **Смесь test/mov в decmod** — ветка test захватила байты 0x88/0x89
   (в E9.2-2 длины совпадали, разница была невидима): «mov rdx, rax»
   печаталось «test rdx, rax». Фикс — точные множества {84,85} /
   {88,89} / {8A,8B}.

Уроки (записаны в исходники):

1. Длинные литералы (HEX-шапка 398 символов) вставлять ГЕНЕРАТОРОМ
   (скриптом), не руками — потерянный байт ловится только полным
   диффтестом текста.
2. Соответствие id ↔ таблица имён проверять на ПЕРВОМ же примечании
   (знаковый сдвиг мнемоник не виден на фактах — только в тексте).
3. При операндном расширении ветвей декодера таблицы байтов
   перепроверять по оракулу: равные длины скрывали смесь семейств
   (test/mov) весь срез E9.2-2.

## Срез E9.2-3b — МЕТКИ И СЕМАНТИКА (сессия 71, режим "H" оракула)

Состояние на входе: E9.2-3a закрыт (батарея 233/233). Выполнен
ПОДСРЕЗ 3b ЦЕЛИКОМ: ветвь L (части bridge_self_l.wall + bridge_self_l2.wall —
разрез по лимиту 500 строк; 17 кирпичей K5-L001..L017) + драйвер
emit_body; ветвь E — только примитивы
(K5-E018 emit_raw СНЯТ — заменён K5-L017); оракул получил три
исправления ДО инструмента (сначала истина семантики): (1) правило
представимости меток импорта (не создаются строго внутри выжившей
инструкции — зонд probe_e92_3b2: прежний вид давал НАЛОЖЕНИЕ строк
разрезов и невалидный b2 «FORMAT AT»); (2) приёмка DD/DQ-строк
дополнительно отвергает строки с меткой строго внутри диапазона;
(3) _san — только ASCII [a-z0-9_] (латиница-1 alnum байты вида «ÿ»
отвергаются enc). Артефакты пересобраны (T-E9-17 зелёный): склейка
89709 Б (3074 строки; ветвь L разрезана на части l/l2 — лимит 500
строк); тело 0xF392; файл 62976 Б; метки 885/2048;
функции 86; w1[32] -> w1[64] — БЕЗУСЛОВНЫЙ инвариант хвоста (урок
E9.2-2 обобщён: хвост < 0x200 Б всегда внутри w1, пересчёт при
росте больше не нужен); круг над bridge.exe M=12998 H=0; bridge.b2
== оракулу WALL; SHA bridge.exe 283CA3D7… — НЕ ИЗМЕНИЛСЯ при разрезе
l/l2 (только комментарии; реестр актуален); шаги
351949143+45361314+34316664+5046. T-E9-22
эволюционировал в диффтест режима "H" (12 артефактов + синтетика
спуска + синтетика меток: мутанты hint-ins — правило
представимости, imp0 — пустая таблица импорта, оба с КРУГОМ
валидности b2); батарея 233/233; секция 18 выделена в группу 4
battery_groups (группа 3 с ней не вмещалась в 10-минутный лимит
песочницы). Ядро и другие модули KERNEL/ не менялись (R7).

Дефекты (2, оба пойманы ДО фиксации якорей):

1. **Сравнение с 2^63 в знаковой qword-арифметике WALL** — маска
   бита 63 записана как `if v >= 2^63: v -= 2^63`; произведение
   16777216*256*16777216*128 представимо ТОЛЬКО как -2^63,
   сравнение всегда истинно, вычитание на деле ПРИБАВЛЯЕТ бит 63:
   hint-RVA 0x1190 превращался в 0x8000000000001190, все метки
   импорта «выпадали» из границ (impbad=1 — выход оставался
   корректным, но без меток/DD/DQ). Пойман зондом probe_heap.py
   (дамп кучи/глобалей под эмулятором). Фикс: v < 0 -> v + 2^63.
2. **Булевы скобки не поддерживаются WALL** — `(a || b)` в
   условии это арифметическая группировка: после первого операнда
   парсер ждёт «)», а видит «==» (отказ компиляции). Фикс —
   дистрибуция конъюнкции без скобок.

Уроки (записаны в исходники и MAP):

1. В WALL литералы <= 2^31-1, а ПРОИЗВЕДЕНИЯ >= 2^63 живут со
   знаком: сравнивать с ними нельзя — только складывать/вычитать
   (2^63 = «достаточно прибавить к отрицательному»).
2. Диагностика инструмента под эмулятором дампом кучи/глобалей
   (probe_heap.py: журнал GlobalAlloc + чтение скаляров по карте
   меток артефакта) быстрее слепых догадок — дефект №1 найден за
   один прогон.
