# Карточка модуля M0-HXDUMP (файловый ввод: hex-дамп)

Паспорт файла: KERNEL/L0-HXDUMP/CARD.md | слой: L0 | роль: карточка модуля.

| Поле | Значение |
|---|---|
| ID модуля | M0-HXDUMP |
| Слой | L0 (МАШИНА) |
| Назначение | Первый инструмент файлового ввода: читает произвольный файл и печатает его hex-дамп со смещениями и ASCII-колонкой |
| Вход | командная строка Windows: `hxdump.exe <файл>` |
| Выход | строки дампа в stdout + CRLF; код возврата 0 (успех) / 2 (нет аргумента) / 3 (имя длиннее 127) / 4 (файл не открыт) / 5 (ошибка чтения) |
| Размер | 3584 байта (0xE00) |
| Платформа | Windows x64, консольная подсистема, PE32+ |
| Импорты | kernel32.dll: GetStdHandle, WriteFile, ExitProcess, GetCommandLineA, CreateFileA, ReadFile, CloseHandle |

## Формат строки дампа

```
00000000: 4D 5A 90 00 03 00 00 00 04 00 00 00 FF FF 00 00  MZ..............
```

8 hex-цифр смещения, «: », 16 × «XX », пробел, 16 символов ASCII
(непечатное — «.»), CRLF. Последняя строка файла может быть короче.

## Состав (что читать для работы с модулем)

| Файл | Назначение |
|---|---|
| `hxdump.hex` | исходник в формате ATOM v1 — источник истины |
| `hxdump.exe` | материализация исходника (байт-в-байт) |
| `BYTECODE.md` | полный разбор: заголовки, 244 записи кода, данные, импорты |
| `VERIFY.md` | SHA-256, три уровня проверки, журнал |

## Кирпичи модуля (карточки — MAP/M0-HXDUMP.md)

```
Поток исполнения:
  K0-X021 prepare_stack        (кадр 0x48: тень + стековые аргументы CreateFileA)
  K0-S021 get_image_base       (реинкарнация K0-S011)
  init                         (GetStdHandle -> hstdout; без карточки, как в M0-SEED2)
  K0-C011 get_cmdline          (реинкарнация K0-C001)
  K0-C012 skip_argv0           (реинкарнация K0-C002)
  K0-C013 read_word            (реинкарнация K0-C003)
  K0-C014 copy_word            (новое: слово -> fname-буфер, NUL, флаг обрезки)
  K0-G021 dispatch             (новое: главный поток hxdump)
  K0-F001 open_file_read       (новое: CreateFileA, 7 аргументов)
  K0-B001 dump_loop            (новое: чанки 0x400 -> строки)
  K0-F002 read_chunk           (новое: ReadFile -> RAX = байты | -1)
  K0-B002 build_line           (новое: форматирование и печать строки)
  K0-F003 close_file           (новое: CloseHandle)
  K0-U021 print_usage          (реинкарнация K0-U001, строка 33 байта)
  K0-X022 exit_code            (реинкарнация K0-X012)
Подпрограммы:
  K0-H021 hex32_to_ascii8      (реинкарнация K0-H011)
  K0-H022 hex8_to_ascii2       (новое: байт -> 2 цифры, rol al,4)
  K0-P021 print_line           (реинкарнация K0-P011)
Данные:
  K0-D021 linebuf              (буфер строки дампа, 77 байт)
  K0-D022 fname                (буфер имени файла, 128 байт)
  K0-D023 filebuf              (буфер чтения чанка, 0x400 байт)
  K0-D024 служебные данные     (digits, hstdout, written, nread)
  K0-D025 строки вывода        (справка, ERR=LONG/OPEN/READ)
  K0-D026 таблица импортов     (7 функций kernel32.dll)
```

## Что M0-HXDUMP доказывает

1. **Файловый ввод** (ветвь F): открытие, чтение чанками, закрытие —
   чужие данные входят в наш мир как байты.
2. **Вызов Win64 с 5–7 аргументами**: CreateFileA получает аргументы 5–7
   на стеке [rsp+0x20..0x30] — кадр увеличен до 0x48.
3. **Потоковая обработка**: файлы любого размера читаются чанками по
   0x400 байт — память образа не растёт с размером файла.
4. **Кирпичность форматирования**: строка дампа собирается из H021+H022
   в буфер и печатается одним WriteFile на строку.
5. **Вежливые ошибки**: каждый отказ имеет свой код возврата и строку.

## Ограничения (снять в следующих этапах)

- Имя файла до 127 байт (буфер fname; длиннее — код 3).
- Смещения печатаются по модулю 2^32 (файлы > 4 ГБ).
- Нет поддержки «-» (stdin) и диапазонов — при необходимости позже.
