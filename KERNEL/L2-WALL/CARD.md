## Формат вызова

```
wall.exe <вход.wall> <выход.b2>
```

Оба аргумента обязательны. Выход создаётся заново (CREATE_ALWAYS).
Полный цикл компиляции программы на WALL (DoD E6.4b, T-E6-28):

```
wall.exe  <программа>.wall  <программа>.b2
enc.exe   <программа>.b2    <программа>.brick
brick.exe <программа>.brick <программа>-body.bin
pegen.exe <программа>-body.bin <программа>.peg <программа>.exe
```

## Архитектура (три прохода)

1. **Проход 0 (ветви N):** разбиение текста на строки (LF/CRLF/CR — как
   re.split оракула), ПОЛНАЯ лексика каждой строки до стопа (`;`/конец),
   стоп-позиция и обрезанный текст строки -> `sm_arr[строка]` = {ptr, len}
   (карта текстов комментариев канона); lastnonempty; nlines (правило
   хвостового терминатора).
2. **Проход 1 (ветви S, режим статов):** разбор имён/утверждений;
   реестры ntab (имена; вид 5 = массив с E6.4c-3/4), ftab (функции:
   nparams, maxd, maxc, flags setb/ext5, locoff, loccnt, nslots — сумма
   слотов с массивами, строка заголовка; запись 80 Б), larr
   (параметры+локали; запись 32 Б {ptr, len, size} — размер для
   раскладки), sarr (строки), varr (глобальные var; запись 16 Б
   {ntab_idx, size} — DZ 8n), earr (ext); статистика
   T/C/S-слотов по правилам SPEC/11 п.5; ошибки всех проверок
   (main ровно одна, арности, дубликаты имён, структура блоков).
3. **Проход 2 (ветви Y + эмиттеры E, режим эмитции):** заголовок,
   фиксированная область импортов 0x200 (SPEC/11 п.6), вход, функции
   (пролог/эпилог/утверждения/выражения канона п.8), секции данных.

**Ключевая механика выражений:** левоассоциативные цепочки `a + b + c` и
`a << b << c` эмитятся БЕЗ построения AST: предварительный подсчёт числа
операций уровня (chain_count, K2-P009) задаёт глубину T-склада
`tdepth = d + K - 1`, убывающую с каждой операцией; первый операнд
генерируется на глубине `d + K`, правые — на `tdepth + 1`. Это точно
воспроизводит раскладку оракула (t(d+K-1)..t(d)). С E6.4c-3/1 между
конъюнкцией и унарным есть уровень `* / %` (p_mdm, K2-P01A) — тот же
механизм (chain_count ур.2); сравнения — терминаторы ЛЮБОЙ цепочки,
с E6.4c-3/3 и `&&` / `||` — тоже (правый операнд за цепочкой не
считается в цепочку левого); с E6.4c-3/4 `[` `]` — скобки глубины
(индексация — постфикс первичного, содержимое прозрачно для внешней
цепочки, `]` на глубине 0 завершает скан — подготовка среза 4b).
**Индексация (срез 4b, wall_pp.b2 + wall_pi.b2):** p_prim (P013) —
обёртка: pp_prim0 разбирает первичное, peek `[` -> pp_strchk (P01E:
база-ИМЯ вида str запрещена, скобки снимаются k '(' + id + k ')')
-> pp_pcount (P01B: число пар [..] вперёд, скан без потребления,
флаг v2). k=0 — прежний v1-путь байт-в-байт; k>0 — глубина базы d+k
известна только после peek, поэтому эмит ОТКАТЫВАЕТ r12 и перепознаёт
prim на d+k, затем pp_pairs (P01C): на каждую пару — T-склад t(cur-1),
индекс на cur, хвост канона (shl r10,3 / mov r11,r10 / mov r10,[T] /
add r10,r11 / mov r10,[r10]); статы — need = 1 + max по цепочке.
**Astore** (S00D/Y00B): после имени pre-count пар; k=1 — база = имя
(emit_load), k>1 — цепочка базы pp_prim0(k) + pp_pairs(1, k-1);
пара/значение ПОРОЗНЬ через S0/S1/S2 (emit_sstore; флаг S-слотов —
бит 0 ftab: setb ИЛИ astore), затем хвост mov r10,[S0] / mov r11,[S1]
/ shl r11,3 / add / mov r11,[S2] / mov [r10],r11; maxd = max(need
базы, need индекса, need значения); имя-цель проверяет astore_chk
(P01D: локаль/параметр/var/массив; str/func/ext/неизвестное — ERR).
Условия if/while (p_cond, K2-P018):
дизъюнкты по `||`, внутри — сравнения по `&&`; m — предподсчёт числа
`||` в строке (скан без потребления); каждое сравнение — j<инв> на
lfail (`d<i+1>` при i<m, иначе lfalse), между дизъюнктами
`jmp $<pfx><k>t` + метка `d<i+1>`; m=1 — выход байт-в-байт как v1.
**Стек блоков (bstk):** записи 32 байта {kind(1/2/3/4), k, ifseq,
lineidx} — с E6.4c-3/2 (дефект №15): ранее 24 байта, из-за чего push if
затирал lineidx объемлющего while (неправильный комментарий обратного
прыжка). Площадь области не изменилась (0x18000): ёмкость 4096 -> 3072.

## Регистровые соглашения модуля

- `rbx` — свободен (не используется; строки адресуются от `strblob`);
  `r10` — база outbuf; `r12` — курсор вывода; `r13` — база :scalars
  (bstk[3072x32] + 65 скаляров, смещения — в bss);
  `rsi` — курсор текста; `r14`/`r15` — начало/конец строки; `rbp` — кадры.
- Подпрограммы сохраняют RSI,R10,R12,R13,R14,R15,RBP и могут менять
  RAX,RCX,RDX,RDI,R8,R9,R11 (уроки E6.4b: счётчики циклов — только в
  кадрах, NEVER в R8/R9/RAX через вызовы out_*/emit_*).
- Состояние — в :scalars (r13+X): curline, lineidx, tok_*, pc_*, st_*,
  lay_*, tmp1..8, счётчики таблиц; стек блоков — bstk в начале области.

## Данные (ветвь D)

- `kwtab` — 14 ключевых слов {имя(8Б), длина, код, 0}: E6.4c-3/2
  +break (индекс 0C) и +continue (индекс 0D) В КОНЕЦ таблицы;
- `jcctab/alutab/argtab` — {смещение в strblob, длина};
- `errtab` — 7 записей {смещение, длина, код, 0};
- `strblob` — единый блоб 113 строк канона (байт-точные из оракула),
  `strtab2` — {смещение, длина} по индексу (экономия меток brick:
  528 меток вместо 660+);
- импорты kernel32 (7 функций), hint-записи на чётных RVA (инвариант 7;
  калибровка DZ 2 после dll_name — прецедент E4a/E6.4c-1);
- bss 0x7A1418 — ЕДИНАЯ область :scalars (bstk 3072x32 + скаляры +
  ВСЕ буферы, база R13; E6.4c-3/1: метки буферов заменены смещениями
  r13+X — освобождено 14 записей labtab при пределе 512; E6.4c-3/2:
  записи bstk 24 -> 32 Б — дефект №15, ёмкость 4096 -> 3072);
  флаг v2 — скаляр [r13+18190] (ставится * / %, break/continue
  и цепочками && / || — E6.4c-3/3);
  буферы: filebuf 0x21000, outbuf 0x200000
  (2 МиБ: максимум вывода big_source 641237 Б x3 запас).

## Ограничения (снять в следующих этапах)

- Вход ≤ 256 КиБ и метки исходника ≤ 2048 записей labtab (пределы
  конвейера: enc 1 МиБ — E6.4d-4 (было 512 КиБ — E6.4f-1), brick
  E6.4f-2 512 КиБ/2048 меток; до этого E6.4e: 256 КиБ/1024): плоский
  wall.b2 = 138126 Б,
  меток исходника 528; каркас wall.wall (E6.4d-4/3b): плоский текст
  3011 строк / 107476 Б, .b2 775770 (73% предела enc 1 МиБ; срез C
  добавит ~150-250 КБ — подъём enc до 2 МиБ по образцу E6.4d-4/1 при
  ~85%), .brick 737556 (70% предела brick 1 МиБ — E6.4g-1), ТЕЛО
  60967/64К (93% — срез C добавит ~10-15 КБ: подъём предела тела
  brick 64К -> 128К ОБЯЗАТЕЛЕН до среза C — E6.4g-2), метки
  исходника 663/2048, метки выхода 663/2000;
  EXE каркаса 61952 Б.
  Меток в ВЫХОДЕ ≤ 2000 (nlab, E6.4d-3/3-1: было 500 при ёмкости brick
  512; цепочки с m>1 добавляют m: (m-1) d-метка + 1 t-метка) —
  проверяется в конце Y001, ERR=FORMAT строка 0; ёмкость brick 2048
  вкл. base -> запас 48; граница 2000/2001 защищена T-E6-50.
- Выход ≤ 2 МиБ (outbuf); большие программы потребуют потоковой записи.
- Индексация выражений-вызовов `(f(x))[0]`, `getb(...)[0]` и
  `(s)[0]`-скобочные базы поддержаны обёрткой (откат+перепознание).
- Самохостинг на WALL — E6.4d: проходы 0/1 ПОЛНЫ (все статы прохода 1
  реинкарнированы, E6.4d-3/3); проход 2 — срезы A+B ВЫПОЛНЕНЫ
  (E6.4d-4/3a — пролог: примитивы вывода wall_self_e.wall (курсор —
  глобаль outcur), блоб канона 2048 Б (wall_self_blob.wall —
  hex-литералы sd0..sd7, кириллица >= 0x80 невыразима в str-
  литерале; декодер blob_dec), pass2-пролог wall_self_y.wall
  (emit_header/imports/entry — E015/E026/E016; область вывода
  outmem 2103264 = блоб + scr 64 + outbuf 2 МиБ);
  E6.4d-4/3b — ФУНКЦИИ: wall_self_y.wall (p2_line Y002 +
  p2_funchdr Y00A + p2s_var/end/return Y003/Y004/Y008 +
  механика bstk if/while/else Y005/Y006/Y007) + НОВАЯ часть
  wall_self_f.wall (кадры E010/E011/E017/E018/E019).
  E6.4d-4/3c-1 — СЕКЦИИ ДАННЫХ: emit_cmt E009 + str_dlen E013 +
  str_emit E014 (+se_doline, esc_code) в wall_self_e.wall; НОВАЯ
  часть wall_self_d.wall (set_cmt + emit_strdata E027 +
  emit_globdata E028); глобали cmt_ptr/cmt_len корня; p2_line
  ставит их текущей строкой. Выход каркаса == оракулу байт-в-байт
  на классе «тела из var/голого return/end» — ЦЕЛИКОМ, ВКЛЮЧАЯ
  глобальные str/var (T-E6-52 + T-E6-54; dev wall_self_emit 3/3
  = 13 источников); статы-выражения — код 0 без эмитции (вне
  класса; bstk-механика сохраняет стек блоков). Статы и выражения
  (E020-E024, E02A-E02D, E034-E038, плечи P010..P018 в режиме
  эмитции) — срезы C-2+.
