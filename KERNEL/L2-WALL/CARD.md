# Карточка модуля M2-WALL (компилятор WALL v1)

Паспорт файла: KERNEL/L2-WALL/CARD.md | слой: L2 | роль: карточка модуля.

| Поле | Значение |
|---|---|
| ID модуля | M2-WALL |
| Слой | L2 (ЯЗЫК); исходник — BRICK v2 (M-строки, SPEC/09) с разрезом по !include (SPEC/10) |
| Назначение | Компилятор языка WALL v1/v2 (SPEC/11): исходник `.wall` -> текст BRICK v2 (`.b2`). Три прохода: полная лексика строк + карта текстов; разбор + таблицы имён + статистика кадров; эмитция канона SPEC/11 п.8. С E6.4c-3/1 понимает операторы `* / %`; с E6.4c-3/2 — `break`/`continue` (только в while; прочие v2-конструкции — ERR=FORMAT до своих срезов) и печатает заголовок «WALL v1/v2» по флагу v2. Выход байт-в-байт равен оракулу `LAB/py/lab_l2*.py` (правило R8, как enc в E6.2) |
| Вход | командная строка Windows: `wall.exe <вход.wall> <выход.b2>` |
| Выход | текст .b2 — детерминированный (канон эмиттера SPEC/11 п.8); коды 0 / 2 (мало аргументов) / 3 (имя > 127) / 4 (не открыт вход) / 5 (чтение) / 6 (`ERR=FORMAT AT=<строка>`) / 7 (вход > 128 КиБ) / 8 (выход не создан) / 9 (запись) |
| Размер | 24064 байта (0x5E00) |
| Платформа | Windows x64, консольная подсистема, PE32+ |
| Импорты | kernel32.dll: GetStdHandle, WriteFile, ExitProcess, GetCommandLineA, CreateFileA, ReadFile, CloseHandle |
| Самохостинг | Инструмент написан на BRICK v2 (как enc/splice); самохостинг НА языке WALL (wall.wall) — этап E6.4d: требует роста языка до v2 (массивы/память), см. ROADMAP |

## Формат вызова

```
wall.exe <вход.wall> <выход.b2>
```

Оба аргумента обязательны. Выход создаётся заново (CREATE_ALWAYS).
Полный цикл компиляции программы на WALL (DoD E6.4b, T-E6-28):

```
wall.exe  <программа>.wall  <программа>.b2
enc.exe   <программа>.b2    <программа>.brick
brick.exe <программа>.brick <программа>-body.bin
pegen.exe <программа>-body.bin <программа>.peg <программа>.exe
```

## Архитектура (три прохода)

1. **Проход 0 (ветви N):** разбиение текста на строки (LF/CRLF/CR — как
   re.split оракула), ПОЛНАЯ лексика каждой строки до стопа (`;`/конец),
   стоп-позиция и обрезанный текст строки -> `sm_arr[строка]` = {ptr, len}
   (карта текстов комментариев канона); lastnonempty; nlines (правило
   хвостового терминатора).
2. **Проход 1 (ветви S, режим статов):** разбор имён/утверждений;
   реестры ntab (имена), ftab (функции: nparams, maxd, maxc, flags
   setb/ext5, locoff, loccnt, строка заголовка), larr (параметры+локали),
   sarr (строки), varr (глобальные var), earr (ext); статистика
   T/C/S-слотов по правилам SPEC/11 п.5; ошибки всех проверок
   (main ровно одна, арности, дубликаты имён, структура блоков).
3. **Проход 2 (ветви Y + эмиттеры E, режим эмитции):** заголовок,
   фиксированная область импортов 0x200 (SPEC/11 п.6), вход, функции
   (пролог/эпилог/утверждения/выражения канона п.8), секции данных.

**Ключевая механика выражений:** левоассоциативные цепочки `a + b + c` и
`a << b << c` эмитятся БЕЗ построения AST: предварительный подсчёт числа
операций уровня (chain_count, K2-P009) задаёт глубину T-склада
`tdepth = d + K - 1`, убывающую с каждой операцией; первый операнд
генерируется на глубине `d + K`, правые — на `tdepth + 1`. Это точно
воспроизводит раскладку оракула (t(d+K-1)..t(d)). С E6.4c-3/1 между
конъюнкцией и унарным есть уровень `* / %` (p_mdm, K2-P01A) — тот же
механизм (chain_count ур.2); сравнения — терминаторы ЛЮБОЙ цепочки.
**Стек блоков (bstk):** записи 32 байта {kind(1/2/3/4), k, ifseq,
lineidx} — с E6.4c-3/2 (дефект №15): ранее 24 байта, из-за чего push if
затирал lineidx объемлющего while (неправильный комментарий обратного
прыжка). Площадь области не изменилась (0x18000): ёмкость 4096 -> 3072.

## Регистровые соглашения модуля

- `rbx` — свободен (не используется; строки адресуются от `strblob`);
  `r10` — база outbuf; `r12` — курсор вывода; `r13` — база :scalars
  (bstk[3072x32] + 65 скаляров, смещения — в bss);
  `rsi` — курсор текста; `r14`/`r15` — начало/конец строки; `rbp` — кадры.
- Подпрограммы сохраняют RSI,R10,R12,R13,R14,R15,RBP и могут менять
  RAX,RCX,RDX,RDI,R8,R9,R11 (уроки E6.4b: счётчики циклов — только в
  кадрах, NEVER в R8/R9/RAX через вызовы out_*/emit_*).
- Состояние — в :scalars (r13+X): curline, lineidx, tok_*, pc_*, st_*,
  lay_*, tmp1..8, счётчики таблиц; стек блоков — bstk в начале области.

## Данные (ветвь D)

- `kwtab` — 14 ключевых слов {имя(8Б), длина, код, 0}: E6.4c-3/2
  +break (индекс 0C) и +continue (индекс 0D) В КОНЕЦ таблицы;
- `jcctab/alutab/argtab` — {смещение в strblob, длина};
- `errtab` — 7 записей {смещение, длина, код, 0};
- `strblob` — единый блоб 113 строк канона (байт-точные из оракула),
  `strtab2` — {смещение, длина} по индексу (экономия меток brick:
  507 меток вместо 660+);
- импорты kernel32 (7 функций), hint-записи на чётных RVA (инвариант 7;
  калибровка DZ 2 после dll_name — прецедент E4a/E6.4c-1);
- bss 0x7A1418 — ЕДИНАЯ область :scalars (bstk 3072x32 + скаляры +
  ВСЕ буферы, база R13; E6.4c-3/1: метки буферов заменены смещениями
  r13+X — освобождено 14 записей labtab при пределе 512; E6.4c-3/2:
  записи bstk 24 -> 32 Б — дефект №15, ёмкость 4096 -> 3072);
  флаг v2 — скаляр [r13+18190] (ставится * / % и break/continue);
  буферы: filebuf 0x21000, outbuf 0x200000
  (2 МиБ: максимум вывода big_source 641237 Б x3 запас).

## Ограничения (снять в следующих этапах)

- Вход ≤ 128 КиБ (предел enc-конвейера; срез 2 исчерпал бюджет почти
  полностью: плоский wall.b2 = 130217 Б, запас до 0x20000 — 855 Б;
  срезы 3—5 потребуют роста пределов конвейера — кандидат E6.4e,
  см. журнал LAB/ai сессия 10); меток в ВЫХОДЕ ≤ 500 (предел
  brick) — проверяется, ERR=FORMAT строка 0. Метки в ИСХОДНИКЕ ≤ 511
  (labtab brick, вкл. предопределённую base): срез 2 — 507/511
  (запас 4: срезы 3—5 метки экономить; прецедент — замена bss-меток
  смещениями r13+X в E6.4c-3/1).
- Выход ≤ 2 МиБ (outbuf); большие программы потребуют потоковой записи.
- v2-конструкции СЛЕДУЮЩИХ срезов (массивы, && ||) ещё не поддержаны
  инструментом — ERR=FORMAT (срез 1: * / %; срез 2: break/continue).
- Самохостинг на WALL — E6.4d (нужен весь v2).

## Примеры

```
cmd -> KERNEL\L2-WALL\wall.exe
Вывод:   U-L2-WALL CMDS: WALL <SRC.WALL> <OUT.B2>   (40 байт, CRLF)
Код:     2

Компиляция + сборка DEMO (из папки KERNEL):
  L2-WALL\wall.exe   t.wall t.b2
  L1-ENC\enc.exe     t.b2 t.brick
  L1-BRICK\brick.exe t.brick t.bin
  L0-PEGEN\pegen.exe t.bin walldemo.peg t.exe
  t.exe -> печатает "U-WALL-OK 37", код 0 (T-E6-28)

Демо среза 1 (v2: * / %): a=6*7=42; b=42/5=8; c=42%5=2;
  v=b*10+c=82=0x52; печатает "U-MDM-OK 52", код 0
  (dev-тест LAB/ai/wall_test_v2.py, полный круг до эмуляции)

Демо среза 2 (v2: break/continue): сумма 1..20 без кратных 3,
  break при s > 30: s=37=0x25; печатает "U-BC-OK 25", код 0
  (dev-тест LAB/ai/wall_test_bc.py, полный круг до эмуляции)
```
