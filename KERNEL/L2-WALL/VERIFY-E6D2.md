## E6.4d-3/2 — выражения стат-режимом + статы return/setb/namestmt

Состояние на входе: E6.4d-3/1 закрыт, батарея 130/130 (протокол входа
выполнен). Задача — следующий под-шаг E6.4d-3: выражения P010..P01E
стат-режимом (общая зависимость return/setb/if/while) и статы S00B
return + S00C setb + S00D namestmt. Статы S008/S009/S00A/S00F
(bstk-механика) — следующий под-шаг 3/3.

### Что сделано

1. **Уровни выражений** (НОВАЯ часть wall_self_ph.wall, 77 строк;
   состав == wall_ph.b2 стат-плечи): p_expr (P010, '+', '-', '|',
   '^'), p_mul (P011, '&', '<<', '>>'), p_mdm (P01A, '*', '/', '%',
   ставит v2flag), p_unary (P012, унарный '-' — рекурсия на той же
   глубине). Курсор разбора — глобали pcur/ple (аналог pc_cur/R15
   wall.exe): заглядывание — tok_next(pcur, ple), потребление —
   pcur = tokend. Стат-механика: операнд на d+1, need =
   max(need, need_оп) + 1 на операцию; глубина d передаётся вниз для
   будущей эмитции, на need не влияет (как у wall.exe: chain_count —
   только эмит). Отличие (эквивалентно): v2flag := 1 (wall.exe — код
   операции; читается только «не ноль»).
2. **Первичные + индексация** (НОВАЯ часть wall_self_pp.wall, 215
   строк; состав == wall_pp.b2 + индексация wall_pi.b2): p_prim
   (P013-обёртка: prim0, peek '[', pp_strchk, pp_pcount, pp_pairs),
   pp_prim0 (P013a: число; '(' выр ')'; '&'имя — имя НЕ проверяется,
   emit_addr — проход 2; имя: getb(выр,выр) — need max+1, len(имя) —
   0, вызов — pc_extflg по виду ntab + p_args + call_stats, need =
   pc_argmax; имя-значение — 0, имя НЕ проверяется — emit_load
   проход 2; литерал/двухсимвольный символ — ERR), pp_pcount (P01B —
   скан без потребления, '[' глубины 0 — новая пара, стоп — EOL или
   односимвольный токен глубины 0 вне пары; k>0 — v2flag), pp_pairs
   (P01C — k пар '['выр']', c = 1 + max(c, need)), pp_strchk (P01E —
   корень базы: k '(', имя не getb/len, k ')'; локаль ок; str — ERR).
3. **Вызовы + astore-проверка** (НОВАЯ часть wall_self_pa.wall, 95
   строк; состав == wall_pa.b2 стат-плечи + astore_chk wall_pi.b2):
   p_args (P014: '()' | выр (',' выр)*; ')'), pa_stage (P017:
   pc_argcnt++, pc_argmax = max), call_stats (P016: ext — maxc =
   max(maxc, min(argcnt,4)), argcnt==5 — st_ext5; НЕ ext (вкл.
   неизвестное) — maxc = max(maxc, argcnt)), astore_chk (P01D:
   копия окна st -> lay, local_find; глобаль вид 1/5 ок; str/func/
   ext/неизвестное — ERR). Аккумуляторы pc_argcnt/pc_argmax/pc_extflg
   — аналоги tmp5/tmp6/pc_extflg wall.exe.
4. **local_find + хелперы экономии меток** (wall_self_pe.wall 371 ->
   434): local_find (P008) — окно lay_lo/lay_hi (в проходе 1 пусто;
   заполняет astore_chk копией st; проход 2 будет ставить своё —
   Y00A); max2(a,b) — каждый if-прыжок = метка в выходе .b2, а каркас
   у предела nlab 500 wall.exe; tok_is1(c) — «текущий токен =
   односимвольный символ c» для свёртки условий циклов. Предел меток
   решён в рамках шага: 526 -> 493/500 (свёртки условий в дизъюнкции
   конъюнкций, max2, замена инлайн-сканов окна дублей p1s_var/fh_param
   (E6.4d-3/1/2/4) на local_find — предикат тот же: длина +
   побайтовое сравнение).
5. **Статы S00B/S00C/S00D** (wall_self_p1s.wall 106 -> 184): p1s_
   return (выражение есть — p_expr(1) + maxd, иначе at_end), p1s_setb
   ('(' выр ',' выр ',' выр ')' + at_end + st_setb=1), p1_namestmt
   (имя из tokptr/tokend ДО потребления; peek '(' — вызов-утверждение
   p_args(1)+call_stats+at_end; peek '[' — astore: pp_pcount ->
   astore_chk -> k>1: база pp_prim0(k)+pp_pairs(1,k-1,0) -> последняя
   пара/значение порознь p_expr(1) -> maxd (max2) + st_setb=1;
   иначе — присваивание '=' p_expr(1) + at_end). Диспетчер p1_line
   (wall_self_p1.wall 123 -> 131): kw-плечи var(0)/end(4)/return(8)/
   setb(9) + ПРОЧЕЕ имя -> p1_namestmt — форма wall.exe (kw 5/6/7/C/D
   — else/if/while/break/continue — до E6.4d-3/3 попадают в
   namestmt: обычные формы дают ERR=FORMAT той же строки, патологи-
   ческие «KW = выр» / «KW(арг)» принимаются — источник вне класса).
6. **Дефект №18 (ЛАТЕНТНЫЙ, ПОЙМАН): s_sym2 каркаса без «>>».** Со
   времён E6.4d-2/2 строка s_sym2 = '==!=<=>=<<>&&||' (15 байт —
   транскрипция «>>» как «>&»+хвост) портила лексер каркаса: «>>»
   дробился на два односимвольных «>» (wall.exe даёт двухсимвольный
   «>>» спец-путём lt_gt; оракул _SYM2 содержит «>>»). Наружу не
   выходило: строки с «>>» до этого шага не доходили до разбора
   (статы-выражения не были реализованы, F7 был вне класса).
   Пойман канарейками F7/«скобки-сдвиги» (каркас ERR=FORMAT там, где
   wall.exe даёт код 0). Фикс: s_sym2 = '==!=<=>=<<>>&&||' (16 байт,
   8 пар — цикл k<8 сходится). Причина живучести: тесты T-E6-49c/d
   покрывали лексер только через ошибки лексера и статы вне класса.
7. **Модель класса + корпус** (lab_t_wallself.py 421 -> 200 + НОВЫЕ
