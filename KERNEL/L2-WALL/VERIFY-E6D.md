## E6.4d-2/2 — проход 0 на WALL: разбиение строк + лексика + карта текстов

Состояние на входе: E6.4d-2/1 закрыт, батарея 129/129. Задача —
под-шаг 2 из плана сессии 20 (журнал LAB/ai): реинкарнация ветви N
(K2-N001/N002/N003, wall_n.b2 + лексер K2-L001 из wall_l.b2) на WALL v2.

### Что сделано

1. **Разрез каркаса** (сплит — механизм SPEC/10, прецедент enc.b2):
   wall.wall (245 строк, у лимита 500) -> корень 124 строки (паспорт,
   ext/var/str, main) + `wall_self_c.wall` 147 (сервис: print_error,
   skip0, read_arg, widen) + `wall_self_n.wall` 262 (проход 0). Плоский
   текст 531 строка / 16334 байта (12% бюджета входа 128 КиБ); выход
   оракула 94853 байта. T-E6-49a компилирует СПРЯМЛЁННЫЙ текст
   (склейка — оракул lab_splice), полный круг enc+brick+pegen не
   изменился (T-E6-49b).
2. **Проход 0** (wall_self_n.wall, функции): pass0 — разбиение строк
   LF/CRLF/CR (терминаторов+1 записей, пустой вход = 1 запись;
   lineidx/curline инкрементируются ДО лексики строки — как line_next);
   lex_line — полная лексика до стопа: пробелы/табы/CR, ';' стоп,
   литерал с экранами n r t 0 \ ' (байты 0x20..0x7E, <= 512
   декодированных байтов), числа 0..2147483647 (переполнение ловится
   ПРИ накоплении — монотонность накопления делает эквивалент
   финальной проверки оракула), имена [A-Za-z_][A-Za-z0-9_]*,
   двухсимвольные == != <= >= << >> && || (таблица s_sym2) и
   односимвольные ()=,-+<>|&^![]*/% (s_sym1), иное — fail_format;
   затем обрезка [ls, stop) от пробелов/табов и запись карты текстов.
3. **Карта текстов** — smem = GlobalAlloc(0, 1048592): 16 Б на строку
   ([+0] смещение текста в srcbuf, [+8] длина), запись i по смещению
   16*i, индексация с 1 — зеркально sm_arr wall.exe (та же ёмкость
   65537 = математический максимум строк входа 128 КиБ). Отличие: в
   записи хранится СМЕЩЕНИЕ (не указатель) — чтение позже через
   getb(srcbuf, off+k); qword-запись в кучу — побайтовая stq (8 x setb
   со сдвигом shr), у языка нет qword-доступа по произвольному адресу.
4. **fail_format** — 'U-L2-WALL ERR=FORMAT AT=' (s_fmt, 24 байта,
   байт-точный из strtab2[0x1B] strblob) + 4 ЗАГЛАВНЫЕ hex-цифры
   (curline & 0xFFFF, таблица s_hexd = K2-D001 digits) + CRLF, код 6 —
   байт-в-байт как K2-G002+H001. Сборка в fmtbuf[64].
5. **Скаляры прохода**: srclen (глобаль — бывшая локаль got: ReadFile
   пишет в &srclen, обнуляется ДО вызова — дисциплина DWORD), lineidx,
   curline, nlentries, nlines (правило хвостового терминатора),
   lastnonempty. nlines/nlentries/lastnonempty пока не читаются
   (проходы 1/2) — заполняются зеркально N002.
6. **main**: после CloseHandle(src) — smem = GlobalAlloc(0, 1048592);
   NULL -> ERR=READ SRC код 5 (решение E6.4d-2/1 — новых кодов в
   CLI-контракт не вводится); затем pass0(); ЗАТЕМ CreateFile2(out) —
   порядок как у wall.exe: ошибки FORMAT старше OPEN OUT (путь
   проверен матрицей: источник с лекс-ошибкой и несуществующим выходом
   печатает FORMAT, не OPEN OUT).
7. **Эмулятор**: HEAP_SIZE 0x100000 -> 0x400000 (4 МиБ): srcbuf
   131073 + smem 1048592 = 1.13 МиБ не помещались в 1 МиБ; 4 МиБ
   покрывает и будущий outbuf 2 МиБ (решение сессии 20 исполнено
   досрочно). Заглушки не менялись.
8. **Батарея** (секция 12, `lab_t_wallself.py` 101 -> 218 строк):
   T-E6-49a — splice(корень) -> wall.exe == оракулу байт-в-байт;
   T-E6-49c — матрица CLI 13 -> **19 путей** (+CRLF/CR-разбиение с
   ошибкой в строке 3, +неизвестный экран, +незакрытая строка, +число
   больше 31 бита, +не-ASCII имя UTF-8, +успех «все виды лексем» —
   литерал со всеми экранами, массивы, индексация, цепочки);
   НОВЫЙ T-E6-49d — корпус 65 исходников (якоря v1 4+6, v2 2+7,
   ERRORS 26 + ERRORS2 13 без 2 не-ASCII, 7 микро: CR-разбиение /
   без хвостового перевода / только комментарий / пустой файл /
   литерал 512 и 513 байт / `==` в выражении, big_source 1203 +
   big_source2 705): лексер каркаса == оракулу _lex — источники с
   лекс-ошибкой дают код 6 и 'AT=%04X' той же строки, без — код 0 и
   пустой .b2. Не-ASCII источники из корпуса исключены (оракул _lex
   работает со str — кириллица для него имя; инструменты работают с
   байтами — отказ на лексе): такие случаи сверяются инструмент-в-
   инструмент в T-E6-49c (+1 путь). Батарея 129 -> **130** (~110 с).
9. **Реестры/документация**: MAP/INDEX (новые строки wall_self_c/
   wall_self_n/VERIFY-E6D, счётчики), MAP/M2-WALL (заметка E6.4d-2/2),
   CARD L2-WALL (состав каркаса), DOCS/02 (число проверок), DOCS/03
   (под-шаг 2/2 отмечен), LAB/README, README (статус), журнал (сессия
   21), этот файл. wall.exe НЕ менялся (SHA прежний; все круги
   самохостинга E5/E6.2/E6.3 зелёные).

### Решения (чтобы не передумать)

1. **Смещения вместо указателей в карте текстов**: чтение позже —
   getb(srcbuf, off+k); указатель потребовал бы хранения базы и
   вычитания при каждом чтении — смещение проще и не хуже.
2. **stq побайтовая**: единственный способ qword-записи по адресу в
   куче (setb); 16 setb на строку — для big_source2 (705 строк)
   копейки; переиспользуется проходами 1/2.
3. **Проверка «строка длиннее 512» в проходе 0** (как в оракуле _lex),
   а не в проходе 1 (как wall.exe str_dlen): литерал не переходит
   границу строк — номер строки и выход те же; каркас остаётся
   эквивалентен обоим.
4. **Разрез ДО исчерпания 500 строк**: оценка была ~480-485 — без
   запаса на правки; сплит снял ограничение роста (проход 1 заведомо
   больше 500).

### Найденное (не блокирует; учтено)

1. **Латентный дефект wall.exe (№17, очередь):** вход 131072 байта из
   одних LF даёт 131073 записи разбиения — sm_arr wall.exe рассчитан
   на 65537; записи поверх затирают начало ntab (bss). Следствие
   только для этого вырожденного входа (программ из одних переводов
   строк): поведение не определено. Оракул на том же входе даёт
   ошибку «нет main» со строкой 131073 ('%04X' печатает 5 цифр —
   маска & 0xFFFF у инструмента дала бы 0001) — формальное
   расхождение формата номера. Не тестировалось никем; каркас
   зеркалит поведение wall.exe (ёмкость та же). Исправление —
   отдельной итерацией при росте пределов (проверка nlentries).
2. **Различие оракул/инструмент на не-ASCII**: _lex(str) считает
   кириллицу именем (isalpha), инструмент байтов — недопустимым
   символом. Корпус T-E6-49d отфильтрован по ASCII; не-ASCII путь
   закрыт матрицей T-E6-49c (инструмент == инструмент). Задокументиро-
   вано в docstring lab_t_wallself.py.

## E6.4d-2/3 — проход 1 на WALL: читатели карты + объявления + пост-проверка main

Состояние на входе: E6.4d-2/2 закрыт, батарея 130/130. Задача — план
сессии 21 (журнал LAB/ai): читатели карты текстов (smem) и первые
кирпичи прохода 1 — S001 каркас, S002 диспетчер, S003 объявления.

### Что сделано

1. **Разрез** (3 новые части, слой за слоем — как части wall_*.b2):
   `wall_self_pe.wall` 371 (хелперы: getq, tok_next, kw_lookup,
   chk_name, names_find, names_find_ci, names_add, arr_size, at_end,
   want_id, want_sym1 — реинкарнации K2-L001 + P001..P007 + P019 +
   S005) + `wall_self_pd.wall` 97 (K2-S003 p1_decl: var/str/ext,
   порядок проверок == wall.exe) + `wall_self_p1.wall` 113 (K2-S001
   pass1 + K2-S002 p1_line + K2-N004 set_lastline). Корень 157 (было
   124: +16 скаляров состояния, s_kws, 3 !include, tabmem + pass1()).
   Плоский текст 1142 строки / 34762 байта (27% бюджета 128 КиБ);
   выход оракула 217071 байт.
2. **Читатели карты**: pass1 идёт по записям smem 1..nlentries (те же
   записи, что разбил проход 0 — wall.exe повторяет разбиение
   line_next'ом; записи идентичны), curline = номер записи до разбора
   строки; текст строки [t0, t0+t1) — getq(smem+16i / +16i+8) + getb.
   Токен-состояние — глобали tokptr/tokend/tokval (аналог 18060/18068/
   18058); курсор передаётся аргументами (у wall.exe — скаляр 18070).
3. **Диспетчер p1_line** — финальная форма wall.exe (порядок плеч):
   пусто (вид 4) — пропуск; не-имя — FORMAT; func (индекс 3) — FORMAT
   (заголовки S004 НЕ реализованы — шаг E6.4d-2/4; временное плечо,
   заменяется по мере роста); fcur (тело — статы S006+, шаг E6.4d-3) и
   seenfunc (между func — только func) — FORMAT. Объявления (до func)
   — p1_decl. kwtab — str s_kws (пробел-разделители, порядок 14 записей
   == kwtab wall_data.b2); kw_lookup сравнивает длину и байты.
4. **p1_decl**: var (want_id, chk_name, [n] 1..4096 — вид 5, флаг v2;
   at_end; дубликат names_find; varr {ntab_idx, размер}), str (want_id,
   chk_name, '=' 61, литерал вида 3 — litptr/litlen = содержимое БЕЗ
   кавычек, как 181E8/181F0; at_end; дубликат; sarr {ntab_idx, litptr,
   litln}), ext (want_id, chk_name(1), <= 31 байта ДО at_end — как
   wall.exe; дубликат names_find_ci; <= 8; earr {ntab_idx}).
5. **Пост-проверки pass1** (финальная форма, активируется ростом):
   незакрытый блок fdepth/fcur -> set_lastline + FORMAT; ftab-скан
   «ровно одна main без параметров»: namelen 4 + байты 'main' —
   mline/mparams; 1 с параметрами -> FORMAT в строке main (как
   S001/p1_mainchk); != 1 -> set_lastline + FORMAT. ftab пуст до S004
   -> «нет main» на последней непустой — зеркально wall.exe.
6. **Таблицы в куче** (DZ в теле невозможен из WALL — var глобали
   эмитятся DZ в data, тело ограничено 64 КиБ brick): tabmem =
   GlobalAlloc(0, 3539008), одна область, смещения в коде:
   ntab 32768x40 @ 0 (вида 5 нет до среза 4b-реинкарнации), varr
   32768x16 @ 1310720, sarr 16384x24 @ 1835008, ftab 16384x80 @
   2228224 {nameptr, namelen, nparams, maxd, maxc, flags, locoff,
   loccnt, hdrline, nslots} — 10 qword как ftab wall.exe, earr 8x8 @
   3538944. Доступ stq/getq (побайтовые, прецедент smem). Ёмкости —
   теоретический максимум входа 131072 Б с запасом: имена <= 21845
   (мин. «var x\n» 6 Б; ёмкость 32768), func <= 13107 («func f\nend\n»
   10 Б; 16384), str <= 14563 («str s=''\n» 9 Б; 16384); проверок
   переполнения НЕТ, как у wall.exe (кроме ext <= 8 — SPEC/11 п.6).
7. **Отличия от wall.exe (выход эквивалентен, задокументировано)**:
   (а) tok_next работает по тексту из smem (без ';' — проход 0 срезал):
   стоп — только конец текста, ';' в тексте не бывает; (б) tok_next не
   повторяет проверки литералов (байты 0x20..0x7E, экраны) — текст
   провалидирован в проходе 0; число 31 бит — проверяется (lt_nbig);
   (в) НЕТ str_dlen/E013: <= 512 проверено в проходе 0 (slen); у
   wall.exe — в проходе 1; литерал не переходит границу строк — строка
   ошибки та же; (г) no-op ветки нет — первая буква chk_name тремя if
   (эквивалент цепочки cmp P005).
8. **Эмулятор**: HEAP_SIZE 0x400000 -> 0x800000 (8 МиБ): srcbuf 131073
   + smem 1048592 + tabmem 3539008 = 4.72 МиБ; 8 МиБ покрывает и
   будущий outbuf 2 МиБ (прецедент решения 2/2 — поднятие кучи).
9. **Батарея** (секция 12; T-E6-49d переопределён с _lex на parse,
   число проверок батареи НЕ менялось — 130):
   T-E6-49c — матрица: пути «успех» заменены на «нет main» (вар g /
   все виды объявлений / граница 131072 — оба инструмента дают
   AT=0002); «пустой .b2»-утверждение снято (каркас до S004/S006+ не
   бывает кода 0 — класс задокументирован). T-E6-49d — ТРИ стороны:
   оракул parse (_expect_line: лекс-ошибка | parse-ошибка L при
   первой строке-func >= L | принято без func -> last_line) против
   каркаса И инструмента wall.exe; корпус 91 = 65 прежних + 26 микро
   объявлений (все спот-чеки сессии: дубликаты, [0]/[n]/[5000]/[4097],
   9 ext, 32 байта, не-ключевое, end наверху, var 5, _x, X, 64 байта,
   str без =, = 1, лишний токен, переводы строк, main(x), незакрытый
   блок); 42 доступно / 49 пропущено (func-класс). Прогон: 130/130.
   Замеры: тело каркаса 23615/65536 (36%), меток 356/1024, .brick
   202839/262144 (77%), .b2 217071 (вход enc <= 256 КиБ — 85%).
10. **Реестры/документация**: CARD (состав + самохостинг), MAP/INDEX
    (+3 части, счётчики), MAP/M2-WALL (заметка), DOCS/03 (под-шаг
    2/3), LAB/README + README (статус), журнал (сессия 22), этот файл.
    wall.exe НЕ менялся (SHA прежний — T-E6-30; круги E5/E6.2/E6.3
    зелёные).

### Решения (чтобы не передумать)

1. **Нереализованные плечи диспетчера = FORMAT на текущей строке**:
   монотонный рост класса эквивалентности (каждый следующий шаг
   заменяет fail_format на реальный разбор; диспетчер больше НЕ
   переписывается). Источник с func до точки решения даёт расходящийся
   с wall.exe номер строки — класс зафиксирован в _expect_line и
   VERIFY; при S004/S006+ класс сузится до «пропущено 0».
2. **Курсор аргументами, а не скаляром**: у WALL есть вызовы с <= 4
   аргументами — явный (pos, le) чище скрытой глобали; токен-спан —
   глобали (как 18060/18068 — нужен многим).
3. **Таблицы одной областью tabmem**: один GlobalAlloc (8-й ext занят
   с 2/1 — новых ext не вводим); смещения в коде — прецедент r13+X.
4. **arr_size возвращает размер, глобали aspos/asflag**: два
   результата (размер + признак + курсор) — возврат один, остальное
   глобали (аналог RAX/RDX у wall.exe).

### Найденное (не блокирует; очередь)

1. **Рост .brick/.b2 каркаса**: 202839/262144 (77%) входа brick и
   217071/262144 (85%) входа enc; S004+статы+проход 2 добавят столько
   же — потребуется подъём пределов конвейера (прецедент E6.4e
   128 -> 256 КиБ) ИЛИ потоковая запись. Следить на каждом шаге.
2. Дефект №15 brick (DZ после DBZ), №17 wall.exe (LF-131072), ревизия
   счётчиков METHODS.md, реестр образов SPEC/04 — перенесены (очередь
   с шага 2/2).
3. **Инструмент vs оракул на «func в теле»**: p1_line wall.exe
   отправляет func в funchdr ЛЮБОЙ строкой (плечо kw==3 раньше
   fcur-плеча) — оракул в теле ждёт статы и падает на «func x»
   иначе; источник «func f\nfunc g\nend\nend\n» — проверить при
   реинкарнации S004 (E6.4d-2/4): ожидаем расхождение формулировки,
   не строки (оба дадут FORMAT на строке 2... у оракула «не разобрано»
   на строке 2, у wall.exe — приём g как вложенной func). Вынесено
   в журнал; НЕ влияет на класс 2/3 (func-строки пропущены).

### Что дальше (E6.4d-2/4)

S004 p1_funchdr на WALL (заголовки: имя, <= 4 параметров, дубликаты
параметров, larr-окно, bstk push kind 1, ftab-запись 80 Б, seenfunc/
fcur = 1) + S007-плечо end закрывает func (fcur = 0, финальная запись
ftab) — тогда «main с параметром» и «нет main» станут точными (не
совпадением строк), а класс расширится на все источники с func.
Затем E6.4d-3: статы S006+ (var-локаль, end/else, if/while, return,
setb, namestmt) и пост-проверка незакрытого блока (bstk).
