## E6.4d-2/2 — проход 0 на WALL: разбиение строк + лексика + карта текстов

Состояние на входе: E6.4d-2/1 закрыт, батарея 129/129. Задача —
под-шаг 2 из плана сессии 20 (журнал LAB/ai): реинкарнация ветви N
(K2-N001/N002/N003, wall_n.b2 + лексер K2-L001 из wall_l.b2) на WALL v2.

### Что сделано

1. **Разрез каркаса** (сплит — механизм SPEC/10, прецедент enc.b2):
   wall.wall (245 строк, у лимита 500) -> корень 124 строки (паспорт,
   ext/var/str, main) + `wall_self_c.wall` 147 (сервис: print_error,
   skip0, read_arg, widen) + `wall_self_n.wall` 262 (проход 0). Плоский
   текст 531 строка / 16334 байта (12% бюджета входа 128 КиБ); выход
   оракула 94853 байта. T-E6-49a компилирует СПРЯМЛЁННЫЙ текст
   (склейка — оракул lab_splice), полный круг enc+brick+pegen не
   изменился (T-E6-49b).
2. **Проход 0** (wall_self_n.wall, функции): pass0 — разбиение строк
   LF/CRLF/CR (терминаторов+1 записей, пустой вход = 1 запись;
   lineidx/curline инкрементируются ДО лексики строки — как line_next);
   lex_line — полная лексика до стопа: пробелы/табы/CR, ';' стоп,
   литерал с экранами n r t 0 \ ' (байты 0x20..0x7E, <= 512
   декодированных байтов), числа 0..2147483647 (переполнение ловится
   ПРИ накоплении — монотонность накопления делает эквивалент
   финальной проверки оракула), имена [A-Za-z_][A-Za-z0-9_]*,
   двухсимвольные == != <= >= << >> && || (таблица s_sym2) и
   односимвольные ()=,-+<>|&^![]*/% (s_sym1), иное — fail_format;
   затем обрезка [ls, stop) от пробелов/табов и запись карты текстов.
3. **Карта текстов** — smem = GlobalAlloc(0, 1048592): 16 Б на строку
   ([+0] смещение текста в srcbuf, [+8] длина), запись i по смещению
   16*i, индексация с 1 — зеркально sm_arr wall.exe (та же ёмкость
   65537 = математический максимум строк входа 128 КиБ). Отличие: в
   записи хранится СМЕЩЕНИЕ (не указатель) — чтение позже через
   getb(srcbuf, off+k); qword-запись в кучу — побайтовая stq (8 x setb
   со сдвигом shr), у языка нет qword-доступа по произвольному адресу.
4. **fail_format** — 'U-L2-WALL ERR=FORMAT AT=' (s_fmt, 24 байта,
   байт-точный из strtab2[0x1B] strblob) + 4 ЗАГЛАВНЫЕ hex-цифры
   (curline & 0xFFFF, таблица s_hexd = K2-D001 digits) + CRLF, код 6 —
   байт-в-байт как K2-G002+H001. Сборка в fmtbuf[64].
5. **Скаляры прохода**: srclen (глобаль — бывшая локаль got: ReadFile
   пишет в &srclen, обнуляется ДО вызова — дисциплина DWORD), lineidx,
   curline, nlentries, nlines (правило хвостового терминатора),
   lastnonempty. nlines/nlentries/lastnonempty пока не читаются
   (проходы 1/2) — заполняются зеркально N002.
6. **main**: после CloseHandle(src) — smem = GlobalAlloc(0, 1048592);
   NULL -> ERR=READ SRC код 5 (решение E6.4d-2/1 — новых кодов в
   CLI-контракт не вводится); затем pass0(); ЗАТЕМ CreateFile2(out) —
   порядок как у wall.exe: ошибки FORMAT старше OPEN OUT (путь
   проверен матрицей: источник с лекс-ошибкой и несуществующим выходом
   печатает FORMAT, не OPEN OUT).
7. **Эмулятор**: HEAP_SIZE 0x100000 -> 0x400000 (4 МиБ): srcbuf
   131073 + smem 1048592 = 1.13 МиБ не помещались в 1 МиБ; 4 МиБ
   покрывает и будущий outbuf 2 МиБ (решение сессии 20 исполнено
   досрочно). Заглушки не менялись.
8. **Батарея** (секция 12, `lab_t_wallself.py` 101 -> 218 строк):
   T-E6-49a — splice(корень) -> wall.exe == оракулу байт-в-байт;
   T-E6-49c — матрица CLI 13 -> **19 путей** (+CRLF/CR-разбиение с
   ошибкой в строке 3, +неизвестный экран, +незакрытая строка, +число
   больше 31 бита, +не-ASCII имя UTF-8, +успех «все виды лексем» —
   литерал со всеми экранами, массивы, индексация, цепочки);
   НОВЫЙ T-E6-49d — корпус 65 исходников (якоря v1 4+6, v2 2+7,
   ERRORS 26 + ERRORS2 13 без 2 не-ASCII, 7 микро: CR-разбиение /
   без хвостового перевода / только комментарий / пустой файл /
   литерал 512 и 513 байт / `==` в выражении, big_source 1203 +
   big_source2 705): лексер каркаса == оракулу _lex — источники с
   лекс-ошибкой дают код 6 и 'AT=%04X' той же строки, без — код 0 и
   пустой .b2. Не-ASCII источники из корпуса исключены (оракул _lex
   работает со str — кириллица для него имя; инструменты работают с
   байтами — отказ на лексе): такие случаи сверяются инструмент-в-
   инструмент в T-E6-49c (+1 путь). Батарея 129 -> **130** (~110 с).
9. **Реестры/документация**: MAP/INDEX (новые строки wall_self_c/
   wall_self_n/VERIFY-E6D, счётчики), MAP/M2-WALL (заметка E6.4d-2/2),
   CARD L2-WALL (состав каркаса), DOCS/02 (число проверок), DOCS/03
   (под-шаг 2/2 отмечен), LAB/README, README (статус), журнал (сессия
   21), этот файл. wall.exe НЕ менялся (SHA прежний; все круги
   самохостинга E5/E6.2/E6.3 зелёные).

### Решения (чтобы не передумать)

1. **Смещения вместо указателей в карте текстов**: чтение позже —
   getb(srcbuf, off+k); указатель потребовал бы хранения базы и
   вычитания при каждом чтении — смещение проще и не хуже.
2. **stq побайтовая**: единственный способ qword-записи по адресу в
   куче (setb); 16 setb на строку — для big_source2 (705 строк)
   копейки; переиспользуется проходами 1/2.
3. **Проверка «строка длиннее 512» в проходе 0** (как в оракуле _lex),
   а не в проходе 1 (как wall.exe str_dlen): литерал не переходит
   границу строк — номер строки и выход те же; каркас остаётся
   эквивалентен обоим.
4. **Разрез ДО исчерпания 500 строк**: оценка была ~480-485 — без
   запаса на правки; сплит снял ограничение роста (проход 1 заведомо
   больше 500).

### Найденное (не блокирует; учтено)

1. **Латентный дефект wall.exe (№17, очередь):** вход 131072 байта из
   одних LF даёт 131073 записи разбиения — sm_arr wall.exe рассчитан
   на 65537; записи поверх затирают начало ntab (bss). Следствие
   только для этого вырожденного входа (программ из одних переводов
   строк): поведение не определено. Оракул на том же входе даёт
   ошибку «нет main» со строкой 131073 ('%04X' печатает 5 цифр —
   маска & 0xFFFF у инструмента дала бы 0001) — формальное
   расхождение формата номера. Не тестировалось никем; каркас
   зеркалит поведение wall.exe (ёмкость та же). Исправление —
   отдельной итерацией при росте пределов (проверка nlentries).
2. **Различие оракул/инструмент на не-ASCII**: _lex(str) считает
   кириллицу именем (isalpha), инструмент байтов — недопустимым
   символом. Корпус T-E6-49d отфильтрован по ASCII; не-ASCII путь
   закрыт матрицей T-E6-49c (инструмент == инструмент). Задокументиро-
   вано в docstring lab_t_wallself.py.
