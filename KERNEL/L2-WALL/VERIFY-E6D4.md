# VERIFY-E6D4 — журнал шага E6.4d-4/3: проход 2 каркаса, срезы B, C-1, C-2/1

Паспорт файла: KERNEL/L2-WALL/VERIFY-E6D4.md | слой: L2 | роль: журнал
верификации срезов B (эмитция ФУНКЦИЙ), C-1 (СЕКЦИИ ДАННЫХ) и C-2/1
(ВЫРАЖЕНИЯ return эмит-режимом) каркасом wall.wall. (Срез A —
VERIFY-E6D2.md, раздел эмитции.)

## Контекст

Срез A (E6.4d-4/3a) закрыл пролог эмитции: примитивы вывода, блоб
канона, заголовок/импорты/вход; канарейка — точный префикс оракула
до строки int3 входа (T-E6-52). Срез B — следующий вертикальный
срез прохода 2: ФУНКЦИИ (заголовок func -> пролог, end -> эпилог,
локали var, return) + цикл строк + bstk-механика if/while/else.
Верификационная ГРАНИЦА среза: класс источников, тела которых
содержат только var / голый return / end — для них выход каркаса
обязан совпадать с выходом оракула байт-в-байт ЦЕЛИКОМ (если нет
глобальных str/var — секции данных ещё не эмитятся) или быть
ТОЧНЫМ ПРЕФИКСОМ до секции «; --- данные: ...». Источники с
прочими статами тел компилируются (код 0), но статы не эмитятся —
вне класса среза (срез C).

## Решения (чтобы не передумывать)

1. **Граница класса среза B** — «тела из var/голого return/end»:
   выход == оракулу ЦЕЛИКОМ (без данных); прочие статы — код 0 без
   эмитции (bstk-механика цела — регресс в dev и T-E6-49d).
2. **Механика вместо пропуска:** if/while/else пушат/мутируют bstk
   (как wall.exe), иначе «end» читал бы чужие записи. Голой return
   эмитит эпилог сразу — поведение полно уже в B.
3. **Не эмитятся (до среза C):** guard-условия, метки закрытия,
   выражения, srctxt, секции данных, lay-окна.
4. **Тело 93% — снято E6.4g-2** (предел тела 128 КиБ).
5. **Сжатие документации:** завершённые записи этапов сжаты в
   сводки, детали — здесь и в LAB/ai/JOURNAL.md.

## Срез C-1 (E6.4d-4/3c-1): СЕКЦИИ ДАННЫХ

Контекст: срезы A+B эмитят пролог и функции, но выход обрывается
префиксом у секции «; --- данные: ...» — секции данных (строки и
глобальные var) не эмитятся. Срез C по плану сессий 31/32 слишком
велик для одной сессии — разбит на части: C-1 (данные — этот шаг),
C-2 (выражения эмит-режимом), C-3 (guard-статы if/while/else/
break/continue + setb/astore). Верификационная ГРАНИЦА C-1: класс
срезов A+B (тела из var / голого return / end) — выход == оракулу
ЦЕЛИКОМ при ЛЮБЫХ глобальных str/var (префикс больше не нужен).

1. **wall_self_e.wall (174 -> 280 строк) — примитивы данных:**

     строка — НОВЫЕ глобали cmt_ptr/cmt_len корня (аналог
     [r13+181A0/181A8] wall.exe); текущую строку ставит p2_line,
     строку объявления — set_cmt;

## E6.4d-4/3c-2/2 + дефект №21 (срез C часть 2 шаг 2: вызовы/getb/индексация)

батарея 136/136. Класс полного выхода расширен на return <выражение>

### Что сделано (E6.4d-4/3c-2/2)

1. **ДЕФЕКТ №21 (НАЙДЕН И ЗАКРЫТ, синхронно wall.exe + каркас):**
   pc_staged хранил только СЧЁТ застейдженных аргументов без базы
   вызова — при ДВОЙНОЙ вложенности (вызов в аргументе вызова,
   сам имеющий base > 0) внутренний вызов получал базу 0: его
   стейджинг затирал C-слоты объемлющего, а maxc/framesize
   занижались. Спецификация (SPEC/11 п.5, фикс №19) и оракул
   (lab_l2_lay._call: ccur = base + i - 1) требуют base+staged.
   Якорь: f(g(h(1), 2), h(g(3, h(4)))) — maxc 2 -> 3, кадр main
   0x40 -> 0x50; стейджинг g уходит в C2/C3 (не затирает C1
   объемлющего f). НЕ ЛОВИЛСЯ с E6.4d-4/2: все источники корпуса
   (DEMO_NEST, cases) — вложенность не глубже 2 уровней, где
   объемлющий всегда base 0 (различие не проявляется). Фикс
   wall_pa.b2 P014 (+3 M-строки, тело 27326 -> 27338 = +0xC):
   вход pc_staged := base (было 0), на каждый аргумент pc_staged :=

   пересборка wall_build.py: SHA 81DB0498… -> 295730EF…, idata
   79A2 -> 79AE; карта ветвей BYTECODE.md переведена
   bytecode_rows.py (+75 строк; попутно закрыт ДРЕЙФ hints-строки
   и arr_size/p_prim/p_args-строк эпохи №20 — старые RVA были
