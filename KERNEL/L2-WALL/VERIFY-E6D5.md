# VERIFY-E6D5 — журнал финала E6.4d: фикс-пункт и замена артефактов

Паспорт файла: KERNEL/L2-WALL/VERIFY-E6D5.md | слой: L2 | роль: протокол
закрытия этапа E6.4d — доказательство фикс-пункта самосборки (E6.4d-5/3-1,
сессия 42) и замена артефактов модуля сборкой из wall.wall (E6.4d-5/3-2,
сессия 43). Продолжение VERIFY-E6D4.md.

## Контекст

Сессия 42 доказала фикс-пункт: круг wall.wall -> s1.b2 -> enc -> s.brick ->
brick -> pegen -> s1.exe, затем s1.exe(wall.wall) = s2.b2 == s1.b2
байт-в-байт (548 385 615 шагов, дважды, детерминизм подтверждён). DoD
этапа «wall(wall.wall) воспроизводит собственный .b2» выполнен; замена
артефактов разблокирована. Diff-анализ порядка функций (часть B
wall_self_diff.py): общих 78, LCS 35, инверсий 651, полное выравнивание
недостижимо (разные множества функций: 39 только в каркасе / 16 только
в старом каноне).

## Решения (E6.4d-5/3-2)

1. **Перестановка include-порядка каркаса — НЕ ДЕЛАЕТСЯ** (окончательно).
   Обоснование: фикс-пункт от порядка функций не зависит (порядок выхода
   = порядок func в исходнике); навигация идёт по частям wall_self_*.wall
   (CARD.md); новый wall.b2 — ГЕНЕРИРУЕМЫЙ артефакт, его чтение — не
   рабочий процесс. Данные для решения — wall_self_diff.py, часть B.
2. **Артефакты модуля — сборка из wall.wall** (источник истины —
   KERNEL/L2-WALL/wall.wall, корень + 18 частей; компилятор — сам
   wall.exe; конвейер — CARD.md «Контроль воспроизведения»):
   - wall.b2 := сборка (1 009 314 Б, SHA-256 0FE267F9A24ECA91F874EFB4
     C2EE2D71883D2282BA85C4E1FBD05C4EC191A1C4) — плоский, генерируемый;
   - wall.brick := enc(wall.b2) (956 497 Б, SHA-256 76194F086F444CBB
     B37D4275723D6BC0AC997653BC96D4AB2276A251AFC504FF);
   - wall.exe := brick+pegen+wall.peg (87 040 Б, SHA-256 FE41C2B77C6759
     FB9F7D08FDF561D7799F04BDD70387C7307EFFBE1D61482BC3);
   - wall.peg := КОНСТАНТА SPEC/11 п.6 (!module wall; !entry 1200;
     !idata 1000 28; !iat 1028 48; !stackcom/heapcom 4000). Прежний
     wall.peg содержал адреса СТАРОГО образа (entry 1000, idata 79AE,
     iat 79D6, bss 7E2418) — для программы, скомпилированной WALL,
     правильна константа (SPEC/11 п.6: обёртка PEG постоянна, !bss не
     нужен — глобальные var эмитятся DZ в теле).
3. **Отклонение от плана сессии 42** (запланирован был бинар s1.exe,
   SHA-16 DAE4933716B76D80): s1.exe собирался кругом с DEMO_WALL_PEG
   (!module walldemo) — pegen записывает имя модуля в DOS-заглушку
   («Universal L0 walldemo. No DOS support.»). Финальный артефакт
   собран с wall.peg (!module wall) — отличается от s1.exe ТОЛЬКО
   22 байтами DOS-заглушки (0x40..0x80); тело/код байт-в-байт
   идентичны, поэтому фикс-пункт переносится на финальный бинар —
   и доказан им самим (T-E6-49a: см. ниже).
4. **Старые части wall_*.b2 (20 файлов) удалены.** Они были источником
   СТАРОГО wall.exe (BRICK v2, ручная сборка каркаса до E6.4d);
   источник истины теперь wall.wall. История — в git (коммит до
   E6.4d-5/3-2) и в картах VERIFY-E6D*.md. Реинкарнации переносили
   алгоритмы, не байты — потерь нет.

## Изменения батареи (синхронно с артефактами)

1. lab_verify.py: SHA-256 wall.exe (секция 1); фильтр «точка входа !=
   0x1000» для L2-WALL в t_pe_invariants — вход 0x1200 — документированное
   отклонение SPEC/11 п.6 (тот же фильтр, что в T-E6-30).
2. lab_t_wall2.py: WALL_SHA; T-E6-30 — цепочка импортов ВОСЬМЁРКА
   (CreateFile2 + GlobalAlloc вместо CreateFileA; последняя —
   GlobalAlloc, 8 записей).
3. lab_t_exe.py: T-E6-17 — splice-корень модуля wall.wall (прежде
   wall.b2): wall.b2 теперь плоский ~1 МБ — выше предела входа splice
   256 КиБ; крупнейший потребитель пределов — корень каркаса
   (19 частей, склейка 168 050 Б).
4. lab_t_wallself.py: T-E6-49a — теперь ФИКСПУНКТ (wall.exe — самосборный,
   компиляция wall.wall им самим ~0.55 млрд шагов — выше дефолтного
   лимита lab_run 200 млн: прямой вызов lab_win.Machine.run(
   max_steps=2 млрд), приём wall_self_diff.py) и сверка не только с
   оракулом, но и с АРТЕФАКТОМ wall.b2; T-E6-49b — обёртка wall.peg
   (вместо DEMO_WALL_PEG) и побайтовая сверка s.brick == wall.brick,
   s.exe == wall.exe — АРТЕФАКТЫ ВОСПРОИЗВОДИМЫ из wall.wall в каждом
   прогоне батареи.
5. LAB/ai/wall_self_canary.py: сборка каркаса — прямой lab_win с лимитом
   2 млрд (та же причина) и обёртка wall.peg.

## DoD этапа E6.4d — ВЫПОЛНЕН

«wall(wall.wall) воспроизводит собственный .b2; полный круг
wall.wall -> ... -> wall.exe совпадает с артефактом» — доказано
фикс-пунктом (сессия 42) и закреплено в батарее навсегда (T-E6-49a/49b,
каждый пуш). Ядро UNIVERSAL самодостаточно: компилятор языка WALL
написан на самом WALL и собирает себя.
