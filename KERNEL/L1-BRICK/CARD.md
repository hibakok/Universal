# Карточка модуля M1-BRICK (ассемблер BRICK v1: ссылки поверх байтов)

Паспорт файла: KERNEL/L1-BRICK/CARD.md | слой: L1 | роль: карточка модуля.

| Поле | Значение |
|---|---|
| ID модуля | M1-BRICK |
| Слой | L1 (СБОРКА); исходник тела — ATOM L0 (телесная форма) |
| Назначение | Ассемблер формата BRICK v1 (SPEC/08): метки, имена, автоматический расчёт rip-смещений и rel-переходов. Ручной счёт адресов прекращается: смещения, disp32 и rel8/rel32 вычисляет инструмент. Кодировки байтов инструкций по-прежнему назначает автор (реестр SPEC/05) |
| Вход | командная строка Windows: `brick.exe <вход.brick> <выход.bin>` |
| Выход | тело секции (RVA 0x1000 = смещение 0); код возврата 0 (успех) / 2 (мало аргументов) / 3 (имя длиннее 127) / 4 (вход не открыт) / 5 (ошибка чтения) / 6 (плохой формат, `AT=<строка>`) / 7 (вход больше 128 КиБ) / 8 (выход не создан) / 9 (ошибка записи) / 10 (тело больше 64 КиБ) |
| Размер | 3584 байта (0xE00) |
| Платформа | Windows x64, консольная подсистема, PE32+ |
| Импорты | kernel32.dll: GetStdHandle, WriteFile, ExitProcess, GetCommandLineA, CreateFileA, ReadFile, CloseHandle |
| Самохостинг | `brick.exe brick.brick self.bin` воспроизводит собственное тело байт-в-байт (DoD E5) |

## Формат вызова

```
brick.exe <вход.brick> <выход.bin>
```

Оба аргумента обязательны. Вход — BRICK v1 (грамматика: `SPEC/08-BRICK-FORMAT.md`).
Выход создаётся заново (CREATE_ALWAYS). Полный цикл сборки модуля:

```
brick.exe <модуль>.brick  <модуль>-body.bin
pegen.exe  <модуль>-body.bin  <модуль>.peg  <модуль>.exe
```

## Строгость разбора

- Принимается всё, что удовлетворяет грамматике SPEC/08: метки, H/DB/DZ/DBZ/DD/DQ,
  ссылки `$имя` / `$имя:1`, комментарии `;`, пустые строки, CRLF, ЗАГЛАВНЫЕ hex-цифры.
- Отвергается (код 6, с номером строки в hex): посторонний символ; строчная
  hex-цифра; одиночная цифра байта; имя длиннее 63 или с посторонними символами;
  суффикс `:1` с иной цифрой; ссылка в DB; ссылка не в конце строки H; пустые
  DB/DD/DQ; дубликат метки (включая `:base`); неопределённая метка; rel8 вне
  −128..127; неизвестная директива; мусор в хвосте строки.
- Не проверяется (ответственность исходника): корректность кодировок инструкций,
  достижимость меток, попадание RVA в секцию.

## Состав (что читать для работы с модулем)

| Файл | Назначение |
|---|---|
| `brick.hex` | исходник тела секции в формате ATOM v1, телесная форма (истина для E5-бутстрапа) |
| `brick.brick` | тот же источник в формате BRICK v1 — канонический исходник; равносилен brick.hex байт-в-байт |
| `brick.peg` | управляющий файл обёртки (PEG v1, SPEC/07) |
| `brick.exe` | материализация: hexgen+pegen над brick.hex/brick.peg, байт-в-байт |
| `BYTECODE.md` | сводка образа, карта кирпичей, данные, импорты, виртуальные нули |
| `VERIFY.md` | SHA-256, четыре уровня проверки, журнал пойманных ошибок |

## Кирпичи модуля (карточки — MAP/M1-BRICK.md)

```
Поток исполнения:
  K1-X001 prepare_stack        (кадр 0x38)
  K1-S001 get_image_base       (lea rbx,[rip+base]; RBX = RVA 0)
  init                         (GetStdHandle -> hstdout; init таблицы меток: base)
  K1-C001 get_cmdline          (GetCommandLineA)
  K1-C002 skip_argv0           (кавычки, разделители)
  K1-G001 dispatch             (главный поток: чтение, 2 пассажа, запись)
  K1-X002 exit_code            (ExitProcess(0) + int3)
Командная строка:
  K1-C003 next_arg             (аргумент целиком; диагностика длинного имени)
  K1-C004 read_word            (границы слова)
  K1-C005 copy_word_dst        (копирование в буфер R8, предел 127)
  K1-C006 skip_seps            (пробелы/табуляции, RDI)
Сборка (новая ветвь A):
  K1-A001 assemble_pass        (главный цикл строк; RBP=пассаж, R10=старт, R15=файловая длина)
  K1-A002 parse_h              (строка-байтов со слотом $имя/$имя:1)
  K1-A003 parse_db             (байты данных без ссылок)
  K1-A004 parse_dz             (нули в файл; пассаж 1 не пишет)
  K1-A005 parse_ddq            (DD/DQ: числа и RVA-ссылки; ширина в R11D)
  K1-A006 emit_le              (значение -> 4/8 байт LE)
  K1-A007 read_hex_byte        (2 ЗАГЛАВНЫЕ цифры -> байт | −1)
  K1-A008 parse_data           (диспетчер DB/DBZ/DZ/DD/DQ)
  K1-A009 expect_eol           (строгий хвост строки)
  K1-A010 parse_dbz            (виртуальные нули: курсор без записи)
Лексика (новая ветвь T):
  K1-T001 skip_seps_rsi        (пробелы/табуляции, RSI)
  K1-T002 hex_digit            (символ -> 0..15 | −1; строго ЗАГЛАВНЫЕ)
  K1-T003 read_hexval          (1..8 цифр -> значение | −1)
  K1-T004 read_name            ([a-z0-9_]+ -> адрес/длина; пределы 1..63)
Таблица меток (новая ветвь N):
  K1-N001 define_label         (дубликаты, предел 512; запись {адрес, длина, значение})
  K1-N002 find_label           (линейный поиск; R11 сохраняется)
Печать:
  K1-H001 hex16_to_4           (число -> 4 hex-цифры в [RDI])
  K1-G002 print_error          (errtab: строка + ExitProcess)
  K1-G003 fail_format          (ERR=FORMAT AT=<строка> + ExitProcess(6))
  K1-P001 print_line           (WriteFile в stdout)
Файлы:
  K1-F001 open_file_read       (OPEN_EXISTING)
  K1-F002 create_file_write    (CREATE_ALWAYS)
  K1-F003 close_file
  K1-F004 read_whole_dst       (весь файл одним ReadFile)
  K1-F005 write_all            (запись + сверка длины)
Данные:
  K1-D001 таблица цифр         (16 байт ASCII)
  K1-D002 errtab               (8 записей × 16 байт)
  K1-D003 строки вывода        (справка, 7 ошибок, префикс FORMAT, base_name)
  K1-D004 таблица импортов     (IDT/IAT/INT + имя DLL)
  K1-D005 hint-записи          (7 функций; чётные RVA)
  K1-D006 виртуальные нули     (ячейки, буферы: labtab/filebuf/imagebuf)
```

## Что M1-BRICK доказывает

1. **Конец ручного счёта адресов.** Смещения, rip-смещения и длины переходов
   вычисляет инструмент: исходник кирпича правится вставкой строки — и всё
   пересчитывается само (главная боль L0 по SPEC/02 устранена).
2. **Самохостинг слоя L1.** brick.exe собирает собственный исходник
   brick.brick в тело, равное выходу hexgen(brick.hex), байт-в-байт;
   pegen оборачивает его в тот же brick.exe. Круг замкнут на BRICK-тексте.
3. **Таблицы вместо кода.** errtab, лабел-таблица, hint-записи — данные;
   обработчики обобщены (parse_data обслуживает 5 директив одним диспетчером).
4. **Кирпичность.** 35 кодовых кирпичей; 12 реинкарнаций из M0-PEGEN
   (C/F/P/G/X/S-ветви) переносятся копией байтов с заменой адресных констант
   на слоты — сам BRICK делает реинкарнации дешёвыми.

## Ограничения (снять в следующих этапах)

- Ссылка в строке H — ровно одна и только последним элементом (rel/disp
  считается от конца строки; SPEC/08, «Ограничения v1»).
- Кодировки инструкций назначает автор (SPEC/05); автоматический кодировщик —
  BRICK v2 (этап E6 вместе с языком высокого уровня).
- Тело ≤ 64 КиБ (проверка после пассажа 1); imagebuf 0x20010 — запас на
  пассаж 1 любого исходника ≤ 128 КиБ.
- Исходник ≤ 128 КиБ; меток ≤ 512; имя ≤ 63 байт.

## Примеры

```
cmd -> KERNEL\L1-BRICK\brick.exe
Вывод:   U-L1-BRICK CMDS: BRICK <SRC.BRICK> <OUT.BIN>   (46 байт, CRLF)
Код:     2

Из папки KERNEL (самохостинг):
  L1-BRICK\brick.exe L1-BRICK\brick.brick t_self.bin
  L0-HEXGEN\hexgen.exe L1-BRICK\brick.hex t_body.bin
  fc /b t_self.bin t_body.bin   ->  различий нет (2968 байт)
  L0-PEGEN\pegen.exe t_self.bin L1-BRICK\brick.peg t_brick.exe
  fc /b t_brick.exe L1-BRICK\brick.exe   ->  различий нет
```
