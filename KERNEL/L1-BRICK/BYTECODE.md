# BYTECODE.md — разбор brick.exe

Паспорт файла: KERNEL/L1-BRICK/BYTECODE.md | слой: L1 | роль: разбор образа.

Источник истины — `brick.hex` (ATOM, телесная форма: смещение 0 = RVA 0x1000);
равносильный канонический исходник — `brick.brick` (BRICK v1, SPEC/08).
По-инструкционная деталь (мнемоника + K-ID у каждого байта) — в обоих
листингах: с E4 BYTECODE содержит структуру, а не дублирует листинг.

## 1. Заголовки

Генерируются pegen из `brick.peg`: SizeOfImage = 0x85000, VirtualSize =
0x84D10, SizeOfRawData = 0xC00, DD[1] = RVA 0x1A7E (размер 0x28), DD[12] =
RVA 0x1AA6 (размер 0x40), фиксации стека/кучи = 0x4000. Инварианты SPEC/04
выполняются (hint-записи — на чётных RVA).

## 4. Данные

- **errtab** (тело 0x0903): 8 записей — справка (код 2), LONG NAME (3),
  OPEN SRC (4), READ SRC (5), BIG SRC (7), OPEN OUT (8), WRITE OUT (9),
  BIG OUT (10). Индексация: `mov ecx,<индекс>` в K1-G001/K1-C003.
- **строки** (тело 0x0983): все заканчиваются CRLF; fmt_pfx =
  "U-L1-BRICK ERR=FORMAT AT=" (25 байт, без CRLF) — к нему K1-G003
  дописывает 4 hex-цифры номера строки и CRLF (итого 31).
- **base_name** (тело ~0x0A79): "base\0" — имя предопределённой метки;
  K1-G001 заносит её в labtab до пассажа 1.
- **Импорты**: 7 функций kernel32.dll, порядок как в M0-PEGEN; hint-записи
  выровнены на чётные RVA (DZ 1 после имени DLL — инвариант 7 SPEC/04).
- **Ячейки** (RVA 0x1B98+): hstdout (q), written (q), srclen (d), outlen (d),
  curline (d), labcnt (d).

## 5. Регистровые соглашения модуля

- `rbx` — база образа (RVA 0); `rsi` — курсор исходника; `rdi` — курсор
  записи (виртуальный); `rbp` — номер пассажа (1/2); `r10` — старт imagebuf;
  `r15` — файловая длина (по первому DBZ); `r11` — размер слота/ширина
  значения (сохраняется в K1-N002); `r12` — текущий хэндл файла.

## 6. Инварианты (проверены эмуляцией и кругами)

1. `brick.hex` материализуется в тело 0xB98 байта; SRD = 0xC00; файл 0xE00;
   VirtualSize = 0xB98 + bss 0x84178 = 0x84D10.
2. brick.exe = hexgen(brick.hex) + pegen(·, brick.peg) байт-в-байт.
3. **Самохостинг:** brick.exe(brick.brick) == hexgen(brick.hex) (2968 байта);
   pegen(brick(brick.brick)) == brick.exe.
4. Прогон пассажа 2 детерминирован: итоговая длина равна длине пассажа 1
   (иначе — внутренняя ошибка формата).

## 7. История изменений образа

- **E6.4e-3 (рост пределов):** предел исходника 128 -> 256 КиБ (K1-G001:
  mov r8d/cmp rax 0x20000 -> 0x40000 — 2 imm32), предел меток 512 ->
  1024 записи (K1-N001: cmp r11d 0x200 -> 0x400), буферы labtab
  0x2000 -> 0x4000, filebuf 0x20008 -> 0x40008, imagebuf 0x20010 ->
  0x40010 (DBZ в brick.brick — виртуальные). Тело 0xB98 и файл 0xE00 НЕ
  изменились; изменены 8 слов (imm32 x3 + disp32 x5: ссылки на filebuf
  +0x2000 x3, на imagebuf +0x22000 x2) + 2 байта заголовков (VirtualSize,
  SizeOfImage 0x44000 -> 0x85000); bss 0x42178 -> 0x84178, vsize
  0x42D10 -> 0x84D10; brick.peg: !bss 84178. SHA 5F7F9EFD… -> FEDA2B1A….
  Мотивация: wall.brick 123170 Б упирался в предел 128 КиБ (94%), метки
  wall 507/512 — срезы 3-5 и E6.4d требовали запаса. Проверено: 8 слов
  побайтовым diff (LAB/ai/brick_build_lim.py), круги E5, батарея 114/114
  (+T-E6-36: 132 КиБ и 513 меток приняты / 256 КиБ отвергнут).
- **E5a (лаборатория LAB):** в K1-H001 (hex16_to_4) добавлен `shl eax,16`
  (тело 0x73B) — до этого 4 ротации по 4 бита читали только биты 16..31
  eax, и номер строки в ERR=FORMAT AT= всегда печатался как 0000 для
  строк 1..65535 (реальный дефект, найден оракулом LAB/py/lab_brick.py
  при сверке с brick.exe). Тогда же добавлено DZ 1 после имени DLL
  (чётность hint-RVA после сдвига). Тело: 0xB94 -> 0xB98.
