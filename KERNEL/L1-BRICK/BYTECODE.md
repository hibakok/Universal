# BYTECODE.md — разбор brick.exe

Паспорт файла: KERNEL/L1-BRICK/BYTECODE.md | слой: L1 | роль: разбор образа.

Источник истины — `brick.hex` (ATOM, телесная форма: смещение 0 = RVA 0x1000);
равносильный канонический исходник — `brick.brick` (BRICK v1, SPEC/08).
По-инструкционная деталь (мнемоника + K-ID у каждого байта) — в обоих
листингах: с E4 BYTECODE содержит структуру, а не дублирует листинг.

## 0. Сводка

| Свойство | Значение |
|---|---|
| Размер файла | 3584 байта (0xE00) |
| SHA-256 | `A32C943A907867728DD1CBF578AB7A5692CDFC8AFF4BEC5C466D22972C2F8CC2` |
| Точка входа | RVA 0x1000 (тело 0x0000, K1-X001) |
| Код | 0x8F8 байта (тело 0x0000..0x08F7), 669 инструкций (LAB disasm, без сбоев декодирования) |
| Данные | 0x2D0 байта @ тело 0x8F8 (таблицы, строки, импорты) |
| Виртуальные нули | 0x1500178 байт @ тело 0x0BC8 (ячейки, labtab, filebuf, imagebuf) |
| Смещение → RVA | RVA = телесное смещение + 0x1000 |

## 1. Заголовки

Генерируются pegen из `brick.peg`: SizeOfImage = 0x1510000, VirtualSize =
0x1500D40, SizeOfRawData = 0xC00, DD[1] = RVA 0x1AAE (размер 0x28), DD[12] =
RVA 0x1AD6 (размер 0x40), фиксации стека/кучи = 0x4000. Инварианты SPEC/04
выполняются (hint-записи — на чётных RVA).

## 2. Раскладка внутри .text (RVA = тело + 0x1000)

```
тело 0x0000  код: главный поток, подпрограммы (0x8F8 байта)
тело 0x08F8  digits: 16 байт "0123456789ABCDEF"
тело 0x0908  errtab: 9 записей × 16 байт {dword RVA, dword длина, dword код, 0}
тело 0x0998  usage_str (46) + 7 строк ошибок + err_biglab (27, E9.5-2)
             + fmt_pfx (25) + base_name
тело 0x0AAE  IDT: описатель {INT=0x1B16, 0, 0, Name=0x1B56, IAT=0x1AD6} + терминатор
тело 0x0AD6  IAT: 7 адресов + терминатор (заполняет загрузчик)
тело 0x0B16  INT: копия IAT до заполнения
тело 0x0B56  имя "kernel32.dll"; DZ 1 (выравнивание); hint-записи 7 функций (чётные RVA)
тело 0x0BC8  [виртуальные нули] ячейки и буферы:
             hstdout/written/srclen/outlen/curline/labcnt (RVA 0x1BC8..),
             fname_in/fname_out (0x100), linebuf (0x40), labtab (0x200000),
             filebuf (0x1100008), imagebuf (0x200010)
тело 0x1500D40 конец секции (VirtualSize)
```

## 4. Данные

- **errtab** (тело 0x0908): 9 записей — справка (код 2), LONG NAME (3),
  OPEN SRC (4), READ SRC (5), BIG SRC (7), OPEN OUT (8), WRITE OUT (9),
  BIG OUT (10), BIG LABELS (11; E9.5-2 — запись {RVA err_biglab, длина
  0x1B, код 0xB, 0}). Индексация: `mov ecx,<индекс>` в
  K1-G001/K1-C003/K1-N001 (dl_full).
- **строки** (тело 0x0998+): все заканчиваются CRLF; fmt_pfx =
  "U-L1-BRICK ERR=FORMAT AT=" (25 байт, без CRLF) — к нему K1-G003
  дописывает 4 hex-цифры номера строки и CRLF (итого 31); err_biglab =
  "U-L1-BRICK ERR=BIG LABELS" + CRLF (27 байт, E9.5-2).
- **base_name** (тело 0x0AA9): "base\0" — имя предопределённой метки;
  K1-G001 заносит её в labtab до пассажа 1.
- **Импорты**: 7 функций kernel32.dll, порядок как в M0-PEGEN; hint-записи
  выровнены на чётные RVA (DZ 1 после имени DLL — инвариант 7 SPEC/04).
- **Ячейки** (RVA 0x1BC8+): hstdout (q), written (q), srclen (d), outlen (d),
  curline (d), labcnt (d).

## 5. Регистровые соглашения модуля

- `rbx` — база образа (RVA 0); `rsi` — курсор исходника; `rdi` — курсор
  записи (виртуальный); `rbp` — номер пассажа (1/2); `r10` — старт imagebuf;
  `r15` — файловая длина (по первому DBZ); `r11` — размер слота/ширина
  значения (сохраняется в K1-N002); `r12` — текущий хэндл файла.

## 6. Инварианты (проверены эмуляцией и кругами)

1. `brick.hex` материализуется в тело 0xBC8 байта; SRD = 0xC00; файл 0xE00;
   VirtualSize = 0xBC8 + bss 0x1500178 = 0x1500D40.
2. brick.exe = hexgen(brick.hex) + pegen(·, brick.peg) байт-в-байт.
3. **Самохостинг:** brick.exe(brick.brick) == hexgen(brick.hex) (3016 байта);
   pegen(brick(brick.brick)) == brick.exe.
4. Прогон пассажа 2 детерминирован: итоговая длина равна длине пассажа 1
   (иначе — внутренняя ошибка формата).
