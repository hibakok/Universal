# Карточка модуля M3-UNIVM (ядро виртуальной машины UNIVM)

Паспорт файла: KERNEL/L3-UNIVM/CARD.md | слой: L3 | роль: карточка модуля.

| Поле | Значение |
|---|---|
| ID модуля | M3-UNIVM |
| Слой | L3 (ВИРТМАШИНА); исходник — WALL v2 (слой L2, SPEC/11) с разрезом по !include (SPEC/10) |
| Назначение | **Ядро UNIVM**: читает внешнюю программу `.UP` (SPEC/13 v1/v2) по пути из командной строки и исполняет её по ISA SPEC/12; поведение обязано совпадать с оракулом `LAB/py/lab_vm.py` (правило R8 — консоль/код возврата/ловушки/шаги). Срезы E7.2-1..4 — ЭТАП 7.2 ЗАКРЫТ: разбор контейнера полный (порядок отказов == оракулу parse_up; после разбора — RAM: GlobalAlloc(0, memsize) + обнуление, ветвь M); исполнение — ВСЕ 18 ОПКОДОВ ISA v0: регистры + ALU (`const/mov/add/sub/and/or/xor/shl/shr/lt/eq` — 11 кирпичей K3-V101..V111, массив regs[16], r0 равноправен), ПАМЯТЬ И УСТРОЙСТВА (`ldb/stb/ldq/stq` — 4 кирпича K3-M101..M104: RAM, ловушки 3/4, окно устройств — окно+0 = консоль), ПЕРЕХОДЫ (`jmp/jnz` — 2 кирпича K3-J101..J102, ветвь J) и `halt` (0x12); порядок проверок SPEC/12 п. 7, длина валидного опкода проверяется до исполнителя (обрезка — ловушка 2). ПРЕДЕЛ ШАГОВ — ловушка 6 (диагностика хозяина): проверка «steps >= steplim» ДО выборки инструкции (как run(max_steps) оракула); глобаль steplim — необязательный 2-й аргумент CLI (0..2147483647, умолчание 200 млн — SPEC/12 п. 7). E7.4-2a: КОНТЕЙНЕР V2 — версии {1, 2}; dataoff = 24+codesize — секция данных за кодом -> RAM[0:datalen] при загрузке (K3-U003 read_data: чтение кусками 4096 Б прямо в RAM; отказ DATA — datalen > memsize; v1-файлы валидны навсегда). E7.4-2b: ALU V1 — опкоды 13..16 (mul/div/mod/sra, F1) — часть alu ветви V (K3-V113..V116 + фундамент K3-V112 udivmod: беззнаковое деление из простых операций WALL — деление WALL знаковое; глобали uq/ur); ЛОВУШКА 7 — деление на ноль у div/mod (после проверки полей). E7.4-2c: CALL/RET — опкоды 17..18 (F3/F0) + АППАРАТНЫЙ СТЕК ВЫЗОВОВ глубины 1024 (ловушка 5: call при полном / ret при пустом) — часть call ветви V (K3-V117 op_call: занос pc+6, pc := imm32; K3-V118 op_ret: pc := адрес возврата; глобали cstack[1024]/csp — состояние управления, как pc: данные программы его не видят). ISA v0+v1 исполнена полностью (24 опкода) |
| Вход | командная строка Windows: `kernel.exe <файл.up> [предел_шагов]` (1-2 аргумента) |
| Выход | программа: консоль в stdout + код возврата = `halt` imm32 (u32). Диагностика ядра: справка `U-L3-UNIVM CMDS: KERNEL <FILE.UP> [STEPS]` (код 2); `ERR=LONG NAME` (3); `ERR=OPEN UP` (4); `ERR=READ UP` (5, вкл. отказ распределения кода); `ERR=SIG/VER/MEM/CODE0/LEN/RES/DATA` (6 — отказы контейнера SPEC/13 п. 4, v1+v2); ловушка программы: `U-L3-UNIVM TRAP=<n> STEPS=<s>` (код 1; n = 1-5 — ISA-ловушки (5 — стек вызовов, E7.4-2c), 6 — предел шагов, 7 — деление на ноль — E7.4-2b; консоль программы выводится до диагностики) |
| Версия | E7.4-2c (сессия 57) — call/ret + аппаратный стек вызовов 1024 (ловушка 5); ISA v0+v1 исполнена полностью; до этого E7.4-2b (56) — ALU v1: mul/div/mod/sra + ловушка 7; E7.4-2a (55) — контейнер .UP v2: секция данных -> RAM + отказ DATA; E7.2-4 (49) — ФИНАЛ этапа 7.2: переходы + предел шагов |
| Размер | 36352 байт (0x8E00); тело 35474 Б (0x8A92; вкл. cstack — DZ 8192); вход 0x1200 (SPEC/11 п. 6) |
| Платформа | Windows x64, консольная подсистема, PE32+ |
| Импорты | kernel32.dll (8): GetStdHandle, WriteFile, ExitProcess, GetCommandLineA, CreateFile2, ReadFile, CloseHandle, GlobalAlloc |
| Самохостинг | артефакты `kernel.b2/brick/exe` — ГЕНЕРИРУЕМАЯ сборка из `kernel.wall` конвейером инструментов (wall → enc → brick → pegen + kernel.peg) под эмуляцией LAB; фикс-пункт воспроизводимости — батарея T-E7-09 (каждый пуш); kernel.b2 == оракулу WALL байт-в-байт |

## Формат вызова

```
kernel.exe program.up [steps]
```

Аргументы: путь .UP (≤ 127 байт ANSI) + необязательный предел шагов
(E7.2-4: десятичные цифры, 0..2147483647; умолчание 200 000 000;
третий аргумент или неверное слово — справка, код 2).
Валидная программа: любая последовательность инструкций ISA v0
(18 опкодов) + v1 (mul/div/mod/sra — E7.4-2b; call/ret со стеком
вызовов — E7.4-2c; всего 24 опкода) → консоль (байты,
записанные stb в окно+0) + код возврата halt. E7.4-2a: контейнер
v1 ИЛИ v2 — версия 2 с dataoff = 24+codesize дополнительно
инициализирует RAM[0:datalen] секцией данных до первой инструкции.
Диффтест: `LAB/py/lab_t_kernel.py` (секция 14 батареи, T-E7-09..18 +
T-E7-32/33/34; корпуса — lab_t_kernel_corpus.py + _v1.py).

## Регистровые соглашения модуля

Канон WALL (SPEC/11 п. 5): rbp-кадры, ARGREG rcx/rdx/r8/r9, рабочие
r10/r11; вызываемые сохраняют rbx/rbp/rsi/rdi/r12-r15. Глобальное
состояние ядра — глобали образа (BYTECODE.md §3): pc/steps/steplim
(предел шагов — 2-й аргумент CLI, умолчание 200 млн),
**regs[16] (регистры UNIVM — 16 равноправных qword, старт — нули)**,
**uq/ur (частное/остаток udivmod — E7.4-2b)**,
**csp + cstack[1024] (аппаратный стек вызовов — E7.4-2c; состояние
управления, как pc: глубина и адреса возврата, данные программы
их не видят — SPEC/12 п. 3.4)**,
codebuf/codesize/memsize, **ram (указатель RAM программы; старт —
нули)**, hdrbuf/trapbuf (массивы), hstdout/cmdline.

## Данные образа

- строки s_use..s_crlf (14 диагностических литералов, CRLF; s_data —
  ERR=DATA, E7.4-2a);
- глобальные массивы: arg1[64]/w1[64] (CLI), hdrbuf[8] (заголовок .UP
  + контрольный байт), **regs[16] (регистры UNIVM)**, trapbuf[48]
  (строка диагностики ловушки), **cstack[1024] (стек вызовов —
  E7.4-2c: 8192 Б DZ-нулей в данных, как все глобальные массивы
  WALL)**;
- код программы .UP — в куче GlobalAlloc(0, codesize) в рантайме
  (ёмкость — до 64 МиБ по SPEC/13; в эмуляторе LAB — до 16 МиБ кучи);
- RAM программы — в куче GlobalAlloc(0, memsize) + обнуление
  (get_ram, ветвь M); консоль программы — байты stb в окно+0,
  выводятся в stdout немедленно (WriteFile байтом).

## Ограничения (снять в следующих срезах)

- Предел шагов по умолчанию 200 млн нельзя прогнать под эмуляцией
  LAB за разумное время — диффтест проверяет ловушку 6 малыми
  лимитами (2-й аргумент CLI); точное значение умолчания — константа
  SPEC/12 п. 7 (код — K3-C008 read_lim).
- Чтение .UP или RAM крупнее кучи (в эмуляторе LAB — 16 МиБ на код
  и RAM суммарно) — ERR=READ UP (код 5); на реальном Windows — до
  64 МиБ каждое (SPEC/13).
- Шаги нормального останова ядром не печатаются (наблюдаемы только
  через ловушечную диагностику — контракт SPEC/13 п. 4).
- Консоль — только вывод (окно+0); ввода и других устройств в v0 нет
  (SPEC/12 п. 6 — рост окном устройств, без новых инструкций).
- Мнемоники v1 (mul/div/mod/sra/call/ret) и директива .data в
  ассемблере uva.exe — срез E7.4-3 (ядро уже исполняет ВСЕ 24 опкода
  v0+v1 и читает собранные v2-файлы оракула/ручной сборки; до среза
  v1-программы для ядра собирает lab_vm.assemble).

## Примеры

```
cmd -> KERNEL\L3-UNIVM\kernel.exe
Вывод:   U-L3-UNIVM CMDS: KERNEL <FILE.UP> [STEPS]   (42 байта, CRLF)
Код:     2

kernel.exe program.up     (program.up: "const r1, 5" + "halt 37")
Вывод:   (пусто)
Код:     37

kernel.exe hello.up       (.mem 8; "const r1, 8" + "const r2, 65"
                          + "stb r1+0, r2" + "halt 0" — печать байта
                          в окно+0, SPEC/12 п. 8)
Вывод:   A
Код:     0

kernel.exe bad.up         (заголовок: версия 3)
Вывод:   U-L3-UNIVM ERR=VER
Код:     6

kernel.exe data.up       (v2: dataoff = 24+codesize; .data 14 Б
                          «U-DATA-OK 00\r\n» -> RAM[0:14], код
                          дописывает на место «00» hex-цифры 97
                          («61») и печатает строку; T-E7-32)
Вывод:   U-DATA-OK 61
Код:     0

kernel.exe big.up         (v2: .mem 8, данные 9 Б — длиннее RAM)
Вывод:   U-L3-UNIVM ERR=DATA
Код:     6

kernel.exe trap.up        (.mem 16; "const r1, 99" + "ldb r2, r1+0")
Вывод:   U-L3-UNIVM TRAP=3 STEPS=1
Код:     1

kernel.exe div0.up       (.mem 0; "const r1, 5" + "const r2, 0"
                          + "div r3, r1, r2" — деление на ноль,
                          SPEC/12 п. 7; E7.4-2b)
Вывод:   U-L3-UNIVM TRAP=7 STEPS=2
Код:     1

kernel.exe ovf.up        (.mem 0; "loop:" + "call loop" — бесконечная
                          рекурсия; 1024 call исполняются, 1025-й
                          видит полный стек вызовов — SPEC/12 п. 3.4;
                          E7.4-2c; T-E7-34)
Вывод:   U-L3-UNIVM TRAP=5 STEPS=1024
Код:     1

kernel.exe lonely.up     (.mem 0; "ret" — ret на пустом стеке
                          вызовов; E7.4-2c)
Вывод:   U-L3-UNIVM TRAP=5 STEPS=0
Код:     1

kernel.exe loop.up 100    (loop.up: ".mem 4096" + "loop:" +
                          "jmp loop" — вечный цикл; предел 100 шагов,
                          SPEC/12 п. 7 — как max_steps оракула)
Вывод:   U-L3-UNIVM TRAP=6 STEPS=100
Код:     1
```
