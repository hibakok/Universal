# Карточка модуля M3-UNIVM (ядро виртуальной машины UNIVM)

Паспорт файла: KERNEL/L3-UNIVM/CARD.md | слой: L3 | роль: карточка модуля.

| Поле | Значение |
|---|---|
| ID модуля | M3-UNIVM |
| Слой | L3 (ВИРТМАШИНА); исходник — WALL v2 (слой L2, SPEC/11) с разрезом по !include (SPEC/10) |
| Назначение | **Ядро UNIVM**: читает внешнюю программу `.UP` (SPEC/13) по пути из командной строки и исполняет её по ISA SPEC/12; поведение обязано совпадать с оракулом `LAB/py/lab_vm.py` (правило R8 — консоль/код возврата/ловушки/шаги). Срезы E7.2-1..3: разбор контейнера полный (порядок отказов == оракулу parse_up; после разбора — RAM: GlobalAlloc(0, memsize) + обнуление, ветвь M); исполнение — регистры + ALU (`const/mov/add/sub/and/or/xor/shl/shr/lt/eq` — 11 кирпичей K3-V101..V111, массив regs[16], r0 равноправен), ПАМЯТЬ И УСТРОЙСТВА (`ldb/stb/ldq/stq` — 4 кирпича K3-M101..M104: RAM, ловушки 3/4, окно устройств — окно+0 = консоль, байт в stdout через WriteFile байтом) и `halt` (0x12); порядок проверок SPEC/12 п. 7, длина валидного опкода проверяется ДО заглушки (обрезка — ловушка 2). Опкоды 10..11 (переходы) — заглушка ловушкой 1 (исполнение — срез E7.2-4); предел шагов 200 млн — E7.2-4 |
| Вход | командная строка Windows: `kernel.exe <файл.up>` (строго один аргумент) |
| Выход | программа: консоль в stdout + код возврата = `halt` imm32 (u32). Диагностика ядра: справка `U-L3-UNIVM CMDS: KERNEL <FILE.UP>` (код 2); `ERR=LONG NAME` (3); `ERR=OPEN UP` (4); `ERR=READ UP` (5, вкл. отказ распределения кода); `ERR=SIG/VER/MEM/CODE0/LEN/RES` (6 — отказы контейнера SPEC/13 п. 4); ловушка программы: `U-L3-UNIVM TRAP=<n> STEPS=<s>` (код 1; консоль программы выводится до диагностики) |
| Версия | E7.2-3 (сессия 48): память + устройства (ветвь M — RAM/окно/консоль); до этого E7.2-2 (сессия 46) — регистры + ALU, E7.2-1 (сессия 45) — каркас: CLI, контейнер, halt |
| Размер | 21504 байт (0x5400); тело 20570 Б (0x505A); вход 0x1200 (SPEC/11 п. 6) |
| Платформа | Windows x64, консольная подсистема, PE32+ |
| Импорты | kernel32.dll (8): GetStdHandle, WriteFile, ExitProcess, GetCommandLineA, CreateFile2, ReadFile, CloseHandle, GlobalAlloc |
| Самохостинг | артефакты `kernel.b2/brick/exe` — ГЕНЕРИРУЕМАЯ сборка из `kernel.wall` конвейером инструментов (wall → enc → brick → pegen + kernel.peg) под эмуляцией LAB; фикс-пункт воспроизводимости — батарея T-E7-09 (каждый пуш); kernel.b2 == оракулу WALL байт-в-байт |

## Формат вызова

```
kernel.exe program.up
```

Аргумент строго один (лишний — справка, код 2); путь ≤ 127 байт ANSI.
Валидная программа: последовательность const/ALU-опкодов, операций
памяти и `halt N` → консоль (байты, записанные stb в окно+0) +
код возврата N.
Диффтест: `LAB/py/lab_t_kernel.py` (секция 14 батареи, T-E7-09..16).

| `kernel_self_mem.wall` | ветвь M — память и устройства (срез E7.2-3): get_ram (RAM = GlobalAlloc + обнуление), op_ldb/op_stb/op_ldq/op_stq (кирпичи опкодов 0C..0F: RAM, окно+0 = консоль, ловушки 3/4) |

| `kernel.b2` / `kernel.brick` / `kernel.exe` | ГЕНЕРИРУЕМЫЕ артефакты (фикс-пункт T-E7-09) |

## Регистровые соглашения модуля

Канон WALL (SPEC/11 п. 5): rbp-кадры, ARGREG rcx/rdx/r8/r9, рабочие
r10/r11; вызываемые сохраняют rbx/rbp/rsi/rdi/r12-r15. Глобальное
состояние ядра — глобали образа (BYTECODE.md §3): pc/steps,
**regs[16] (регистры UNIVM — 16 равноправных qword, старт — нули)**,
codebuf/codesize/memsize, **ram (указатель RAM программы; старт —
нули)**, hdrbuf/trapbuf (массивы), hstdout/cmdline.

## Данные образа

- строки s_use..s_crlf (13 диагностических литералов, CRLF);
- глобальные массивы: arg1[64]/w1[64] (CLI), hdrbuf[8] (заголовок .UP
  + контрольный байт), **regs[16] (регистры UNIVM)**, trapbuf[48]
  (строка диагностики ловушки);
- код программы .UP — в куче GlobalAlloc(0, codesize) в рантайме
  (ёмкость — до 64 МиБ по SPEC/13; в эмуляторе LAB — до 16 МиБ кучи);
- RAM программы — в куче GlobalAlloc(0, memsize) + обнуление
  (get_ram, ветвь M); консоль программы — байты stb в окно+0,
  выводятся в stdout немедленно (WriteFile байтом).

## Ограничения (снять в следующих срезах)

- **E7.2-4:** переходы jmp/jnz — заглушка ловушкой 1 (длина
  проверяется); предел шагов 200 млн (ловушка 6) не реализован
  (без переходов вечный цикл невозможен).
- Чтение .UP или RAM крупнее кучи (в эмуляторе LAB — 16 МиБ на код
  и RAM суммарно) — ERR=READ UP (код 5); на реальном Windows — до
  64 МиБ каждое (SPEC/13).
- Шаги нормального останова ядром не печатаются (наблюдаемы только
  через ловушечную диагностику — контракт SPEC/13 п. 4).
- Консоль — только вывод (окно+0); ввода и других устройств в v0 нет
  (SPEC/12 п. 6 — рост окном устройств, без новых инструкций).

## Примеры

```
cmd -> KERNEL\L3-UNIVM\kernel.exe
Вывод:   U-L3-UNIVM CMDS: KERNEL <FILE.UP>   (34 байта, CRLF)
Код:     2

kernel.exe program.up     (program.up: "const r1, 5" + "halt 37")
Вывод:   (пусто)
Код:     37

kernel.exe hello.up       (.mem 8; "const r1, 8" + "const r2, 65"
                          + "stb r1+0, r2" + "halt 0" — печать байта
                          в окно+0, SPEC/12 п. 8)
Вывод:   A
Код:     0

kernel.exe bad.up         (заголовок: версия 2)
Вывод:   U-L3-UNIVM ERR=VER
Код:     6

kernel.exe trap.up        (.mem 16; "const r1, 99" + "ldb r2, r1+0")
Вывод:   U-L3-UNIVM TRAP=3 STEPS=1
Код:     1
```
