## 2. Уровни проверки (SPEC/02; батарея 159/159)

1. Целостность: SHA-256 (лаборатория — реестр SHA lab_verify.py).
2. PE-инварианты SPEC/04: hint-записи на чётных RVA, одна секция,
   обёртка PEG kernel.peg (SPEC/11 п. 6 — константа для WALL-программ).
3. Фикс-пункт воспроизводимости (T-E7-09): сборка kernel.wall
   конвейером wall → enc → brick → pegen (эмуляция, ~84 млн шагов)
   == артефактам байт-в-байт; kernel.b2 == оракулу WALL.
4. Контракт CLI/контейнера (T-E7-10/11): справка/лишний аргумент/
   LONG NAME/OPEN UP; отказы SIG/VER/MEM/CODE0/LEN/RES — в порядке
   оракула parse_up (SPEC/13 п. 4).
5. Диффтест с оракулом UNIVM (T-E7-12/13/15/16): halt-программы
   (консоль/код возврата), ловушки 1/2 (диагностика TRAP/STEPS,
   код 1), ALU среза 2 (поля-заполнители, обрезки всех форматов,
   точные счётчики шагов, отсутствие ложных ловушек) и срез 3 —
   ПАМЯТЬ/УСТРОЙСТВА (RAM: запись/чтение/sext8/нулевой старт,
   невыровненные слова; окно: консоль/резерв/чтение; ловушки 3/4 —
   границы, бит 31, заворот; memsize = 0) == LAB/py/lab_vm.py;
   детерминизм (T-E7-14).

## 3. Журнал срезов

- **E7.2-1 (сессия 45, 2026-11-19):** каркас ядра — CLI (skip0/
  read_arg/check_end — один аргумент строго), чтение файла, разбор
  контейнера .UP (rd32 + read_up; беззнаковое сравнение memsize по
  старшему dword), цикл интерпретатора с halt (op_halt/fail_trap +
  copy_str/out_dec для диагностики «U-L3-UNIVM TRAP=n STEPS=s»).
  Артефакты впервые зафиксированы; корпус среза 1 — зелёный.
  Дефектов не найдено (первая сборка совпала с оракулом WALL
  байт-в-байт и прошла весь корпус с первого прогона).
- **E7.2-2 (сессия 46, 2026-11-19):** регистры + ALU — глобальный
  массив regs[16] (r0 равноправен), кирпичи K3-V101..V111 (const с
  sext32 через сдвиг imm >> 31 — без литералей > 2^31-1; mov с
  проверкой rb = 0; add/sub/and/or/xor — битовый образ совпадает с
  беззнаковым UNIVM; shl/shr со маской счётчика 63; lt/eq — знаковое
  сравнение WALL == семантика SPEC/12 п. 5); interp: проверка длины
  для ВСЕХ валидных опкодов 01..12 (F1 3 Б / F2+F3 6 Б) — обрезка
  валидного опкода даёт ловушку 2 ДО заглушки (как оракул; в срезе 1
  заглушки не различали). Корпус T-E7-15 (17 случаев) — зелёный с
  первого прогона; артефакты пересобраны (10240 → 16384 Б).
  Попутно НАЙДЕН ДЕФЕКТ №23 wall.exe (pp_pcount — двухсимвольные
  операторы не завершают скан пар индексации; «индекс == индекс» —
  ложный ERR=FORMAT): в op_eq правый операнд взят в скобки
  (прозрачны, вывод тот же); фикс инструмента — отдельный срез
  (журнал — KERNEL/L2-WALL/VERIFY.md §4, №23).
- **E7.2-2F (сессия 47, 2026-11-19):** скобки-обход дефекта №23 в
  op_eq СНЯТЫ («regs[ra] == regs[b2]» — прямой вид): фикс pp_pcount
  в wall.exe применён (срез E7.2-2F, L2-WALL), сравнение «индекс ==
  индекс» снова легально. Артефакты пересобраны новым wall.exe:
  kernel.exe БАЙТ-В-БАЙТ прежний (9B33FDFD… — скобки прозрачны для
  кода); kernel.b2/.brick изменили только текст комментариев
  (заголовок «исходник: 757 -> 755 строк» и 22 M-строки op_eq без
  «()», -44 Б). Фикс-пункт T-E7-09 зелёный; корпус среза 2 — 7/7;
  батарея 157 -> 158/158 (якорь фикса T-E6-61 в секции 11 L2-WALL).

- **E7.2-3 (сессия 48, 2026-11-19):** память и устройства — ВЕТВЬ M
  (новая часть kernel_self_mem.wall): K3-M001 get_ram (RAM =
  GlobalAlloc(0, memsize) + обнуление — qword-цикл ram[zi] = 0 + хвост
  setb; отказ — ERR=READ UP (5); memsize = 0 — без распределения) +
  4 кирпича опкодов K3-M101..M104 (op_ldb/op_stb/op_ldq/op_stq — по
  кирпичу на опкод 0C..0F). Адресация: (базовый регистр + sext imm32)
  mod 2^64 — аппаратный заворот WALL; беззнаковые границы — фильтр
  «a >> 31 != 0» (адрес >= 2^31 недопустим всегда: пределы < 2^31) +
  знаковые сравнения (в [0, 2^31) эквивалентны беззнаковым); sext8 —
  вычитанием 256 (битовый образ == оракулу); слова — 8 байт LE по
  любому адресу (сборка/разбор байтами, сдвиги 8..56). Окно устройств:
  окно+0 = консоль (WriteFile байтом, немедленно), чтение окна = 0,
  резерв 1..4095 игнорируется; словный доступ к окну невозможен
  (ловушка 3/4). RAM распределяется в read_up после ВСЕХ отказов
  контейнера (порядок отказов .UP не изменился). Артефакты: тело
  15384 -> 20570 Б (файл 16384 -> 21504); корпус T-E7-16 (15 случаев:
  консоль-строка, sext8 + нулевой старт, невыровненные слова + LE,
  заворот адреса, окно, memsize=0 + 9 ловушек 3/4) — зелёный с
  первого прогона; батарея 158 -> 159/159. Дефектов не найдено.
