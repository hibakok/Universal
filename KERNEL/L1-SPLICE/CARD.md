# Карточка модуля M1-SPLICE (склейка исходников SPLICE v1)

Паспорт файла: KERNEL/L1-SPLICE/CARD.md | слой: L1 | роль: карточка модуля.

| Поле | Значение |
|---|---|
| ID модуля | M1-SPLICE |
| Слой | L1 (СБОРКА); исходник — BRICK v2 (M-строки, SPEC/09) с разрезом по !include (SPEC/10) |
| Назначение | Склейка «корневого» исходника с директивами `!include <путь>` в один плоский текст для конвейера enc/brick. Решает лимит 500 строк: большие исходники режутся на части, собираемые перед сборкой. Формат включений и разрешение имён — SPEC/10 |
| Вход | командная строка Windows: `splice.exe <корень.b2> <выход.плоско>` |
| Выход | плоский текст (каждая строка + LF, без CR): строки-директивы заменяются содержимым включаемых файлов (вложенность ≤ 7, каталог включающего файла); коды 0 / 2 (мало аргументов) / 3 (имя > 127) / 4 (не открыт) / 5 (чтение) / 6 (`ERR=FORMAT AT=<строка>`) / 7 (файл ≥ 128 КиБ) / 8 (выход не создан) / 9 (запись) / 10 (выход > 128 КиБ) / 11 (глубина > 7) |
| Размер | 3584 байта (0xE00) |
| Платформа | Windows x64, консольная подсистема, PE32+ |
| Импорты | kernel32.dll: GetStdHandle, WriteFile, ExitProcess, GetCommandLineA, CreateFileA, ReadFile, CloseHandle |
| Самохостинг | `splice.exe splice.b2 t.b2` собирает плоскую форму собственного разрезанного исходника; конвейер splice+enc+brick+pegen воспроизводит splice.exe (DoD E6.3, T-E6-18) |

## Формат вызова

```
splice.exe <корень.b2> <выход.плоско>
```

Оба аргумента обязательны. Выход создаётся заново (CREATE_ALWAYS).
Полный цикл сборки модуля на BRICK v2 с разрезом:

```
splice.exe <модуль>.b2        <модуль>-flat.b2
enc.exe    <модуль>-flat.b2   <модуль>.brick
brick.exe  <модуль>.brick     <модуль>-body.bin
pegen.exe  <модуль>-body.bin  <модуль>.peg  <модуль>.exe
```

## Строгость разбора

- Директива — строка, начинающаяся с `!include ` в КОЛОНКЕ 0; путь —
  все байты после префикса (пробел перед `!` делает строку обычной).
- Любая строка с `!` в колонке 0, но не являющаяся корректной директивой, —
  `ERR=FORMAT AT=XXXX`; XXXX — сквозной номер строки по порядку чтения
  всех файлов (16 бит, обрезка как у enc).
- Полное имя включения = каталог включающего файла + путь (`/` и `\`
  равнозначны, регистр не важен); ≤ 127 байт; повтор — повторная вставка.
- Концы строк — LF/CRLF/CR (как enc); байт 00 — сентинел конца файла;
  пустой корень → пустой выход (специфик SPLICE, отличие от quirk enc).
- Пределы: 8 уровней (корень + 7), файл < 0x20000, выход ≤ 0x20000.

## Кирпичи модуля (карточки — MAP/M1-SPLICE.md)

```
Поток исполнения:
  K1-X021 prepare_stack        (кадр 0x38; GetStdHandle -> hstdout)
  K1-C021 get_cmdline          (GetCommandLineA -> RDI)
  K1-C022 skip_argv0           (кавычки, разделители)
  K1-G021 dispatch             (корень -> буфер уровня 0; цикл; запись)
  K1-X022 exit_code            (ExitProcess(0) + int3)
Склейка:  K1-S011 process_loop (цикл строк текущего уровня; EOF -> pop),
          K1-S012 handle_line  ('!include' -> спуск; иначе вывод),
          K1-S013 emit_line    (строка -> outbuf + LF; предел 128 КиБ)
Имена:    K1-N011 name_prefix  (последний '/'/'\\' -> длина префикса)
Печать:   K1-H021 hex16_to_4, K1-G022 print_error,
          K1-G023 fail_format, K1-U021 print_line
Командная строка: K1-C023 next_arg, K1-C024 read_word,
                  K1-C025 copy_word_dst, K1-C026 skip_seps
Файлы:    K1-F021..F025 (реинкарнации K1-F001..F005)
Данные:   K1-D021 цифры, K1-D022 errtab (9), K1-D023 строки,
          K1-D024 импорты, K1-D025 виртуальные нули
```

## Регистровые соглашения модуля

- `rbx` — база образа (RVA 0); `r10` — база outbuf; `r12` — курсор вывода;
  `r13` — ТЕКУЩИЙ УРОВЕНЬ (0..7 — отличие от enc, где r13 = opbuf);
  `rsi` — курсор текста; `r14`/`r15` — начало/конец строки; `rbp` — свободен.
- Подпрограммы сохраняют RBX,RSI,R10,R12,R13,R14,R15,RBP и могут менять
  RAX,RCX,RDX,RDI,R8,R9,R11. **Исключение:** process_loop/handle_line
  меняют RSI и R13 — это их контракт (спуск/возврат по уровням).
- Состояние уровней — в bss: `lv_name[8]×0x80`, `lv_cur[8]×8`,
  `lv_pref[8]×1`; буферы уровней `filebufs[8]×0x20000` (адресация уровня —
  `shl <reg>, 11`, т.е. ×0x20000).

## Что M1-SPLICE доказывает

1. **Конец монолитных исходников.** Все исходники L1 (enc 2651 строка,
   brick 850, splice 692) разрезаны на файлы ≤ 500 строк; сборка —
   через `!include`. Каждая часть — одна ветвь/группа ветвей: ИИ читает
   только нужную часть.
2. **Самохостинг include.** splice.exe собирает СВОЙ разрезанный исходник
   в плоскую форму, и конвейер воспроизводит splice.exe (T-E6-18).
3. **Разрезы воспроизводимы.** splice(enc.b2) == исходный текст enc.b2
   байт-в-байт; аналогично brick.brick и splice.b2 (T-E6-17): тела и
   артефакты не изменились — круги E5/E6.2 зелёные на разрезанных
   исходниках.
4. **Плоский цикл вместо рекурсии.** Спуск по включениям — уровень в R13
   и массивы lv_*; стек вызовов постоянен, глубина ограничена данными.

## Ограничения (снять в следующих этапах)

- Включения условные/по спискам каталогов не поддерживаются (SPEC/10 «не делает»).
- Ошибки OPEN SRC не сообщают, КАКОЙ файл не открылся (кандидатов немного).
- Выход ≤ 128 КиБ (предел потребителей enc/brick — сделано намеренно).

## Примеры

```
cmd -> KERNEL\L1-SPLICE\splice.exe
Вывод:   U-L1-SPLICE CMDS: SPLICE <ROOT.SRC> <OUT.FLAT>   (48 байт, CRLF)
Код:     2

Из папки KERNEL (самохостинг через собственный разрез):
  L1-SPLICE\splice.exe L1-SPLICE\splice.b2 t.b2
  L1-ENC\enc.exe t.b2 t.brick
  L1-BRICK\brick.exe t.brick t_body.bin
  L0-PEGEN\pegen.exe t_body.bin L1-SPLICE\splice.peg t.exe
  fc /b t.exe L1-SPLICE\splice.exe    ->  различий нет
  fc /b t.brick L1-SPLICE\splice.brick ->  различий нет
```
