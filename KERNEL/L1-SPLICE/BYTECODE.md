# BYTECODE.md — разбор splice.exe

Паспорт файла: KERNEL/L1-SPLICE/BYTECODE.md | слой: L1 | роль: разбор образа.

Источник истины — разрезанный исходник `splice.b2` (корень + части,
SPEC/10) в BRICK v2 (M-строки, SPEC/09); плоская форма — `splice.brick`
(= `enc(splice(splice.b2))` байт-в-байт). По-инструкционная деталь
(мнемоника + K-ID у каждой строки) — в исходниках; BYTECODE содержит
структуру.

## 1. Заголовки

Генерируются pegen из `splice.peg`: SizeOfImage = 0x243000, VirtualSize =
0x241102, SizeOfRawData = 0xC00, DD[1] = RVA 0x19B9 (размер 0x28), DD[12] =
RVA 0x19E1 (размер 0x40), фиксации стека/кучи = 0x4000. Инварианты SPEC/04
выполняются (hint-записи — на чётных RVA: 0x1A6E, 0x1A7E, 0x1A8A, 0x1A98,
0x1AAC, 0x1ABA, 0x1AC6).

## 4. Данные

- **errtab** (тело 0x0812): 9 записей — справка (код 2), LONG NAME (3),
  OPEN SRC (4), READ SRC (5), BIG SRC (7), OPEN OUT (8), WRITE OUT (9),
  BIG OUT (10), DEPTH (11); FORMAT (6) печатает K1-G023 из fmt_pfx +
  hex-номер строки. Длины в записях — hex-байты (включая CRLF).
- **строки** (тело 0x08A2): CRLF-terminated; префикс FORMAT =
  "U-L1-SPLICE ERR=FORMAT AT=" (26 байт) + 4 цифры + CRLF = 32.
- **импорты**: 7 функций kernel32.dll, порядок как в M1-ENC. Выравнивание
  hint-записей (SPEC/04 п.7) — DZ 1 после GetStdHandle и ReadFile
  (раскладка модуля отличается от enc — выравнивания пересчитаны).
- **ячейки** (тело 0x0AD2+): hstdout (q), written (q), wa_len (q),
  srclen (q, dword-счётчик чтения), curline (q, dword-номер строки),
  fname_in/fname_out/namebuild (0x80), lv_name (8×0x80 — полные имена
  уровней), lv_cur (8×8 — сохранённые курсоры), lv_pref (8×1 — длины
  префиксов), linebuf (0x40), filebufs (8×0x40000), outbuf (0x40000).

## 5. Регистровые соглашения модуля

- См. `CARD.md`: RBX база образа; R10 база outbuf; R12 курсор вывода;
  **R13 — уровень 0..7**; RSI курсор текста; R14/R15 границы строки.
- Отличие от M1-ENC: R13 — уровень (у enc — база opbuf); K1-S011/S012
  меняют RSI/R13 (спуск по включениям — их контракт).

## 6. Инварианты (проверены эмуляцией и кругами)

1. splice.brick материализуется в тело 0xAD2 байта; SRD = 0xC00;
   файл 0xE00; VirtualSize = 0xAD2 + bss 0x240630 = 0x241102.
2. splice.exe = brick(splice.brick) + pegen(·, splice.peg) байт-в-байт.
3. **Самохостинг разреза:** splice.exe(splice.b2) == плоская форма;
   enc(·) == splice.brick; pegen(brick(·)) == splice.exe (T-E6-18).
4. splice.exe == оракулу LAB (lab_splice) на 14 якорях + 13 ошибках
   + большом исходнике + четырёх корнях репозитория — enc.b2,
   brick.brick, splice.b2, wall.b2 (T-E6-13..17).
5. Детерминизм: один вход — один выход (R8); концы строк LF/CRLF/CR —
   как у enc; пустой корень → пустой выход (специфик SPLICE).

## 7. История изменений образа

- **E6.3 (первая сборка):** создан целиком на BRICK v2 (M-строки), сразу
  разрезан на корень + 3 части собственным механизмом. Найденные в
  процессе дефекты — `VERIFY.md` §4 (сдвиг 17→11 hex, EOF-спуск,
  выравнивание hint-записей).
- **E6.4e-2 (рост пределов):** FILECAP/OUTCAP и буферы уровней
  128 → 256 КиБ. Изменены 9 байтов кода: imm 0x20000→0x40000 ×5
  (mov r8d ×2, cmp rax ×2, cmp rdx ×1), shl 11→12 ×3 (адресация
  уровней ×0x40000), rip-смещение $outbuf ×1 (метка уехала на
  +0x100000 за filebufs); ещё 2 байта — заголовки (VirtualSize,
  SizeOfImage). Тело 0xAD2 и файл 0xE00 не изменились; bss 0x120630
  → 0x240630, vsize 0x121102 → 0x241102, SizeOfImage 0x123000 →
  0x243000; splice.peg: !bss 120630 → 240630. Самохостинг и все
  круги зелёные.
