## 2. Уровни проверки (SPEC/02; все — в батарее `LAB/py/lab_verify.py`)

1. **Целостность:** SHA-256 выше; равенство
   `splice.exe == brick(splice.brick) + pegen(splice.peg)` (эмуляция,
   T-E6-18); равенство `splice.brick == enc(splice(splice.b2))`.
2. **PE-инварианты SPEC/04:** одна секция, один импорт, точка входа
   0x1000, hint-RVA чётные, VirtualSize 0x241102 = 0xAD2 + bss 0x240630
   (E6.4e-2).
3. **Эмуляция сценариев TESTS/T-L1-SPLICE.md:** справка (T-E6-12), 14
   якорей склейки (T-E6-14), 13 ошибок с кодами и строками (T-E6-15,
   пределы BIG SRC/BIG OUT — 256 КиБ), большой исходник 23 КиБ (T-E6-16),
   пределы 256 КиБ — корень и включение 132 КиБ приняты / 256 КиБ
   отвергнут (T-E6-16b, E6.4e-2).
4. **Оракул LAB:** splice.exe == lab_splice.splice байт-в-байт на всех
   якорях и на четырёх корнях репозитория — enc.b2, brick.brick,
   splice.b2, wall.b2 (T-E6-17; wall — крупнейший потребитель
   пределов); самохостинг разреза — полный круг
   splice -> enc -> brick -> pegen -> splice.exe (T-E6-18).

## 3. Доказанная оценка буферов

Выход ≤ вход + 1 байт на строку (каждая строка получает ровно один LF,
CR съедается терминатором): выход ≤ вход + число строк ≤ 2×вход.
Пределы SPEC/10 (E6.4e-2): файл < 0x40000 (сентинел), выход ≤ 0x40000,
суммарный вход ≤ 8×0x40000 (уровни), имя ≤ 0x7F. Буферы уровней — DBZ
(виртуальные нули): 8×0x40000 не увеличивают файл (SRD 0xC00 от тела
0xAD2); адресация уровня — сдвиг shl 18.

## 4. Журнал дефектов, найденных при создании (эмуляция + оракул)

Собственный код splice (исправлены до фиксации артефакта):

1. **Числа в M-строках — hex:** `M shl rdx, 17` означал сдвиг на 0x17=23,
   а не на 17: буфер уровня уезжал на +0x800000, эмуляция ловила доступ
   вне регионов на первом же включении. Правильно: `shl rdx, 11`
   (0x11 = 17). Та же ловушка зафиксирована в E6.1 (журнал, сессия 3).
2. **EOF-спуск не сканировался:** после handle_line на последней строке
   без терминатора поток проваливался в pl_filedone — включение в
   последней строке не разворачивалось (якорь «директива в последней
   строке» поймал). Исправление: после вызова — проверка роста уровня
   (test r13,r13) и переход к циклу при спуске.
3. **Счётчик строк:** инкремент ПЕРЕД обработкой строки (для сквозной
   нумерации в порядке чтения) требовал инициализации curline = 0, а не 1
   (первая строка получала номер 2; поймано якорями FORMAT AT=).

Дефекты раскладки (пойманы PE-инвариантами SPEC/04, секция 2 батареи):

4. **Выравнивание hint-записей:** выравнивания DZ 1 скопированы из enc —
   но раскладка splice иная: 7 подсказок уехали на нечётные RVA. Правило:
   выравнивания пересчитываются под конкретную раскладку (DZ 1 после
   GetStdHandle и ReadFile; после dll_name — не нужно). Поймано
   инвариантом «hint-RVA чётные» при первом прогоне батареи.

Дефектов оракула и эмулятора LAB на этот раз не найдено (оракул писался
до инструмента; якоря — вручную, независимо от оракула).

## 5. Регламент регресса

Любое изменение splice.b2 или его частей: батарея 113/113; T-E6-14/15
на всех якорях (пределы BIG SRC/BIG OUT — 256 КиБ); T-E6-16b (корень
и включение 132 КиБ); самохостинг T-E6-18; разрезы T-E6-17 (splice
четырёх корней == оракулу). Изменение SPEC/10: сначала CASES/ERRORS в
`LAB/py/lab_splice_cases.py` (лаборатория — эталон; расхождение оракула
с инструментом — находка, не повод подогнать — прецедент E6.2, VERIFY
enc §4).
