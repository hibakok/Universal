# Проверка модуля M0-HEXGEN

Паспорт файла: KERNEL/L0-HEXGEN/VERIFY.md | слой: L0 | роль: инструкция проверки.

## Паспорт артефакта

| Свойство | Значение |
|---|---|
| Файл | `KERNEL/L0-HEXGEN/hexgen.exe` |
| Размер | 2560 байт (0xA00) |
| SHA-256 | `947AD0182A0162CB402CB4D92A7932681CE6B2BF16B5B524ACCE07AB3FD241BF` |
| Тип | PE32+ (консоль, x86-64), 1 секция, импорт kernel32.dll (7 функций) |
| Особенность | SizeOfRawData (0x800) < VirtualSize (0x20880): буферы — виртуальные нули (bss) |
| Исходник | `hexgen.hex` (формат ATOM v1) — полный байтовый листинг |
| Использование | `hexgen.exe <вход.hex> <выход.bin>` (см. CARD.md) |

## Проверка 1: подлинность (хэш)

```
certutil -hashfile hexgen.exe SHA256
```

Вывод должен совпасть с SHA-256 из таблицы выше (регистр не важен).

## Проверка 2: DoD этапа E3 — сборка семени

```
cd KERNEL\L0-HEXGEN
hexgen.exe ..\L0-SEED\seed.hex t_seed.exe
certutil -hashfile t_seed.exe SHA256
fc /b t_seed.exe ..\L0-SEED\seed.exe
```

SHA-256 = `615D3292CCDD08664F7ACFCF9EF39E55F37443D1BF5A5F3E40D1CC796E64DBDF`
(эталон seed.exe); `fc` сообщает «Различий не найдено». Это главный
критерий готовности этапа E3 (см. DOCS/03-ROADMAP.md).

## Проверка 3: самосборка (круг замкнулся)

```
hexgen.exe hexgen.hex t_hexgen.exe
fc /b t_hexgen.exe hexgen.exe
```

Различий нет: компилятор собирает сам себя из собственного исходника.

## Проверка 4: остальные образы

```
hexgen.exe ..\L0-SEED2\seed2.hex t2.exe      -> fc: различий нет с seed2.exe
hexgen.exe ..\L0-HXDUMP\hxdump.hex t3.exe    -> fc: различий нет с hxdump.exe
```

## Проверка 5: коды возврата и строки ошибок

```
hexgen.exe                     -> справка (45 байт), код 2
hexgen.exe a.hex               -> справка, код 2
hexgen.exe no_such.hex t.bin   -> ERR=OPEN INPUT, код 4
hexgen.exe <файл с мусором>    -> ERR=FORMAT, код 7
hexgen.exe ok.hex nodir\t.bin  -> ERR=OPEN OUTPUT, код 8
```

Полный список сценариев — `TESTS/T-L0-HEXGEN.md` (T-M4-01..14).

## Журнал верификации

| Дата | Кто | Уровни | Результат |
|---|---|---|---|
| Этап E3 | ИИ (GLM) | PE-разбор (30 инвариантов, включая новое правило raw ≤ virtual) + objdump (370 инструкций, границы совпадают, без (bad)) + эмуляция (22 сценария: 4 круга сборки байт-в-байт, включая самосборку; 15 ошибок/толерантностей) | все зелёные |

Эмулятор перед прогоном hexgen был повторно валидирован на трёх образцах
E0–E2: seed (эталонная строка), seed2 (5 команд + справка), hxdump
(полный дамп seed.exe — 64 строки, сверка с независимым генератором).

## Пойманные ошибки сборки (почему нужна трёхуровневая проверка)

Эмуляция уровня 3 поймала три реальных дефекта, прозёванных разбором и
дизассемблированием:

1. **RVA вместо файловых смещений в импортах.** Генераторы таблицы
   импортов записали в IDT/IAT/INT смещения меток в ФАЙЛЕ (0x916) вместо
   RVA (0x1716): вызов `call [rip]GetStdHandle` уводил управление по
   адресу 0x916. Класс ошибки: смешение двух систем координат —
   ловится только исполнением.
2. **Инвертированное условие в K0-R005.** После `cmp r13d,r11d` стоял
   `jbe` (переход при top ≤ до) вместо `jae` (при top ≥ до): диапазон `Z`
   никогда не расширял образ — собранный seed.exe был 954 байта вместо
   1024 (хэш не совпадал, первые 954 байта были верны). Класс: направление
   сравнения в ветвлении.
3. **Потерянное перечитывание [rdi] в K0-C022.** Некавыччный путь
   skip_argv0 переходил на метку после `movzx` (без повторного чтения
   символа): разбор argv[0] зацикливался навсегда на первом символе.
   Класс: цель перехода в скопированном коде (реинкарнация изменила
   раскладку меток прародителя).

Вывод: уровень 3 обязателен для каждого образа L0 (правило SPEC/02);
реинкарнации копируются с пересмотром целей каждого перехода.

## Замечания

- Файл не подписан: SmartScreen/антивирус могут спросить подтверждение.
- Программа читает один входной файл и создаёт один выходной; ничего
  другого на диске не изменяет; сеть не использует.
- Работает на Windows 7+ x64 и под Wine.
