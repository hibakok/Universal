# Карточка модуля M0-HEXGEN (первый компилятор: ATOM → бинарник)

Паспорт файла: KERNEL/L0-HEXGEN/CARD.md | слой: L0 | роль: карточка модуля.

| Поле | Значение |
|---|---|
| ID модуля | M0-HEXGEN |
| Слой | L0 (МАШИНА) |
| Назначение | Первый компилятор проекта: читает ATOM-листинг (текст) и материализует бинарный файл байт-в-байт. Исчезает необходимость ручной материализации байтов |
| Вход | командная строка Windows: `hexgen.exe <вход.hex> <выход.bin>` |
| Выход | бинарный файл, собранный по листингу; код возврата 0 (успех) / 2 (нет аргумента) / 3 (имя длиннее 127) / 4 (вход не открыт) / 5 (ошибка чтения) / 6 (вход больше 64 КиБ) / 7 (плохой формат ATOM) / 8 (выход не создан) / 9 (ошибка записи) |
| Размер | 2560 байт (0xA00) |
| Платформа | Windows x64, консольная подсистема, PE32+ |
| Импорты | kernel32.dll: GetStdHandle, WriteFile, ExitProcess, GetCommandLineA, CreateFileA, ReadFile, CloseHandle |

## Формат вызова

```
hexgen.exe <вход.hex> <выход.bin>
```

Оба аргумента обязательны. Вход — ATOM v1 (грамматика: `SPEC/03-ATOM-FORMAT.md`).
Выход создаётся заново (CREATE_ALWAYS). Длина образа = максимум концов всех
@-строк и Z-диапазонов листинга (imgtop).

## Строгость разбора

- Принимаются: строки `@`, `Z`, комментарии `;`, пустые строки; CRLF.
- Отвергаются (код 7): посторонний символ в начале строки; строчные
  hex-цифры (ATOM v1 требует ЗАГЛАВНЫЕ); не-4-значное смещение; одиночная
  цифра байта; смещение/диапазон за пределами 64 КиБ; перевёрнутый `Z`;
  мусор после `Z от до` (кроме пробелов и комментария).
- Не проверяются (ответственность листинга): порядок строк, перекрытия
  диапазонов (поздняя запись перекрывает раннюю).

## Состав (что читать для работы с модулем)

| Файл | Назначение |
|---|---|
| `hexgen.hex` | исходник в формате ATOM v1 — источник истины |

## Что M0-HEXGEN доказывает

1. **Первый компилятор.** Текст (ATOM) автоматически превращается в байты:
   исчезает ручная материализация — правка листинга + `hexgen` = готовый
   артефакт. Круг замыкается на себе: hexgen собирает сам себя из
   собственного листинга (T-M4-04).
2. **Файловый вывод** (ветвь F): создание и запись файлов — данные
   покидают наш мир так же легко, как входят.
3. **Виртуальные нули (bss).** Впервые SizeOfRawData < VirtualSize:
   буферы по 64 КиБ не занимают места в файле (образ 2560 байт) и
   остаются описанными спецификацией. Это снимает барьер роста образов
   при сохранении ATOM v1 с 4-значными смещениями.
4. **Кирпичность разбора.** Грамматика ATOM разобрана на 6 кирпичей
   ветви R; строгость разбора ловит ошибки ручного редактирования
   листингов (строчные буквы, мусор, перевёрнутые диапазоны).
5. **Универсальные обобщения.** copy_word_dst (приёмник-параметр) и
   read_word (подпрограмма) переиспользуются при любом числе аргументов.

## Ограничения (снять в следующих этапах)

- Имена файлов до 127 байт (буферы fname; длиннее — код 3).
- Вход-листинг до 64 КиБ (filebuf; больше — код 6).
- Собираемый образ до 64 КиБ (предел 4-значных смещений ATOM v1;
  расширение формата — по мере роста образов, с сохранением
  обратной совместимости).
- Порядок строк и перекрытия не проверяются (ответственность листинга).
