# Проверка модуля M0-PEGEN

Паспорт файла: KERNEL/L0-PEGEN/VERIFY.md | слой: L0 | роль: инструкция проверки.

## Паспорт артефакта

| Свойство | Значение |
|---|---|
| Файл | `KERNEL/L0-PEGEN/pegen.exe` |
| Размер | 4096 байт (0x1000) |
| SHA-256 | `A371EB9154C9A94C6B85D7EB658F44A8AC7529AF716428F8B677967D47792081` |
| Тип | PE32+ (консоль, x86-64), 1 секция + bss, импорт kernel32.dll |
| Исходники | `pegen.hex` (тело секции, ATOM v1) + `pegen.peg` (обёртка, SPEC/07) |

## Проверка 1: подлинность (хэш)

```
certutil -hashfile pegen.exe SHA256
```

Должно совпасть с SHA-256 из таблицы выше.

## Проверка 2: справка

```
pegen.exe
```

Ожидаемый вывод (57 байт + CRLF): `U-L0-PEGEN CMDS: PEGEN <IMAGE.BIN> <CTRL.PEG> <OUT.EXE>`
Код возврата: 2.

## Проверка 3: коды возврата

Таблица кодов — SPEC/07 (2..11). Каждый код воспроизводится сценариями
тест-плана `TESTS/T-L0-PEGEN.md` (T-M5-07..14).

## Проверка 4: круги сборки (главная)

```
Из папки KERNEL:
  L0-HEXGEN\hexgen.exe L0-SEED\seed.hex t_body.bin
  L0-PEGEN\pegen.exe t_body.bin L0-SEED\seed.peg t_seed.exe
  fc /b t_seed.exe L0-SEED\seed.exe        -> различий нет

  (аналогично seed2 / hxdump / hexgen)

Самосборка:
  L0-HEXGEN\hexgen.exe L0-PEGEN\pegen.hex t_pb.bin
  L0-PEGEN\pegen.exe t_pb.bin L0-PEGEN\pegen.peg t_pegen.exe
  fc /b t_pegen.exe L0-PEGEN\pegen.exe     -> различий нет
```

## Пойманные ошибки ручной сборки (все — уровнем 3, эмуляция)

Уроки E4 (дизассемблер пропустил все: кодировки были валидны, но неверны):

1. Направление `89 /r` (повтор урока E1): `mov rsi,rdi` собран как
   `48 89 F7` = mov rdi,rsi.
2. REX-биты (ШЕСТЬ ошибок одного класса): `mov r13,r8` без REX.B
   (4C→4D); `add r8,rbx` — R вместо B (4C 01 D8→49); `add r11,rax` —
   лишний R (4D→49); `movzx eax,[rsi+r10]` — B вместо X (41→42, ×2);
   `mov r8,[r11]` — WB вместо WRB (49→4D); `lea rsi,[rsi+r10]` — WB
   вместо WX (49→4A). Правило: REX = 0100 WRXB (W-вес 8, R-4, X-2, B-1).
3. Знакорасширение imm8 в форме `83 /7`: `cmp rdx,0x80` собран как
   `48 83 FA 80` = cmp rdx,−0x80 → цикл дозаписи заглушки не завершался
   (запись за пределы секции). Заменено на 32-битное `81 FA 80 00 00 00`.
4. Знак в align_up: `add eax,ecx` при ecx=−a давал v−a вместо v+a−1
   (длина дополнения = 0xFFFFFC40). Исправлено на lea eax,[rax+rcx-1].
5. Потеря инструкций при реинкарнации: в skip_argv0 пропущены
   `inc rdi; jmp sa_start` (цикл посимвольного пропуска argv0) —
   первым аргументом становилось имя самой программы.
6. Забыт `add rdi,0x40` в build_stub — заглушка писалась поверх
   DOS-заголовка.
7. Данные: слоты IAT/INT по 7 байт вместо 8; IDT 25 байт вместо 0x28
   (терминатор — полная нулевая запись 20 байт, не 8); записи errtab по
   7 байт вместо 16 (длина/код — dword, не байт).
8. vdesc: в поле перем.2 стоял RVA маркера-нуля вместо самого нуля —
   однозначные директивы требовали второе значение.
9. Спецметка image_base (RVA 0 = тело −0x1000) была перекрыта обычной
   меткой — RBX указывал внутрь кода.

Вывод: уровень 3 (исполнение) обязателен для каждого образа L0 —
подтверждено в третий раз (E0: 3 ошибки, E1: 5, E2: 6, E3: 3, E4: 9
классов, частично по несколько экземпляров).
