# Карточка модуля M0-PEGEN (обёртка образов: тело + PEG → EXE)

Паспорт файла: KERNEL/L0-PEGEN/CARD.md | слой: L0 | роль: карточка модуля.

| Поле | Значение |
|---|---|
| ID модуля | M0-PEGEN |
| Слой | L0 (МАШИНА) |
| Назначение | Второй компилятор проекта: оборачивает бинарное тело секции в готовый PE32+ EXE — заголовки генерируются автоматически по управляющему файлу PEG (SPEC/07). Ручное сопровождение PE-заголовков прекращается |
| Вход | командная строка Windows: `pegen.exe <image.bin> <ctrl.peg> <out.exe>` |
| Выход | готовый EXE; код возврата 0 (успех) / 2 (мало аргументов) / 3 (имя длиннее 127) / 4 (образ не открыт) / 5 (ошибка чтения образа) / 6 (образ больше 64 КиБ) / 7 (peg не открыт) / 8 (ошибка чтения peg) / 9 (плохой формат PEG) / 10 (выход не создан) / 11 (ошибка записи) |
| Размер | 4096 байт (0x1000) |
| Платформа | Windows x64, консольная подсистема, PE32+ |
| Импорты | kernel32.dll: GetStdHandle, WriteFile, ExitProcess, GetCommandLineA, CreateFileA, ReadFile, CloseHandle |

## Формат вызова

```
pegen.exe <image.bin> <ctrl.peg> <out.exe>
```

`image.bin` — тело секции (RVA 0x1000 = смещение 0), обычно выход
`hexgen.exe`. `ctrl.peg` — директивы обёртки (грамматика: `SPEC/07-PEG-FORMAT.md`).
Полный цикл сборки модуля (E4):

```
hexgen.exe <модуль>.hex  <модуль>-body.bin
pegen.exe  <модуль>-body.bin  <модуль>.peg  <модуль>.exe
```

## Строгость разбора

- Принимаются: директивы `!…` (строчные ключевые слова), комментарии `;`,
  пустые строки, CRLF; значения 1..8 ЗАГЛАВНЫХ hex-цифр.
- Отвергается (код 9): посторонний символ; неизвестное/ искажённое ключевое
  слово; отсутствие обязательной директивы (module, entry, idata, iat);
  пустое или длиннее 31 байта имя модуля; ноль или больше 8 цифр в значении;
  мусор в хвосте директивы.
- Не проверяется (ответственность .peg): семантика значений, попадание
  точки входа в секцию, достаточность фиксаций.

## Состав (что читать для работы с модулем)

| Файл | Назначение |
|---|---|
| `pegen.hex` | исходник тела секции в формате ATOM v1, телесная форма (источник истины) |
| `pegen.peg` | управляющий файл собственной обёртки |
| `pegen.exe` | материализация: hexgen + pegen, байт-в-байт |
| `BYTECODE.md` | сводка образа, карта кирпичей, данные, импорты |
| `VERIFY.md` | SHA-256, три уровня проверки, журнал пойманных ошибок |

Файлы (обобщения ветви F):

  K0-E002 patch_dirs           (вход, каталоги, фиксации)

  K0-P041 print_line           (реинкарнация K0-P031)

  K0-D041 служебные ячейки     (hstdout…soi, bss)
  K0-D042 таблицы              (kwtab, vdesc, errtab, ключевые слова)

  K0-D044 шаблон заголовка     (0x200 байт, патч-зоны обнулены)
  K0-D045 таблица импортов     (7 функций kernel32.dll)

## Что M0-PEGEN доказывает

1. **Конец ручных заголовков.** Полный цикл «правка ATOM-текста → готовый
   EXE» = HEXGEN + PEGEN. Инварианты SPEC/04 больше не копируются руками:
   SizeOfImage/SizeOfRawData/фиксации вычисляются, заглушка строится.
2. **Самосборка на новом уровне.** pegen собирает сам себя из собственного
   телесного листинга и pegen.peg (T-M5-06); hexgen и pegen взаимно
   воспроизводят весь инструментарий из текстов (T-M5-02..06).
3. **Таблицы вместо кода.** Ключевые слова, описатели директив, сообщения
   ошибок — данные; обработчики обобщены (Q011 обслуживает 6 директив
   одной подпрограммой по описателю).
4. **Кирпичность.** 26 кодовых кирпичей, старые ветви реинкарнированы,
   файловые подпрограммы обобщены до параметрических (F024/F025).

## Ограничения (снять в следующих этапах)

- Резерв стека/кучи фиксирован 1 МиБ (расширение — PEG v2).
- Одна секция, один импорт kernel32.dll (шаблон SPEC/04).
- Значения директив не валидируются семантически.

## Примеры

```
cmd -> KERNEL\L0-PEGEN\pegen.exe
Вывод:   U-L0-PEGEN CMDS: PEGEN <IMAGE.BIN> <CTRL.PEG> <OUT.EXE>   (57 байт, CRLF)
Код:     2

Из папки KERNEL (полный цикл модуля):
  L0-HEXGEN\hexgen.exe L0-SEED\seed.hex t_body.bin
  L0-PEGEN\pegen.exe t_body.bin L0-SEED\seed.peg t_seed.exe
  fc /b t_seed.exe L0-SEED\seed.exe   ->  различий нет
```
