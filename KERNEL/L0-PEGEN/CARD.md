# Карточка модуля M0-PEGEN (обёртка образов: тело + PEG → EXE)

Паспорт файла: KERNEL/L0-PEGEN/CARD.md | слой: L0 | роль: карточка модуля.

| Поле | Значение |
|---|---|
| ID модуля | M0-PEGEN |
| Слой | L0 (МАШИНА) |
| Назначение | Второй компилятор проекта: оборачивает бинарное тело секции в готовый PE32+ EXE — заголовки генерируются автоматически по управляющему файлу PEG. v1 (образы семейства, шаблон SPEC/04) — как было; v2 (E9.4-4b-4): сборщик wrap2 — чужие образы PE32+ как патчи над нулями (!pev2/!hdr/!body/!sec, SPEC/07 «Рост v2»; оракул lab_pegen.wrap2). Ручное сопровождение PE-заголовков прекращается |
| Вход | командная строка Windows: `pegen.exe <image.bin> <ctrl.peg> <out.exe>` |
| Выход | готовый EXE; код возврата 0 (успех) / 2 (мало аргументов) / 3 (имя длиннее 127) / 4 (образ не открыт) / 5 (ошибка чтения образа) / 6 (образ больше 128 КиБ — E6.4g-3) / 7 (peg не открыт) / 8 (ошибка чтения peg) / 9 (плохой формат PEG — вкл. все отказы v2: синтаксис, границы, наложения, самоописание) / 10 (выход не создан) / 11 (ошибка записи) |
| Размер | 6144 байта (0x1800; E9.4-4b-4 — было 4096) |
| Платформа | Windows x64, консольная подсистема, PE32+ |
| Импорты | kernel32.dll: GetStdHandle, WriteFile, ExitProcess, GetCommandLineA, CreateFileA, ReadFile, CloseHandle |

## Формат вызова

```
pegen.exe <image.bin> <ctrl.peg> <out.exe>
```

`image.bin` — тело секции (RVA 0x1000 = смещение 0), обычно выход
`hexgen.exe`. `ctrl.peg` — директивы обёртки (грамматика: `SPEC/07-PEG-FORMAT.md`).
Развилка версий (E9.4-4b-4): первая директива `!pev2` — путь v2 (wrap2:
нули + патчи, чужие образы), иначе — v1 (шаблон SPEC/04, семейство;
v1-тексты ведут себя как до порта — нейтральность T-M5-02..06/18).
Полный цикл сборки модуля (E4):

```
hexgen.exe <модуль>.hex  <модуль>-body.bin
pegen.exe  <модуль>-body.bin  <модуль>.peg  <модуль>.exe
```

## Строгость разбора

- Принимаются: директивы `!…` (строчные ключевые слова), комментарии `;`,
  пустые строки, CRLF; значения 1..8 ЗАГЛАВНЫХ hex-цифр.
- Отвергается (код 9): посторонний символ; неизвестное/ искажённое ключевое
  слово; отсутствие обязательной директивы (module, entry, idata, iat);
  пустое или длиннее 31 байта имя модуля; ноль или больше 8 цифр в значении;
  мусор в хвосте директивы.
- Не проверяется (ответственность .peg): семантика значений, попадание
  точки входа в секцию, достаточность фиксаций. В v2 проверяется
  САМООПИСАНИЕ собранной области заголовков (MZ/PE/таблица секций/
  raw-области — SPEC/07 «Сборка»): инструмент собирает чужой EXE
  байт-в-байт == оракулу (T-M5-18).

## Состав (что читать для работы с модулем)

## Что M0-PEGEN доказывает

1. **Конец ручных заголовков.** Полный цикл «правка ATOM-текста → готовый
   EXE» = HEXGEN + PEGEN. Инварианты SPEC/04 больше не копируются руками:
   SizeOfImage/SizeOfRawData/фиксации вычисляются, заглушка строится.
2. **Самосборка на новом уровне.** pegen собирает сам себя из собственного
   телесного листинга и pegen.peg (T-M5-06); hexgen и pegen взаимно
   воспроизводят весь инструментарий из текстов (T-M5-02..06).
3. **Таблицы вместо кода.** Ключевые слова, описатели директив, сообщения
   ошибок — данные; обработчики обобщены (Q011 обслуживает 6 директив
   одной подпрограммой по описателю).
4. **Кирпичность.** 26 кодовых кирпичей v1, старые ветви реинкарнированы,
   файловые подпрограммы обобщены до параметрических (F024/F025); v2
   (E9.4-4b-4) — +12 кодовых кирпичей (Q012..Q019, E005..E007, G043)
   и +2 данных (D047/D048): развилка версий, разбор директив v2,
   самоописание, применение тела и патчей — минимальные шаги.
5. **Чужие EXE собираются из текста.** wrap2 в инструменте: чужой
   EXE -> (тело b2 + PEG v2) мостом -> pegen.exe -> байт-в-байт образ
   (T-M5-18; первый чужой круг — следующий срез E9.4).

## Ограничения (снять в следующих этапах)

- Резерв стека/кучи фиксирован 1 МиБ (расширение — PEG v2).
- v1: одна секция, один импорт kernel32.dll (шаблон SPEC/04); значения
  директив не валидируются семантически.
- image.bin ≤ 128 КиБ (E6.4g-3; для v2 — тоже, снять при первом чужом
  круге — SPEC/07 «Ограничения v2»). ctrl.peg < 64 КиБ не менялся.
- v2, инструмент (E9.4-4b-4): область заголовков H ≤ 0x40000 и файл
  ≤ 0x40000 (outbuf); патчей !hdr ≤ 64, записей !sec ≤ 128, данных
  секций ≤ 8 КиБ, таблица raw ≤ 4096 секций — пределы буферов bss
  (снять при первом чужом круге; оракул пределов не имеет).

## Примеры

```
cmd -> KERNEL\L0-PEGEN\pegen.exe
Вывод:   U-L0-PEGEN CMDS: PEGEN <IMAGE.BIN> <CTRL.PEG> <OUT.EXE>   (57 байт, CRLF)
Код:     2

Из папки KERNEL (полный цикл модуля):
  L0-HEXGEN\hexgen.exe L0-SEED\seed.hex t_body.bin
  L0-PEGEN\pegen.exe t_body.bin L0-SEED\seed.peg t_seed.exe
  fc /b t_seed.exe L0-SEED\seed.exe   ->  различий нет
```
