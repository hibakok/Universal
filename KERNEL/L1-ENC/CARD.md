# Карточка модуля M1-ENC (кодировщик BRICK v2 -> BRICK v1)

Паспорт файла: KERNEL/L1-ENC/CARD.md | слой: L1 | роль: карточка модуля.

| Поле | Значение |
|---|---|
| ID модуля | M1-ENC |
| Слой | L1 (СБОРКА); исходник — BRICK v2 (M-строки, SPEC/09) |
| Назначение | Нормализатор BRICK v2 -> BRICK v1: кодирует M-строки (мнемоники + операнды) в канонические H-строки по SPEC/09. Ручное назначение байтов кодировок прекращается: последняя ручная работа L1 по SPEC/08 устранена. Адресов НЕ считает: ссылки `$имя`/`$имя:1` проходят сквозь enc в слоты H-строк нетронутыми — их разрешает brick.exe (нулевый риск для самохостинга E5) |
| Вход | командная строка Windows: `enc.exe <вход.b2> <выход.brick>` |
| Выход | текст BRICK v1 (все строки с LF): M-строки заменены на H-строки, прочие строки (метки, H/DB/DZ/DBZ/DD/DQ, комментарии, пустые) проходят байт-в-байт; коды возврата 0 / 2 (мало аргументов) / 3 (имя длиннее 127) / 4 (вход не открыт) / 5 (ошибка чтения) / 6 (плохой формат, `AT=<строка>`) / 7 (вход больше 128 КиБ) / 8 (выход не создан) / 9 (ошибка записи) |
| Размер | 11776 байт (0x2E00) |
| Платформа | Windows x64, консольная подсистема, PE32+ |
| Импорты | kernel32.dll: GetStdHandle, WriteFile, ExitProcess, GetCommandLineA, CreateFileA, ReadFile, CloseHandle |
| Самохостинг | `enc.exe enc.b2 out.brick` воспроизводит enc.brick байт-в-байт; конвейер enc+brick+pegen воспроизводит enc.exe (DoD E6.2) |

## Формат вызова

```
enc.exe <вход.b2> <выход.brick>
```

Оба аргумента обязательны. Вход — BRICK v2 (грамматика: `SPEC/09-ENC-FORMAT.md`).
Выход создаётся заново (CREATE_ALWAYS). Полный цикл сборки модуля:

```
enc.exe   <модуль>.b2      <модуль>.brick
brick.exe <модуль>.brick   <модуль>-body.bin
pegen.exe <модуль>-body.bin <модуль>.peg  <модуль>.exe
```

## Строгость разбора

- M-строка распознаётся по stripped-строке, начинающейся с `M ` (пробел; не
  табуляция), либо состоящей из одного `M`. Прочие строки не анализируются
  и проходят в выход без изменений (их проверяет brick).
- Ошибки формата M-строки: код 6, `ERR=FORMAT AT=<hex-номер строки с 1>`
  (нумерация всех строк входа, как у оракула LAB). Номер совпадает с
  исключением оракула `lab_enc` байт-в-байт (проверено батареей на 21
  ошибке и 109 якорях).
- Концы строк — семантика Python splitlines: LF, CRLF и одиночный CR —
  терминаторы строк (CRLF — один); пустой вход даёт выход из одного LF
  (quirk оракула, воспроизведён намеренно и зафиксирован тестом).
- Выход всегда завершается LF; выход <= вход x 23/11 + 1 байт (худший
  случай — короткая строка с imm32-формой 81; буфер 0x44010 покрывает
  вход 128 КиБ с запасом).

## Состав (что читать для работы с модулем)

| Файл | Назначение |
|---|---|
| `enc.b2` | само-исходник в BRICK v2 (M-строки + данные) — канонический исходник |

## Регистровые соглашения модуля

- `rbx` — база образа (RVA 0); `r10` — база outbuf; `r12` — курсор вывода;
  `r13` — база opbuf (структуры операндов 2 x 0x40); `rsi` — курсор текста;
  `r14`/`r15` — начало/конец текущей строки; `rbp` — свободен.
- Подпрограммы сохраняют RBX,RSI,R10,R12,R13,R14,R15,RBP и могут менять
  RAX,RCX,RDX,RDI,R8,R9,R11. Аргументы — RCX,RDX,R8,R9; результат — RAX/RDX.
- Структура операнда (opbuf + i*0x40): +0 вид (0 рег / 1 imm / 2 ссылка /
  3 память), +8 код|значение, +10 размер (0 = не задан), +18 имя|база,
  +20 длина имени|индекс (-1 нет), +28 слот|смещение, +30 rip-имя, +38 длина.

## Что M1-ENC доказывает

1. **Конец ручной кодировки байтов.** Мнемоники, REX, modrm/SIB, выбор
   disp8/disp32 и imm8/imm32 назначает инструмент по каноническим формам
   SPEC/09 — последняя ручная работа L1 (SPEC/08) устранена.
2. **Самохостинг BRICK v2.** enc.exe собирает собственный исходник enc.b2
   (2651 строка, ~77 КиБ, полностью на M-строках и директивах данных) в
   enc.brick байт-в-байт; конвейер enc+brick+pegen воспроизводит enc.exe.
   Круг замкнут на M-строках.
3. **Таблицы вместо кода.** 48 регистров, 41 мнемоника, 4 ключа размера —
   данные (записи по 16 байт); один линейный поиск обслуживает всё.
4. **Кирпичность.** 55 кодовых кирпичей; 15 реинкарнаций из M1-BRICK
   (C/F/U/G/X-ветви) перенесены на M-строки с новыми K-ID — реинкарнация
   в эпоху BRICK v2 стала переносом АЛГОРИТМА, а не байтов.

## Ограничения (снять в следующих этапах)

- Автовыбора rel8/rel32 нет (нужно знание адресов — слой brick; SPEC/09).
- Исходник enc.b2 — 2651 строка (превышает лимит 500; известное отклонение,
  как brick.brick 851) — разрез по include-механизму запланирован этапом
  E6.3 (SPEC/08a).
- Вход <= 128 КиБ (предел filebuf); выход <= 0x44010 (доказанная оценка
  вход x 23/11 + 1).
- Вертикальная табуляция/NEL как разделители строк (quirk splitlines) не
  поддерживаются — вне контракта SPEC/08/09 (LF/CRLF/CR покрыты тестами).

## Примеры

```
cmd -> KERNEL\L1-ENC\enc.exe
Вывод:   U-L1-ENC CMDS: ENC <SRC.B2> <OUT.BRICK>   (41 байт, CRLF)
Код:     2

Из папки KERNEL (самохостинг):
  L1-ENC\enc.exe L1-ENC\enc.b2 t.brick
  fc /b t.brick L1-ENC\enc.brick   ->  различий нет
  L1-BRICK\brick.exe t.brick t_body.bin
  L0-PEGEN\pegen.exe t_body.bin L1-ENC\enc.peg t_enc.exe
  fc /b t_enc.exe L1-ENC\enc.exe   ->  различий нет
```
