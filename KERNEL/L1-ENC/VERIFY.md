## 2. Уровни проверки (SPEC/02; все — в батарее `LAB/py/lab_verify.py`)

1. **Целостность:** SHA-256 выше; равенство `enc.exe == brick(enc.brick) +
   pegen(enc.peg)` (эмуляция, секция кругов батареи).
2. **PE-инварианты SPEC/04:** одна секция, один импорт, точка входа
   0x1000, hint-RVA чётные, VirtualSize 0x69EE4 = 0x2CCE + !bss 67216.
3. **Эмуляция сценариев TESTS/T-L1-ENC.md:** справка (T-E6-05), все 117
   якорей одним файлом (T-E6-06), 27 ошибок с точными номерами строк
   (T-E6-07/11), круг enc+brick+pegen -> «U-ENC-OK» (T-E6-08), большой
   исходник 23 КиБ (T-E6-10), 8 граничных концов строк.
4. **Оракул LAB:** enc.exe == lab_enc.normalize байт-в-байт на всём
   вышеупомянутом; самохостинг enc(splice(enc.b2)) == enc.brick
   (76243 байта, T-E6-09) и полный круг -> enc.exe.

Автоматически: `python3 LAB/py/lab_verify.py` -> 111/111 OK (~70 с; CI
запускает на каждый пуш). Без LAB, на Windows (из папки KERNEL):

```
L1-ENC\enc.exe
  -> U-L1-ENC CMDS: ENC <SRC.B2> <OUT.BRICK>   код 2

Самохостинг на Windows (enc не разрешает !include — сначала склеить):

```
L1-SPLICE\splice.exe L1-ENC\enc.b2 t_flat.b2
L1-ENC\enc.exe t_flat.b2 t.brick
L1-BRICK\brick.exe t.brick t_body.bin
L0-PEGEN\pegen.exe t_body.bin L1-ENC\enc.peg t_enc.exe
fc /b t_enc.exe L1-ENC\enc.exe    -> различий нет (самохостинг)
fc /b t.brick L1-ENC\enc.brick    -> различий нет

L1-ENC\enc.exe нет.b2 t.brick
  -> U-L1-ENC ERR=OPEN SRC                      код 4

  -> t.brick: H 4D 0F AF D3                     (рост ISA E6.4c)

echo M bogus rax, rax> t.b2 && L1-ENC\enc.exe t.b2 t.brick
  -> U-L1-ENC ERR=FORMAT AT=0001                код 6
```

## 3. Доказанная оценка буфера вывода

Худшая строка входа — `M or r8,80` (11 байт с LF) -> `H 49 81 C8 80 00 00
00` + LF (23 байта): рост 23/11. Все прочие формы растут меньше либо
сжимаются; проход не-M-строк 1:1. Итого выход < вход x 23/11 + 1; для
входа 128 КиБ выход < 0x42E6D, буфер outbuf 0x44010 — с запасом.

## 4. Журнал дефектов, найденных при создании (эмуляция + оракул)

Собственный код enc (исправлены до фиксации артефакта):

1. **span операндов захватывал LF** — el_p2 хранит КОНЕЦ последнего
   непустого символа, а parse_m прибавлял к нему ещё 1 (и сравнение
   «голого M» шло по неверной паре указателей): все операнды «наследовали»
   символ перевода строки и не совпадали с таблицами.
2. **emit2 не маскировал AL** — вызовы с значением > 0xFF в EAX уходили
   индексом за таблицу цифр (мусор в hex-выводе; на `mov ecx,-1` —
   доступ вне регионов).
3. **lookup_sizekw читал счётчик как qword** (`mov rcx,[r11+8]` вместо
   `ecx`) — в счётчик попадало поле размера записи, сравнение ключей
   читало память за таблицей.
4. **REX из флагов emit_rm** — флаг r (бит 1) сдвигался на 3 позиции
   вместо 1: `mov r8d,[rip+..]` получал REX 50 вместо 44. И **emit_slot не
   оставлял хвостовой пробел** — завершение строки съедало последний
   символ каждого слота (`$base` -> `$bas`).

Дефекты оракула LAB (E6.1), найденные enc/objdump-сверкой (исправлены,
якоря расширены):

5. **lab_enc._enc_mem: база r12 без индекса не давала SIB** — условие было
   `m.base == 4` вместо `m.base & 7 == 4`: `[r12]` кодировался с rm=100 без
   SIB-байта (невалидная инструкция). SPEC/09 прав: база rsp/r12 (&7==4)
   всегда требует SIB. Якоря: `[r12]`, `[r12+8]`, `[r13]`, `[r13+8]`,
   `[r11+r12]` (сверены objdump).
6. **lab_enc._enc_movzx: приоритет операторов** — `dst.code & 7 << 3`
   вычислялось как `dst.code & 56`: reg-поле обнулялось для приёмников с
   кодом 1..7 (`movzx edx,dl` кодировался как `movzx eax,dl`). Якоря:
   `movzx edx,dl` -> `0F B6 D2`, `movzx ecx,bl` -> `0F B6 CB`.

Дефекты эмулятора LAB, найденные enc (исправлены):

7. **lab_x86/lab_cpu: маска счётчика сдвига** — 64-битные сдвиги
   маскировались 5 битами (imm & 0x1F), а Intel определяет 6 бит при
   REX.W: `shr rax,32` (48 C1 E8 20) выполнялся как сдвиг на 0.
8. Подтверждено objdump: `43 88 14 27` = `[r15+r12]` — r12 ДОПУСТИМ как
   индекс (REX.X=1 + SIB index=100); формулировка SPEC/09 «индекс rsp/r12
   — ошибка» исправлена на «индекс rsp — ошибка; r12 допустим (REX.X)».

## 5. Регламент регресса

Любое изменение enc.b2: батарея 111/111; T-E6-06 на всех якорях; самохостинг
обоих кругов. Изменение SPEC/09: сначала CASES/ERRORS (лаборатория —
эталон; расхождение оракула с инструментом — находка, не повод
подгонять — см. §4).

## 6. Рост ISA (E6.4c, для WALL v2)

Добавлены мнемоники **imul** (семейство 0E — новый кирпич K1-E033:
REX.W 0F AF /r mod11, reg-поле = приёмник, только r64,r64), **idiv**
(семейство 9 как neg: F7 /7, r32/r64) и **cqo** (семейство D, байты
48 99). Декодер lab_x86 и исполнитель lab_cpu расширены (imul —
младшие 64 бита знакового произведения, CF=OF при неполном
знакорасширении; idiv — частное rax/остаток rdx, усечение к нулю,
деление на 0 и переполнение частного — #DE; cqo/cdq — знак rax ->
rdx:rax / eax -> edx:eax). Якоря: 109 -> 117 (+8), ошибки: 21 -> 27
(+6). Дефектов собственного кода при росте не найдено; найден и
исправлен перекос чётности RVA hint-записей от нечётного прироста
кода (калибровка DZ 1 -> DZ 2 после имени DLL — механизм E4a).
