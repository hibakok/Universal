# BYTECODE.md — разбор enc.exe

Паспорт файла: KERNEL/L1-ENC/BYTECODE.md | слой: L1 | роль: разбор образа.

Источник истины — `enc.b2` (BRICK v2: M-строки + данные, SPEC/09);
равносильная v1-форма — `enc.brick` (= `enc(enc.b2)` байт-в-байт).
По-инструкционная деталь (мнемоника + K-ID у каждой строки) — в обоих
исходниках; с E4 BYTECODE содержит структуру, а не дублирует листинг.

## 1. Заголовки

Генерируются pegen из `enc.peg`: SizeOfImage = 0x68000, VirtualSize =
0x67146, SizeOfRawData = 0x2C00, DD[1] = RVA 0x3AE4 (размер 0x28), DD[12] =
RVA 0x3B0C (размер 0x40), фиксации стека/кучи = 0x4000. Инварианты SPEC/04
выполняются (hint-записи — на чётных RVA: 0x3B9A, 0x3BAA, 0x3BB6, 0x3BC4,

## 4. Данные

- **regtab** (тело 0x23D9): 48 записей — 64/32/8-битные имена всех 16
  регистров (rax..r15, eax..r15d, al..r15b; sil/dil/spl/bpl = коды
  6/7/4/5). Запись: имя ≤ 8 байт (LEN-управляемое сравнение), длина,
  `код | размер<<8`.
- **mnemtab** (тело 0x26D9): 41 запись — add/or/and/sub/xor/cmp (параметр =
  база|расш<<8), rol/ror/shl/shr/sar (расш), 16 jcc (cc, je/jne — синонимы),
  mov/movzx/lea/test/call, neg/inc/dec (опк|расш<<8), push/pop (50/58),
  jmp, cdqe/ret/int3 (байты: 9848/C3/CC). Запись: имя ≤ 8 байт, длина,
  `семейство | параметр<<8`.
- **sizetab** (тело 0x2969): "byte ", "word ", "dword ", "qword " (с
  пробелом) -> 8/16/32/64.
- **errtab** (тело 0x29A9): 7 записей — справка (код 2), LONG NAME (3),
  OPEN SRC (4), READ SRC (5), BIG SRC (7), OPEN OUT (8), WRITE OUT (9);
  FORMAT (6) печатает K1-G013 из fmt_pfx + hex-номер строки.
- **строки** (тело 0x2A19): CRLF-terminated; префикс FORMAT =
  "U-L1-ENC ERR=FORMAT AT=" (23 байта) + 4 цифры + CRLF = 29.
- **Импорты**: 7 функций kernel32.dll, порядок как в M1-BRICK.
- **Ячейки** (RVA 0x3BFE+): hstdout (q), written (q), srclen (q, dword
  счётчик), curline (q, dword номер строки), wa_len (q), затем буферы.

## 5. Регистровые соглашения модуля

- См. `CARD.md`: RBX база образа; R10 база outbuf; R12 курсор вывода; R13
  база opbuf; RSI курсор текста; R14/R15 границы строки; подпрограммы
  сохраняют их и RBX/RBP, меняют RAX,RCX,RDX,RDI,R8,R9,R11.
- Отличие от M1-BRICK: R12 — курсор ВЫВОДА (у brick — хэндл файла);
  хэндлы входа/выхода живут в R12 (временно, до нормализации) и R15.

## 6. Инварианты (проверены эмуляцией и кругами)

1. enc.brick материализуется в тело 0x2BFE байта; SRD = 0x2C00; файл 0x2E00;
   VirtualSize = 0x2BFE + bss 0x64548 = 0x67146.
2. enc.exe = brick(enc.brick) + pegen(·, enc.peg) байт-в-байт.
3. **Самохостинг:** enc.exe(enc.b2) == enc.brick (74586 байт);
   pegen(brick(enc(enc.b2))) == enc.exe. Круг: v2 -> v1 -> тело -> EXE.
4. enc.exe == оракулу LAB на всех 109 якорях и 21 ошибке (батарея,
   секция 7); каждая H-строка кода enc.brick декодируется lab_x86
   ровно той же длины (структурный контроль, как T-E6-03).
5. Детерминизм: один вход — один выход (R8); концы строк LF/CRLF/CR —
   как у оракула (8 граничных тестов батареи).

## 7. История изменений образа
