# BYTECODE.md — разбор enc.exe

Паспорт файла: KERNEL/L1-ENC/BYTECODE.md | слой: L1 | роль: разбор образа.

Источник истины — `enc.b2` (BRICK v2: M-строки + данные, SPEC/09);
равносильная v1-форма — `enc.brick` (= `enc(enc.b2)` байт-в-байт).
По-инструкционная деталь (мнемоника + K-ID у каждой строки) — в обоих
исходниках; с E4 BYTECODE содержит структуру, а не дублирует листинг.

## 1. Заголовки

Генерируются pegen из `enc.peg`: SizeOfImage = 0x6B000, VirtualSize =
0x69EE4 (= filelen 0x2CCE + `!bss 67216`; конвенция этапа E6.2 — значение
!bss задаёт полный виртуальный конец секции), SizeOfRawData = 0x2E00,
DD[1] = RVA 0x3BB3 (размер 0x28), DD[12] = RVA 0x3BDB (размер 0x40),
фиксации стека/кучи = 0x4000. Инварианты SPEC/04 выполняются
(hint-записи — на чётных RVA: 0x3C6A, 0x3C7A, 0x3C86, 0x3C94, 0x3CA6,
0x3CB4, 0x3CC0).

## 4. Данные

- **regtab** (тело 0x2478): 48 записей — 64/32/8-битные имена всех 16
  регистров (rax..r15, eax..r15d, al..r15b; sil/dil/spl/bpl = коды
  6/7/4/5). Запись: имя ≤ 8 байт (LEN-управляемое сравнение), длина,
  `код | размер<<8`.
- **mnemtab** (тело 0x2778): 44 записи — add/or/and/sub/xor/cmp (параметр =
  база|расш<<8), rol/ror/shl/shr/sar (расш), 16 jcc (cc, je/jne — синонимы),
  mov/movzx/lea/test/call, neg/idiv/inc/dec (опк|расш<<8; idiv = F7 /7 —
  E6.4c), push/pop (50/58), jmp, cdqe/ret/int3/cqo (байты: 9848/C3/CC/
  9948), imul (семейство 0E — E6.4c). Запись: имя ≤ 8 байт, длина,
  `семейство | параметр<<8`.
- **sizetab** (тело 0x2A38): "byte ", "word ", "dword ", "qword " (с
  пробелом) -> 8/16/32/64.
- **errtab** (тело 0x2A78): 7 записей — справка (код 2), LONG NAME (3),
  OPEN SRC (4), READ SRC (5), BIG SRC (7), OPEN OUT (8), WRITE OUT (9);
  FORMAT (6) печатает K1-G013 из fmt_pfx + hex-номер строки.
- **строки** (тело 0x2AE8): CRLF-terminated; префикс FORMAT =
  "U-L1-ENC ERR=FORMAT AT=" (23 байта) + 4 цифры + CRLF = 29.
- **Импорты**: 7 функций kernel32.dll, порядок как в M1-BRICK.
- **Ячейки** (RVA 0x3CCE+): hstdout (q), written (q), srclen (q, dword
  счётчик), curline (q, dword номер строки), wa_len (q), затем буферы.

## 5. Регистровые соглашения модуля

- См. `CARD.md`: RBX база образа; R10 база outbuf; R12 курсор вывода; R13
  база opbuf; RSI курсор текста; R14/R15 границы строки; подпрограммы
  сохраняют их и RBX/RBP, меняют RAX,RCX,RDX,RDI,R8,R9,R11.
- Отличие от M1-BRICK: R12 — курсор ВЫВОДА (у brick — хэндл файла);
  хэндлы входа/выхода живут в R12 (временно, до нормализации) и R15.

## 6. Инварианты (проверены эмуляцией и кругами)

1. enc.brick материализуется в тело 0x2CCE байта; SRD = 0x2E00; файл 0x3000;
   VirtualSize = 0x2CCE + !bss 0x67216 = 0x69EE4.
2. enc.exe = brick(enc.brick) + pegen(·, enc.peg) байт-в-байт.
3. **Самохостинг:** enc.exe(splice(enc.b2)) == enc.brick (76243 байта);
   pegen(brick(enc(enc.b2))) == enc.exe. Круг: v2 -> v1 -> тело -> EXE.
4. enc.exe == оракулу LAB на всех 117 якорях и 27 ошибках (батарея,
   секция 7); каждая H-строка кода enc.brick декодируется lab_x86
   ровно той же длины (структурный контроль, как T-E6-03).
5. Детерминизм: один вход — один выход (R8); концы строк LF/CRLF/CR —
   как у оракула (8 граничных тестов батареи).

## 7. История изменений образа

- **E6.2 (первая сборка):** создан целиком на BRICK v2 (M-строки); enc.brick
  сгенерирован оракулом LAB (E6.1, якоря сверены с реальными байтами),
  затем воспроизводится самим enc.exe. Найденные в процессе дефекты —
  `VERIFY.md` §4 (4 дефекта собственного кода, 2 дефекта оракула,
  2 дефекта эмулятора LAB).
- **E6.4c (рост ISA для WALL v2):** mnemtab 41 -> 44 записи (+imul/idiv/
  cqo); новый кирпич K1-E033 enc_imul (семейство 0E: imul r64,r64 —
  REX.W 0F AF /r mod11, reg-поле = приёмник); диспетчер P011 — две
  проверки семейства 0E (счёт операндов + переход); idiv вошёл в
  существующее семейство 9 (F7 /7, как neg), cqo — в семейство D
  (простые байты 48 99). Данные сдвинуты на +0x30 (mnemtab) после кода;
  чётность RVA hint-записей восстановлена калибровкой DZ 1 -> DZ 2
  после имени DLL (урок E4a).
  Код 0x23C9 -> 0x2468 (+0x9F: E033 + диспетчер); тело 0x2BFE -> 0x2CCE
  байта; файл 0x2E00 -> 0x3000.
