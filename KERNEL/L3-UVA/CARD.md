# Карточка модуля M3-UVA (ассемблер UNIVM)

Паспорт файла: KERNEL/L3-UVA/CARD.md | слой: L3 | роль: карточка модуля.

| Поле | Значение |
|---|---|
| ID модуля | M3-UVA |
| Слой | L3 (ВИРТМАШИНА); исходник — WALL v2 (слой L2, SPEC/11) с разрезом по !include (SPEC/10). Второй модуль слоя L3 (сериал кирпичей 011 — по прецеденту M0-SEED2) |
| Назначение | **Ассемблер .uva -> .UP**: читает текст программы UNIVM (мнемоники SPEC/12 п. 8, директива `.mem`, метки) и собирает контейнер .UP (SPEC/13); выход обязан совпадать с ассемблером оракула `LAB/py/lab_vm.py` (`assemble`) байт-в-байт — правило R8, общие свидетели — якоря T-E7-01/26. Срезы E7.3-1..4 (ЭТАП 7.3 ЗАКРЫТ): полный конвейер CLI -> чтение -> разбор строк (комментарии `;`, края-разделители, токены) -> `.mem` (одна, до инструкций, 0..64 МиБ) -> все 18 мнемоник v0 в проходе 1 (таблица s_mn: индекс i => опкод i+1; длины: F1 = 3, F2/F3 = 6) -> МЕТКИ (префикс `имя:` — имя [a-z_][a-z0-9_]*, после ':' конец строки или пробел/таб/CR/VT/FF, НО НЕ запятая; таблица lsta/lend/lval[512] — имена-границы в srcbuf, без копий; дубликат — строка второго вхождения; регистрация проходом 1 ДО .mem/мнемоники, значение = pc до инструкции строки) -> кодировка F1 (mov: 2 операнда, rb = 0; 9 АЛУ: 3 операнда — K3-E003), F2 (const/ldb/ldq/stb/stq с операндами rA[+смещ], у stb/stq адрес первым — K3-E004; смещения без диапазона — маска младших 32 бит) и **F3: jmp/jnz + метки** (jmp: ровно 1 операнд — метка или число, `10 00 imm32 LE`; jnz: ровно 2 — регистр затем цель, `11 rd imm32 LE`; цель-имя ищется в таблице — промах = неизвестная метка: `jmp r5` без объявления — ошибка метки, не числа; halt принимает ТОЛЬКО число) -> запись .UP (заголовок 24 Б + код одним WriteFile). Срез E7.4-3a: **МНЕМОНИКИ ISA v1** — s_mn 24 имени (индексы 18..23 = mul/div/mod/sra/call/ret => опкоды 0x13..0x18); длины прохода 1: F1 = 3 (i 1..10 и 18..21), F3 = 6 (вкл. call i 22), F0 = 1 (ret i 23 — НОВЫЙ одно-байтовый формат); кодировка: mul/div/mod/sra — enc_f1 (3 операнда), call — enc_f3 как jmp (`23 00 imm32 LE`, цель метка|число), ret — НОВЫЙ K3-E006 enc_f0 (0 операндов, байт `18`). Приёмка: якоря T-E7-01/26 (24 опкода) + программы T-E7-04..08/27/28 (DEMO_VM/OPS_VM/DEV_VM + OPS2_VM/FACT_VM) == оракулу (T-E7-25). Директива `.data` и контейнер .UP v2 — срез E7.4-3b (очередь) |
| Вход | командная строка Windows: `uva.exe <вход.uva> <выход.up>` (ровно 2 аргумента; исходник ≤ 65536 байт) |
| Выход | файл .UP v1 (24 + codesize байт). Диагностика: справка `U-L3-UVA CMDS: UVA <SRC.UVA> <OUT.UP>` (код 2 — 0/1/3 аргумента); `ERR=LONG NAME` (3); `ERR=OPEN SRC` (4); `ERR=READ SRC` (5, вкл. отказ распределения буферов); `ERR=FORMAT AT=XXXX` (6 — XXXX ЗАГЛАВНЫЙ hex-номер строки с 1: ошибки разбора, как `AsmError.line` оракула; «нет .mem» — всегда строка 1, как `AsmError(1)` оракула; дубликат метки — строка второго вхождения); `ERR=CODE0` (6 — .mem без инструкций, как `make_up` оракула, вкл. программа из одних меток); `ERR=BIG SRC` (7 — исходник > 65536 Б); `ERR=OPEN OUT` (8); `ERR=WRITE OUT` (9) |
| Версия | E7.4-3a (сессия 58) — МНЕМОНИКИ ISA v1: mul/div/mod/sra (F1, 3 операнда — как АЛУ v0) + call (F3, цель метка|число — как jmp: `23 00 imm32 LE`) + ret (НОВЫЙ формат F0: 1 байт, 0 операндов — K3-E006 enc_f0; зеркало _enc_f0 оракула); таблица s_mn 24 имени, mn_find 0..23; корпуса диффтеста 85 -> 104 успеха + 97 -> 113 отвержений, круги 8 -> 10 (mul -> '*' в консоль; call/ret-подпрограмма -> 'A', код 5 — стек вызовов ядра), якоря T-E7-01/26 (24) + программы T-E7-04..08/27/28 (5, вкл. OPS2_VM/FACT_VM) == оракулу; директива .data/.UP v2 — срез E7.4-3b. До этого E7.3-4 (сессия 53): F3 jmp/jnz + МЕТКИ; ЭТАП 7.3 ЗАКРЫТ (приёмка DoD — T-E7-25) |
| Размер | 38400 байта (0x9600); тело 37420 Б (0x924C); вход 0x1200 (SPEC/11 п. 6) |
| Платформа | Windows x64, консольная подсистема, PE32+ |
| Импорты | kernel32.dll (8): GetStdHandle, WriteFile, ExitProcess, GetCommandLineA, CreateFile2, ReadFile, CloseHandle, GlobalAlloc |
| Самохостинг | артефакты `uva.b2/brick/exe` — ГЕНЕРИРУЕМАЯ сборка из `uva.wall` конвейером инструментов (wall → enc → brick → pegen + uva.peg) под эмуляцией LAB; фикс-пункт воспроизводимости — батарея T-E7-19 (каждый пуш); uva.b2 == оракулу WALL байт-в-байт |

## Формат вызова

```
uva.exe program.uva program.up
```

Аргументы: путь исходника .uva (≤ 127 байт ANSI) + путь выхода .up.
Язык исходника срезов 1-4 + E7.4-3a: строки `[метка:]... [директива |
инструкция] [';' комментарий]`, разделители токенов — пробел/таб/CR/VT/FF/
запятая (как `[,\s]+` оракула); метки `имя:` (имя [a-z_][a-z0-9_]*;
после ':' конец строки или пробельный разделитель — запятая НЕ годится;
несколько на строке; до .mem и на строке с ней/с инструкцией;
дубликат — ошибка строки второго вхождения);
директива `.mem <число>` (0..67108864, одна, до первой инструкции);
инструкции: `halt <число>` (imm32: −2147483648..4294967295, dec со знаком
или 0x-hex; метку НЕ принимает), F1 — `mov rD, rA` / `add|sub|and|or|xor|
shl|shr|lt|eq rD, rA, rB` / `mul|div|mod|sra rD, rA, rB` (v1), F2 —
`const rD, число` / `ldb|ldq rD, rA[+смещ]` / `stb|stq rA[+смещ], rB`
(регистры r0..r15 строчными; смещение [+-](dec|0x-hex), без диапазона
— маскируется; голый регистр = смещ 0), F3 — `jmp метка|число` /
`jnz rD, метка|число` / `call метка|число` (v1; цель — смещение
в коде, вперёд и назад; имя ищется в таблице меток) и F0 — `ret` (v1;
без операндов, 1 байт).
Строки из одних разделителей пусты (фикс оракула E7.3-1). Ошибки
операндов — на проходе 2 (как у оракула: счёт операндов, потом
операнды по порядку). Диффтест:
`LAB/py/lab_t_uva.py` (секция 15 батареи, T-E7-19..25).

## Регистровые соглашения модуля

Канон WALL (SPEC/11 п. 5): rbp-кадры, ARGREG rcx/rdx/r8/r9, рабочие
r10/r11. Состояние ассемблера — глобали образа (BYTECODE.md §3):
srcbuf/srclen (исходник в куче), outbuf (выход: заголовок + код),
memsize (−1 = нет .mem), pc (длина кода), lpos/lln/lna/lne (итератор
строк), tcnt/tstart[12]/tend[12] (токены текущей строки), nval
(разобранное число/регистр), moff (смещение операнда памяти),
nsa/nsb (имя потреблённой метки), lcnt/lsta[512]/lend[512]/lval[512]
(таблица меток: имена — границы в srcbuf, значения — pc).

## Данные образа

- строки s_use..s_mn (14 литералов, CRLF; s_hexd — hex-цифры,
  s_up01 = 'UP01', s_dotmem = '.mem', s_mn — таблица 18 мнемоник
  ISA v0 через пробел в порядке опкодов 01..12);
- глобальные массивы: arg1[64]/arg2[64]/w1[64]/w2[64] (CLI),
  tstart[12]/tend[12] (позиции токенов в srcbuf), fmtbuf[48]
  (строка ERR=FORMAT), lsta[512]/lend[512]/lval[512] (таблица
  меток — 12 КиБ DZ в образе);
- исходник — в куче GlobalAlloc(0, 65537); выход — GlobalAlloc(0, 65560)
  (24 + максимум кода 65536: строка-инструкция F1/F2/F3 ≥ 6 байт
  исходника, отношение код/исходник ≤ 1).

## Ограничения

- Все 24 мнемоники ISA v0+v1 кодируются (E7.4-3a: v1 — mul/div/mod/
  sra/call/ret); директива `.data` и контейнер .UP v2 — срез E7.4-3b
  (весь класс ассемблера оракула будет покрыт ею).
- Исходник ≤ 65536 байт, строка-литерал ошибки ≤ 0xFFFF (границы
  тестированы T-E7-20); код ≤ 65536 байт (ёмкость outbuf).
- Таблица меток: ёмкость 512 записей (дубликат/переполнение —
  ERR=FORMAT на строке; оракул предела не имеет — программы с > 512
  метками вне класса диффтеста; прецедент brick.exe); длина имени
  не ограничена (имена — границы в srcbuf).
- Числа .mem/halt/const/целей jmp/jnz/call — только imm32-диапазон
  оракула (−2^31..2^32−1); смещения операндов rA+смещ — без
  диапазона (как _memop оракула: копится mod 2^64, кодируются
  младшие 32 бита).
