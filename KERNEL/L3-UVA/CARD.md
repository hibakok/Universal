# Карточка модуля M3-UVA (ассемблер UNIVM)

Паспорт файла: KERNEL/L3-UVA/CARD.md | слой: L3 | роль: карточка модуля.

| Поле | Значение |
|---|---|
| ID модуля | M3-UVA |
| Слой | L3 (ВИРТМАШИНА); исходник — WALL v2 (слой L2, SPEC/11) с разрезом по !include (SPEC/10). Второй модуль слоя L3 (сериал кирпичей 011 — по прецеденту M0-SEED2) |
| Назначение | **Ассемблер .uva -> .UP**: читает текст программы UNIVM (мнемоники SPEC/12 п. 8, директива `.mem`, метки) и собирает контейнер .UP (SPEC/13); выход обязан совпадать с ассемблером оракула `LAB/py/lab_vm.py` (`assemble`) байт-в-байт — правило R8, общие свидетели — якоря T-E7-01/26. Срезы E7.3-1..4 (ЭТАП 7.3 ЗАКРЫТ): полный конвейер CLI -> чтение -> разбор строк (комментарии `;`, края-разделители, токены) -> `.mem` (одна, до инструкций, 0..64 МиБ) -> все 18 мнемоник v0 в проходе 1 (таблица s_mn: индекс i => опкод i+1; длины: F1 = 3, F2/F3 = 6) -> МЕТКИ (префикс `имя:` — имя [a-z_][a-z0-9_]*, после ':' конец строки или пробел/таб/CR/VT/FF, НО НЕ запятая; таблица lsta/lend/lval[512] — имена-границы в srcbuf, без копий; дубликат — строка второго вхождения; регистрация проходом 1 ДО .mem/мнемоники, значение = pc до инструкции строки) -> кодировка F1 (mov: 2 операнда, rb = 0; 9 АЛУ: 3 операнда — K3-E003), F2 (const/ldb/ldq/stb/stq с операндами rA[+смещ], у stb/stq адрес первым — K3-E004; смещения без диапазона — маска младших 32 бит) и **F3: jmp/jnz + метки** (jmp: ровно 1 операнд — метка или число, `10 00 imm32 LE`; jnz: ровно 2 — регистр затем цель, `11 rd imm32 LE`; цель-имя ищется в таблице — промах = неизвестная метка: `jmp r5` без объявления — ошибка метки, не числа; halt принимает ТОЛЬКО число) -> запись .UP (заголовок 24 Б + код одним WriteFile). Срез E7.4-3a: **МНЕМОНИКИ ISA v1** — s_mn 24 имени (индексы 18..23 = mul/div/mod/sra/call/ret => опкоды 0x13..0x18); длины прохода 1: F1 = 3 (i 1..10 и 18..21), F3 = 6 (вкл. call i 22), F0 = 1 (ret i 23 — НОВЫЙ одно-байтовый формат); кодировка: mul/div/mod/sra — enc_f1 (3 операнда), call — enc_f3 как jmp (`23 00 imm32 LE`, цель метка|число), ret — НОВЫЙ K3-E006 enc_f0 (0 операндов, байт `18`). Приёмка: якоря T-E7-01/26 (24 опкода) + программы T-E7-04..08/27/28 (DEMO_VM/OPS_VM/DEV_VM + OPS2_VM/FACT_VM) == оракулу (T-E7-25). Срез E7.4-3b: **ДИРЕКТИВА .data + КОНТЕЙНЕР .UP v2** — K3-T009 data_next (потоковый итератор байтов hex2: положение НЕ через tstart/tend — предел 12 токенов не ограничивает строку данных; байты копятся по порядку появления — dcnt, после .mem, в любом месте вкл. между инструкциями и на строке с меткой; несколько .data допустимы; хотя бы 1 байт на строку; `.data` до .mem — AT=0001); проход 2 пишет байты за кодом (outbuf+24+pc+dcnt); make_header — версия 2 + dataoff = 24+pc при dcnt > 0 (без .data — v1 байт-в-байт), отказ DATA — dcnt > memsize (как make_up оракула, ПОСЛЕ ошибок операндов: `ERR=DATA`, код 6); write_out — 24+pc+dcnt. Весь класс ассемблера оракула (SPEC/12 п. 8 + SPEC/13 п. 2.1) покрыт; далее E7.4-4 — приёмка DoD этапа |
| Вход | командная строка Windows: `uva.exe <вход.uva> <выход.up>` (ровно 2 аргумента; исходник ≤ 65536 байт) |
| Выход | файл .UP v1/v2 (24 + codesize [+ datalen] байт — с .data v2, SPEC/13 п. 2.1). Диагностика: справка `U-L3-UVA CMDS: UVA <SRC.UVA> <OUT.UP>` (код 2 — 0/1/3 аргумента); `ERR=LONG NAME` (3); `ERR=OPEN SRC` (4); `ERR=READ SRC` (5, вкл. отказ распределения буферов); `ERR=FORMAT AT=XXXX` (6 — XXXX ЗАГЛАВНЫЙ hex-номер строки с 1: ошибки разбора, как `AsmError.line` оракула; «нет .mem» — всегда строка 1, как `AsmError(1)` оракула; дубликат метки — строка второго вхождения; E7.4-3b: пустая строка .data / плохой байт / .data до .mem — AT=0001); `ERR=CODE0` (6 — .mem без инструкций, как `make_up` оракула, вкл. программа из одних меток и .mem+.data без кода); `ERR=DATA` (6 — данные длиннее RAM: dcnt > memsize, как `make_up` оракула, ПОСЛЕ ошибок операндов — E7.4-3b); `ERR=BIG SRC` (7 — исходник > 65536 Б); `ERR=OPEN OUT` (8); `ERR=WRITE OUT` (9) |
| Версия | E7.4-3b (сессия 59) — ДИРЕКТИВА .data + контейнер .UP v2: НОВЫЙ K3-T009 data_next (потоковый итератор байтов hex2, без предела 12 токенов — dpos/lne в srcbuf напрямую); pass1 копит dcnt (валидация: хотя бы 1 байт, ровно 2 hex-цифры + разделитель/конец); pass2 — эмиссия за кодом (outbuf+24+pc+dcnt); make_header — v2 + dataoff = 24+pc (без .data — v1 байт-в-байт), отказ DATA (dcnt > memsize — ERR=DATA, код 6); корпуса диффтеста 104 → 124 успеха + 113 → 127 отвержений + 3 DATA (lab_t_uva_corpus.py), круги 10 → 11 (демо DATA_VM «U-DATA-OK 61» — секция данных → RAM при загрузке), НОВЫЙ T-E7-35 (контракт DATA); весь класс ассемблера оракула покрыт. До этого E7.4-3a (сессия 58): мнемоники ISA v1 — mul/div/mod/sra (F1) + call (F3) + ret (F0); s_mn 24 имени; корпуса 104/113, круги 10; E7.3-4 (сессия 53): F3 jmp/jnz + МЕТКИ; ЭТАП 7.3 ЗАКРЫТ (приёмка DoD — T-E7-25) |
| Размер | 40960 байт (0xA000); тело 40022 Б (0x9C56); вход 0x1200 (SPEC/11 п. 6) |
| Платформа | Windows x64, консольная подсистема, PE32+ |
| Импорты | kernel32.dll (8): GetStdHandle, WriteFile, ExitProcess, GetCommandLineA, CreateFile2, ReadFile, CloseHandle, GlobalAlloc |
| Самохостинг | артефакты `uva.b2/brick/exe` — ГЕНЕРИРУЕМАЯ сборка из `uva.wall` конвейером инструментов (wall → enc → brick → pegen + uva.peg) под эмуляцией LAB; фикс-пункт воспроизводимости — батарея T-E7-19 (каждый пуш); uva.b2 == оракулу WALL байт-в-байт |

## Формат вызова

```
uva.exe program.uva program.up
```

Аргументы: путь исходника .uva (≤ 127 байт ANSI) + путь выхода .up.
Язык исходника срезов 1-4 + E7.4-3a/b: строки `[метка:]... [директива |
инструкция] [';' комментарий]`, разделители токенов — пробел/таб/CR/VT/FF/
запятая (как `[,\s]+` оракула); метки `имя:` (имя [a-z_][a-z0-9_]*;
после ':' конец строки или пробельный разделитель — запятая НЕ годится;
несколько на строке; до .mem и на строке с ней/с инструкцией;
дубликат — ошибка строки второго вхождения);
директива `.mem <число>` (0..67108864, одна, до первой инструкции);
директива `.data <байты>` (E7.4-3b — SPEC/13 п. 2.1: токены по 2
hex-цифры (обе регистры), байты копятся по порядку появления;
после .mem — в любом месте исходника, вкл. между инструкциями
и на строке с меткой; несколько .data допустимы; хотя бы 1 байт
на строку; без .data выход — v1 байт-в-байт);
инструкции: `halt <число>` (imm32: −2147483648..4294967295, dec со знаком
или 0x-hex; метку НЕ принимает), F1 — `mov rD, rA` / `add|sub|and|or|xor|
shl|shr|lt|eq rD, rA, rB` / `mul|div|mod|sra rD, rA, rB` (v1), F2 —
`const rD, число` / `ldb|ldq rD, rA[+смещ]` / `stb|stq rA[+смещ], rB`
(регистры r0..r15 строчными; смещение [+-](dec|0x-hex), без диапазона
— маскируется; голый регистр = смещ 0), F3 — `jmp метка|число` /
`jnz rD, метка|число` / `call метка|число` (v1; цель — смещение
в коде, вперёд и назад; имя ищется в таблице меток) и F0 — `ret` (v1;
без операндов, 1 байт).
Строки из одних разделителей пусты (фикс оракула E7.3-1). Ошибки
операндов — на проходе 2 (как у оракула: счёт операндов, потом
операнды по порядку). Диффтест:
`LAB/py/lab_t_uva.py` (секция 15 батареи, T-E7-19..25).

## Регистровые соглашения модуля

Канон WALL (SPEC/11 п. 5): rbp-кадры, ARGREG rcx/rdx/r8/r9, рабочие
r10/r11. Состояние ассемблера — глобали образа (BYTECODE.md §3):
srcbuf/srclen (исходник в куче), outbuf (выход: заголовок + код +
данные), memsize (−1 = нет .mem), pc (длина кода), dcnt/dpos (байты
.data: счёт секции и позиция итератора — E7.4-3b), lpos/lln/lna/lne
(итератор строк), tcnt/tstart[12]/tend[12] (токены текущей строки),
nval (разобранное число/регистр/байт данных), moff (смещение
операнда памяти), nsa/nsb (имя потреблённой метки),
lcnt/lsta[512]/lend[512]/lval[512] (таблица меток: имена — границы
в srcbuf, значения — pc).

## Данные образа

- строки s_use..s_mn (16 литералов, CRLF; s_hexd — hex-цифры,
  s_up01 = 'UP01', s_dotmem = '.mem', s_dotdata = '.data',
  s_data = 'U-L3-UVA ERR=DATA' — E7.4-3b, s_mn — таблица 24
  мнемоник ISA v0+v1 через пробел в порядке опкодов 01..18 — E7.4-3a);
- глобальные массивы: arg1[64]/arg2[64]/w1[64]/w2[64] (CLI),
  tstart[12]/tend[12] (позиции токенов в srcbuf), fmtbuf[48]
  (строка ERR=FORMAT), lsta[512]/lend[512]/lval[512] (таблица
  меток — 12 КиБ DZ в образе);
- исходник — в куче GlobalAlloc(0, 65537); выход — GlobalAlloc(0, 65560)
  (24 + максимум кода 65536: строка-инструкция F1/F2/F3 ≥ 6 байт
  исходника, отношение код/исходник ≤ 1; с E7.4-3b сюда же данные:
  байт данных требует ≥ 3 байта исходника (2 цифры + разделитель),
  код + данные ≤ srclen ≤ 65536 — ёмкость достаточна и для v2).

## Ограничения

- Весь класс ассемблера оракула покрыт (E7.4-3b): все 24 мнемоники
  ISA v0+v1 (E7.4-3a) + директива `.data` + контейнер .UP v2
  (E7.4-3b) — кодирование, отвержение и контейнеры совпадают
  с оракулом байт-в-байт (диффтест секции 15 батареи).
- Исходник ≤ 65536 байт, строка-литерал ошибки ≤ 0xFFFF (границы
  тестированы T-E7-20); код+данные ≤ 65536 байт (ёмкость outbuf);
  строка .data любой длины — не ограничена пределом 12 токенов
  (итератор K3-T009 работает по srcbuf напрямую — E7.4-3b).
- Секция данных: суммарно dcnt ≤ memsize (иначе ERR=DATA — как
  make_up оракула; данные ≤ 64 МиБ — оракул вне класса диффтеста
  допускает больше, но memsize ≤ 64 МиБ и так ограничивает).
- Таблица меток: ёмкость 512 записей (дубликат/переполнение —
  ERR=FORMAT на строке; оракул предела не имеет — программы с > 512
  метками вне класса диффтеста; прецедент brick.exe); длина имени
  не ограничена (имена — границы в srcbuf).
- Числа .mem/halt/const/целей jmp/jnz/call — только imm32-диапазон
  оракула (−2^31..2^32−1); смещения операндов rA+смещ — без
  диапазона (как _memop оракула: копится mod 2^64, кодируются
  младшие 32 бита).

## Примеры

```

Вывод:   U-L3-UVA CMDS: UVA <SRC.UVA> <OUT.UP>   (40 байт, CRLF)

Вывод:   (пусто); b.up: 30 байт (заголовок + 12 00 2A 00 00 00)

Код:     0

                         "stb r1+0, r1" + "halt 7")

         0D 11 00 00 00 00 12 00 07 00 00 00 (const: ra = 0;
```
