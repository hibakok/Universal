## 2. Уровни проверки (все — батарея, секция 15: LAB/py/lab_t_uva.py)

1. **Целостность/PE:** SHA-256 uva.exe (секция 1), инварианты SPEC/04
   (секция 2; вход 0x1200 — документированное отклонение SPEC/11 п. 6).
2. **Фикс-пункт (T-E7-19):** сборка из uva.wall конвейером == артефактам
   байт-в-байт + uva.b2 == оракулу WALL.
3. **CLI (T-E7-20):** справка (0/1/3 аргумента, код 2), LONG NAME (3),
   OPEN SRC (4), BIG SRC 65536/65537 (7) — 7 случаев.
4. **Диффтест с оракулом (T-E7-21):** срезы 1-4 — out.uva ==
   lab_vm.assemble байт-в-байт (85: halt-корпус среза 1 — числа
   dec/hex/знак/границы imm32, .mem 0..64 МиБ/hex, комментарии/
   пустые/CRLF/без хвостового LF/строки-разделители/запятая-разделитель;
   F1-корпус среза 2 — mov + все 9 АЛУ, регистры r0/r10/r15, без
   пробелов/с запятыми, комментарии, CRLF, без хвостового LF;
   F2-корпус среза 3 — const/ldb/stb/ldq/stq, голые регистры rN/r1X
   как адреса, смещения +16/-8/hex обоих регистров, ведущие нули,
   границы 2^31/2^32−1/2^32 и сверх — маска младших 32 бит, смесь F1+F2;
   F3-корпус среза 4 — jmp/jnz с числами/hex/знаком/границами imm32,
   метки прямые/обратные, до/после .mem, две на строке, хвостовые,
   имена-мнемоники/регистры, CR после ':', метка + инструкция на
   строке, без хвостового LF).
5. **Отвержение (T-E7-22):** 97 случаев — ERR=FORMAT AT=XXXX, XXXX ==
   AsmError.line оракула (нет .mem — всегда 0001; порядок проверок
   оракула: МЕТКИ и их дубликат раньше мнемоники, мнемоника раньше
   .mem; операнды — проход 2; F1/F2: счёт операндов, потом операнды
   по порядку; r01/R1/r0x/r-1/r16 — не регистры; F2: r2+/r2+-5/
   r2++5/r2+0x/r2+0X10/r16+5/r01+5/r19/r3x — не операнды памяти;
   F3: 'a:,halt'/'a : '/'a:halt'/'A:'/'1a:'/':' — не метки (запятая
   после ':' — не \s), неизвестная метка ('jmp r5' без объявления —
   ошибка МЕТКИ, не числа), счёт операндов jmp/jnz, плохой рег jnz
   РАНЬШЕ цели, halt метку НЕ принимает).
6. **CODE0 (T-E7-23):** .mem без инструкций — ERR=CODE0 (как make_up
   оракула), в т.ч. программа из одних меток (pc == 0); пустой вход —
   FORMAT AT=0001 (нет .mem), НЕ CODE0.
7. **Сквозной круг (T-E7-24):** uva собирает -> kernel.exe исполняет
   (halt 42 -> код 42; mov+add -> код 7 — F1; const+stb -> байт 'A' в
   консоль окном устройств; stq/ldq RAM + add + stb -> 'F' — F2;
   jnz-цикл суммы 1..2 -> код 5 и jmp-переход через halt — код 2 —
   F3 целиком) + детерминизм (2 прогона идентичны).
8. **DoD этапа 7.3 (T-E7-25):** якорные кодировки всех 18 опкодов
   (T-E7-01 — ручные свидетели, сверяются с байтами выхода uva
   напрямую) и все программы секции 13 (DEMO_VM/OPS_VM/DEV_VM —
   T-E7-04..08) собираются uva == оракулу байт-в-байт.

## 3. Журнал срезов

### E7.3-4 (сессия 53) — F3: jmp/jnz + метки; ЭТАП 7.3 ЗАКРЫТ

- 5 новых кирпичей: K3-B001 lab_skip (префикс метки как regex оракула
  ^([a-z_][a-z0-9_]*):(\s+(.*))?$ — после ':' конец строки или
  пробел/таб/CR/VT/FF, НО НЕ запятая: 'a:,halt' — неизвестная
  мнемоника 'a:'), K3-B002 lab_find (поиск по таблице: имена НЕ
  копируются — границы [lsta, lend) в srcbuf, буфер исходника
  неизменен), K3-B003 lab_add (дубликат — строка ВТОРОГО вхождения,
  как «дубликат метки» оракула; ёмкость 512 — прецедент brick.exe),
  K3-B004 parse_target (как _target: токен-имя ищется в таблице,
  промах = неизвестная метка — 'jmp r5' без объявления — ошибка
  МЕТКИ, не числа; иначе parse_num; halt метку НЕ принимает) и
  K3-E005 enc_f3 (jmp: ровно 1 операнд, [16][00][imm32]; jnz: ровно
  2, регистр затем цель, [17][rd][imm32]). Новая часть
  uva_self_b.wall (ветвь B — метки; лимит 500 строк не даст расти
  uva_self_t.wall); глобали nsa/nsb/lcnt/lsta/lend/lval[512].
- Проход 1 — метки регистрируются ДО .mem/мнемоники строки (как
  оракул: дубликат раньше неизвестной мнемоники; метка допустима до
  .mem и на строке с ней; значение = pc до добавления длины
  инструкции строки); проход 2 — только пропуск (lab_skip без
  lab_add). Диспетчер pass2: i 15/16 -> enc_f3 (все 18 форм
  кодируются; недостижимая ветка fail_at удалена).
- Зонд оракула ДО реализации (probe_e73_4.py): 17 валидных + 26
  ошибочных прогонов — сняты кодировки (прямые/обратные ссылки, две
  метки на строке, метка до .mem, хвостовая), порядок ошибок
  (дубликат на строке 2-го вхождения; 'jmp r5' — неизвестная метка,
  НЕ плохое число; halt x — плохое число) и синтаксис ('a:,halt' —
  не метка: запятая не \s).
- Корпуса диффтеста: 65 -> 85 успехов (+20 F3: числа/hex/знак/
  границы imm32 у целей, прямые/обратные/хвостовые метки, до .mem,
  две на строке, имена-мнемоники/регистры, CR после ':', без
  хвостового LF), 72 -> 97 отвержений (+25: синтаксис меток,
  дубликаты, неизвестные метки, счёт операндов, плохой рег jnz,
  цели не-имя-не-число, halt метка), CODE0 3 -> 4 (только метки —
  pc == 0); T-E7-24 + 2 круга (jnz-цикл -> код 5; jmp через halt ->
  код 2 — F3 исполняется ядром). НОВЫЙ T-E7-25 — приёмка DoD
  этапа 7.3: 18 якорей T-E7-01 (ручные hex-свидетели == байты
  ВЫХОДА uva) + программы DEMO_VM/OPS_VM/DEV_VM == оракулу.
  Батарея 169 -> 170.
- Дефектов не найдено: корпуса зелёные с первого прогона (первая
  сборка нового uva.exe + полный корпус — без правок исходника).
- Артефакты: файл 21504 -> 37888 Б (+16384: код ветви B/enc_f3 ~4 КБ
  + таблица меток lsta/lend/lval 3×512 qword = 12 КиБ нулей DZ в
  образе), тело 20820 -> 36907, метки 331 -> 398, функций 23 -> 28;
  сборка ~102,2 млн шагов.

### E7.3-3 (сессия 52) — F2: const + память

- 2 новых кирпича: K3-T008 parse_memop (операнд памяти rA[+смещ] как
  _memop оракула: бэктрекинг rN/r1X — r11/r15 голые валидны, r16/r19/
  r01/r3x — нет; смещение [+-](dec|0x-hex) БЕЗ проверки диапазона —
  копится mod 2^64, гомоморфизм колец даёт те же младшие 32 бита,
  что и маска _i32 bigint-оракула) и K3-E004 enc_f2 (порядок
  операндов оракула: const — рег потом число, ldb/ldq — рег потом
  память, stb/stq — память потом рег; байт rd:ra = адрес:значение у
  stb/stq). Новая глобаль moff (смещение). Зонд оракула ДО реализации:
  18 валидных + 30 ошибочных прогонов (кодировки, порядок ошибок,
  отсутствие диапазона у смещения).
- Корпуса диффтеста: 29 -> 65 успехов (+36 F2: все 5 мнемоник, голые
  rN/r1X-адреса, hex обоих регистров, ведущие нули, границы
  2^31/2^32−1/2^32/сверх-гигант без диапазона, смесь F1+F2, CRLF/
  комментарии/без хвостового LF), 39 -> 72 отвержений (+33 F2: счёт
  операндов, плохие рег/число/memop, r2+/r2+-5/r2++5/r2+0x/r2+0X10,
  r16+5/r01+5/r19/r3x, memop первым у ldb, memop с пробелом,
  ошибка в 3-й строке); T-E7-24 + 2 круга (консоль 'A' через окно
  устройств; RAM stq/ldq + add + консоль 'F'). Батарея — та же
  169/169 (растут корпуса внутри T-E7-21/22).
- Дефектов не найдено: корпуса зелёные с первого прогона (первая
  сборка нового uva.exe + полный корпус — без правок исходника).
- Артефакты: файл 17920 -> 21504 Б (+3584), тело 17293 -> 20820,
  метки 275 -> 331, функций 21 -> 23; сборка ~80,5 млн шагов.

### E7.3-2 (сессия 51) — таблица 18 мнемоник + регистры + F1

- 3 новых кирпича: K3-T006 mn_find (таблица s_mn — 18 имён через пробел
  в порядке опкодов: индекс i => опкод i+1 — последовательность 01..12
  делает параллельные таблицы опкодов ненужными), K3-T007 parse_reg
  (r0..r9 — 2 символа; r10..r15 — 3 со второй цифрой 1 — как _reg
  оракула), K3-E003 enc_f1 (счёт операндов, потом регистры по порядку —
  как _enc_f1 оракула; mov: rb = 0). Проход 1 — все 18 мнемоник:
  pc += 3 (F1, i 1..10) / 6 (F2/F3); порядок проверок оракула сохранён
  (неизвестная мнемоника РАНЬШЕ «нет .mem»; случай «mov до .mem» —
  AT=0001). Длина таблицы имён в таблице — одна строка данных вместо
  массивов; s_halt удалена (специфическая проверка halt больше не
  нужна — mn_find покрывает).
- Корпуса диффтеста: 17 -> 29 успехов (+12 F1: mov/9 АЛУ/регистры/
  без пробелов/комментарии/CRLF/без хвостового LF), 21 -> 39
  отвержений (+18 F1: счёт операндов 1/3/2/4, плохие rd/ra/rb, числа
  вместо регистров, r01/R1/r0x/r-1/r16, мнемоника-префикс haltx, mov
  до .mem, ошибка в F2-строке ПОЗЖЕ F1 — оба на строке инструкции);
  T-E7-24 + 1 круг (mov+add -> код 7). Батарея — та же 169/169
  (число проверок не меняется — растут корпуса внутри T-E7-21/22).
- Дефектов не найдено: корпуса зелёные с первого прогона (первая
  сборка нового uva.exe + полный корпус — без правок исходника).
- Артефакты: файл 17920 Б (+2560), тело 17293, метки 275, функций 21;
  сборка ~64,8 млн шагов.

### E7.3-1 (сессия 50) — каркас: CLI + строки/токены/числа + .mem + halt

- Новый модуль KERNEL/L3-UVA (M3-UVA, второй модуль L3; кирпичи
  K3-C011..C016/T001..T005/L001/E001..E002/W001..W003/X011 — 18).
- Найден и закрыт ДЕФЕКТ ОРАКУЛА lab_vm (№24): строка из одних
  разделителей/запятых (",,,") — _toks давал пустой список, toks[0] —
  крах IndexError вместо AsmError; фикс: пустые токены = пустая строка
  (пропуск) — докстрока и корпус T-E7-21 («sep line») зафиксировали.
- Найден и исправлен ДЕФЕКТ СОБСТВЕННОГО ИСХОДНИКА (урок для будущих
  срезов): идиома `while go == 1 / go = line_next() / <тело>` — тело
  выполняется и при go == 0 (условие проверяется только в голове
  цикла), lna/lne остаются от последней строки — последняя строка
  без хвостового LF кодировалась ДВАЖДЫ (поймано диффтестом T-E7-21
  «no final lf»: codesize 12 вместо 6). ИСПРАВЛЕНО идиомой чтения
  ВПЕРЁД: `go = line_next() / while go == 1 / <тело> / go =
  line_next()` — обе стороны итератора (pass1/pass2). Локализация:
  трассировка эмулятора (poll глобалей pc/lpos/lln по шагам).
- Артефакты: файл 15360 Б, тело 14681, метки 240, функций 18; сборка
  ~52,5 млн шагов. Батарея 161 -> 169 (секция 15, T-E7-19..24).
