# Карточка модуля M4-LIB (библиотека L4 — переиспользуемые кирпичи)

Паспорт файла: KERNEL/L4-LIB/CARD.md | слой: L4 | роль: карточка модуля.

| Поле | Значение |
|---|---|
| ID модуля | M4-LIB |
| Слой | L4 (БИБЛИОТЕКА над L3-UNIVM, SPEC/06); исходники — ассемблер `.uva` (мнемоники SPEC/12 п. 8) |
| Назначение | Переиспользуемые кирпичи для любых UNIVM-программ: числа, строки, память (слой LIB-1, SPEC/14 п. 4). Кирпич = функция `.uva` с контрактом карточки (MAP/M4-LIB.md); собирается в программу-потребителя текстовой склейкой ДО ассемблирования |
| Вход | части `lib_<ветвь>.uva` (инструкции/метки/комментарии — без `.mem`/`.data`) + программа-потребитель `.uva` с директивами `!include` |
| Выход | плоский `.uva` (splice) -> `.UP` (uva.exe) -> исполнение kernel.exe; наблюдаемое поведение кирпичей обязано совпадать с оракулом `LAB/py/lab_l4.py` на якорях `LAB/py/lab_l4_cases.py` (SPEC/14 п. 6) |
| Ядро | kernel.exe библиотеку НЕ знает (правило R7): ядро и его артефакты не пересобираются при изменении библиотеки |
| ABI | SPEC/14 п. 3 (стабилен навсегда): аргументы r1..r4, результат r1; r1..r4 — временные; r5..r12, r13 (sp), r14 (devbase), r15 — сохраняемые; печатающим кирпичам нужен r14 = memsize |
| Платформа | UNIVM (виртуальный процессор SPEC/12); платформы запуска ядра |

## Композиция программы с библиотекой (рецепт)

```
PROJECTS/<имя>/demo.uva          ; программа-потребитель
  ──splice.exe──> demo.flat.uva  ; склейка !include (SPEC/10)
  ──uva.exe──> demo.up           ; ассемблирование (SPEC/12 п. 8)
  ──kernel.exe──> исполнение     ; ядро библиотеку не знает
```

Структура программы-потребителя (порядок ОБЯЗАТЕЛЕН):

```
.mem <memsize>                   ; контейнер принадлежит программе
[.data <байты hex2> ...]         ; секция данных — по желанию программы
<код программы: const r14, memsize; вызовы call lib_*; halt>
!include ../../KERNEL/L4-LIB/lib_<ветвь>.uva   ; ПОСЛЕ кода программы
```

Почему include в конце: (1) `.mem` обязана стоять до ПЕРВОЙ инструкции
плоского текста — часть библиотеки инструкций не содержит, но и не
содержит `.mem`, поэтому она не может быть первой; (2) исполнение
начинается со смещения 0 — на смещении 0 обязан стоять код программы
(вход), а кирпичи библиотеки вызываются по меткам `lib_*` после `halt`.
Смещения строк программы в `.data` считает автор программы вручную
(SPEC/14 п. 2; метки на данных — вопрос роста ассемблера, вне ABI).

## Состав (что читать для работы с модулем)

| Файл | Ветвь | Кирпичи | Статус |
|---|---|---|---|
| `lib_c.uva` | C — консоль | K4-C001 chr_out, K4-C002 crlf_out, K4-C003 buf_out, K4-C004 buf_out_rev | готов (E8.2a, сессия 62) |
| `lib_n.uva` | N — числа | K4-N001 u64_to_dec_rev, K4-N002 print_u64, K4-N003 print_i64 | готов (E8.2b, сессия 63) |
| `lib_s.uva` | S — строки | K4-S001 str_len, K4-S002 str_out | готов (E8.2c, сессия 64) |
| `lib_m.uva` | M — память | K4-M001 mem_copy, K4-M002 mem_fill | готов (E8.2d, сессия 65) |

Карточки кирпичей (вход/выход/функция/состав) — `MAP/M4-LIB.md`;
семантика слоя LIB-1 — `SPEC/14` п. 4; оракул — `LAB/py/lab_l4.py`,
якоря — `LAB/py/lab_l4_cases.py`.

Зависимости ветвей (важно для композиции):

- **N зависит от C**: print_u64/print_i64 вызывают lib_buf_out_rev,
  print_i64 — ещё и lib_chr_out. Программа, включающая lib_n.uva,
  обязана включить и lib_c.uva (метки решаются в общем плоском тексте).
- **Ветвь N использует программный стек** (конвенция SPEC/12 п. 3.4;
  впервые в библиотеке): кирпичи хранят адрес буфера в слоте
  [sp-8, sp) и снимают слот перед ret — r13 после вызова равен
  входному значению (баланс стека проверяет T-E8-15). Программа
  ОБЯЗАНА поставить r13 = корректный адрес RAM до вызова; у ячейки
  [sp-8, sp) не должно быть ценных данных программы.
- **S — АВТОНОМНАЯ ветвь (без зависимостей; E8.2c)**: кирпичи S
  атомарны — lib_c/lib_n НЕ вызываются, программа включает ОДНУ
  часть lib_s.uva. Стек НЕ используется: четырёх временных r1..r4
  достаточно (addr/p/шаг/байт), r13 программе ставить НЕ нужно
  (кирпич его не трогает — ABI). r14 = memsize нужен только
  lib_str_out (печатающий кирпич); lib_str_len консоль не трогает.
- **M — АВТОНОМНАЯ ветвь как S (без зависимостей; E8.2d)**: кирпичи
  M атомарны — ОДНО !include lib_m.uva. Стек НЕ используется
  (аргументов r1..r3 + временной r4 достаточно), r13 НЕ нужен.
  Консоль НЕ трогается — r14 (devbase) НЕ нужен ни одному кирпичу
  M: эффект наблюдается в RAM программы (сверка диффтестов —
  по r.mem ПОСЛЕ прогона). Копирование — ПО ВОЗРАСТАНИЮ адресов
  (формула SPEC/14 п. 4): перекрытие «вперёд» (dst > src)
  размножает байт, «назад» — источник цел.

## Верификация

- Батарея, секция 16 (`LAB/py/lab_t_l4.py`, группа 3): T-E8-01..07 —
  оракул против якорей (E8.1); T-E8-08..10 — диффтест ветви C:
  композиция программы + lib_c.uva оракулом splice -> прогон
  `lab_vm.run_asm` -> консоль/регистры == оракулу lab_l4 (E8.2a);
  T-E8-11 — сквозной круг ветви C инструментами (E8.2a); T-E8-12..15 —
  диффтест ветви N на якорях REV/DEC/I64 + ABI (сентинелы и баланс
  sp = r13; E8.2b); T-E8-16 — сквозной круг ветви N с ДВУМЯ частями
  (lib_c + lib_n) инструментами (E8.2b); T-E8-17..18 — диффтест
  ветви S на якорях STR: str_len (r1 = len; консоль пуста — r14/r13
  не нужны) и str_out (консоль == оракулу; E8.2c); T-E8-19 —
  композиция ТРЁХ ветвей C+N+S — первая трёхчастная программа
  (E8.2c); T-E8-20 — ABI ветви S: сентинелы r5..r13/r15 (r13 —
  сентинелом: S стек не использует) + RAM-слог len (E8.2c);
  T-E8-21 — сквозной круг ветви S с ОДНОЙ частью инструментами
  (E8.2c); T-E8-22..23 — диффтест ветви M на якорях CPY/FILL:
  эффект RAM по r.mem ПОСЛЕ прогона — тройной свидетель
  (программа == оракулу на ВСЕЙ RAM; оракул == якорю; E8.2d);
  T-E8-24 — композиция ЧЕТЫРЁХ ветвей C+N+S+M — первая
  четырёхчастная программа (консоль И ВСЯ RAM == модели оракула,
  вкл. цифры буфера N001 и стек-слоты; E8.2d); T-E8-25 — ABI
  ветви M: сентинелы r5..r13/r15 (r13 — сентинелом: M без
  стека) + RAM-эффект copy+fill == модели (E8.2d); T-E8-26 —
  сквозной круг ветви M с ОДНОЙ частью инструментами — программа
  печатает эффекты НАПРЯМУЮ (stb r14+0), без других библиотек
  (E8.2d).
- Срез E8.3 (демо-программы DoD): полный круг splice.exe ->
  uva.exe -> kernel.exe (эмуляция LAB) — как секции 14/15 батареи.

## Журнал модуля

- E8.2a (сессия 62): ветвь C реализована (lib_c.uva, 4 кирпича,
  46 строк) + CARD.md модуля + диффтесты T-E8-08..10 (батарея
  187 -> 190/190). Первая реализация библиотеки; ядро не менялось.
- E8.2b (сессия 63): ветвь N реализована (lib_n.uva, 3 кирпича,
  77 строк; стек-слоты [sp-8,sp) — конвенция SPEC/12 п. 3.4 впервые
  в библиотеке) + диффтесты T-E8-12..16 (REV: r1 = len + RAM-цифры;
  DEC/I64: консоль == оракулу И якорным литералам; ABI: сентинелы
  + баланс sp; круг инструментами с двумя частями C+N). Батарея
  191 -> 196/196. Ядро не менялось (R7).
- E8.2c (сессия 64): ветвь S реализована (lib_s.uva, 2 кирпича,
  46 строк; ПЕРВАЯ АВТОНОМНАЯ ветвь — без зависимостей и без стека:
  r13 не нужен, r14 — только str_out) + диффтесты T-E8-17..21
  (STR: r1 = len и консоль == оракулу; композиция ТРЁХ ветвей
  C+N+S — первая трёхчастная программа; ABI с r13-сентинелом;
  круг инструментами с ОДНОЙ частью). Батарея 196 -> 201/201.
  Ядро не менялось (R7).
- E8.2d (сессия 65): ветвь M реализована (lib_m.uva, 2 кирпича,
  40 строк; АВТОНОМНАЯ ветвь как S — без зависимостей, БЕЗ стека
  и БЕЗ консоли: r13/r14 не нужны; цикл «jnz на тело / ret на
  выход» — счётчик n в r3, шаг 1 в r4, метка входа = голова
  цикла) + диффтесты T-E8-22..26 (CPY/FILL — эффект RAM по r.mem
  на ВСЕЙ RAM против модели оракула; композиция ЧЕТЫРЁХ ветвей
  C+N+S+M — первая четырёхчастная программа, консоль + ВСЯ RAM;
  ABI с r13-сентинелом; круг инструментами с ОДНОЙ частью —
  программа печатает эффекты НАПРЯМУЙ stb r14+0). Батарея
  201 -> 206/206. Слой LIB-1 реализован ЦЕЛИКОМ (11/11 кирпичей).
  Ядро не менялось (R7).
