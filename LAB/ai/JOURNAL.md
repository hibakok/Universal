Паспорт файла: LAB/ai/JOURNAL.md | слой: внешний инструмент | роль:

## Как возобновить работу (протокол для новой сессии ИИ)

1. Прочитать этот журнал (последняя запись = актуальное состояние).
2. Прочитать `DOCS/03-ROADMAP.md` — текущий этап.
3. Прогнать `python3 LAB/py/lab_verify.py` — обязано быть 71/71 OK
   (если нет — чинить до всего остального).
4. Продолжать малыми шагами (правила `DOCS/01-METHODOLOGY.md`).
5. По завершении итерации: добавить запись в этот журнал (дата,
   что сделано, решения, что дальше) и обновить счётчики `MAP/INDEX.md`.

Правила ведения: записи добавляются СВЕРХУ (новее — выше); каждая
итерация = одна запись; формулировки короткие, ссылки на файлы
точные; планы следующих этапов детальны настолько, чтобы сессия без
памяти могла их исполнить.

### Что сделано

### Найденные и исправленные дефекты (в этой сессии)

- Тест-IDs этапа E6: T-E6-xx (не T-M7-xx: модуль ещё не существует,

## План E6.2 (следующая итерация): enc.exe — самохостинг кодировщика

Цель: `KERNEL/L1-ENC/enc.exe` — нормализатор BRICK v2 -> v1, написанный
в BRICK v1 (H-строки), собирающий себя. DoD: T-E6-05..11 зелёные
(TESTS/T-L1-ENC.md), батарея расширена равенством enc.exe == оракулу.

Архитектурная заготовка (ветви кирпичей M1-ENC, ID K1-*):

- ветвь X (вход): парс аргументов, чтение файла (реинкарнации
  K0-F-кирпичей hxdump/pegen: open_file_read, read_whole_dst,
  create_file_write, write_all, close_file);
- ветвь P (разбор строки): классификация (метка/директива/M/прочее),
  split операндов по запятым, разбор операнда (reg-таблица, число,
  $ссылка, память с типом);
- ветвь E (кодирование): таблица регистров (имя -> код+размер),
  диспетчер по мнемонике (таблица: мнемоника -> семейство+ext),
  REX-сборка, modrm/SIB/disp, imm8/imm32-выбор;
- ветвь W (выход): буфер H-строки, склейка байт-текстов, запись файла;
- данные: таблицы как DB-строки (как kwtab в pegen).

Оценка: ~40-60 кирпичей, тело ~2,5-4 КиБ. Порядок: карточки (R3) ->
исходник enc.brick -> сборка текущим brick.exe (у пользователя на
Windows) -> батарея (LAB сравнит с оракулом) -> самохостинг
(enc.brick переписывается на M-строки частично, где каноника совпадает).

Риски: таблица имён регистров (3 размера × 16) — объём данных; разбор
запятых и скобок — уже опробован в pegen (ветвь Q); кодирование modrm
для r12-r15 (уроки E2/E4 — rm-коды 100-111, SIB всегда для rsp/r12).
