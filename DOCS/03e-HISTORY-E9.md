### E9.2-3a (сессия 70) — RAW-ЭМИССИЯ b2: операнды декодера + H-строки
### + DZ/DB + запись <выход>.b2

Срез по плану ROADMAP (E9.2-3, раздроблён на подсрезы 3a/3b/3c —
объём эмиссии > одной сессии; режимы наращивания закреплены в
оракуле ДО инструмента): bridge.exe пишет файл .b2 — H-строки
выживших инструкций и данные сегментов, режим RAW оракула. ЯДРО И
АРТЕФАКТЫ ДРУГИХ МОДУЛЕЙ KERNEL/ НЕ МЕНЯЛИСЬ (R7) — только
KERNEL/L5-BRIDGE и тестовая/документационная обвязка.

1. **Оракул (LAB/py/lab_bridge.py):** _emit_lines/emit_b2 получили
   параметр mode (None — канон, БЕЗ изменений: якорь T-E9-02 зелёный;
   "H" — только H-строки, метки/семантика остаются — подслой
   E9.2-3b; "RAW" — H-строки без меток/семантики — сырьё среза 3a).
   Круг RAW байто-точен (H-строка — те же байты; проверено на seed).
2. **Операндное расширение декодера (10 новых кирпичей K5-D014..D023
   + переработка D004..D013):** modrm_read вместо modrm_skip (полный
   разбор: регистр mod=3 / память base+index+scale+disp / rip-rel
   disp32 — quirks оракула: SIB индекс 4 без REX.X = нет, база 5 при
   mod=00 — беззнаковый disp32; цель rip = конец инструкции + disp —
   в decode_ins), u32/u64 (беззнаковые чтения imm32/imm64), setters
   операндов (set_reg/set_rm/set_imm/set_immu/set_tgt/set_cl/set_cnt
   — слоты 1/2 глобалей da1*/da2*), alu_id; семейства выдают
   мнемонику (id 1..28 блоба s_mn с ведущим пустым №0 — сдвиг id
   пойман T-E9-22), dcc (условие jcc), полные операнды: reg (имя по
   таблицам s_r64/s_r8/s_r16/s_r32 — все 4 размера), imm (знаковая
   печать; imm64 — вид 7 беззнаковый), память (поля om*), цель, cl,
   счётчик-маска 63/31 (правило Intel). Спуск (walk) не менялся —
   операнды вычисляются, но walk читает только dlen/dcls/dtgt
   (факты T-E9-18 остались зелёными с первого прогона).
3. **Ветвь E — эмиссия (bridge_self_e.wall, 18 кирпичей K5-E001..E018):**
   fill_offs/init_tables (смещения NUL-имён блобов), tpl_dec (шапка
   SPEC/15 — кириллица UTF-8 в HEX-литерале s_tpl 398 символов:
   литералы WALL только ASCII 0x20..0x7E; идиома wall_self_blob —
   K2-E000), форматтеры (out_hexv/out_hxs/out_hxu64/out_hex2/
   out_hex4m/out_sdec — 2^64 = 16777216*256*2^32 произведением
   малых литералов), примечания note_op/emit_note (== _note оракула:
   «j<cc> <цель>»/имена/«[rip±d]» знаковый dec/«[mem]»/«cl»/счётчики),
   emit_h (H-строка: повторный decode_ins — детерминирован), emit_data
   (DZ >= 3 нулей / DB <= 16 Б — сегменты между выжившими), app_tpl,
   emit_raw (outmem GlobalAlloc 8 МиБ — с запасом над худшим случаем
   ~5.8 МиБ; шапка + цикл по дампу + запись файла CreateFile2
   GENERIC_WRITE/CREATE_ALWAYS — как wall.exe/uva.exe; коды 8
   ERR=OPEN OUT / 9 ERR=WRITE OUT). sweep_ins (K5-W002) дополнил
   СДАМП выживших sdump (куча rawlim*8+8 — по qword на выжившего;
   доказуемый предел: выживших <= rawlim) — эмиссия без повторных
   сканов insmap.
4. **Секция 18 (+2 проверки, 231 -> 233):** T-E9-22 — t.b2 == оракулу
   RAW на ВСЕХ 12 артефактах + синтетике спуска; T-E9-23 — сквозной
   круг raw-текста реальными инструментами (seed/hxdump: enc ->
   brick -> pegen == оригиналу). Сборка (T-E9-17): шаг wall
   247.7 млн шагов — выше лимита lab_run 200 млн, прямой lab_win с
   лимитом 2 млрд (прецедент фикс-пункта T-E6-49a).
5. **Артефакты пересобраны (T-E9-17 зелёный):** склейка 68177 Б
   (2411 строк); тело 47278 Б (0xB8AE); файл 48128 Б; метки 703/2048;
   функции 70; M=9696 H=0 (инвариант w1-хвоста ПОДТВЕРЖДЁН ростом —
   vsize mod 0x200 = 0xAE <= 0x101); bridge.b2 == оракулу WALL
   байт-в-байт; SHA bridge.exe B5536607… — реестр lab_verify.py
   обновлён; шаги ~305 млн (247.7 + 33.7 + 23.0 + 0.005).
6. **Реестры/документация:** CARD/BYTECODE (70 функций — карта RVA
   bridge_labelmap.py)/VERIFY (журнал среза: 3 дефекта + 2 урока),
   MAP/M5-BRIDGE-D.md (D014..D023 + контракты D004..D013/W002/X001),
   НОВЫЙ MAP/M5-BRIDGE-E.md (18 карточек K5-E*), MAP/METHODS-2 (+28
   строк), MAP/INDEX (счётчики), TESTS/T-L5-BRIDGE (T-E9-22/23 +
   статус), TESTS/POLICY (+п. E9.2-3a), SPEC/15 (п. 10 — режимы
   наращивания mode=None/H/RAW), DOCS/03-ROADMAP (E9.2-3 -> подсрезы
   3a/3b/3c, 3a [x]), DOCS/02 (строки моста), README (статус +
   примеры с файлом), LAB/README (время), JOURNAL (эта запись).

Дефекты (3 — все пойманы диффтестом T-E9-22 ДО фиксации якорей):

1. **Потерян байт шапки s_tpl** (396 hex-символов вместо 398 — пробел
   «.exe (»): шапка смещалась на 1 байт. Пойман первым прогоном
   T-E9-22 (размер 1898 != 1896). Урок: длинные литералы вставлять
   генератором (скриптом), не руками.
2. **Сдвиг id мнемоник:** карточки использовали id 1..28, а таблица
   имён — 0-базовая (o_mn[1] = «add» печатал «or»; «sub rsp, 28»
   печаталось «xor»). Фикс — ведущий пустое имя №0 в блобе s_mn
   (id 1..28 == позиции 1..28). Урок: соответствие id-таблица —
   сверять на первом же примечании.
3. **Смесь test/mov в decmod:** ветка test захватила байты 0x88/0x89
   (модификация E9.2-3a; в E9.2-2 разница была невидима — длина та
   же). «mov rdx, rax» печаталось «test rdx, rax». Пойман вторым
   прогоном T-E9-22. Урок: при расширении ветвей таблицу байтов
   перепроверять по оракулу (в E9.2-2 decmod не различал имена).

Решения (чтобы не передумывать):

1. **Режимы наращивания в оракуле (mode=None/H/RAW)** — один контракт
   на весь подслой E9.2-3: канон НЕ меняется (якорь T-E9-02 —
   свидетель), каждый срез закрывается диффтестом своего режима;
   инструмент не «подгоняется» под промежуточное состояние.
2. **Шапка — HEX-литерал + декод при старте** (идиома wall_self_blob):
   литералы WALL только ASCII, а шапка SPEC/15 кириллическая; 199 Б
   UTF-8 = 398 hex-символов < 512 предела литерала.
3. **Дамп выживших sdump в sweep_ins** (вместо повторных сканов
   insmap с курсором теней): эмиссия идёт по готовому курсу — O(1)
   на выжившего; предел кучи доказуем (выживших <= rawlim).
4. **Вид 7 (imm-u64)** — отдельный вид операнда: imm64 печатается
   БЕЗзнаковым (0xFFFFFFFFFFFFFFFF), s32-расширенные imm — знаковым
   («-1»); в WALL qword оба могут быть отрицательными — различает
   вид, а не значение.
5. **Факт-строка остаётся контрактом успеха до E9.2-3c** (замена
   реальным выходом — там же, вместе с M-строками): T-E9-18/19/21
   продолжают охранять спуск, новый T-E9-22/23 — эмиссию.

### E9.2-3b (сессия 71) — МЕТКИ И СЕМАНТИКА: режим "H" — l/d/iat_ +
### DD/DQ + разрезы + драйвер emit_body

Срез по плану ROADMAP (подсрез 3b из раздробления 3a/3b/3c). ЯДРО И
АРТЕФАКТЫ ДРУГИХ МОДУЛЕЙ KERNEL/ НЕ МЕНЯЛИСЬ (R7) — только
KERNEL/L5-BRIDGE и тестовая/документационная обвязка.

**Сначала истина семантики — оракул исправлен ДО инструмента**
(нейтральность каждого исправления доказана кругом канона всех 11
артефактов байт-в-байт + якорь T-E9-02; зонды LAB/ai/probe_e92_3b.py
и probe_e92_3b2.py):

1. **Правило представимости меток импорта** (SPEC/15 п. 4/6): метка
   iat_/d* НЕ создаётся, если её смещение строго внутри выжившей
   инструкции. Прежний вид на вырожденном входе (hint-RVA внутрь
   инструкции, крафт probe_e92_3b2) эмитил разрез ПОВЕРХ уже
   покрытых инструкцией байтов — наложение строк, ассемблер
   отвергал b2 («FORMAT AT=...»). Теперь: метка пропускается,
   DQ-таблица с ссылкой на неё — сырыми байтами, круг байто-точен.
2. **Приёмка DD/DQ** дополнительно отвергает строку, если строго
   внутри её байтов лежит метка (тот же класс наложения).
3. **_san — только ASCII [a-z0-9_]**: прежний вид сохранял
   латиницу-1 alnum байты имени («ÿ», «é» — isalnum у Python) —
   enc такие имена меток отвергает; контракт [a-z0-9_] восстановлен.
4. **impn=0 (пустая таблица импорта)** — без KeyError: known-записи
   только по существующим меткам (DD + DQ «0» терминатора).

**Инструмент (ветвь L — ЧАСТИ bridge_self_l.wall (карты/семантика,
K5-L001..L010+L016) + bridge_self_l2.wall (рендер/драйвер,
K5-L011..L015+L017) — разрез по лимиту 500 строк; 17 кирпичей):** imp_hints (перечитывание записей INT/IAT —
маскированный hint-RVA + имя с quirk C-строки; маска бита 63 —
v < 0 -> v + 2^63, СРАВНЕНИЕ с 2^63 невозможно в знаковой
qword-арифметике WALL — урок), san_put (блоб «iat_»+san), imp_offs,
imp_labels (iat_ слоты присвоением, d* setdefault, known-массив,
представимость), build_sstate (карта выживших 1/2), sem_add
(кандидаты-тройки, замена при том же off — словарь оракула),
dq_base (валидность значений И меток hint), dd_idt, sem_filter
(сортировка + приёмка: конфликты с инструкциями/строками/метками
внутри), ins_labels (метки l*/d* по операндам — повторный decode),
out_hexl/emit_labname/emit_cut/emit_dollar/emit_sem (рендер),
build_maps (оркестратор), **emit_body** — ДРАЙВЕР (шапка + линейный
проход [0, target) по событиям: метка -> семантика -> H-строка ->
данные; запись <выход>.b2, коды 8/9). K5-E018 emit_raw СНЯТ
(драйвер переехал в L; ID вечен — R5). Драйвер scans события
линейно (каждый байт <= 2 раз), карты — байтовые кучи 262145.

**Тесты**: T-E9-22 эволюционировал в диффтест режима "H" — t.b2 ==
оракулу emit_b2(mode="H") на ВСЕХ 12 артефактах + синтетике спуска
+ синтетике меток (мутант hint-ins: INT[0] := RVA 0x102C — строго
внутри rol @0x2B: метка не создаётся, обе DQ-таблицы сырыми
байтами, b2 ВАЛИДЕН — доп. круг оракула == мутанту; мутант imp0:
INT[0] := 0 — impn=0, DD + DQ «0»). T-E9-23 — круг H-текста
инструментами (seed/hxdump). Батарея 233/233; секция 18 выделена в
ГРУППУ 4 battery_groups.py (группа 3 с ней — 9м48с, впритык к
10-минутному лимиту песочницы).

**Артефакты пересобраны** (T-E9-17 зелёный): склейка 89709 Б (3074
строки, 34% предела); тело 0xF392; файл 62976 Б; функции 86; метки
885/2048; **w1[32] -> w1[64]** — урок E9.2-2 обобщён: хвост
(raw-0x1FF..vsize) всегда < 0x200 Б, при w1 последним размером 0x200
он внутри w1 при ЛЮБОМ vsize — БЕЗУСЛОВНЫЙ инвариант (пересчёт при
росте строк/глобалей больше не нужен); круг над bridge.exe

комментарии; реестр актуален); шаги 351949143+45361314+34316664+
5046.

**Дефекты (2, оба пойманы до фиксации якорей)**: (1) сравнение v >=
2^63 — произведение 16777216*256*16777216*128 представимо только

**Реестры**: CARD/BYTECODE (карта — генератор LAB/ai/gen_bytecode.py

### E9.2-3c (сессия 72) — M-СТРОКИ: КАНОН (mode=None) + выход M=/H=

Срез по плану ROADMAP (подсрез 3c из раздробления 3a/3b/3c). ЯДРО И
АРТЕФАКТЫ ДРУГИХ МОДУЛЕЙ KERNEL/ НЕ МЕНЯЛИСЬ (R7) — только
KERNEL/L5-BRIDGE (ветвь M — ЧЕТЫРЕ новые части bridge_self_m/m2/
m3/m4.wall) и тестовая/документационная обвязка.

**Сначала истина — материал и транслитерация ДО инструмента**
(зонды LAB/ai): probe_e92_3c.py — статистика форм M/H по 12
артефактам (46470 инструкций; M-формы — весь канон enc; причины H:

до написания WALL.

**Ветвь M (28 кирпичей K5-M001..M028):** m (ПРИМИТИВЫ: m_put/m_put4 —
буфер кодировки mbuf; m_rex — REX по аргументам-значениям (w==64,
