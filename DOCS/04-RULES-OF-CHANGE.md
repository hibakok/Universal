# 04. Правила внесения изменений

Паспорт файла: DOCS/04-RULES-OF-CHANGE.md | слой: все | роль: регламент изменений.

## Процесс (6 шагов, порядок обязателен)

1. **Определи затронутые кирпичи.** Поиск по указателю `MAP/METHODS.md`
   (поле «Имя») и по карте `MAP/INDEX.md`; карточка — в `MAP/M<модуль>.md`.
2. **Прочитай карточки** затронутых кирпичей и их соседей
   (кто «Состоит из» них и в ком они «Используются»).
3. **Измени код** (листинг ATOM / будущие исходники) и разбор
   `BYTECODE.md` одним логическим изменением.
4. **Обнови реестры:** карточку в `MAP/M<модуль>.md`, строку в указателе
   `MAP/METHODS.md`, счётчики в `MAP/INDEX.md`,
   статус этапа в `DOCS/03-ROADMAP.md`.
5. **Обнови или создай тест** в `TESTS/` и прогони все тесты раздела.
6. **Зафиксируй** изменение с осмысленным сообщением коммита.

## Формат сообщений коммитов

```
E{номер этапа}: {что изменено} — {суть одним предложением}
Примеры:
  E0: M0-SEED — добавлено семя L0 и инфраструктура репозитория
  E1: K0-C001 — чтение командной строки через GetCommandLineA
```

- Один коммит = одно логическое изменение.
- Красный тест = коммит запрещён.
- Сторонний код (даже одна строка) = коммит запрещён (правило R9).

## Что обновляется при изменении кода L0

| Изменил | Обновить обязательно |
|---|---|
| байты кода | `seed.hex`, `KERNEL/L0-SEED/BYTECODE.md`, `VERIFY.md` (хэш) |
| структуру PE | `SPEC/04-PE-MINIMAL.md`, `BYTECODE.md`, все RVA в карточках |
| кирпич | карточку в `MAP/M<модуль>.md`, указатель `MAP/METHODS.md`, поля «Используется в» соседей |
| набор инструкций | `SPEC/05-X86-SUBSET.md` |
| поведение программы | `TESTS/T-L0-SEED.md` (ожидаемый вывод) |

## Проверки перед коммитом (L0)

1. Размер файла не изменился без явного решения (это меняет RVA).
2. `int3` (страховка) остаётся последней инструкцией потока.
3. Точка входа в опциональном заголовке указывает на первый кирпич.
4. Все rip-смещения пересчитаны и сверены с дизассемблером.
5. Тесты T-M0-* зелёные.

## Откат

История Git линейная; откат = обратный коммит с сообщением
`E{n}: revert — {причина}`. Удалённые кирпичи помечаются в
указателе `MAP/METHODS.md` и в `MAP/M<модуль>.md` символом `x` в статусе
(карточка остаётся — ID вечны).
