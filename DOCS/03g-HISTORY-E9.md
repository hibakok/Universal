### Что сделано (E9.4-3c-1)

1. **SPEC/07 «Рост v2»** — модель чужих образов: файл = НУЛИ + ПАТЧИ.
   Область заголовков `!hdr <off> <HEX>` (H байт: DOS-заглушка,
   PE/COFF/опт/каталоги, таблица секций), тело секции кода `!body <n>`
   (обычный image.bin — пишется в raw секции, добивается нулями до
   SizeOfRawData), патчи прочих секций `!sec <n> <off> <HEX>`. Маркер
   версии — первая директива `!pev2 <H>`: v1-тексты его не содержат,
   диспетчер wrap ведёт их прежним путём. Блобы — ЗАГЛАВНЫЙ hex,
   чётная длина, <= 64 Б/строка. Закреплён КАНОН сворачивания образа
   в патчи (для эмиссии мостом — E9.4-3c-2): H = min raw_ptr секций с
   raw; ненулевые пробеги (дырка < 4 нулей сливается); !hdr по
   возрастанию off, !sec — n, затем off.
2. **lab_pegen.py — wrap2 (сборщик) + диспетчер wrap** (v1-код не
   менялся): сборка области заголовков из патчей над нулями, затем
   ЧТЕНИЕ из неё только СТРУКТУРЫ (MZ, e_lfanew, PE-сигнатура,
   NumberOfSections, SizeOfOptionalHeader, таблица секций — философия
   hexgen «доверие данным»: семантику полей сборщик не проверяет);
   сырые области — после H и без взаимных наложений; тело — в raw
   секции !body; размер файла = max(H, концы raw). Отказы — 19
   случаев (SPEC/07), все с детерминированными сообщениями.
3. **Крафты-свидетели:** якорные тексты FOREIGN_PEG2 (крафт E9.4-3a)
   и FOREIGN2_PEG2 (крафт E9.4-3b — спуск, bss-вилка) — выведены

   тела — target-байты (0x24/0x73; у foreign2 — сверка с фактом

4. **НОВЫЙ T-E9-30** (секция 18g — lab_t_bridge_peg2.py,
   самодостаточный, чистый Python, группа 4 + CI): (1) СБОРКА —

### Дефекты (1, пойман до сдачи)

1. В первой версии wrap2 поля слота таблицы секций читались в
   ОБРАТНОМ порядке (raw_size @+0x10 и raw_ptr @+0x14 перепутаны
   местами): первый же прогон генератора якорей упал «raw секции
   @200 залезает в заголовки» (читался raw_size 0x200 как raw_ptr).
   Исправлено по формату PE до коммита. Урок: смещения полей
   структур — только из SPEC (здесь SPEC/04), не по памяти.

### Решения (чтобы не передумывать)

1. PEG v2 = нули + патчи, а НЕ «шаблон + больше директив»: у чужих
   образов нет общего шаблона (e_lfanew/TimeDateStamp/линкер/секции
   произвольны); патчи честно переносят ФАКТЫ, сборщик не додумывает.
   Единственное, что сборщик читает из заголовков, — СТРУКТУРА
   (MZ/e_lfanew/PE/таблица секций): без неё разместить тело нельзя.
2. Граница версий — ПЕРВАЯ директива !pev2: v1-текст с !pev2 внутри —
   ошибка v1 (неизвестная директива); диспетчер никогда не меняет
   поведение существующих v1-файлов (доказано T-E9-30 п. 3 и всей
   батареей). Порт в pegen.exe сохранит тот же диспетчер.
3. !sec на секции !body запрещён: ненулевые байты тела — в image.bin
   (у него уже есть носитель), нули — добивка; второй носитель той
   же области — источник конфликтов.
4. Канон сворачивания (дырка < 4 нулей; куски <= 64 Б) закреплён в
   SPEC/07 СЕЙЧАС — до эмиссии: якоря T-E9-30 станут эталоном
   E9.4-3c-2 (мост обязан повторить их текст).
5. Следующий срез (E9.4-3c-2): эмиссия PEG v2 мостом — рендер-ветвь
   lab_bridge_text.py (_peg2_text: факты parse_foreign -> канон
   патчей) + свидетель == якорям T-E9-30; за ним — b2 чужого тела и
   порты (bridge.exe/pegen.exe) при первом чужом круге.
