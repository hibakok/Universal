# 01. Методология: кирпичи, ветви, слои

Паспорт файла: DOCS/01-METHODOLOGY.md | слой: все | роль: правила построения кода.

## 1. Кирпич

**Кирпич** — минимальный метод программы. Свойства:

- выполняет ровно одну функцию, которую можно описать одной фразой;
- не длиннее ~30 строк в эквиваленте машинного/символьного кода;
- имеет карточку в реестре своего модуля `MAP/M<модуль>.md`
  (формат: `SPEC/01-METHOD-CARD.md`; указатель — `MAP/METHODS.md`);
- имеет стабильный идентификатор `K{слой}-{ветвь}{номер}`, например `K0-H001`.

Кирпич описывается тремя вещами: **вход**, **выход**, **функция**.
Если для описания кирпича нужно больше трёх фраз — он слишком сложный,
разбейте его.

## 2. Ветвь кода

**Ветвь** — изолированная цепочка кирпичей, растущая от простого к сложному.
Ветвь обозначается одной латинской буквой в идентификаторе кирпича.

Пример из семени (слой L0):

```
ветвь S (самопознание):  K0-S001 get_image_base
                          K0-S002 read_sizeofimage   (использует K0-S001)
ветвь H (hex):            K0-H001 hex32_to_ascii8    (использует K0-S002)
ветвь P (печать):         K0-P001 write_stdout       (использует K0-H001)
```

Сложный кирпич состоит из менее сложных, те — из ещё менее сложных.
Так образуются ветви. Ветви изолированы друг от друга: кирпич одной ветви
ссылается на кирпич другой ветви только через объявленную карточку
(вход/выход), никогда — через внутреннее устройство.

## 3. Слои

**Слой** — уровень абстракции. Определены в `MAP/LAYERS.md`:

| Слой | Имя        | Суть                                                |
|------|------------|-----------------------------------------------------|
| L0   | МАШИНА     | ручной машинный код x86-64, формат ATOM             |
| L1   | СБОРКА     | символьный ассемблер BRICK с метками                |
| L2   | ЯЗЫК       | компилируемый язык высокого уровня                  |
| L3   | ВИРТМАШИНА | UNIVM: свой процессор, память, устройства           |
| L4   | БИБЛИОТЕКА | стандартные кирпичи для UNIVM                      |
| L5   | МОСТЫ      | трансляторы EXE в наш мир и обратно                 |
| L6   | ПРОЕКТЫ    | Minecraft-копия, AGI и другие программы             |

## 4. Десять непреложных правил

- **R1.** Слой N зависит только от слоёв с номерами меньше N.
- **R2.** Кирпич — не более ~30 строк; файл — не более 500 строк.
- **R3.** Карточка кирпича создаётся ДО написания кода.
- **R4.** Любое изменение = код + обновление реестра + тест.
- **R5.** Идентификаторы стабильны навсегда и не переиспользуются.
- **R6.** Перед созданием кирпич ищется в реестре; дублирование запрещено.
- **R7.** Ядро не знает о проектах; проекты не изменяют ядро.
- **R8.** Код позиционно-независим; один вход — один детерминированный выход.
- **R9.** Никаких сторонних языков, компиляторов, ассемблеров, библиотек.
- **R10.** Любой байт любого артефакта объясним по документации
  (листинг + байт-за-байтом разбор).

## 5. Паспорт файла

Каждый файл репозитория начинается с 1–2 строк паспорта:

```
Паспорт файла: <путь> | слой: <L0..L6/все> | роль: <одна фраза>
```

Паспорт позволяет ИИ понять назначение файла, не читая его целиком.

## 6. Почему именно так

Главное ограничение исполнителей этого проекта (включая ИИ) — невозможность
удерживать в голове весь большой код. Методология компенсирует это:

- мелкие кирпичи = мелкие контексты изменений;
- карточки = понимание метода без чтения кода;
- реестры = поиск нужного места за один шаг;
- направление зависимостей вниз = изменение нижнего слоя не требует
  чтения верхних, а изменение верхнего — только его карточек-соседей.

## 7. Деградация структуры

Сигналы, требующие рефакторинга:

- файл превысил 500 строк;
- кирпич не описывается фразой «вход → выход → функция»;
- изменение одного кирпича требует чтения более 7 файлов;
- появились две карточки с одинаковой функцией.
