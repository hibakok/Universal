# 03. Дорожная карта

Паспорт файла: DOCS/03-ROADMAP.md | слой: все | роль: этапы развития и критерии готовности.

Принцип: **малые шаги**. Каждый этап — одна короткая итерация с проверяемым
результатом. Следующий этап начинается только после полного выполнения
критериев готовности (DoD) предыдущего.

## Выполнено

### Этап 2 — HXDUMP: файловый ввод (ВЫПОЛНЕН)

- [x] `hxdump.exe` (3584 байта): чтение файла чанками по 0x400 байт,
  hex-дамп со смещениями и ASCII-колонкой; файлы любого размера

- [x] Импорты: CreateFileA (7 аргументов — первые стековые аргументы
  Win64), ReadFile, CloseHandle; ветвь F (файлы).
- [x] Новые ветви: F (файлы), B (буфер/дамп); кирпичи H022 (байт → 2
  цифры), C014 (копирование слова в буфер); реинкарнации X/S/C/H/P/U.
- [x] Тройная верификация: PE-разбор (30 инвариантов), objdump (244
  инструкции), эмуляция (12 прогонов, 143–139 212 шагов; эталон —
  независимый генератор дампа).
- [x] Реестр: +23 карточки (K0-X021..K0-D026); тест-план T-M3-01..13.
- [x] Реестр METHODS.md разделён по модулям (лимит 500 строк):
  указатель + MAP/M0-SEED.md + MAP/M0-SEED2.md + MAP/M0-HXDUMP.md.
- [x] Эмуляция поймала 6 ошибок ручной сборки (журнал —
  KERNEL/L0-HXDUMP/VERIFY.md): modrm-поля r12–r15 ×4, rol eax/rol al,
  порядок проверок в copy_word.

### Этап 3 — HEXGEN: первый компилятор (ВЫПОЛНЕН)

- [x] `hexgen.exe` (2560 байт): первый компилятор проекта — читает
  ATOM-листинг (текст) и материализует бинарный файл байт-в-байт;
  ручная материализация байтов больше не нужна.
- [x] Строгий разбор ATOM v1: строка за строкой, только ЗАГЛАВНЫЕ цифры,
  проверка границ/порядка/хвоста; 9 кодов возврата со строками ошибок.
- [x] Новая ветвь R (разбор): 6 кирпичей (parse_atom, hex_digit,
  read_hex4, parse_data_line, parse_zero_line, skip_spaces);
  реинкарнации X/S/C/G/P/U/F/D; обобщения: copy_word_dst (приёмник в R8),
  read_word (подпрограмма), skip_seps.
- [x] Виртуальные нули (bss): впервые SizeOfRawData < VirtualSize —
  буферы 64+64 КиБ не занимают места в файле (инвариант SPEC/04 обновлён);
  образ остаётся самодостаточным для ATOM v1.
- [x] DoD: seed.hex → seed.exe байт-в-байт (SHA-256 совпадает);
  также seed2/hxdump и самосборка hexgen.hex → hexgen.exe.
- [x] Тройная верификация: PE-разбор (30 инвариантов), objdump (370
  инструкций, без (bad)), эмуляция (22 сценария; эмулятор валидирован
  на трёх образцах E0–E2). Поймано 3 ошибки ручной сборки (журнал —
  KERNEL/L0-HEXGEN/VERIFY.md).
- [x] Реестр: +29 карточек (K0-X031..K0-D037); тест-план T-M4-01..14.
  Примечание: ядро разбора названо ветвью R (генерация), а не G: буква G
  занята диспетчером по традиции модулей (см. CARD.md M0-HEXGEN).

### Этап 4 — PEGEN: сборка EXE (ВЫПОЛНЕН)

- [x] `pegen.exe` (4096 байт): обёртка образов — тело секции + PEG-файл →
  готовый EXE; PE-заголовки генерируются из шаблона SPEC/04 автоматически
  (патч-таблица — SPEC/07). Ручное сопровождение заголовков прекращено.
- [x] Новый формат PEG v1 (SPEC/07): директивы module/entry/idata/iat/bss/
  stackcom/heapcom; строгий разбор (ветвь Q, 9 кирпичей); обобщённая
  директива-значение по таблице описателей (K0-Q011).
- [x] Новые ветви: Q (разбор PEG), E (заголовок EXE: шаблон, патчи,
  DOS-заглушка из имени модуля), M (align_up без деления); таблица ошибок
  (K0-G042) заменила ветвь U; обобщения файлов: read_whole_dst, write_all.
- [x] Миграция листингов E0–E3 в телесную форму (смещение 0 = RVA 0x1000):
  seed/seed2/hxdump/hexgen .hex перезаписаны, добавлены .peg-файлы.
- [x] DoD: конвейер HEXGEN+PEGEN воспроизводит ВСЕ модули (seed, seed2,
  hxdump, hexgen) из ATOM+PEG байт-в-байт (SHA-256 совпадают) и собирает
  сам себя (круг E4). Формат описан в SPEC/07; карточки (37) — MAP/M0-PEGEN.md;
  тест-план T-M5-01..17.
- [x] Тройная верификация: PE-разбор (инварианты SPEC/04), objdump (549
  инструкций диапазона кода, без (bad)), эмуляция (35 сценариев, включая
  валидацию эмулятора на образцах E0–E3). Поймано 9 классов ошибок ручной
  сборки (журнал — KERNEL/L0-PEGEN/VERIFY.md): 6×REX-биты, знакорасширение
  imm8, знак в align_up, потеря инструкций при реинкарнации, забытый +0x40,
  ошибки раскладки таблиц данных.

### Этап 4a — PEGEN: исправление дескриптора импорта (ВЫПОЛНЕН)

- [x] Дефект: в IDT pegen.exe описатель импорта был записан 16 байтами —

  сохранены (VirtualSize = 0x2117C).
- [x] Верификация: все круги E4 и самосборка pegen зелёные (эмуляция);
  SHA-256 обновлён (KERNEL/L0-PEGEN/VERIFY.md).

## Очередь (порядок фиксирован)

### Этап 5 — BRICK v1: конец ручного счёта адресов (ВЫПОЛНЕН)

- [x] Формат BRICK v1 (SPEC/08): метки, имена, слоты ссылок $имя/$имя:1
  (4/1 байт, всегда последний элемент строки), директивы H/DB/DZ/DBZ/DD/DQ,
  предопределённая метка base, числа ЗАГЛАВНЫМ hex; строгий разбор с
  номером строки в ошибке (ERR=FORMAT AT=XXXX).
- [x] `brick.exe` (3584 байта, M1-BRICK, 42 кирпича): два пассажа, таблица
  меток до 512 записей, файловая/виртуальная длина (DBZ — bss), пределы
  (исходник 128 КиБ, тело 64 КиБ, имена 63 байта).
- [x] **DoD выполнен:** brick.exe собирает себя из собственного
  BRICK-исходника — brick.brick → тело (2968 байт) байт-в-байт равно
  hexgen(brick.hex); pegen(brick(brick.brick)) == brick.exe. Ручной счёт
  смещений/rip-смещений/rel-переходов прекращается (главная боль L0 —
  SPEC/02 — устранена).
- [x] Верификация: PE-инварианты; objdump 678 инструкций без (bad);
  эмуляция (16 сценариев) + независимый оракул семантики SPEC/08 (15
  тестов); самохостинг и полный круг воспроизводства. Поймано 11 классов
  ошибок ручной сборки (журнал — KERNEL/L1-BRICK/VERIFY.md).

### Этап 5a — Лаборатория LAB: постоянная верификация (ВЫПОЛНЕН)

- [x] `LAB/` — внешняя лаборатория ИИ (Python 3, только стандартная
  библиотека): эмулятор x86-64 с заглушками kernel32 (LAB/py/lab_cpu,
  lab_win), разбор PE + инварианты SPEC/04 (lab_pe), дизассемблер
  (lab_disasm), оракулы форматов ATOM/BRICK/PEG (lab_atom, lab_brick,
  lab_pegen), батарея из 67 проверок (lab_verify) — все три уровня
  SPEC/02 и круги DoD E3–E5 выполняются одной командой за ~7 секунд
  без Windows.
- [x] **Найден и исправлен реальный дефект brick.exe:** hex16_to_4
  (K1-H001) печатал номер строки ERR=FORMAT AT= как 0000 для всех
  строк 1..65535 (4 ротации по 4 бита читали только биты 16..31 eax).
  Исправление: `shl eax,16`; тело 0xB94 → 0xB98; SHA-256 обновлён;
  самохостинг сохранён. Также: чётность hint-RVA (DZ 1), карта
  кирпичей BYTECODE синхронизирована с метками, опечатка SHA pegen
  в README, зафиксировано отклонение SPEC/08 (пустые DB/DD/DQ
  принимаются — исправление отложено: brick.exe заморожен как
  проверенный самохостинг E5; уточнение войдёт в BRICK v3 вместе
  с include-механизмом E6.3).
- [x] Правило на будущее: любое изменение KERNEL/ сопровождается
  зелёным прогоном `python3 LAB/py/lab_verify.py`.

### Этап 6 — Язык высокого уровня (L2) + BRICK v2 (В РАБОТЕ)

Цель этапа: прекратить ручное назначение байтов кодировок (последняя
ручная работа по SPEC/08) и построить транслятор язык -> BRICK.
Этап разбит на под-этапы (решение E6.1; архитектура — SPEC/09).

#### Этап 6.1 — SPEC/09 + оракул ENC (ВЫПОЛНЕН)

- [x] `SPEC/09-ENC-FORMAT.md`: формат BRICK v2 (M-строки: мнемоники,
  операнды, `$имя`-ссылки), канонические кодировки, правила REX/modrm/
  SIB/imm; контракт `enc.exe <вход.b2> <выход.brick>` — нормализатор
  v2 -> v1, адресов НЕ считает (brick.exe не меняется, риск самохостинга
  E5 нулевой; enc переиспользуется кодогенератором L2).
- [x] Оракул `LAB/py/lab_enc.py` + эталоны `LAB/py/lab_enc_cases.py`
  (102 якоря из brick.brick и SPEC/05, 21 ошибка, демо-программа).
- [x] Батарея: 67 -> 71 проверок; новый тест — полный круг
  v2 -> enc -> brick -> pegen -> EXE -> эмуляция печатает «U-ENC-OK».
- [x] CI: `.github/workflows/verify.yml` — батарея на каждый пуш
  (внешний прибор, как LAB; красный CI = незавершённое изменение).
- [x] Реестр SPEC/05: закрыт пробел E5 (push/pop r64, jge/jle,
  25-форма, эквивалентность `48 31 C9` == `31 C9`).

**DoD:** батарея 71/71; все якоря ENC сверены с реальными байтами
модулей; демо-круг исполнен эмуляцией. Выполнено.

#### Этап 6.2 — enc.exe: самохостинг кодировщика (СЛЕДУЮЩИЙ)

Инструмент M1-ENC (`KERNEL/L1-ENC/`): исходник в BRICK v1, собирается
конвейером brick+pegen, затем самохостится (исходник переписывается
на M-строки частично). Тесты T-E6-05..11 (`TESTS/T-L1-ENC.md`).

**DoD:** enc.exe == оракул на всех 102 якорях + 21 ошибке; полный
конвейер enc+brick+pegen собирает и запускает демонстрационную
программу; самосборка enc (круг аналогичен E5).

#### Этап 6.3 — миграция исходников и разрез (ПЛАН)

Частичная миграция brick.brick на M-строки (канонические строки);
механизм включения файлов (include) для разреза исходников >500 строк
(известное отклонение: brick.brick 851 строка — разрез отложен до
этого под-этапа; лимит соблюдается всеми новыми файлами).

**DoD:** новый модуль L1 полностью на M-строках; brick.brick разрезан
без изменения тела (сборка байт-в-байт).

#### Этап 6.4 — L2: транслятор язык -> BRICK v2 (ПЛАН)

SPEC/10 (синтаксис L2, имя языка), оракул в LAB, затем инструмент на
BRICK с самохостингом. Переменные, функции, условия, циклы, модули.

**DoD:** компилятор самохостится; на языке написана нетривиальная
программа.

### Этап 7 — UNIVM: виртуальная машина

Собственный ISA (регистры, память, устройства), интерпретатор на L2,
формат программ `.UP`, запуск `kernel.exe <путь>`.

**DoD:** `kernel.exe program.up` исполняет внешнюю программу; программу
можно удалить/заменить без пересборки ядра.

### Этап 8 — Библиотека L4

Математика, строки, память, окна, растр, ввод. Все кирпичи переиспользуемые.

**DoD:** библиотека используется минимум двумя разными программами.

### Этап 9 — Мост EXE -> ATOM

Дизассемблер x64-подмножества: чужой EXE превращается в наш ATOM/BRICK.

**DoD:** круг: EXE -> ATOM -> EXE даёт работающий эквивалент.

### Этап 10+ — Проекты

Копия Minecraft современной версии, её улучшение, затем AGI,

## Регламент работы над этапом

1. Прочитать DoD этапа и карточки затрагиваемых кирпичей.
2. Реализовать малыми кирпичами (правила `DOCS/01-METHODOLOGY.md`).
3. Обновить реестры, листинги, тесты.
4. Прогнать все тесты (`TESTS/`), убедиться в зелёном статусе.
5. Зафиксировать этап в этом файле (отметить [x], добавить DoD следующего).
