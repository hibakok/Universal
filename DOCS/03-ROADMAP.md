# 03. Дорожная карта

Паспорт файла: DOCS/03-ROADMAP.md | слой: все | роль: этапы развития и критерии готовности.

Принцип: **малые шаги**. Каждый этап — одна короткая итерация с проверяемым
результатом. Следующий этап начинается только после полного выполнения
критериев готовности (DoD) предыдущего.

## Выполнено

### Этапы 0–4a — L0: семя, семя-2, hxdump, hexgen, pegen (ВЫПОЛНЕНЫ)

- [x] E0 `seed.exe` (1024 Б) — ручной машинный код, PE32+; тройная
  верификация. E1 `seed2.exe` (2048 Б) — командная строка, табличное
  программирование. E2 `hxdump.exe` (3584 Б) — файловый ввод, дамп.
  E3 `hexgen.exe` (2560 Б) — первый компилятор: ATOM-текст -> тело,
  виртуальные нули (bss). E4 `pegen.exe` (4096 Б) — обёртка EXE:
  PE-заголовки из шаблона SPEC/04 автоматически (PEG v1, SPEC/07).
- [x] DoD E4: конвейер HEXGEN+PEGEN воспроизводит ВСЕ модули L0
  байт-в-байт и собирает сам себя (круг E4); эмуляция поймала 23
  класса ошибок ручной сборки на этапах E0–E4a (журналы VERIFY.md
  модулей). E4a — исправление дескриптора импорта pegen (IDT +4 Б).
- Детальные записи этапов (что сделано, реестры, найденные дефекты) —
  `DOCS/03a-HISTORY.md`.

## Очередь (порядок фиксирован)

### Этап 5 — BRICK v1: конец ручного счёта адресов (ВЫПОЛНЕН)

- [x] Формат BRICK v1 (SPEC/08): метки, имена, слоты ссылок $имя/$имя:1
  (4/1 байт, всегда последний элемент строки), директивы H/DB/DZ/DBZ/DD/DQ,
  предопределённая метка base, числа ЗАГЛАВНЫМ hex; строгий разбор с
  номером строки в ошибке (ERR=FORMAT AT=XXXX).
- [x] `brick.exe` (3584 байта, M1-BRICK, 42 кирпича): два пассажа, таблица
  меток до 512 записей, файловая/виртуальная длина (DBZ — bss), пределы
  (исходник 128 КиБ, тело 64 КиБ, имена 63 байта).
- [x] **DoD выполнен:** brick.exe собирает себя из собственного
  BRICK-исходника — brick.brick → тело (2968 байт) байт-в-байт равно
  hexgen(brick.hex); pegen(brick(brick.brick)) == brick.exe. Ручной счёт
  смещений/rip-смещений/rel-переходов прекращается (главная боль L0 —
  SPEC/02 — устранена).
- [x] Верификация: PE-инварианты; objdump 678 инструкций без (bad);
  эмуляция (16 сценариев) + независимый оракул семантики SPEC/08 (15

  ошибок ручной сборки (журнал — KERNEL/L1-BRICK/VERIFY.md).

##### Часть 3 — wall.exe v2 (ВЫПОЛНЕНА: срезы 1–5)

каждый срез проходит всю глубину и сверяется с оракулом байт-в-байт
(мотив: фазовые шаги нельзя проверить до полной сборки; срезы — можно;
якоря готовы в cases2/ERRORS2/big_source2).

1. **Срез 1 — операторы `* / %` (ВЫПОЛНЕН, E6.4c-3/1):** лексер +3

   механизм chain_count/tdepth); эмиттеры E034 (imul) и E035
   (rax/cqo/idiv/rax|rdx); заголовок «WALL v1/v2» (флаг v2
   [r13+18190]). Попутно: дефект E6.4b №12 исправлен (сравнения —
   терминаторы ЛЮБОЙ цепочки chain_count); предел меток brick 512 —
   bss-метки (14 буферов) заменены смещениями r13+X (единая DBZ
   7A1418; 499/512); калибровка чётности hint (DZ 2). Проверки:
