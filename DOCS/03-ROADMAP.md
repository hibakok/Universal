# 03. Дорожная карта

Паспорт файла: DOCS/03-ROADMAP.md | слой: все | роль: этапы развития и критерии готовности.

Принцип: **малые шаги**. Каждый этап — одна короткая итерация с проверяемым
результатом. Следующий этап начинается только после полного выполнения
критериев готовности (DoD) предыдущего.

Детальные записи закрытых этапов — 03-серии истории
(03a/03a2 — E0..E6.4, 03b — E7, 03c — E8, 03d/03e/03f — E9;
переносы из дорожной карты и README при возврате под лимит
500 строк — сессия 77). Здесь — статусы, DoD и очередь.

## Выполнено

### Этапы 0–4a — L0: семя, семя-2, hxdump, hexgen, pegen (ВЫПОЛНЕНЫ)

- [x] E0 `seed.exe` (1024 Б) — ручной машинный код, PE32+; тройная
  верификация. E1 `seed2.exe` (2048 Б) — командная строка, табличное
  программирование. E2 `hxdump.exe` (3584 Б) — файловый ввод, дамп.
  E3 `hexgen.exe` (2560 Б) — первый компилятор: ATOM-текст -> тело,
  виртуальные нули (bss). E4 `pegen.exe` (4096 Б) — обёртка EXE:
  PE-заголовки из шаблона SPEC/04 автоматически (PEG v1, SPEC/07).
- [x] DoD E4: конвейер HEXGEN+PEGEN воспроизводит ВСЕ модули L0
  байт-в-байт и собирает сам себя (круг E4); эмуляция поймала 23
  класса ошибок ручной сборки на этапах E0–E4a (журналы VERIFY.md
  модулей). E4a — исправление дескриптора импорта pegen (IDT +4 Б).
- Детальные записи этапов (что сделано, реестры, найденные дефекты) —
  `DOCS/03a-HISTORY.md` (E0..E6.4) и `DOCS/03b-HISTORY-E7.md` (этап 7).

### Этап 5 — BRICK v1: конец ручного счёта адресов (ВЫПОЛНЕН)

- [x] brick.exe (M1-BRICK, 42 кирпича): два пассажа, таблица меток,
  файловая/виртуальная длина (DBZ — bss); формат BRICK v1 (SPEC/08).
- [x] **DoD выполнен:** brick.exe собирает себя из собственного
  BRICK-исходника байт-в-байт; pegen(brick(brick.brick)) == brick.exe.
  Ручной счёт смещений/rip-смещений/rel-переходов прекращён; поймано
  11 классов ошибок ручной сборки. Детали — `DOCS/03a2-HISTORY.md`.

### Этап 5a — Лаборатория LAB: постоянная верификация (ВЫПОЛНЕН)

- [x] LAB/ — внешняя лаборатория (эмулятор, дизассемблер, оракулы,
  батарея — три уровня SPEC/02 одной командой); найден и исправлен
  реальный дефект brick.exe (hex16_to_4). Правило: любое изменение
  KERNEL/ — с зелёным `python3 LAB/py/lab_verify.py`. Детали —
  `DOCS/03a2-HISTORY.md`.

- [x] **6.3** SPLICE v1: директива !include + разрез исходников
  (splice.exe, 27 кирпичей; нулевой риск замороженному самохостингу

- [x] **6.4a/6.4b** SPEC/11 + оракул WALL v1 + wall.exe (три прохода;

- [x] **6.4e/6.4f/6.4g** рост пределов конвейера: входы 128 -> 256 ->

- [x] **DoD 6.4d (ВЫПОЛНЕН):** wall(wall.wall) воспроизводит

### Этап 7 — UNIVM: виртуальная машина (ЗАКРЫТ: E7.1..E7.4)

Собственный ISA (SPEC/12), формат программ `.UP` (SPEC/13),
интерпретатор на L2, запуск `kernel.exe <путь>`. Срезы:

- [x] **E7.1 (сессия 44) — ISA v0 + .UP v1 + оракул.** SPEC/12
  (модель, 18 инструкций F1/F2/F3, ловушки 1-4, окно устройств)
  + SPEC/13 (контейнер 24 Б + код); оракул LAB/py/lab_vm.py +
  секция 13 батареи (T-E7-01..08). Батарея 148/148 — сначала

- [x] **E7.2 (сессии 45-49; ЭТАП 7.2 ЗАКРЫТ) — ядро kernel.exe на
  WALL, срезы 1..4:** каркас CLI+контейнер+halt (T-E7-09..14;
  148 → 156) → регистры+ALU (K3-V101..V111 + фикс №23; 158) → память
  и устройства (ветвь M; 159) → переходы+предел шагов (ветвь J,
  K3-C008; 161). Диффтест == оракулу; корпуса —
  lab_t_kernel_corpus.py. Подробно — 03b-HISTORY-E7.
- [x] **E7.3-1..4 (сессии 50-53) — ассемблер uva.exe на WALL;

- [x] **E7.4 (сессии 54-60) — рост ISA v1 + .UP v2; ЭТАП 7.4
  ЗАКРЫТ (E7.4-4):** оракул v1 (SPEC/12 v1 + SPEC/13 v2;
  T-E7-26..31) → ядро (контейнер v2; ALU v1 + ловушка 7;
  call/ret + стек вызовов — ISA полна, 24 опкода) → ассемблер

### Этап 9 — Мост EXE -> ATOM (L5; E9.1/E9.2/E9.3 ЗАКРЫТЫ; E9.4 — срезы 1-2 и 3a сделаны)

Дизассемблер x64-подмножества: чужой EXE превращается в наш
BRICK v2 + PEG v1 (SPEC/15). Детали — DOCS/03d-HISTORY-E9.md (E9.1..

DOCS/03f-HISTORY-E9.md (E9.4+, сессии 75+). Срезы:

- [x] **E9.1 (сессия 67)** — SPEC/15 + оракул + секция 18 («сначала
  истина семантики»): круг ВСЕХ 11 артефактов байт-в-байт (T-E9-01..16).
- [x] **E9.2-1..4 (сессии 68-73)** — каркас bridge.exe (26 кирпичей
  K5-C/P/X) -> спуск (декодер SPEC/05 + тени + target/bss, K5-D/W)
  -> RAW-эмиссия -> метки/семантика DD/DQ (K5-L) -> M-строки канона

  ЭТАП E9.2 ЗАКРЫТ: мост полностью самодостаточен (117 кирпичей).
- [x] **E9.3-1 (сессия 74)** — якорная фиксация выхода моста: 24 файла
  .anchor.b2/.peg (все 12 артефактов) + T-E9-25 — ЭТАП E9.3 ЗАКРЫТ.
- [x] **E9.4-1 (сессия 75)** — FF /4: косвенный jmp в оракуле (декодер
  + терминал-семантика + плечи исполнителя + фаззер; T-E9-26,
  секция 18c).
- [x] **E9.4-2 (сессия 76)** — таблицы переходов в оракуле (jmp qword
  [rip+X]: цели-кандидаты из qword-строк данных «до первого non-code

  lab_bridge_text.py).
- [x] **E9.4-3a (сессия 78)** — фундамент чужих EXE в оракуле: разбор

  ВСЕ секции (pe["sections"]), RVA-отображение по секциям, импорты
  многих DLL; семейство нейтрально (T-E9-28, секция 18e — снимок
  до/после + батарея 238/238); parse_family и bridge.exe не
  менялись.
- [ ] **E9.4-3b+** — PEG v2: чужие PE-заголовки/секции/импорты (оракул
  вперёд: parse_family на произвольных образах — фундамент E9.4-3a
  заложен; нейтральность семейства — снимками до/после), затем порт
  декодера FF /4 + таблиц переходов в инструмент bridge.exe
  (при первом чужом круге).

**DoD:** круг EXE -> ATOM/BRICK -> EXE даёт РАБОТАЮЩИЙ эквивалент
(для семейства — байт-в-байт, доказано T-E9-04..14; для чужих EXE —
E9.4+). **DoD этапа E9.2 (ВЫПОЛНЕН — сессия 73):** инструмент
bridge.exe пишет ОБА выхода (b2-канон + peg), оба == оракулу на
полном корпусе (T-E9-22/24), сквозной круг С ВЫХОДАМИ МОСТА
сходится (T-E9-23) — мост полностью самодостаточен.

## Регламент работы над этапом

1. Прочитать DoD этапа и карточки затрагиваемых кирпичей.
2. Реализовать малыми кирпичами (правила `DOCS/01-METHODOLOGY.md`).
3. Обновить реестры, листинги, тесты; прогнать батарею (зелёный
   статус); зафиксировать этап здесь (отметить [x], добавить DoD).
