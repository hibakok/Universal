### Дефекты (1 процессный, пойман до сдачи)

1. Ручные якоря synth6/synth7 выведены с двумя неточностями:
   disp операнда [rip+X] хранится в кортеже декодера (5/13, а не
   0); нулевой пробег терминатора длиннее ожидаемого (DZ 7, а не
   DZ 6 + DB 00 90 — нулевой байт терминатора прирастает к
   пробегу нулей). Пойманы первым же standalone-прогоном T-E9-27
   («операнд jmp»/«строки»), якоря исправлены по фактическому
   выходу оракула до любого коммита. Урок: якорь rip-операнда
   несёт disp; границы DZ — по фактическому пробегу, не по
   «красивой» раскладке.

### Решения (чтобы не передумывать)

1. Терминатор таблицы — ПЕРВЫЙ non-code qword (0 или вне тела);
   qword ПОСЛЕ терминатора — НЕ кандидат, даже если значение
   валидно (synth7: qword 0x20C после 0x9000). «Дыры» в таблице
   завершают её — консервативно и детерминированно; для чужих
   EXE — риск потерять хвост таблицы, пересмотр при первом чужом
   круге (вместе с портом).
2. Кандидат обязан быть `0 < v < VirtualSize`: v == 0 — нулевой
   указатель, не кандидат; v >= VirtualSize — вне тела.
3. Граница BridgeError (кандидат декодируется за VirtualSize) —
   наследует правило E9.2-2 «инструкция за VirtualSize — не
   семейство»; для v1-семейства недостижима (нет FF /4), для
   чужих EXE — риск, зафиксирована в SPEC/15 п. 3.
4. Рендер-ветвь оракула выделена навсегда: правка СЕМАНТИКИ
   моста — lab_bridge.py (фронт), правка ВИДА текста —
   lab_bridge_text.py; зондам LAB/ai оставлен реэкспорт имён
   (обратная совместимость trace_m/probe_e92_3c).
5. Следующий срез (E9.4-3): PEG v2 — чужие PE-заголовки/секции/
   импорты (оракул вперёд: parse_family на произвольные образы;
   нейтральность семейства — снимками); за ним — порт декодера
   FF /4 + таблиц переходов в инструмент bridge.exe
   (bridge_self_d*.wall) при первом чужом круге.
