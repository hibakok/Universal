# Тест-план M0-HXDUMP (файловый ввод: hex-дамп)

Паспорт файла: TESTS/T-L0-HXDUMP.md | слой: L0 | роль: тесты модуля M0-HXDUMP.

Короткий префикс тестов модуля — `T-M3`. Все тесты ручные (до этапа
E3), каждый занимает секунды. Запуск — из папки `KERNEL\L0-HXDUMP`.

## T-M3-01 — подлинность файла

- Шаги: `certutil -hashfile hxdump.exe SHA256`
- Эталон: `F0CEE97E45B1399FF13151BF4587BA2A02465E793FB9C92F525CDD69A7B4A8E3`
- Проверяет: целостность материализации листинга hxdump.hex.
- Время: ~1 с.

## T-M3-02 — дамп известного файла (первые строки)

- Шаги: `hxdump.exe ..\L0-SEED\seed.exe`
- Эталон (первые две строки, строго):
  `00000000: 4D 5A 90 00 03 00 00 00 04 00 00 00 FF FF 00 00  MZ..............`
  `00000010: B8 00 00 00 00 00 00 00 40 00 00 00 00 00 00 00  ........@.......`
- Проверяет: K0-F001, K0-F002, K0-B001, K0-B002, K0-H021, K0-H022, K0-P021.
- Время: ~1 с.

## T-M3-03 — дамп известного файла (полный объём)

- Шаги: `hxdump.exe ..\L0-SEED\seed.exe | find /c /v ""`
- Эталон: 64 строки (1024 байта / 16).
- Проверяет: полноту цикла чтения, последнюю строку `000003F0:`.
- Время: ~1 с.

## T-M3-04 — короткий файл (неполная строка)

- Шаги: создать файл `t.bin` из 5 байт `hello`; `hxdump.exe t.bin`
- Эталон (строго): `00000000: 68 65 6C 6C 6F  hello` + CRLF (31 байт).
- Проверяет: R13 = min(16, остаток) в K0-B001; длину строки 13+4N.
- Время: ~1 с.

## T-M3-05 — пустой файл

- Шаги: создать пустой файл `e.bin`; `hxdump.exe e.bin`
- Эталон: пустой вывод; код возврата 0.
- Проверяет: nread = 0 → выход из K0-B001 без строк.

## T-M3-06 — вызов без аргумента

- Шаги: `hxdump.exe`
- Эталон: `U-L0-HXDUMP CMDS: HXDUMP <FILE>` + CRLF (33 байта); код 2.
- Проверяет: K0-C012 (конец строки), K0-U021.

## T-M3-07 — несуществующий файл

- Шаги: `hxdump.exe no_such_file.bin`
- Эталон: `U-L0-HXDUMP ERR=OPEN FILE` + CRLF (27 байт); код 4.
- Проверяет: ветвь −1 в K0-G021 после CreateFileA.

## T-M3-08 — имя длиннее 127 байт

- Шаги: `hxdump.exe <имя из 128+ символов>`
- Эталон: `U-L0-HXDUMP ERR=LONG NAME` + CRLF; код 3.
- Проверяет: предел буфера K0-D022, флаг K0-C014.

## T-M3-09 — имя ровно 127 байт

- Шаги: из короткого каталога создать файл с именем ровно 127 байт;
  `hxdump.exe <это имя>`
- Эталон: дамп файла; код 0 (не ERR=LONG).
- Проверяет: порядок проверок в K0-C014 (конец слова раньше предела).
- История: тест поймал дефект — предел срабатывал до конца слова.

## T-M3-10 — коды возврата

- Шаги: T-M3-02/06/07 + `echo %errorlevel%` после каждого.
- Эталон: 0, затем 2, затем 4.
- Проверяет: K0-X022.

## T-M3-11 — путь argv[0] в кавычках

- Шаги: `& "путь с пробелами\hxdump.exe" t.bin` (PowerShell)
- Эталон: дамп как в T-M3-04.
- Проверяет: reincarnation K0-C012 в новом образе.

## T-M3-12 — контрольные байты (соответствие листингу)

- Шаги: открыть hxdump.exe в hex-просмотрщике и сверить точки:

| Смещение | Байт | Что это |
|---|---|---|
| 0x000 | `4D` | 'M' сигнатуры MZ |
| 0x03C | `80` | младший байт e_lfanew = 0x80 |
| 0x0A8 | `00` | младший байт точки входа RVA 0x1000 |
| 0x0D0 | `00` | младший байт SizeOfImage = 0x2000 |
| 0x198 | `00` | SizeOfRawData = 0xC00 (байт 0x199 = `0C`) |
| 0x200 | `48` | первый байт кода (REX.W, K0-X021) |
| 0x202 | `EC` | sub rsp,0x48 — кадр 0x48 (отличие от seed2) |
| 0x21F | `FF` | начало call GetCommandLineA |
| 0x269 | `E8` | call print_usage (ветвь noargs) |
| 0x327 | `FF` | call ExitProcess в exit_proc (RVA 0x1127) |
| 0x401 | `48` | начало K0-C014 copy_word (RVA 0x1201) |
| 0x4FC | `C0` | rol al,4 — 8-битная ротация K0-H022 (RVA 0x12FC) |
| 0x570 | `00` | linebuf (RVA 0x1370, нулевая заливка) |
| 0x5C0 | `00` | fname (RVA 0x13C0) |
| 0x640 | `00` | filebuf (RVA 0x1440) |
| 0xA40 | `30` | '0' таблица цифр (RVA 0x1840) |
| 0xAF0 | `58` | младший байт INT RVA 0x1958 (IDT, RVA 0x18F0) |
| 0xB18 | `A6` | младший байт hint RVA 0x19A6 (IAT[0], RVA 0x1918) |
| 0xB98 | `6B` | 'k' "kernel32.dll" (RVA 0x1998) |
| 0xBA8 | `47` | 'G' имя GetStdHandle (RVA 0x19A6 + hint 2) |
| 0xDFF | `00` | последний байт файла (нулевая заливка) |

- Эталон: все 21 точка совпадают.
- Время: ~3 мин вручную (или мгновенно: `hxdump.exe hxdump.exe`
  и сверка первых строк).

## T-M3-13 — самодамп (перекрёстная проверка)

- Шаги: `hxdump.exe hxdump.exe > self.txt`, затем `hxdump.exe self.txt`
- Эталон: первый дамп содержит 224 строки (3584/16); вторая команда
  успешно дампит self.txt (первая строка `00000000: 30 30 30 30 ...`
  — ASCII '0' смещений).
- Проверяет: устойчивость к собственному формату вывода.
