# T-L3-UVA. Тест-план ассемблера uva.exe (M3-UVA)

Паспорт файла: TESTS/T-L3-UVA.md | слой: L3 | роль: тест-план модуля M3-UVA.

Обязательство модуля (SPEC/12 п. 8, этап E7.3): выход uva.exe ==
ассемблеру оракула `LAB/py/lab_vm.py` (`assemble`) байт-в-байт на всех
валидных исходниках класса срезов; отвержение — с теми же номерами
строк, что `AsmError.line` оракула. Срезы 1 (E7.3-1): класс = `.mem` +
`halt`; срез 2 (E7.3-2): + F1 — `mov`/9 АЛУ с регистрами r0..r15
(мнемоники F2 и jmp/jnz + метки — срезы E7.3-3/4; для них у оракула
нет общего свидетеля с инструментом до снятия ограничения — строки
ошибок невалидных операндов совпадают: оба отвергают на строке).

Автоматизация: все тесты — батарея (секция 15, `LAB/py/lab_t_uva.py`);
запуск `python3 LAB/py/lab_verify.py` (группа 3: `python3
LAB/ai/battery_groups.py 3`). Время: секунды на проверку (кроме
сборки ~52,5 млн шагов эмуляции — T-E7-19).

## T-E7-19. Фикс-пункт: сборка артефактов из uva.wall

Шаги: склеить uva.wall (splice-оракул) → wall.exe → uva.b2 → enc.exe →
uva.brick → brick.exe → тело → pegen.exe + uva.peg → uva.exe (эмуляция
конвейера); сравнить с артефактами репозитория байт-в-байт; сравнить
uva.b2 с оракулом WALL (compile_wall).
Эталон: uva.b2 == оракулу == артефакту; uva.brick, uva.exe — те же
байты; шаги 40033371 + 8770334 + 3685750 + 5015.
Время: ~70 с эмуляции.

## T-E7-20. Контракт CLI

Шаги: запустить uva.exe (эмуляция) с 0/1/3 аргументами, именем 128 Б,
отсутствующим входом, входом 65537 Б (BIG SRC) и 65536 Б (валидный:
`.mem 8` + `halt 0` + комментарий-хвост).
Эталон: `U-L3-UVA CMDS: UVA <SRC.UVA> <OUT.UP>\r\n` код 2 (0/1/3
аргумента); `ERR=LONG NAME` 3; `ERR=OPEN SRC` 4; `ERR=BIG SRC` 7
(65537); 65536 — код 0, корректный .UP. 7 случаев.
Время: ~2 с.

## T-E7-21. Диффтест: корпус срезов 1-2 == ассемблеру оракула

Шаги: для каждого исходника корпуса — uva.exe(вход, выход) и
lab_vm.assemble(текст); сравнить выходной файл байт-в-байт.
Корпус (29): срез 1 (17) — `.mem 4096/0/64/67108864/0x1000` + `halt`
с числами 0/37/2147483647/−1/−2147483648/4294967295/0x10/−0x10/+5;
CRLF; комментарии и пустые строки; без хвостового LF; несколько
halt; строка из одних запятых (дефект №24); `halt , 0`; срез 2
(12) — F1: mov r1,r2 / mov r0,r15 / mov r15,r15 / add / sub r15,
r15,r14 / все 9 АЛУ одной программой / mov+add+halt 5 / без пробелов
(запятые-разделители) / CRLF / комментарий / без хвостового LF /
регистры r10..r15.
Эталон: файл == ассемблеру оракула; код 0.
Время: ~4 с.

## T-E7-22. Отвержение: номера строк == AsmError оракула

Шаги: для каждого ошибочного исходника — прогнать оракул (первая
AsmError с номером строки) и uva.exe; сравнить `ERR=FORMAT AT=XXXX`
с номером строки оракула.
Корпус (39): срез 1 (21) — пустой вход и только комментарии (AT=0001
— «нет .mem»); halt без .mem (AT=0001 — строка 1!); неизвестная
мнемоника foo; мнемоника раньше .mem; halt с 0/2 операндами; halt
abc; 9999999999; 0x; повторная .mem; .mem без числа/с двумя числами/−1/
999999999/9999999999; неизвестная директива .foo; const r16 (известная
оракулу, не halt — строка совпадает); заглавный HALT; CR внутри
строки; срез 2 (18) — mov до .mem (AT=0001); mov с 1/3 операндами;
плохие rd/ra (r16); АЛУ с 2/4 операндами; плохие rd/ra/rb АЛУ; число
вместо регистра (mov r1, 2 / add r1, r2, 3); регистры r01/R1/r0x/r-1;
мнемоника-префикс haltx; ошибка в F2-строке позже валидной F1
(mov r1, r2 + const r16, 5 — оба на строке 3).
Эталон: код 6, выход `U-L3-UVA ERR=FORMAT AT=<строка оракула>\r\n`,
файл не создан.
Время: ~4 с.

## T-E7-23. Контракт CODE0 (пустая программа)

Шаги: исходники `.mem 8` / `.mem 8`+комментарий / `.mem 8`+строка из
разделителей — оракул даёт UpError("CODE0") (make_up), uva.exe обязан
дать то же; пустой вход — НЕ CODE0, а FORMAT AT=0001 (нет .mem).
Эталон: `U-L3-UVA ERR=CODE0\r\n` код 6 (3 случая); AT=0001 для пустого.
Время: ~1 с.

## T-E7-24. Сквозной круг uva → kernel.exe + детерминизм

Шаги: uva.exe собирает `.mem 8`+`halt 42`, `.mem 0`+`halt 37`,
`.mem 4096`+`halt 0`+`halt 1`, `.mem 8`+`mov r1, r2`+`add r3, r1,
r2`+`halt 7` (F1); kernel.exe исполняет каждый .UP; два прогона одного
исходника — файлы идентичны.
Эталон: коды возврата ядра 42/37/0/7, пустая консоль; оба прогона
uva — байт-в-байт одинаковые .UP, код 0.
Время: ~4 с.

## Журнал находок

- **Дефект №24 (оракул lab_vm, закрыт E7.3-1):** строка из одних
  разделителей/запятых (",,,") — `_toks` возвращал пустой список,
  `toks[0]` — крах IndexError (не AsmError). Фикс: пустые токены =
  пустая строка (пропуск) — как uva.exe по построению; корпус
  T-E7-21 «sep line» и T-E7-23 «.mem + разделители» зафиксировали.
- **Урок E7.3-1 (собственный исходник):** идиома `while go == 1 /
  go = line_next() / тело` выполняет тело и при go == 0 (условие
  проверяется только в голове цикла) — последняя строка без хвостового
  LF кодировалась дважды (поймано T-E7-21 «no final lf»: codesize 12
  вместо 6; локализовано трассировкой эмулятора). Идиома итератора
  в WALL — чтение ВПЕРЁД: `go = line_next() / while go == 1 / тело /
  go = line_next()` (задокументировано в шапках pass1/pass2).
- **Наблюдение E7.3-2:** номера строк ошибок совпадают с оракулом и на
  невалидных операндах F2-строк (const/ldb/stb/ldq/stq) до реализации
  срезов 3-4 — оба отвергают на строке инструкции (случай «mov +
  константа r16 позже»); валидные F2-программы в корпус не входят
  (оракул собирает, uva — ещё нет).
