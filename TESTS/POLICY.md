# TESTS. Политика тестирования

Паспорт файла: TESTS/POLICY.md | слой: все | роль: принципы тестов проекта.

## Принципы

1. **Секунда — предел.** Каждый тест выполняется за время, неотличимое
   от нуля на глаз. Долгие проверки разбиваются на быстрые шаги
   или помечаются как «приёмочные» и запускаются только при смене этапа.
2. **Глубина не приносится в жертву скорости.** Быстрота достигается
   изоляцией и точностью проверок, а не их сокращением.
3. **Тест = процедура + эталон.** Ожидаемый результат записан заранее
   в тест-плане; сравнение с эталоном — строгим (байт-в-байт).
4. **Пирамида:**
   - кирпич (карточка: вход -> выход) — проверяется в составе модуля;
   - модуль (тест-план вида T-M*-*) — основной уровень;
   - этап (DoD в ROADMAP) — приёмочные проверки.
5. **Детерминизм.** Один вход — один выход. Недетерминированное поведение
   запрещено (правило R8) и не тестируется как «иногда работает».
6. **Красный тест блокирует изменение** (правило процесса, см.
   `DOCS/04-RULES-OF-CHANGE.md`).

## Формат тест-плана модуля

```
T-<модуль>-<номер>  <имя>
  Шаги: ...
  Эталон: ...
  Время: ...
```

## Уровни проверки для L0 (все три обязательны)

1. **Статический разбор** — поля образа сверяются со спецификацией.
2. **Дизассемблирование** — мнемоники и цели rip-смещений сверяются
   с замыслом (ловит ошибки кодировок).
3. **Эмуляция/запуск** — программа исполняется, вывод и код возврата
   сравниваются с эталоном (ловит ошибки логики).

Практика этапа E0 показала: три реальные ошибки ручной сборки
(неверные байты ImageBase, пропущенный бит mod в modrm, неверный порядок
байтов в disp32) были пойманы именно многоуровневой проверкой.
