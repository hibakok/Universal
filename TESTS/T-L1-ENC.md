## Оракул (автоматические, секция 6 батареи)

### T-E6-01  Якорные кодировки
Шаги: для каждой пары (M-строка, H-строка) из `lab_enc_cases.CASES`
(109 случаев: реальный код brick.brick + реестр SPEC/05 + канонические
формы + фиксации дефектов E6.2) выполнить `lab_enc.normalize` и сравнить
с эталоном.
Эталон: байт-в-байт.
Время: < 0,1 с.

### T-E6-02  Отвержение некорректных M-строк
Шаги: для каждой строки из `lab_enc_cases.ERRORS` (21 случай) убедиться,
что `normalize` возбуждает `EncError` ("FORMAT AT=...").
Эталон: все 21 отвергаются; ни одна не проходит.
Время: < 0,1 с.

### T-E6-03  Структурный контроль декодером
Шаги: каждую кодировку из T-E6-01 (слоты заполнены нулями) декодировать
`lab_x86.decode`; длина декодированной инструкции обязана равняться
длине кодировки.
Эталон: 109/109 совпадений длины.
Время: < 0,1 с.

### T-E6-04  Полный круг v2 -> EXE -> эмуляция
Шаги: `DEMO_B2` -> `lab_enc` -> `lab_brick` -> `lab_pegen` -> запуск в
эмуляторе (`lab_run`).
Эталон: stdout `U-ENC-OK\r\n`, код возврата 0.
Время: < 0,5 с.

## Инструмент enc.exe (автоматические, секция 7 батареи)

### T-E6-05  Справка без аргументов  [OK]
Шаги: `enc.exe` без аргументов.
Эталон: `U-L1-ENC CMDS: ENC <SRC.B2> <OUT.BRICK>`, код 2.

### T-E6-06  Равенство оракулу (главный)  [OK]
Шаги: `enc.exe` на синтезированном файле из всех 109 CASES (по одной
M-строке на строку); выход сравнить с выходом оракула.
Эталон: байт-в-байт (109/109).

### T-E6-07  Отвержение ошибок инструментом  [OK]
Шаги: для каждой строки ERRORS (ошибка на строке 3 после двух корректных)
— прогон enc.exe (в эмуляторе).
Эталон: `U-L1-ENC ERR=FORMAT AT=0003`, код 6; строка совпадает с
исключением оракула (см. также T-E6-11).

### T-E6-08  Круг конвейера на реальном модуле  [OK]
Шаги: `enc.exe` + `brick.exe` + `pegen.exe` на DEMO_B2; результат
запустить в эмуляторе.
Эталон: stdout `U-ENC-OK\r\n`, код 0.

### T-E6-09  Самохостинг enc (DoD)  [OK]
Шаги: enc.exe собирает собственный исходник enc.b2; результат равен
enc.brick байт-в-байт; затем brick+pegen воспроизводят enc.exe.
Эталон: оба равенства (fc /b без различий).

### T-E6-10  Большие исходники  [OK]
Шаги: сгенерированный программно файл ~24 КиБ (смесь всех семейств,
память, ссылки, комментарии); сравнение с оракулом.
Эталон: байт-в-байт. Дополнительно (вне батареи): вход 39 КиБ проверен
при создании; выход < вход x 23/11 + 1 (доказательство — VERIFY.md §3).

### T-E6-11  Номер строки в ошибке  [OK]
Шаги: файл с корректными M-строками и одной ошибочной на строке N.
Эталон: `ERR=FORMAT AT=<N в hex>`; номер совпадает с оракулом (покрыто
T-E6-07: 27 ошибок на строке 3).

### (доп.) Граничные концы строк  [OK]
Шаги: пустой вход; строка без LF; CRLF; одиночный CR; строка из одного
LF; M-строка с пробелами по краям; M-строка с комментарием и CRLF.
Эталон: выход enc.exe == выход оракула байт-в-байт (включая quirk:
пустой вход -> один LF).

## Рост ISA (E6.4c, для WALL v2)

### T-E6-06a  Якоря imul/idiv/cqo  [OK]
Шаги: +8 якорей к CASES (imul r10,r11 -> 4D 0F AF D3; imul rax,rcx;
imul r8,rax; imul rax,r8; idiv r11 -> 49 F7 FB; idiv rbx; idiv ebx ->
F7 FB; cqo -> 48 99) и +6 к ERRORS (трёхоперандная imul, 32-битная imul,
imul с памятью, idiv с двумя операндами, idiv al, cqo с операндом).
Эталон: enc.exe == оракулу на всех 117 якорях и 27 ошибках.

### T-E6-06b  Структурный контроль новых форм  [OK]
Шаги: каждая новая кодировка декодируется lab_x86 той же длины
(0F AF — imul reg,r/m; F7 /7 — idiv; 99 — cqo/cdq — расширения
декодера и исполнителя lab_cpu E6.4c).
Эталон: длина совпадает; семантика проверена отдельными прогонами
CPU (imul 7*(-3) = -21; -100/-3 = 33 ост. -1; #DE на 0 и переполнении).
