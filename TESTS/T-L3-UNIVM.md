# T-L3-UNIVM. Тест-план оракула UNIVM (SPEC/12 ISA v0 + SPEC/13 .UP v1)

Паспорт файла: TESTS/T-L3-UNIVM.md | слой: L3 | роль: тест-план UNIVM — оракул (E7.1) и ядро kernel.exe (E7.2).

## Статус

- **E7.1 (выполнено, сессия 44):** спецификации SPEC/12 (ISA v0: модель,
  форматы F1/F2/F3, 18 инструкций, ловушки 1-4, окно устройств) и
  SPEC/13 (контейнер .UP v1) + оракул `LAB/py/lab_vm.py` (исполнитель +
  мини-ассемблер) + секция 13 батареи `LAB/py/lab_t_vm.py`
  (T-E7-01..08). Все проверки исполняются автоматически в батарее
  `LAB/py/lab_verify.py`. Ядро `kernel.exe` (M3-UNIVM) обязано
  совпадать с оракулом по наблюдаемому поведению: консоль, код
  возврата, счётчик шагов, код ловушки.
- **E7.2-1 (выполнено, сессия 45):** ядро `KERNEL/L3-UNIVM/kernel.exe`
  (WALL-исходник kernel.wall, артефакты — фикс-пункт T-E7-09);
  разбор .UP полный; исполнение — halt; опкоды 01..11 — заглушка
  (ловушка 1, срезы E7.2-2..4). Секция 14 батареи
  `LAB/py/lab_t_kernel.py` (T-E7-09..14); контракт ядра — SPEC/13 п. 4.
- **E7.2-2 (выполнено, сессия 46):** регистры + ALU — массив regs[16]
  (r0 равноправен), кирпичи K3-V101..V111 (const с sext32 через
  сдвиг, mov с проверкой rb=0, add/sub/and/or/xor/shl/shr/lt/eq);
  interp: проверка длины для ВСЕХ валидных опкодов 01..12 — обрезка
  даёт ловушку 2 ДО заглушки (как оракул; в срезе 1 не различалось).
  Корпус T-E7-15 (17 случаев) — зелёный с первого прогона.
  Попутно найден дефект №23 wall.exe (pp_pcount — обход в op_eq
  скобками, фикс — отдельный срез; KERNEL/L2-WALL/VERIFY.md §4).

## Оракул (автоматические, секция 13 батареи)

### T-E7-01  Якорные кодировки
Шаги: 18 строк ассемблера (по одной на каждый опкод) собираются
мини-ассемблером; байты сверяются с якорями, выписанными вручную
по SPEC/12 п. 4-5 (независимый свидетель, как якоря ENC).
Эталон: байт-в-байт (`01 10 00 00 01 00` для `const r1, 65536` и т.д.).
Время: < 0,1 с.

### T-E7-02  Отвержение ассемблера
Шаги: 13 некорректных исходников (мнемоника, регистры, imm32, .mem,
метки, арности операндов, порядок stb).
Эталон: AsmError с точным номером строки (1-базируются, как у всех
инструментов проекта).
Время: < 0,1 с.

### T-E7-03  Отвержение контейнера .UP
Шаги: 7 повреждённых контейнеров (SIG/VER/MEM/CODE0/LEN/RES — SPEC/13
п. 4).
Эталон: UpError с причиной.
Время: < 0,1 с.

### T-E7-04  Демо-круг «U-VM-OK 37»
Шаги: демо-программа (строка строится в RAM через const+stb; сумма
1..10 = 55; hex-цифры shr/and; печать 12 байт регистром консоли).
Эталон: консоль `U-VM-OK 37\r\n`, код 0, ловушка 0, **142 шага**
(счётчик закреплён — контракт детерминизма).
Время: < 0,1 с.

### T-E7-05  Ловушки 1-4
Шаги: 14 программ (сырые байты — заполнители mov/const/jmp и номера
регистров; ассемблерные — границы RAM/окна, выборка кода, цели jnz).
Эталон: код ловушки и число выполненных шагов до неё (незавершённая
инструкция шагом не считается — SPEC/12 п. 7).
Время: < 0,1 с.

### T-E7-06  Детерминизм
Шаги: демо исполняется дважды.
Эталон: консоль, код, шаги, ловушка, все 16 регистров и вся память
идентичны (R8).
Время: < 0,1 с.

### T-E7-07  Ops-программа
Шаги: mov/sub/or/xor/shl/shr/eq/jmp/stq/ldq; вычисление
((20-6)|1)^4 = 11, 11<<6 = 704, 704>>3 = 88; слово в RAM[100] и
обратно; jmp через мёртвый код.
Эталон: r3 = r15 = r6 = 88, r4 = 1 (eq), mem64[100] = 88, код 7,
**19 шагов**.
Время: < 0,1 с.

### T-E7-08  Окно устройств и границы
Шаги: (1) консоль = окно+0, окно+1 — запись игнорируется, чтение
окна = 0 (печать «AA», r3 = 0); (2) заворот адреса: r1 = -1,
ldb r2, r1+1 -> адрес 0; (3) memsize = 0: консоль по адресу 0,
ldq — ловушка 3; (4) вечный цикл с лимитом 100 шагов.
Эталон: консоли/регистры/ловушки по SPEC/12 п. 3.3, 6, 7; trap 6
(предел шагов — диагностический).
Время: < 0,1 с.

## Ядро kernel.exe (E7.2 — срезы 1-2 выполнены, сессии 45-46)

Секция 14 батареи `LAB/py/lab_t_kernel.py` (T-E7-09..15; сборка —
под эмуляцией инструментов ядра, ~61 млн шагов). Диффтест — контракт
SPEC/12 п. 10 / SPEC/13 п. 4: ядро == оракулу по консоли/коду
возврата; ловушки — по коду ловушки и счётчику шагов в диагностике.

### T-E7-09  Фикс-пункт артефактов
Шаги: сборка KERNEL/L3-UNIVM/kernel.wall конвейером (splice-оракул
-> wall.exe -> enc.exe -> brick.exe -> pegen.exe + kernel.peg, все
инструменты — эмуляция) обязана дать байт-в-байт артефакты
kernel.b2/brick/exe; kernel.b2 == оракулу WALL байт-в-байт.
Эталон: равенство всех трёх артефактов. Время: ~40 с.

### T-E7-10  CLI ядра
Шаги: без аргументов; лишний аргумент; путь 128 байт; несуществующий
файл. Эталон: справка (код 2), LONG NAME (3), OPEN UP (4).
Время: < 1 с.

### T-E7-11  Отказы контейнера
Шаги: 9 повреждённых .UP (короткий файл, подпись, версия, memsize
64 МиБ+1, memsize с ненулевым старшим dword, codesize 0, LEN-короткий,
LEN-длинный, резерв). Эталон: `U-L3-UNIVM ERR=<причина>`, код 6;
причины — как оракул parse_up (SPEC/13 п. 4). Время: < 1 с.

### T-E7-12  halt-программы — диффтест
Шаги: halt 0 / 37 / 4294967295 / halt 7 при memsize 4096.
Эталон: консоль пуста == оракулу, код возврата == imm32 (u32),
оракул: trap 0, 1 шаг. Время: < 1 с.

### T-E7-13  Ловушки 1/2 — диффтест диагностики
Шаги: опкод 0; опкод 19; halt с rd=1; усечённый halt (2 байта);
однобайтовый halt. Эталон: `U-L3-UNIVM TRAP=<n> STEPS=<s>` ==
оракулу (trap/steps; незавершённая инструкция шагом не считается),
код 1. Время: < 1 с.

### T-E7-14  Детерминизм
Шаги: halt 37 исполняется дважды. Эталон: вывод и код идентичны.
Время: < 1 с.

### T-E7-15  ALU среза 2 — диффтест
Шаги: 17 случаев против оракула (консоль/код возврата/TRAP+STEPS):
(1) поля-заполнители — const ra!=0, mov rb!=0, add rb=16, xor
rb=255 → ловушка 1, шаги 0; (2) обрезанные инструкции — const/add/mov
+ ЗАГЛУШКИ ldb/jmp/jnz (длина валидного опкода проверяется ДО
заглушки: ловушка 2, не 1); jmp rd!=0 и jnz rd=16 — ловушка 1;
(3) программы без halt (r0 равноправен; полный ALU-охват
((20-6)|1)^4<<6>>3 = 88; знаковые sext imm32 -1/-5/0xFFFFFFFF + lt/eq;
сдвиги с маской счётчика 63) → pc за кодом: TRAP=2 STEPS=<точное
число команд> — верифицирует декодирование, продвижение pc и
счётчик шагов; (4) ALU-программа с halt 7 — отсутствие ложных
ловушек (консоль пуста, код 7).
Эталон: ядро == оракулу на каждом случае (R8). Результаты ALU
напрямую не наблюдаемы до среза 3 (консоль-устройство) — значения
регистров станут видны через вывод. Время: < 5 с.

### Срезы 3-4 (план, корпус растёт с исполнением опкодов)

T-E7-16+ — память и устройства (срез 3: RAM GlobalAlloc+zero,
ldb/stb/ldq/stq с ловушками 3/4, окно+0 = консоль WriteFile байтом;
демо-подобные программы с консольным выводом — результаты ALU
станут наблюдаемы), переходы и полный корпус == T-E7-04..08
(срез 4 — приёмка DoD этапа; предел шагов 200 млн).
