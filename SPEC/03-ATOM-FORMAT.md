# S03. Формат ATOM v1

Паспорт файла: SPEC/03-ATOM-FORMAT.md | слой: L0 | роль: текстовый формат исходников слоя L0.

## Назначение

ATOM — человеко- и ИИ-читаемый исходник бинарного образа. Это мост между
«байтами, назначенными вручную» и будущим автоматическим инструментарием:
на этапе 3 (HEXGEN) программа прочтёт ATOM и материализует бинарник;
на этапе 5 BRICK заменит ручной подсчёт адресов, оставаясь надмножеством ATOM.

## Грамматика (v1)

```
файл     := строка*
строка   := пустая | комментарий | запись | директива
комментарий := ';' любой-текст
запись   := '@' смещение байт+ ';' пояснение
директива:= 'Z' от до
смещение := 4 шестнадцатеричные цифры (позиция в ФАЙЛЕ)
байт     := 2 шестнадцатеричные цифры
от, до   := 4 шестнадцатеричные цифры
```

Правила:

1. **Полное покрытие.** Каждый байт итогового файла покрыт ровно один раз:
   либо строкой `@` (явные байты), либо диапазоном `Z` (байты, равные 00).
   Диапазон `Z` полуоткрытый: `[от, до)`.
2. **Порядок строк** — по возрастанию смещений; диапазоны `Z` вставляются
   между записями там, где образ содержит нулевые байты.
3. **Пояснение обязательно** для строк кода: мнемоника, затем `;`,
   затем K-ID кирпича. Пример:
   `@0204 48 8D 1D F5 EF FF FF ; K0-S001 lea rbx,[rip-0x100B]`
4. Все числа шестнадцатеричные, заглавными цифрами (0-9A-F).
5. Кодировка файла — UTF-8, переводы строк — LF; CRLF допускается
   (эталонный разборчик hexgen игнорирует CR перед LF).
6. Образ с виртуальными нулями (bss): листинг покрывает только файловые
   байты; виртуальный хвост секции объявляется полем VirtualSize
   (см. SPEC/04-PE-MINIMAL.md, «Виртуальные нули»).
7. Эталонный разборчик формата — `KERNEL/L0-HEXGEN/hexgen.exe` (этап E3):
   строгая проверка грамматики, ЗАГЛАВНЫЕ цифры, коды ошибок 6/7.

## Пример (фрагмент семени)

```
; --- КОД (RVA 0x1000..) ---
@0200 48 83 EC 28                                  ; K0-X001 sub rsp,0x28
@0204 48 8D 1D F5 EF FF FF                         ; K0-S001 lea rbx,[rip-0x100B]
Z 020B 020C
@020C ...
```

## Что даёт формат

- **Проверяемость**: покрытие полным перебором байтов; повторная сборка
  байт-в-байт (хэш) доказывает идентичность.
- **Диффы**: изменение образа видно в diff текста.
- **ИИ-навигация**: каждая строка атомарна и адресуема по смещению.

## Зарезервировано на будущее (не использовать в v1)

- `!entry <rva>` — точка входа;
- `!imp <dll> <имя>` — объявление импорта;
- `!align <n>` — выравнивание.

С введением HEXGEN (этап 3) синтаксис расширяется с сохранением
обратной совместимости: старый ATOM всегда остаётся корректным.
