# S10. Формат SPLICE v1 (include-механизм и склейка исходников)

## Назначение

SPLICE решает две задачи слоя L1:

1. **Разрез исходников.** Методология требует ≤ 500 строк на файл; исходники
   больших модулей (enc.b2 — 2651 строка, brick.brick — 850) режутся на
   части, не превышающие лимита.
2. **Сборка корня.** Инструмент `splice.exe` (модуль M1-SPLICE) собирает
   «корневой» исходник со включениями в один плоский текст, который
   поступает в `enc` / `brick` — существующие инструменты не меняются.

```
корень.b2 ──splice──> плоско.b2 ──enc──> .brick ──brick──> тело ──pegen──> EXE
             (SPEC/10)            (SPEC/09)      (SPEC/08)        (SPEC/07)
```

`splice` — текстовый трансформатор верхнего уровня конвейера: он НЕ знает
форматов BRICK и работает с любым построчным текстом (в репозитории —
с `.b2` и `.brick`). Ответственность за смысл строк несут потребители.

## Формат вызова

```
splice.exe <корень.b2> <выход.плоско>
```

Оба аргумента обязательны. Выход создаётся заново (CREATE_ALWAYS).

## Директива включения

```
строка     := обычная-строка | директива
директива  := '!include ' путь        — ровно 9 байт префикса в КОЛОНКЕ 0
```

- Директива распознаётся ТОЛЬКО в начале строки (колонка 0); пробелы
  перед `!` не допускаются — такая строка проходит как обычная.
- `путь` — все байты строки после префикса (до конца строки, без
  обрезки хвостовых пробелов): латиница, цифры, `.`, `_`, `-`, `/`, `\`.
  Пустой путь — ошибка формата.
- Любая строка, начинающаяся с `!`, но не являющаяся корректной
  директивой, — ошибка формата. Префикс `!` в BRICK-исходниках не
  используется (грамматика SPEC/08/09 его не содержит).
- Пути в PEG-файлах (SPEC/07) тоже начинаются с `!` — их склейке не
  подвергают: splice предназначен для исходников тел секций.

## Разрешение имён

- Полное имя включаемого файла = **каталог файла, содержащего директиву,
  + путь**. Каталог — байты до последнего `/` или `\` включительно; у
  имени без разделителей каталог пуст. Пример: корень `L1-ENC\enc.b2`
  включает `enc_n.b2` → открывается `L1-ENC\enc_n.b2`.
- Вложенные включения разрешаются от каталога ВКЛЮЧАЮЩЕГО файла:
  `a/b/c.b2` включает `d.b2` → `a/b/d.b2`; тот включает `e.b2` →
  `a/b/e.b2`.
- Регистр имён не важен (семантика Windows; оракул LAB нормализует так
  же). Разделители `/` и `\` равнозначны.
- Полное имя ≤ 127 байт (как у всех инструментов L0/L1); аргументы
  командной строки — тоже ≤ 127 байт.
- Повторное включение того же файла — повторная вставка (это не ошибка;
  контроль циклов — пределом глубины).

## Строки и концы строк

- Терминаторы строк — LF, CRLF и одиночный CR (как у `enc`, SPEC/09);
  CRLF — один терминатор. Байт `00` — сентинел конца файла: всё после
  него игнорируется (вход — текст).
- Выход: каждая строка + ровно один LF; CR в выход не попадает никогда.
  Пустой корень → пустой выход (0 байт). Пустой включённый файл →
  ничего не вставляет.
- Файл без завершающего LF: последняя строка считается и получает LF.

## Пределы

| Предел | Значение | Код |
|---|---|---|
| Глубина вложенности | ≤ 8 уровней (корень + 7 включений) | 11 |
| Размер одного файла | < 0x20000 байт (128 КиБ, как filebuf) | 7 |
| Размер выхода | ≤ 0x20000 байт (предел потребителей) | 10 |
| Полное имя файла | ≤ 127 байт | 3 |
| Номер строки в ошибке | 16 бит (обрезка свыше FFFF, как у enc) | — |

Буферы уровней — виртуальные нули (DBZ): 8 × 0x20000 не занимают места
в файле. Включённый файл может быть любым (не обязан быть «частью»):
splice — универсальный склейщик текстов.

## Коды возврата и сообщения

| Код | Строка | Случай |
|---|---|---|
| 0 | (пусто) | успех |
| 2 | `U-L1-SPLICE CMDS: SPLICE <ROOT.SRC> <OUT.FLAT>` | меньше двух аргументов |
| 3 | `U-L1-SPLICE ERR=LONG NAME` | имя длиннее 127 байт |
| 4 | `U-L1-SPLICE ERR=OPEN SRC` | корень или включение не открыто |
| 5 | `U-L1-SPLICE ERR=READ SRC` | ошибка чтения |
| 6 | `U-L1-SPLICE ERR=FORMAT AT=XXXX` | плохая `!`-строка; XXXX — сквозной номер строки (hex, с 1, по порядку чтения всех файлов) |
| 7 | `U-L1-SPLICE ERR=BIG SRC` | файл ≥ 128 КиБ |
| 8 | `U-L1-SPLICE ERR=OPEN OUT` | выход не создан |
| 9 | `U-L1-SPLICE ERR=WRITE OUT` | ошибка записи |
| 10 | `U-L1-SPLICE ERR=BIG OUT` | выход > 128 КиБ |
| 11 | `U-L1-SPLICE ERR=DEPTH` | глубина включений > 7 |

Ошибки OPEN/READ/BIG SRC относятся и к корню, и к включениям (код
единый; какой именно файл не открылся — видно по набору кандидатов).

## Пример

```
; enc.b2 (корень модуля M1-ENC после разреза E6.3)
; UNIVERSAL / BRICK v2 / слой L1 / модуль M1-ENC ...
:entry
M sub rsp, 38                       ; K1-X011 кадр
... (поток X/C/G модуля)
!include enc_n.b2
!include enc_p1.b2
!include enc_p2.b2
!include enc_data.b2
```

Сборка (из папки KERNEL):
```
L1-SPLICE\splice.exe L1-ENC\enc.b2 t_flat.b2
L1-ENC\enc.exe t_flat.b2 t_v1.brick
L1-BRICK\brick.exe t_v1.brick t_body.bin
L0-PEGEN\pegen.exe t_body.bin L1-ENC\enc.peg t_enc.exe
fc /b t_enc.exe L1-ENC\enc.exe -> различий нет
```

## Критерий правильности разреза (DoD E6.3)

Склейка частей корня обязана воспроизводить исходный текст
байт-в-байт: тело, собираемое из разрезанного исходника, равно телу
до разреза (для enc — круг `splice -> enc -> brick -> pegen`
воспроизводит enc.exe; для brick — `splice -> brick` даёт тело, равное
`hexgen(brick.hex)`). Части содержат ТОЛЬКО строки оригинала — без
добавленных заголовков: любая добавленная строка изменила бы выход.

## Что SPLICE v1 НЕ делает (следующие этапы)

- Условные включения, поиск по спискам каталогов, переменные окружения;
- проверку уникальности включений (повтор = повторная вставка);
- чтение PEG/EXE-файлов (только построчный текст);
- вывод имён файлов в сообщениях об ошибках.
