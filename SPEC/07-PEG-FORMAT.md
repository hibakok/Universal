# S07. Формат PEG v1/v2 (управляющий файл обёртки)

Паспорт файла: SPEC/07-PEG-FORMAT.md | слой: L0 | роль: спецификация
PEGEN и PEG (v1 — образы семейства, шаблон SPEC/04; v2 — чужие образы
PE32+, E9.4-3c: заголовки/секции/импорты как патчи над нулями).

## Назначение

PEGEN — обёртка образов: превращает бинарное тело секции (выход HEXGEN)
в готовый EXE, генерируя PE-заголовки по шаблону `SPEC/04-PE-MINIMAL.md`.
С этапа E4 ручное сопровождение заголовков прекращается: листинг ATOM
покрывает только секцию (телесная форма, см. `SPEC/03-ATOM-FORMAT.md`),
а всё, что было в заголовках, задаётся директивами PEG-файла.

## Формат вызова

```
pegen.exe <image.bin> <ctrl.peg> <out.exe>
```

Все три аргумента обязательны. `image.bin` — тело секции (обычно выход
`hexgen.exe`); `ctrl.peg` — управляющий файл (настоящая спецификация);
`out.exe` — создаётся заново (CREATE_ALWAYS).

## Грамматика PEG v1

```
файл     := строка*
строка   := пустая | комментарий | директива
комментарий := ';' любой-текст
директива:= '!' имя [значение [значение]]
имя      := строчные латинские буквы (module, entry, idata, iat, bss,
            stackcom, heapcom)
значение := 1..8 ЗАГЛАВНЫХ шестнадцатеричных цифр (0-9A-F), 32 бита
```

Разделители значений — пробелы/табуляции. CR перед LF допускается.
Директивы можно записывать в любом порядке; повтор директивы — побеждает
последняя (не ошибка).

## Директивы

| Директива | Значения | Статус | Назначение |
|---|---|---|---|
| `!module <имя>` | имя 1..31 байт | обязательна | имя модуля для DOS-заглушки |
| `!entry <rva>` | 1 значение | обязательна | RVA точки входа (обычно 1000) |
| `!idata <rva> <размер>` | 2 значения | обязательна | каталог импорта DD[1] |
| `!iat <rva> <размер>` | 2 значения | обязательна | каталог IAT DD[12] |
| `!bss <n>` | 1 значение | опциональна | виртуальные нули в хвосте секции (по умолчанию 0) |
| `!stackcom <n>` | 1 значение | опциональна | фиксация стека (по умолчанию 1000) |
| `!heapcom <n>` | 1 значение | опциональна | фиксация кучи (по умолчанию 1000) |

Резерв стека/кучи фиксирован шаблоном (1 МиБ). Прочие поля заголовков
константны (см. «Патчи» ниже); их изменение — расширение PEG v2.

## Вычисляемые поля заголовка

Пусть `imgsize` — размер image.bin, `vsize = imgsize + bss`,
`align(x, a) = (x + a − 1) & ~(a − 1)`:

| Поле заголовка | Смещение | Значение |
|---|---|---|
| DOS-заглушка | 0x040 | «Universal L0 `<module>`. No DOS support.\r\n$», нули до 0x80 |
| SizeOfCode | 0x09C | `align(imgsize, 0x200)` |
| AddressOfEntryPoint | 0x0A8 | `!entry` |
| SizeOfImage | 0x0D0 | `align(vsize, 0x1000) + 0x1000` |
| фиксация стека | 0x0E8 | `!stackcom` (младшее слово, dword-запись) |
| фиксация кучи | 0x0F8 | `!heapcom` (младшее слово, dword-запись) |
| DD[1] Import | 0x110 | `!idata` (rva, размер) |
| DD[12] IAT | 0x168 | `!iat` (rva, размер) |
| VirtualSize | 0x190 | `vsize` |
| SizeOfRawData | 0x198 | `align(imgsize, 0x200)` |

Итоговый файл = 0x200 байт заголовков + image.bin + нули до
`0x200 + SizeOfRawData`. Размер файла = `0x200 + align(imgsize, 0x200)`.

## Ограничения v1

- image.bin ≤ 0x100000 байт (E9.5-1a — было 0x20000 с E6.4g-3
  и 0x10000 с E4; мотив роста: тела чужих EXE — синхронно плану
  E9.5-2 подъёма тела brick до 1 МиБ);
- ctrl.peg < 0x400000 байт (E9.5-1a — было 0x10000 с E4: текст PEG v2
  реальных EXE мегабайтный); имя файла ≤ 127 байт;
- имя модуля ≤ 31 байта (заглушка ≤ 0x40 байт сsuffix-ом);
- семантика значений не проверяется (ответственность .peg-файла —
  философия hexgen: строгий синтаксис, доверие данным).

## Коды возврата и сообщения

| Код | Строка | Случай |
|---|---|---|
| 0 | (пусто) | успех |
| 2 | `U-L0-PEGEN CMDS: PEGEN <IMAGE.BIN> <CTRL.PEG> <OUT.EXE>` | меньше трёх аргументов |
| 3 | `U-L0-PEGEN ERR=LONG NAME` | имя длиннее 127 байт |
| 4 | `U-L0-PEGEN ERR=OPEN IMAGE` | image.bin не открыт |
| 5 | `U-L0-PEGEN ERR=READ IMAGE` | ошибка чтения image.bin |
| 6 | `U-L0-PEGEN ERR=BIG IMAGE` | image.bin больше 128 КиБ (E6.4g-3; было 64 КиБ) |
| 7 | `U-L0-PEGEN ERR=OPEN PEG` | ctrl.peg не открыт |
| 8 | `U-L0-PEGEN ERR=READ PEG` | ошибка чтения/размер ctrl.peg |
| 9 | `U-L0-PEGEN ERR=FORMAT` | плохой формат PEG (в т.ч. нет обязательных директив) |
| 10 | `U-L0-PEGEN ERR=OPEN OUT` | out.exe не создан |
| 11 | `U-L0-PEGEN ERR=WRITE OUT` | ошибка записи out.exe |

## Пример (seed.peg модуля M0-SEED)

```
; UNIVERSAL / PEG v1 / слой L0 / модуль M0-SEED
!module seed
!entry 1000
!idata 1100 28
!iat 1130 20
```

Значения `!idata`/`!iat` берутся из раскладки секции модуля (RVA таблиц
импорта в его BYTECODE.md). Директивы `!bss`, `!stackcom`, `!heapcom`
опущены — действуют значения по умолчанию.

## Рост v2 (E9.4-3c): чужие образы PE32+

v1 строит заголовки из КОНСТАНТНОГО шаблона SPEC/04 — для чужих EXE
(другие e_lfanew/секции/DLL/поля) это невозможно. v2 меняет модель:
**файл = нули, поверх которых лежат ПАТЧИ** — область заголовков
(директива `!hdr`), тело секции кода (`!body` — обычный image.bin) и
сырые байты прочих секций (`!sec`). Заголовки НЕ интерпретируются
сборщиком (философия hexgen: строгий синтаксис, доверие данным) —
кроме САМООПИСАНИЯ: таблица секций читается из собранной области,
чтобы разместить тело и патчи секций.

### Грамматика v2

```
файл   := строка*
строка := пустая | комментарий | директива        (как в v1)
директива := '!pev2' H | '!hdr' off HEX | '!body' n | '!sec' n off HEX
```

- Первая директива файла — ОБЯЗАНА быть `!pev2 <H>` (маркер версии;
  файлы v1 его не содержат — v1-тексты не меняют поведения). Дальше
  порядок свободный; повтор `!pev2`/`!body` — ошибка.
- `H`, `off`, `n` — значения в стиле v1: 1..8 ЗАГЛАВНЫХ hex-цифр.
  `HEX` — блоб: чётное число ЗАГЛАВНЫХ hex-цифр, 1..64 байта
  (128 цифр) на строку.
- `H` — размер ОБЛАСТИ ЗАГОЛОВКОВ: байты файла [0, H) — DOS-заглушка,
  PE/COFF/опциональный заголовок, каталоги, таблица секций.
- `!hdr <off> <HEX>` — патч области заголовков: байты HEX по
  смещению `off` (off + длина <= H); патчи не пересекаются.
- `!body <n>` — секция `n` (номер слота, от 0) несёт ТЕЛО (image.bin):
  пишется с `PointerToRawData(n)`, добивается нулями до
  `SizeOfRawData(n)`. Ровно одна директива.
- `!sec <n> <off> <HEX>` — патч сырой области секции `n` по смещению
  `off` (от начала raw); НЕ допускается на секции `!body` (её не-
  нулевые байты — в теле; нули — добивка).

### Сборка (оракул `lab_pegen.wrap2`; ПОРТ в pegen.exe — срез E9.4-4b-4,
выполнен: ветвь v2 модуля M0-PEGEN, MAP/M0-PEGEN-V.md; развилка версий —
по первой директиве !pev2, v1-тексты неизменны)

1. Собрать область заголовков: нули длиной H + патчи `!hdr`.
2. Прочитать из неё самОописание: `MZ`; `e_lfanew` (0x3C);
   сигнатура `PE\0\0`; `NumberOfSections` (COFF+6); размер
   опционального заголовка (COFF+0x14); таблица секций — от
   `e_lfanew+4+0x14+SizeOfOptionalHeader`, целиком внутри H.
3. Сырые области: у секций с `SizeOfRawData > 0` требуют
   `PointerToRawData >= H` и НЕ пересекаются между собой.
4. Размер файла = max(H, концы сырых областей); всё не покрытое
   патчами/телом — нули.
5. Тело — в raw секции `!body` (SizeOfRawData >= len(image.bin));
   патчи `!sec` — в свои секции.

Отказы (ValueError, детерминированные): `!pev2` не первая / повтор
`!pev2`/`!body` / нет `!body` / нет `!` / неизвестная директива /
плохое значение или блоб / патч за границами своей области /
наложение патчей / H < 0x40 / нет MZ / нет PE-сигнатуры / таблица
секций вне H / `!body` за пределами таблицы / тело больше raw /
raw залезает в заголовки / наложение raw областей / `!sec` за
пределами таблицы / `!sec` на секции `!body` / `!sec` за границами
raw секции.

### Канон патчей (эмиссия мостом — E9.4-3c-2; ПОРТ в bridge.exe — E9.4-4b-3)

Мост сворачивает чужой образ в патчи (`emit_peg_v2` — факты
parse_foreign -> текст; ИНСТРУМЕНТ bridge.exe повторяет его байт-в-байт
срезом E9.4-4b-3 — ветвь G: peg2_check/gtpl_dec/fold_emit/emit_peg2,
SPEC/15 п. 10): `H` = минимум `PointerToRawData` секций
с raw; каждая raw-область обязана вмещаться в файл — иначе отказ
эмиссии (у инструмента — ДО спуска, ERR=FAMILY без частичных
выходов); пробег НЕнулевых байтов — один патч (пробеги с дыркой
< 4 нулей сливаются); патч длиннее 64 байт режется кусками по 64;
строки `!hdr` по возрастанию off, `!sec` — по возрастанию n, затем
off; слот `!body` — секция кода по точке входа. Свидетели: сборка —
T-E9-30 (секция 18g: якорные тексты чужих крафтов собираются
байт-в-байт), эмиссия == якорям + круг через ВЫХОД моста —
T-E9-31 (секция 18h; семья 12/12 через чужой путь); ПОРТ —
T-E9-29/T-E9-19 (t.peg инструмента == оракулу на крафтах и
перевёртышах).

### Ограничения v2

- image.bin <= SizeOfRawData секции `!body` (предел 128 КиБ v1
  снимается — рост при первом реальном чужом круге);
- H >= 0x40 (читаем e_lfanew) и H вмещает таблицу секций;
- NumberOfSections >= 1; слоты за H — отказ (не усечение).

### Ограничения v2 — инструмент (E9.4-4b-4; оракул пределов не имеет;
ПОДНЯТЫ — E9.5-1a, сессия 89)

- image.bin <= 1 МиБ (v1-предел E6.4g-3 128 КиБ поднят: тело чужой
  секции кода; синхронно плану E9.5-2 подъёма тела brick);
- ctrl.peg < 4 МиБ (v1-предел E4 64 КиБ поднят: текст PEG v2 реальных
  EXE мегабайтный — блобы ~2х байтов + строки директив);
- H <= 0x400000 и файл <= 0x400000 (outbuf; было 0x40000 — 256 КиБ);
- патчей !hdr <= 256 (spantab 0x800; было 64), записей !sec <= 16384
  (sectab 0x40000; было 128), сек-данных <= 0x100000 (secdata;
  16384 x 64 Б; было 0x2000), таблица raw <= 4096 записей (rawtab —
  БЕЗ ИЗМЕНЕНИЙ: реальные EXE < 100 секций) — пределы буферов bss;
  пересборка — LAB/ai/pegen_build_e95.py (ветвь v2 ПЕРЕИЗЛУЧЕНА из
  листинга pegen_v2_code.py: SPANMAX=256 требует imm32 — форма растёт
  4 -> 7 Б, адреса меток v2 пересчитаны; v1-слова пределов — 4 иммедиата
  диспетчера; rip-ссылки v1 на imagebuf/zeropad переточены ростом
  filebuf/imagebuf); ПЕРВЫЙ ЧУЖОЙ КРУГ (E9.4-4b-5) и границы bridge
  (образ < 256 КиБ — ERR=BIG EXE) и brick (тело > 128 КиБ — ERR=BIG OUT)
  — снятие остальных пределов — E9.5-1b (bridge)/E9.5-2 (brick);
- попарная проверка наложений !hdr/!sec — O(n^2) от числа записей
  (нативно — микросекунды; эмуляция 16К записей ≈ 800 млн шагов —
  граница 16384/16385 поведенчески не тестируется, форма инструкции
  покрыта спан-границей 256/257, рост — стресс-крафтом 1152 записи);
- порядок проверки отказов может отличаться от оракула (набор отказов
  идентичен — T-M5-18); отказ — БЕЗ частичных выходов.

### Дефекты, закрытые при подъёме пределов (E9.5-1a; найдены
стресс-крафтом и разбором эмиссии; все — в v2-ветви сессии 87,
корпус T-M5-18 их не покрывал)

1. hex_blob (K0-Q014): предел записи проверялся ДО чтения цифр пары —
   блоб, кончающийся РОВНО на пределе (outbuf+H / secdata+SECLEN),
   ложно отвергался (оракул принимает off+len <= H). Исправлено:
   предел — после чтения пары цифр (конец блоба видит следующая
   итерация).
2. do_hdr (K0-Q016): проверка наложений без сложений — сравнивались
   off с len_j и start_j с len (вместо off+len/end_j) — перекрытия на
   смещениях >= ~64 ПРОПУСКАЛИСЬ (оракул ловит; корпус — только
   низкие смещения). Исправлено: end_j = start_j+len_j и off+len —
   как в do_sec.
3. Мини-ассемблер pegen_v2_asm.py: mov_rip_i32/cmp_rip_i8 считали
   disp32 от КОНЦА ПОЛЯ disp, а не от КОНЦА ИНСТРУКЦИИ (+imm32/+imm8) —
   записи/чтения флагов уходили на +4/+1 мимо ячеек (взаимно
   компенсировались — поведение было верным — но любые новые ячейки
   или смена раскладки сломали бы код). Исправлено: база rip — конец
   инструкции.
