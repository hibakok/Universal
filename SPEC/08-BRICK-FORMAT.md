# S08. Формат BRICK v1 (символьные ссылки поверх байтов)

Паспорт файла: SPEC/08-BRICK-FORMAT.md | слой: L1 | роль: спецификация BRICK и поведение brick.

## Назначение

BRICK v1 — исходник тела секции с МЕТКАМИ и ИМЕНАМИ: смещения, rip-смещения
и длины переходов вычисляет ассемблер `KERNEL/L1-BRICK/brick.exe`, а не
человек. Кодировку байтов инструкций автор по-прежнему назначает явно
(реестр кодировок — `SPEC/05-X86-SUBSET.md`); BRICK v1 убирает ручной счёт
адресов — главную боль L0 (см. `SPEC/02-LAYER0-SPEC.md`, «Ограничения»).

`brick.exe <вход.brick> <выход.bin>`: выход — тело секции (RVA 0x1000 =
смещение 0), как у hexgen; обёртка в EXE — pegen (`SPEC/07-PEG-FORMAT.md`).

## Грамматика (v1)

```
файл     := строка*
строка   := пустая | комментарий | метка | строка-байтов | данные
комментарий := ';' любой-текст
метка     := ':' имя
строка-байтов := 'H' элемент+
элемент   := байт | ссылка
байт      := 2 ЗАГЛАВНЫЕ шестнадцатеричные цифры (0-9A-F)
ссылка    := '$' имя | '$' имя ':' '1'
данные    := ('DB' байт+) | ('DZ' число) | ('DBZ' число) |
             ('DD' значение+) | ('DQ' значение+)
значение  := число | ссылка-значение '$' имя
число     := 1..8 ЗАГЛАВНЫХ шестнадцатеричных цифр (0-9A-F)
имя       := 1..63 символа [a-z0-9_]
```

Разделители — пробелы/табуляции; CR перед LF допускается. Пояснение после
`;` обязательно для строк-байтов кода (мнемоника + K-ID — как в ATOM).

## Директивы

| Директива | Назначение |
|---|---|
| `:имя` | определить метку в текущем смещении (только пассаж 1) |
| `H <элементы...>` | материализовать байты; `$имя` — 4-байтовый слот, `$имя:1` — 1-байтовый |
| `DB <байты...>` | материализовать байты данных (ссылки недопустимы) |
| `DZ <число>` | число нулевых байт в файле (выравнивание/пробелы) |
| `DBZ <число>` | виртуальные нули (bss): курсор растёт, байты НЕ материализуются |
| `DD <значения...>` | по 4 байта LE на значение |
| `DQ <значения...>` | по 8 байт LE на значение |

`DBZ` отличается от `DZ`: `DZ` пишет нули в выходной файл, `DBZ` только
сдвигает виртуальный курсор (метки после него — адреса виртуальных нулей,
как ячейки и буферы bss в `!bss` обёртки PEG). Файловая длина результата
определяется последней файловой директивой до первого `DBZ`.

## Семантика ссылок

Пусть `L(имя)` — смещение метки (телесное, RVA = L + 0x1000), `E` —
смещение КОНЦА текущей строки (после всех её байтов и слотов).

1. **Слот `$имя` (4 байта):** значение = `L(имя) − E`, знаковое, LE.
   Это в точности disp32 rip-относительной адресации и rel32 переходов:
   `lea rbx,[rip+base]`, `call [rip+iat_x]`, `jmp`/`call rel32`.
2. **Слот `$имя:1` (1 байт):** значение = `L(имя) − E`, знаковое;
   ошибка, если не входит в −128..127 (rel8 переходов).
3. **Значение `$имя` в DD/DQ:** RVA метки = `L(имя) + 0x1000` (LE) —
   для таблиц, хранящих RVA (kwtab/errtab/IAT/IDT).
4. **Предопределённая метка `base`** = −0x1000 (RVA 0; адрес заголовков
   образа). Единственная, не требующая определения; определение `:base`
   или дубликат — ошибка формата. Слот `$base` даёт disp32 «назад к базе
   образа» (K1-S001). Реализация: кирпичи BRICK записывают её в таблицу
   меток до пассажа 1 (K1-G001).

Формулы п. 1–2 идентичны: адресация x86-64 считает и rip, и rel от конца
инструкции; строка-байтов BRICK соответствует одной инструкции (или их
упаковке — тогда автор сам отвечает за разбиение на строки).

## Два пассажа

- **Пассаж 1:** вычислить длины всех строк, определить метки, получить
  `outlen`. Значения ссылок не вычисляются.
- **Пассаж 2:** повторный разбор того же текста с материализацией байтов
  и вычислением ссылок; несоответствие итоговой длины `outlen` — внутренняя
  ошибка формата. Дубликат метки, неопределённая метка, выход rel8 за
  пределы байта — ошибка формата с номером строки.

Детерминизм: один вход — один выход (правило R8).

## Строгость разбора

- Принимаются: строки по грамматике выше; комментарии/пустые строки/CRLF;
  ЗАГЛАВНЫЕ hex-цифры; имена строчными [a-z0-9_].
- Отвергается (код 6, `ERR=FORMAT AT=<строка>`): посторонний символ;
  одиночная цифра байта; строчная hex-цифра; число длиннее 8 цифр или
  пустое; имя длиннее 63 символов или с посторонними символами; `$имя:1`
  с иным суффиксом; директива DB/DZ/DD/DQ с пустым списком; ссылка в DB;
  метка в пассаже 2 (дубликат); неопределённая метка; rel8 вне −128..127;
  неизвестная директива; мусор в хвосте строки.
- Не проверяется (ответственность исходника): достижимость меток,
  корректность кодировок инструкций, попадание RVA в секцию.

## Коды возврата и сообщения

| Код | Строка | Случай |
|---|---|---|
| 0 | (пусто) | успех |
| 2 | `U-L1-BRICK CMDS: BRICK <SRC.BRICK> <OUT.BIN>` | меньше двух аргументов |
| 3 | `U-L1-BRICK ERR=LONG NAME` | имя файла длиннее 127 байт |
| 4 | `U-L1-BRICK ERR=OPEN SRC` | исходник не открыт |
| 5 | `U-L1-BRICK ERR=READ SRC` | ошибка чтения исходника |
| 6 | `U-L1-BRICK ERR=FORMAT AT=XXXX` | ошибка формата; XXXX — номер строки (hex, с 1) |
| 7 | `U-L1-BRICK ERR=BIG SRC` | исходник больше 128 КиБ (предел filebuf) |
| 8 | `U-L1-BRICK ERR=OPEN OUT` | выход не создан |
| 9 | `U-L1-BRICK ERR=WRITE OUT` | ошибка записи выхода |
| 10 | `U-L1-BRICK ERR=BIG OUT` | тело больше 64 КиБ (предел imagebuf) |

## Ограничения v1

- Тело ≤ 64 КиБ (imagebuf; как у hexgen/pegen).
- Исходник ≤ 128 КиБ (filebuf 0x20000; больше, чем у hexgen — исходники
  со ссылками длиннее листингов).
- Меток ≤ 512 (labtab); имя ≤ 63 байт.
- Каждая строка-байтов — одна «инструкция» для целей ссылок: слот всегда
  считается от конца СТРОКИ. Слияние нескольких инструкций в одну строку
  с последним слотом допустимо; слот в середине упаковки автор обязан
  разнести по строкам (иначе смещение конца не совпадёт с концом
  инструкции).
- Числа — беззнаковые; отрицательные значения задаются дополнением
  (например, `FFFFFFF5` = −0xB как disp32).

## Пример (фрагмент)

```
; UNIVERSAL / BRICK v1 / модуль M1-BRICK
:entry
H 48 83 EC 38                       ; K1-X001 sub rsp,0x38
H 48 8D 1D $base                    ; K1-S001 lea rbx,[rip+base]
H 48 C7 C1 F5 FF FF FF              ; init mov rcx,-11
H FF 15 $iat_getstd                 ; init call [rip+iat_getstd]
...
:iat_getstd
DQ $hint_gsh                        ; RVA hint-записи GetStdHandle
...
:err1_str
DB 55 2D 4C 31 2D 42 52 49 43 4B    ; "U-L1-BRICK"
DZ 3
```

## Что BRICK v1 НЕ делает (следующие этапы)

- Мнемоники и кодировщик инструкций (автоматическая кодировка x86-64 —
  расширение BRICK v2 на базе реестра SPEC/05).
- Выражения над метками (`$имя+4`), выравнивания, макросы.
- Листинги ATOM остаются корректным входом hexgen (обратная
  совместимость: BRICK — надстройка, не замена).
