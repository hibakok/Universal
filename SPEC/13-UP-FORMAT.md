# S13. Формат .UP v1/v2 (контейнер программы UNIVM)

## 1. Назначение

`.UP` (UNIVERSAL Program) — файл внешней программы для UNIVM (SPEC/06:
проект — «программа на компьютере», ядро её только исполняет). Контейнер
несёт заголовок, код и (с v2) секцию данных; семантика кода — ISA
(SPEC/12). Файл читается целиком; программа не может изменить себя
(код и RAM — разные пространства, SPEC/12 п. 3.2).

```
program.up ──kernel.exe──> UNIVM: код → PC, memsize → RAM, исполнение
                    (v2: данные → RAM[0:datalen] при загрузке)
```

## 2. Заголовок (24 байта)

| Смещение | Размер | Поле | Значение |
|---|---|---|---|
| 0 | 4 | сигнатура | `55 50 30 31` — ASCII `UP01` (неизменна навсегда) |
| 4 | 4 | версия формата | u32 LE: v1 = 1, v2 = 2 (E7.4-1) |
| 8 | 8 | memsize | u64 LE — размер RAM в байтах |
| 16 | 4 | codesize | u32 LE — размер кода в байтах |
| 20 | 4 | dataoff | u32 LE: v1 — резерв 0 (обязательно); v2 — смещение данных (п. 2.1) |

Затем — код: ровно `codesize` байт (инструкции SPEC/12). Для v1 файл
обязан кончаться вместе с кодом; v2 может нести секцию данных за кодом.

### 2.1 Секция данных (v2, E7.4-1)

- `dataoff = 0` — данных нет: файл кончается кодом. Полный эквивалент
  v1 (файлы без данных собираются как v1 — байт-в-байт; «резерв v1 = 0
  совместим по построению»).
- `dataoff = 24 + codesize` — сразу за кодом следует секция данных до
  конца файла: `datalen = размер_файла − dataoff`, datalen >= 1; байты
  копируются в начало RAM: `RAM[0:datalen] := данные` (остальная RAM —
  нули, как v1). Инициализация выполняется при загрузке, до первой
  инструкции. Иное значение dataoff — отказ RES (мусор не молчит).
- Сторона ассемблера: директива `.data <байты>` — токены по 2
  hex-цифры, байты накапливаются по порядку появления (после `.mem`,
  в любом месте исходника, включая между инструкциями); несколько
  `.data` допустимы. Без `.data` выход ассемблера — v1.

## 3. Пределы

| Предел | Значение |
|---|---|
| memsize | 0 .. 67 108 864 (64 МиБ); memsize = 0 допустима — программа только на регистрах и устройствах |
| codesize | 1 .. 67 108 864 (64 МиБ) |
| datalen (v2, dataoff ≠ 0) | 1 .. memsize (данные длиннее RAM — отказ DATA) |
| размер файла | v1: ровно 24 + codesize; v2: 24 + codesize + datalen (при dataoff ≠ 0) |
| dataoff | v1: 0; v2: 0 или ровно 24 + codesize |

## 4. Разбор и отказы

Читатель (оракул `parse_up` в `LAB/py/lab_up.py`; ядро E7.2 — v1,
v2 — срез E7.4-2) отвергает файл при (порядок сверху вниз; v1-файлы
навсегда валидны — читатель принимает обе версии):

| Причина | Условие |
|---|---|
| `SIG` | файл короче 24 байт или сигнатура != `UP01` |
| `VER` | версия ∉ {1, 2} |
| `MEM` | memsize > 64 МиБ |
| `CODE0` | codesize = 0 |
| `LEN` | v1 и v2-dataoff=0: длина != 24+codesize (лишние/недостающие байты); v2-dataoff≠0: длина < 24+codesize (код обрезан) |
| `RES` | v1: поле ≠ 0; v2: dataoff ∉ {0, 24+codesize} или dataoff ≠ 0 при отсутствии байтов данных (длина = dataoff) |
| `DATA` | v2: datalen > memsize — инициализация не влезает в RAM |

До среза E7.4-2 ядро kernel.exe читает только v1 (v2-файл — отказ
`VER`); оракул уже читает v2. Ассемблер uva.exe принимает `.data`
срезом E7.4-3.

Коды возврата/сообщения ядра kernel.exe — контракт этапа E7.2
(единый стиль с инструментами L1/L2: `U-L3-UNIVM ERR=…`); оракул
поднимает исключение с теми же причинами.

### Контракт ядра kernel.exe (E7.2-1..4, замкнут)

| Ситуация | Вывод (stdout) | Код возврата |
|---|---|---|
| нет аргумента / третий аргумент / неверный предел шагов | `U-L3-UNIVM CMDS: KERNEL <FILE.UP> [STEPS]\r\n` | 2 |
| путь ≥ 128 байт | `U-L3-UNIVM ERR=LONG NAME\r\n` | 3 |
| файл не открыт | `U-L3-UNIVM ERR=OPEN UP\r\n` | 4 |
| отказ чтения / распределения кода | `U-L3-UNIVM ERR=READ UP\r\n` | 5 |
| отказ контейнера (причина — таблица выше) | `U-L3-UNIVM ERR=<причина>\r\n` | 6 |
| нормальный останов (halt) | консоль программы | imm32 (u32) |
| ловушка программы (SPEC/12 п. 7) | консоль программы + `U-L3-UNIVM TRAP=<n> STEPS=<s>\r\n` | 1 |

Консоль программы выводится до останова (SPEC/12 п. 6); s — счётчик
завершённых инструкций (незавершённая шагом не считается). Шаги
нормального останова ядром не печатаются — наблюдаемы только через
диагностику ловушек (диффтест — секция 14 батареи, T-E7-12/13).

Второй аргумент CLI (E7.2-4) — необязательный предел шагов `[STEPS]`:
десятичные цифры, значение 0..2147483647 (иное слово — справка,
код 2); умолчание 200 000 000. Достигнув предела, ядро печатает
`U-L3-UNIVM TRAP=6 STEPS=<N>` и выходит кодом 1 — как параметр
`max_steps` оракула (SPEC/12 п. 7; проверка ДО выборки инструкции).

## 5. Рост формата (правила версий)

- v2 (ВЫПОЛНЕНО — E7.4-1, срез 1 оракула): секция инициализации RAM —
  поле резерва стало смещением данных; старые v1-файлы остаются
  валидными (резерв v1 = 0 совместим по построению: dataoff = 0 —
  данных нет).
- Новые поля добавляются только с ростом версии; читатель, встретивший
  неизвестную версию, отвергает файл (`VER`) — молчаливое угадывание
  запрещено (принцип явности SPEC/12 п. 2).
- Сигнатура `UP01` неизменна навсегда — опознаватель формата.
- Программы .UP не содержат меток и имён: это атрибуты ассемблера
  (E7.3), в контейнер попадает только готовый код (и данные).

## 6. Примеры

Программа «печать A и останов» (v1; мини-ассемблер оракула):

```
.mem 4096
const r1, 4096      ; devbase: окно устройств
const r2, 65        ; 'A'
stb r1+0, r2        ; консоль += 'A'
halt 0
```

Контейнер: заголовок `55 50 30 31 | 01 00 00 00 | 00 10 00 00 00 00
00 00 | 19 00 00 00 | 00 00 00 00` + 25 байт кода (4 инструкции:
6+6+6+6, последняя — halt). Полный разбор демо-программы
«U-VM-OK 37» — TESTS/T-L3-UNIVM.md.

Программа v2 с секцией данных (T-E7-30, демо «U-DATA-OK 61»):

```
.mem 4096
.data 55 2D 44 41 54 41 2D 4F 4B 20 30 30 0D 0A
const r5, 97         ; код дописывает hex-цифры 0x61
...
halt 0
```

Контейнер: заголовок `55 50 30 31 | 02 00 00 00 | 00 10 00 00 00 00
00 00 | 7B 00 00 00 | 93 00 00 00` (codesize 123, dataoff =
24+codesize = 147) + 123 байта кода + 14 байт данных (строка
«U-DATA-OK 00\r\n» -> RAM[0:14] при загрузке).
