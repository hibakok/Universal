# S05. Подмножество x86-64 (используемое в L0)

Паспорт файла: SPEC/05-X86-SUBSET.md | слой: L0 | роль: реестр инструкций и кодировок.

## Принцип

В L0 используется минимальное проверенное подмножество инструкций x86-64.
Каждая инструкция внесена в этот реестр только после ручной проверки
кодировки и верификации дизассемблером. Новая инструкция = новая строка
реестра + пример использования.

## Соглашения записи

- `ib` — байт-непосредственный, `id` — двойное слово, `rel8` — знаковое
  смещение байта. Порядок байтов — little-endian.
- REX-префикс `48` = W (64-бит), `41` = B (расширение rm/base/r8),
  `4C` = W+R (расширение reg/r8+), `44` = R+B, `49` = W+B.
- modrm: `mod` (2 бита), `reg` (3), `rm` (3). rm=100 -> далее SIB;
  mod=00 & rm=101 -> rip-относительная адресация.

## Реестр инструкций (используются в семени)

| Мнемоника | Кодировка | Описание |
|---|---|---|
| `sub rsp, ib` | `48 83 EC ib` | вычесть из rsp знаковый байт |
| `lea r64, [rip+disp32]` | `48/4C 8D /r disp32` | адрес относительно конца инструкции |
| `mov eax, [rbx+ib]` | `8B 43 ib` | чтение 32 бит из [rbx+смещ] |
| `mov eax, [rbx+rax+ib]` | `8B 44 03 ib` | чтение 32 бит, SIB-адресация |
| `cdqe` | `48 98` | знаковое расширение eax -> rax |
| `add rsi, ib` | `48 83 C6 ib` | прибавить к rsi знаковый байт |
| `mov ecx, id` | `B9 id` | загрузить 32-бит константы (B8+rd) |
| `mov r8d, id` | `41 B8 id` | то же для r8d |
| `rol eax, ib` | `C1 C0 ib` | циклический сдвиг влево на 4 бита |
| `mov rdx, rax` | `48 89 C2` | пересылка регистр-регистр |
| `mov rcx, rax` | `48 89 C1` | пересылка регистр-регистр |
| `and edx, ib` | `83 E2 ib` | побитовое И (здесь: выделение тетрады) |
| `movzx rdx, byte [r8+rdx]` | `41 0F B6 14 10` | байт -> 64 бит с расширением нулём |
| `mov [rsi], dl` | `88 16` | запись младшего байта dl в память |
| `inc rsi` | `48 FF C6` | инкремент rsi |
| `dec ecx` | `FF C9` | декремент ecx (ставит ZF) |
| `jnz rel8` | `75 rel8` | переход, если ZF=0 |
| `mov rcx, id` | `48 C7 C1 id` | 64-бит константа (id знакорасширяется) |
| `call [rip+disp32]` | `FF 15 disp32` | косвенный вызов через IAT |
| `mov qword [rsp+ib], id` | `48 C7 44 24 ib id` | запись в тень стека (5-й аргумент) |
| `xor ecx, ecx` | `48 31 C9` | обнуление регистра |
| `int3` | `CC` | страховочная ловушка |

## Расширение E1 (введено в M0-SEED2)

Семейства записаны обобщённо: REX.R расширяет поле reg, REX.B —
rm/base, REX.X — индекс SIB. Формы с конкретными регистрами —
примеры; кодировка по тем же правилам.

| Мнемоника | Кодировка | Описание |
|---|---|---|
| `mov r64,r64` | `REX 89 /r` (mod11) | пересылка reg -> rm (ВНИМАНИЕ: reg — источник) |
| `add r64,r64` | `REX 01 /r` (mod11) | сложение rm <- reg |
| `xor r32,r32` | `31 /r` (mod11) | обнуление 32 бит (48 31 /r — 64 бит) |
| `test r/m,r` | `84 /r` (байт) / `REX 85 /r` (32/64) | AND без записи результата; ставит ZF |
| `cmp al,ib` | `3C ib` | сравнение байта с константой (ставит ZF) |
| `cmp r8,r8` | `38 /r` (mod11) | сравнение байтов (ставит ZF) |
| `mov r8,[r/m]` | `8A /r` | чтение байта в младшие 8 бит |
| `movzx r32,byte [r/m]` | `0F B6 /r` | байт -> 32 с нулём; формы `[rdi]`=07, `[r10]`=41 0F B6 12, `[r8+rdx]`=41 0F B6 14 10, `[r12+ib]`=41 0F B6 54 24 ib |
| `movzx r32,word [r+rdx]` | `0F B7 04 10` | слово -> 32 с нулём |
| `mov r32,[r12+ib]` | `41 8B 54 24 ib` | чтение dword из [r12+смещ] |
| `mov r11d,[r12+ib]` | `45 8B 5C 24 ib` | то же с REX.R |
| `mov r64,[rip+d]` | `48 8B 0D d` | чтение qword rip-относительно |
| `mov [rip+d],r64` | `48 89 05 d` | запись qword rip-относительно |
| `inc r/m` | `REX FF /0` | инкремент (48 FF C7 = rdi; 41-префикс для r8-r15) |
| `dec r/m` | `REX FF /1` | декремент (41 FF C9 = r9d) |
| `add r64,ib` | `REX 83 /0 ib` | прибавить байт (49 83 C0 10 = r8,16) |
| `add rsp,ib` | `48 83 C4 ib` | освобождение кадра |
| `mov r9d,id` | `41 B9 id` | константа в r9d (B8+rd с REX.B) |
| `jmp rel8/rel32` | `EB cb` / `E9 cd` | безусловный переход |
| `jz/je rel8` | `74 cb` | переход по ZF=1 |
| `jcc rel32` | `0F 8x cd` | дальний условный (84=JZ, 85=JNZ) |
| `call rel32` | `E8 cd` | прямой вызов подпрограммы |
| `ret` | `C3` | возврат (снимает адрес со стека) |

Направление операндов в `89 /r` и `01 /r` — источник reg, приёмник rm.
Ошибка этого направления в `mov rax,r8` была реально допущена и поймана
эмуляцией на этапе E1 (журнал — KERNEL/L0-SEED2/VERIFY.md): правило —
кодировка каждого пересцепленного переноса сверяется дизассемблером.


## Расширение E2 (введено в M0-HXDUMP)

Семейства записаны обобщённо, как в расширении E1. Формы без REX —
32-битные операнды; REX-префиксы расширяют поля reg/rm как обычно.

| Мнемоника | Кодировка | Описание |
|---|---|---|
| `mov r8,ib` | `B0+r ib` | байт-непосредственный в 8-битный регистр (B0 20 = al,0x20) |
| `rol r8,ib` | `C0 /0 ib` | 8-битная циклическая ротация (C0 C0 04 = rol al,4) |
| `cmp r64/r32,ib` | `REX 83 /7 ib` | сравнение со знаковым байтом (48 83 F8 FF = rax,−1; 41 83 FE 10 = r14d,16) |
| `sub r64,r64` | `REX 29 /r` (mod11) | вычитание rm ← rm − reg (4D 29 EE = sub r14,r13; 48 29 D0 = sub rax,rdx) |
| `cmp r64,r64` | `REX 39 /r` (mod11) | сравнение reg с rm (48 39 FE = cmp rsi,rdi) |
| `shl r32,ib` | `C1 /4 ib` | сдвиг влево (41 C1 E0 02 = shl r8d,2) |
| `jb rel8` | `72 cb` | переход, если CF=1 (ниже) |
| `jae rel8` | `73 cb` | переход, если CF=0 (выше или равно) |
| `jbe rel8` | `76 cb` | переход, если CF=1 или ZF=1 (не выше) |

Новые конкретные формы существующих семейств (примеры из M0-HXDUMP):

- `mov r32,r32` без REX: `89 C2` = mov edx,eax; `89 C1` = mov ecx,eax.
- `mov r/m8,r8` с REX.B: `41 88 12` = mov [r10],dl; `41 88 02` = mov [r10],al.
- `mov r8,[r/m]`: `8A 16` = mov dl,[rsi]; `movzx r32,r8`: `0F B6 C2` = movzx eax,dl.
- `movzx r32,byte [r8+r11]` = `43 0F B6 14 03` (REX.X+B: индекс r11, база r8).
- `mov r32,[rip+d]` = `8B 05 d` (mov eax,[rip+nread]); чтение dword.
- `mov qword [rsp+ib],id`: disp8 расширен до 0x28/0x30 — аргументы 6/7
  CreateFileA (`48 C7 44 24 28 80 00 00 00`).
- `and r32,ib`: `41 83 E3 0F` = and r11d,0xF (обобщение `and edx,ib`).

Уроки E2 (каждая ошибка поймана эмуляцией, журнал —
KERNEL/L0-HXDUMP/VERIFY.md): поле rm modrm для r12–r15 требует REX.B и
кодов 100–111 (не 000–011!); 8-битная тетрада выделяется `rol al,4`,
а не `rol eax,4` (32-битная ротация уносит тетраду в биты 11..8).

## Важные семантические правила

1. **32-битные записи обнуляют старшие 32 бита регистра** (например,
   `rol eax,4` очищает биты 63..32 rax).
2. **rip-относительная адресация**: эффективный адрес = rip ПОСЛЕ всей
   инструкции + disp32. Формула смещения:
   `disp32 = RVA(цели) − RVA(конца инструкции)`.
3. **call [rip+disp32]** читает адрес функции из ячейки IAT и кладёт
   адрес возврата в стек; выравнивание rsp на 16 в точке вызова.
4. `dec/inc` меняют ZF; `rol` ZF не меняет.
5. Порядок байтов little-endian: 32-битное значение 0xFFFFEFF5
   записывается как `F5 EF FF FF`.

## Вызов Win64 (конвенция Microsoft x64)

- Аргументы 1–4: rcx, rdx, r8, r9; 5-й и далее: [rsp+0x20], [rsp+0x28]...
- Перед `call` rsp должен быть кратен 16 (после push адреса возврата
  внутри вызываемой функции rsp%16==8).
- Результат — в rax.
- Вызываемые функции вправе испортить rcx, rdx, r8, r9, rax, r10, r11 —
  сохранять нужное должен вызывающий.
