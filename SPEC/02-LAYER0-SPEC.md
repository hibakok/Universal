# S02. Спецификация слоя L0 (МАШИНА)

Паспорт файла: SPEC/02-LAYER0-SPEC.md | слой: L0 | роль: правила ручного машинного кода.

## Что такое L0

Слой L0 — это исполняемые артефакты, написанные **вручную** байтами
машинного кода x86-64 в формате PE32+ (Windows x64). До этапа 3 (HEXGEN)
никаких инструментов сборки не существует: байты назначаются человеком/ИИ
напрямую в листинге ATOM и материализуются в файл.

## Правила слоя

1. **Источник истины — листинг ATOM** (`seed.hex`). Каждый байт образа
   либо явно назначен строкой `@`, либо покрыт диапазоном нулей `Z`.
2. **Каждая строка кода комментируется**: мнемоника + кирпич (K-ID).
3. **Документирование обязательно**: `BYTECODE.md` содержит байт-за-байтом
   разбор всего образа (правило R10).
4. **Позиционная независимость**: адресация только rip-относительная
   (lea/call [rip+disp]) или регистровая; абсолютных адресов в коде нет.
   Образ работает при любой базе загрузки.
5. **Поток управления**: вход — точка входа PE; выход — только через
   `ExitProcess` (после неё — страховочный `int3`).
6. **Соглашения вызовов Win64**: аргументы rcx/rdx/r8/r9; 5-й аргумент —
   [rsp+0x20]; перед вызовом rsp выровнен по 16; тень 0x20 резервируется.
7. **Импорты** — только из kernel32.dll, перечислены в IDT/IAT (см.
   `SPEC/04-PE-MINIMAL.md`). Расширение набора импортов = новая карточка
   ветви I (импорты) и обновление `SPEC/05-X86-SUBSET.md` не требуется
   (это не инструкция), но BYTECODE — обязательно.
8. **Регистровые соглашения проекта**: `rbx` — база образа; `rsi` — курсор
   записи; `rax/rcx/rdx/r8/r9` — передача данных и вызовы.

## Верификация L0 (обязательная, три уровня)

1. **Разбор PE**: все поля заголовков сверяются со спецификацией
   (значения — в `SPEC/04-PE-MINIMAL.md`).
2. **Дизассемблирование**: последовательность мнемоник и цели всех
   rip-смещений сверяются с замыслом.
3. **Эмуляция**: образ загружается в эмулятор x86-64 (заголовки + секция,
   IAT заполняется адресами-заглушками), исполняется от точки входа;
   вывод и код возврата сравниваются с ожидаемыми.

Все три уровня должны быть зелёными до фиксации изменения.

## Ограничения этапа

- Смещения rip-относительных ссылок вычисляются вручную (это главная
  боль L0). Методика: адрес_цели − адрес_конца_инструкции; для lea rbx
  в семени: 0 − 0x100B = −0x100B = 0xFFFFEFF5 = байты `F5 EF FF FF`.
  Будьте внимательны с порядком байтов little-endian.
- Изменение длины любой инструкции до последней сдвигает все смещения —
  пересчитать всё заново (список смещений — в BYTECODE.md, раздел «Код»).
- Секция одна; содержимое растёт с задачей (M0-HXDUMP — 0xA0A байт).
  При изменении — пересборка заголовков по инвариантам SPEC/04 и
  пересчёт всех RVA (инструментально — с этапа E3/HEXGEN).
