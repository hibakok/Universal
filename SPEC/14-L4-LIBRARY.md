# S14. Библиотека L4 (переиспользуемые кирпичи для UNIVM-программ)

## 1. Назначение

**Библиотека L4** — набор переиспользуемых кирпичей для программ UNIVM
(SPEC/06: слой L4 над L3). Кирпич библиотеки — функция на ассемблере
`.uva` (мнемоники SPEC/12 п. 8): у неё есть имя-метка, контракт
вход/выход/функция (карточка — `MAP/M4-LIB.md`) и реализация,
исполняемая ядром `kernel.exe` как часть программы-потребителя.

Ключевые свойства (манифест DOCS/00):

- **Переиспользуемость:** кирпич используется любыми программами без
  дублирования (правило R6); один и тот же кирпич — во многих проектах.
- **Ядро библиотеку НЕ знает** (правило R7): ядро kernel.exe исполняет
  байты; библиотека не «вживлена» в ядро и не меняет его.
- **Составной кирпич из простых:** сложные кирпичи (print_u64) строятся
  из простых (u64_to_dec_rev + buf_out_rev), как ветви кода L0.

Ответственность за распределение: реализация (инструмент — этап E8.2)
обязана повторять семантику оракула `LAB/py/lab_l4.py` (п. 6) по
наблюдаемому поведению (консоль, RAM, регистры) — как ядро повторяет
оракул UNIVM (SPEC/12 п. 10).

## 2. Композиция: программа + библиотека

Программа-потребитель собирается из текстов ДО ассемблирования:

```
demo.uva (!include ../../KERNEL/L4-LIB/lib_n.uva ...)
  ──splice.exe (SPEC/10)──> demo.flat.uva
  ──uva.exe (SPEC/12 п. 8)──> demo.UP ──kernel.exe──> исполнение
```

1. **Части библиотеки** — файлы `.uva` в `KERNEL/L4-LIB/` (модуль
   M4-LIB; состав файлов и карточка модуля — `CARD.md`, MAP/M4-LIB.md).
   Часть = фрагмент ассемблерного текста: только инструкции, метки и
   комментарии. Часть НЕ содержит `.mem`/`.data` — контейнер (memsize,
   данные) полностью принадлежит программе-потребителю.
2. **Включение** — директива `!include <путь>` (SPEC/10, колонка 0);
   склейщик `splice.exe` — текстовый трансформатор верхнего уровня, он
   не знает формата .uva и работает с любым построчным текстом
   (прецедент E6.3: склейщик НЕ встроен в ассемблер — инструменты
   не меняются). Разрешение пути — от каталога включающего файла
   (SPEC/10 п. «Разрешение имён»); программа в `PROJECTS/<имя>/`
   включает части как `../../KERNEL/L4-LIB/<часть>.uva`. Положение
   директив — ПОСЛЕ кода программы (после `halt`): исполнение
   начинается со смещения 0 (SPEC/12 п. 3), поэтому на смещении 0
   обязан стоять вход программы, а кирпичи вызываются по меткам;
   кроме того, `.mem` обязана предшествовать первой инструкции
   плоского текста (SPEC/12 п. 8) — а части `.mem` не содержат
   (уточнение E8.2a; рецепт целиком — KERNEL/L4-LIB/CARD.md).
3. **Пространство имён меток** общее в склеенном тексте: метки
   библиотечных кирпичей имеют зарезервированный префикс `lib_`
   (`lib_print_u64`, ...); метки программы НЕ начинаются с `lib_`
   (коллизия меток = ошибка ассемблера, как всегда в uva).
4. **.mem/.data остаются за программой:** memsize выбирает программа
   (библиотечным кирпичам достаточно RAM программы; консольные кирпичи
   требуют r14 = memsize — п. 3).

Адресация строк программы в секции данных (.data → RAM[0:...]):
смещения отсчитывает автор программы (метки на данных — вопрос роста
ассемблера uva, вне ABI библиотеки; см. п. 7).

## 3. ABI — конвенция вызова (стабильна навсегда)

Единая конвенция всех кирпичей L4 (как форматы F0..F3 для ISA — R5):

| Регистр | Роль |
|---|---|
| `r1` | аргумент 1; он же — результат |
| `r2`, `r3`, `r4` | аргументы 2..4 (по порядку карточки) |
| `r1..r4` | **временные**: вызываемый вправе затереть; вызывающий не надеется |
| `r5..r12` | **сохраняемые**: вызываемый обязан вернуть неизменными |
| `r13` | `sp` — программный стек (SPEC/12 п. 3.4); вызываемый сохраняет |
| `r14` | `devbase` — база окна устройств: программа ОБЯЗАНА установить `const r14, <memsize>` до первого консольного кирпича; вызываемый сохраняет |
| `r15` | резерв (сохраняемый); занят будущими глобальными конвенциями L4 |

- **Вызов:** `call lib_<имя>`; **возврат:** `ret` (стек вызовов UNIVM,
  глубина ≤ 1024). Кирпичи LIB-1 нерекурсивны.
- **Аргументы ≤ 4.** Кирпичам LIB-1 этого достаточно; будущим кирпичам
  с большим числом аргументов — блок RAM по указателю (рост — п. 7).
- **Буферы выделяет вызывающий** (в своей RAM): например, буфер цифр
  u64 — минимум 20 байт.
- **Проверок аргументов НЕТ** — их делает машина: обращение вне RAM =
  ловушка 3/4 UNIVM (SPEC/12 п. 7), не «молчаливое угадывание»
  (принцип явности). Сбой программы не роняет ядро (SPEC/06).

## 4. Слой LIB-1: числа и строки (реестр)

Ветви: **C** — консоль (байты потока), **N** — числа (десятичная
запись), **S** — строки (байты до NUL), **M** — память (блочные
операции). Карточки — `MAP/M4-LIB.md`; реализации — части
`KERNEL/L4-LIB/lib_<ветвь>.uva` (срезы E8.2+).

Семантика (v = значение регистра, приведённое к u64):

| ID | Имя (метка) | Вход | Выход | Функция |
|---|---|---|---|---|
| K4-C001 | chr_out (`lib_chr_out`) | r1 = байт | консоль += v AND 255 | Печатает один байт в консоль |
| K4-C002 | crlf_out (`lib_crlf_out`) | — | консоль += 0D 0A | Печатает перевод строки (CRLF) |
| K4-C003 | buf_out (`lib_buf_out`) | r1 = addr, r2 = len | консоль += RAM[addr..addr+len) | Печатает len байт буфера в прямом порядке |
| K4-C004 | buf_out_rev (`lib_buf_out_rev`) | r1 = addr, r2 = len | консоль += RAM[addr+len-1], ..., RAM[addr] | Печатает буфер в обратном порядке |
| K4-N001 | u64_to_dec_rev (`lib_u64_to_dec_rev`) | r1 = значение, r2 = addr (буфер ≥ 20 Б) | r1 = len ≥ 1; RAM[addr..addr+len) = ASCII-цифры | Превращает u64 в десятичные цифры; addr[0] = цифра единиц (младшая), addr[len-1] = старшая; 0 → len=1, буфер = "0" |
| K4-N002 | print_u64 (`lib_print_u64`) | r1 = значение, r2 = addr (буфер ≥ 20 Б) | консоль += десятичная запись (старшая слева) | Печатает u64 без знака; состоит из K4-N001 + K4-C004 |
| K4-N003 | print_i64 (`lib_print_i64`) | r1 = значение (дополнение до двух), r2 = addr (буфер ≥ 20 Б) | консоль += знаковая запись | Печатает i64: при v ≥ 2^63 — "-" и цифры 2^64−v, иначе цифры v; состоит из K4-C001 + K4-N001 + K4-C004 |
| K4-S001 | str_len (`lib_str_len`) | r1 = addr | r1 = длина | Считает байты до первого 0 (не включая его) |
| K4-S002 | str_out (`lib_str_out`) | r1 = addr | консоль += байты до первого 0 | Печатает строку байтов, ограниченную нулём |
| K4-M001 | mem_copy (`lib_mem_copy`) | r1 = dst, r2 = src, r3 = n | RAM[dst+i] := RAM[src+i], i = 0..n−1 | Копирует n байт по возрастанию адресов (формула задаёт поведение при перекрытии: источник читается байт-за-байтом до записи в ту же ячейку) |
| K4-M002 | mem_fill (`lib_mem_fill`) | r1 = dst, r2 = байт, r3 = n | RAM[dst..dst+n) := v(r2) AND 255 | Заполняет n байт значением |

Правила чтения таблицы:

- «консоль +=» — байты дописываются в выходной поток (окно устройств,
  смещение 0; SPEC/12 п. 6). Печатающие кирпичи требуют r14 = memsize.
- n = 0 у блочных кирпичей — нет эффекта (цикл не выполняется).
- Адреса вне [0, memsize) — ловушка 3/4 UNIVM при первом же
  обращении (п. 3); частичное выполнение до ловушки видимо в RAM —
  детерминировано формулой.

## 5. Пример: программа с библиотекой (DoD этапа 8)

```
.mem 4096
.data 55 2D 4C 34 2D 4F 4B 20 00      ; "U-L4-OK " → RAM[0..8)
const r14, 4096                        ; devbase (ABI п. 3)
const r1, 0                            ; число
const r2, 100                          ; буфер цифр: RAM[100..120)
call lib_print_u64                     ; консоль: "0"
const r1, 0
call lib_str_out                       ; консоль: "U-L4-OK "
call lib_crlf_out                      ; консоль: CRLF
halt 0
```

Склейка/сборка/запуск: `splice demo.uva flat.uva` → `uva flat.uva
demo.up` → `kernel.exe demo.up`; вывод: `0U-L4-OK <CRLF>`.
(Рабочие демо-программы этапа — KERNEL/L4-LIB/, начиная с E8.2.)

## 6. Оракул

`LAB/py/lab_l4.py` — эталонная семантика каждого кирпича LIB-1
(два независимых свидетеля, как lab_vm для ISA):

- `chr_out/ crlf_out/ buf_out/ buf_out_rev/ u64_to_dec_rev/
  print_u64/ print_i64/ str_len/ str_out` — консоль-эффект (и буфер
  цифр у u64_to_dec_rev) как `bytes`;
- `mem_copy/ mem_fill` — эффект RAM по формуле п. 4.

Якоря (третий свидетель, вручную): `LAB/py/lab_l4_cases.py` —
десятичные записи краёв u64/i64, реверс-цифры, строки до NUL,
эффекты памяти с перекрытием. Батарея (секция 16, T-E8-01..07,
`LAB/py/lab_t_l4.py`) проверяет оракул против якорей. Реализация
(E8.2+) подключается к тем же якорям диффтестом: .uva-программа
вызывает кирпичи → uva.exe → kernel.exe (двойной прогон — оракул
UNIVM lab_vm) → консоль/RAM обязаны совпасть с оракулом библиотеки.

## 7. Рост библиотеки

- **Новые кирпичи** — новые ID `K4-<ветвь><номер>` (R5: вечны,
  не переиспользуются); карточка — ДО кода (R3), в MAP/M4-LIB.md.
- **ABI стабилен навсегда** (как кодировка ISA, SPEC/12 п. 9):
  изменение семантики выданного кирпича запрещено; рост — только
  новые кирпичи и новые ветви.
- **Слои LIB:** LIB-1 (этот файл, п. 4) — числа/строки/память;
  LIB-2 — окна/растр/ввод (свои таблицы при старте слоя); далее —
  математика (fixed-point для проектов), структуры данных. Кандидаты
  роста LIB-1: hex-печать, u64→hex, сравнение строк, reverse, поиск
  байта.
- **Аргументы > 4** — блок параметров в RAM по указателю в r2/r3
  (решение при первом таком кирпиче; ABI п. 3 не меняется).
- **Композиция и метки данных** — по мере роста: метки на секции
  данных в ассемблере uva (адресация строк .data) — отдельное решение
  этапа, вне этого SPEC, пока программы считают смещения вручную.
