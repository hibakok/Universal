# S12. UNIVM ISA (виртуальный процессор: v0 + v1)

## 1. Назначение

**UNIVM** — собственная виртуальная машина слоя L3 (SPEC/06): виртуальный
процессор, исполняющий внешние программы `.UP` (SPEC/13). ISA спроектирован
заново — это не копия x86. v0 — минимальный набор из 18 инструкций
(01..12), достаточный для любых вычислений; v1 (E7.4-1, срез 1 оракула)
добавляет 6 инструкций (13..18): умножение/деление/остаток, знаковый
сдвиг, вызовы и стек (п. 3.4, 5).

Ответственность за распределение: интерпретатор (ядро `kernel.exe`,
модуль M3-UNIVM, этап E7.2; v1 — срез E7.4-2) обязан повторять семантику
оракула `LAB/py/lab_vm.py` (п. 10) байт-в-байт по наблюдаемому поведению.

## 2. Принципы

1. **Явность.** Нет регистра флагов, нет неявных регистров (SP/LR),
   нет скрытых побочных эффектов: результат каждой инструкции виден
   в регистрах/памяти/консоли. Регистры равноправны — r0 не спец.
   Единственное состояние помимо регистров/RAM/консоли — состояние
   УПРАВЛЕНИЯ: pc и стек вызовов (v1, п. 3.4), как адреса, а не данные.
2. **Безопасность.** Всякое обращение к памяти проверяется; программа
   не может выйти за свой код/RAM/окно устройств — нарушение = ловушка,
   а не порча хозяина (SPEC/06: сбой проекта не роняет ядро).
3. **Кирпичность.** Каждая инструкция — кирпич: одна функция, описывается
   одной строкой семантики. Сложные операции собираются из простых.
4. **Детерминизм (R8).** Один вход — один выход: регистры, память,
   консоль, счётчик шагов полностью определяются программой.
5. **Малый порядок байт** (LE) — во всей кодировке, как весь проект.

## 3. Модель

### 3.1 Регистры

- 16 регистров общего назначения `r0..r15`, каждый 64 бита.
- Запись — всегда полные 64 бита; чтение — 64-битное значение.
- Значения трактуются как беззнаковые (0..2^64-1); знаковая интерпретация
  (дополнение до двух) применяется только операциями `lt`, `ldb` и `sra`
  (п. 5). Никакой регистр не имеет скрытой роли.

### 3.2 Пространства

Три независимых пространства — программа не может изменить свой код:

| Пространство | Диапазон | Доступ |
|---|---|---|
| **Код** | байты 0..codesize-1 | только чтение исполнителем (PC) |
| **RAM** | байты 0..memsize-1 | чтение/запись программой; старт — нули (v2 .UP: секция данных — SPEC/13 п. 2.1) |
| **Окно устройств** | байты 0..4095 за RAM | регистры устройств (п. 6) |

- `memsize` и `codesize` задаёт заголовок .UP (SPEC/13).
- **PC** — беззнаковый байтовый оффсет в коде; старт = 0.
- Адрес устройства = `memsize + смещение_в_окне` (адресация сквозная).

### 3.3 Адресация памяти

Адрес = `(rbазовый_регистр + знаковое_смещение) mod 2^64` — обычное
64-битное сложение с заворотом; результат трактуется как беззнаковый.
Допустимые диапазоны (иначе ловушка, п. 7):

| Операция | Допустимый адрес |
|---|---|
| байт (`ldb`/`stb`) | [0, memsize+4096) — RAM или окно |
| слово (`ldq`/`stq`) | [0, memsize) и целиком: addr+8 <= memsize (только RAM) |

Слово — 8 байт LE по любому адресу (выравнивание не требуется).

### 3.4 Стек вызовов и стековая конвенция (v1)

**Стек вызовов** — часть машины, состояние управления (как PC, не
данные программы): глубина 1024 записи, элемент — адрес возврата.
`call` заносит pc+6 и переходит; `ret` извлекает адрес и переходит.
Переполнение (`call` при глубине 1024) и пустота (`ret` при пустом
стеке) — ловушка 5. Программа не может читать/писать стек вызовов:
ошибка в данных не искажает адреса возврата (безопасность SPEC/06).
Рекурсия глубже 1024 — программным стеком:

**Программный стек — конвенция, не ISA.** Локальные данные и сохранение
регистров — в RAM программы через регистр-указатель ПО СОГЛАШЕНИЮ:
`sp = r13` (в корпусах v0 не занят; выбор v1), растёт вниз. push —
`const rN, 8; sub r13, r13, rN; stq r13+0, rX`; pop —
`ldq rX, r13+0; add r13, r13, rN`. ISA НЕ проверяет соглашение (r13 —
обычный регистр); конвенция обязательна для кирпичей L4 (этап 8).

## 4. Кодировка

Четыре формата фиксированной длины; первый байт — всегда опкод:

```
F0 (1 байт):  [op]                        — ret (v1; полей нет)
F1 (3 байта):  [op] [rd:ra] [rb]        — регистровые операции
F2 (6 байт):  [op] [rd:ra] [imm32 LE]   — константа и память
F3 (6 байта):  [op] [rd]     [imm32 LE]  — переходы, вызов и останов
```

- `rd:ra` — один байт: старшая тетрада `rd`, младшая `ra`
  (запись `rd*16 + ra`; в hex-дампе читается по порядку операндов).
- `rb` — один байт: номер регистра.
- `imm32` — 4 байта LE; для F2 знаковое (расширяется до 64 бит),
  для F3 беззнаковое.
- **Заполнители.** Поля, не несущие операнда в данном опкоде
  (`rb` у `mov`, `ra` у `const`, `rd` у `jmp`/`halt`/`call`), обязаны
  быть 0; ненулевой заполнитель — ловушка 1 (строгость: мусор не
  молчит). `ret` (F0) полей не имеет — проверять нечего.

## 5. Реестр инструкций (v0: 01..12; v1: 13..18)

| Оп | Имя | Ф | Семантика |
|---|---|---|---|
| 01 | `const` | F2 | `rd := sext(imm32)` |
| 02 | `mov` | F1 | `rd := ra` (rb = 0) |
| 03 | `add` | F1 | `rd := (ra + rb) mod 2^64` |
| 04 | `sub` | F1 | `rd := (ra - rb) mod 2^64` |
| 05 | `and` | F1 | `rd := ra AND rb` |
| 06 | `or`  | F1 | `rd := ra OR rb` |
| 07 | `xor` | F1 | `rd := ra XOR rb` |
| 08 | `shl` | F1 | `rd := (ra << (rb AND 63)) mod 2^64` |
| 09 | `shr` | F1 | `rd := ra >> (rb AND 63)` — логический |
| 0A | `lt`  | F1 | `rd := 1, если ra < rb (знаково), иначе 0` |
| 0B | `eq`  | F1 | `rd := 1, если ra = rb, иначе 0` |
| 0C | `ldb` | F2 | `rd := sext8(байт по адресу ra+imm32)` |
| 0D | `stb` | F2 | `байт по адресу rd+imm32 := ra AND 255` |
| 0E | `ldq` | F2 | `rd := слово LE по адресу ra+imm32` |
| 0F | `stq` | F2 | `слово LE по адресу rd+imm32 := ra` |
| 10 | `jmp` | F3 | `pc := imm32` (rd = 0) |
| 11 | `jnz` | F3 | если `rd != 0`, то `pc := imm32`, иначе pc+6 |
| 12 | `halt`| F3 | останов; код возврата программы = imm32 (rd = 0) |
| 13 | `mul` | F1 | `rd := (ra × rb) mod 2^64` — беззнаковое, младшие 64 бита (v1) |
| 14 | `div` | F1 | `rd := ra div rb` — беззнаковое частное; rb = 0 — ловушка 7 (v1) |
| 15 | `mod` | F1 | `rd := остаток беззнакового деления ra на rb; rb = 0 — ловушка 7 (v1) |
| 16 | `sra` | F1 | `rd := sext(ra) >> (rb AND 63)` — арифметический сдвиг вправо, знак сохраняется (v1) |
| 17 | `call`| F3 | стек вызовов: занести pc+6, `pc := imm32` (rd = 0); полон — ловушка 5 (v1) |
| 18 | `ret` | F0 | стек вызовов: `pc := извлечённый адрес`; пуст — ловушка 5 (v1) |

Примечания:

- Все прочие комбинации сравнений выводимы: `>` = `lt` с обменом
  операндов; `!=` = `eq` + `xor 1`; `>=` = инверсия `lt` (`xor 1`).
- Опкод `00` не используется — зарезервирован как гарантированно
  недопустимый (исполнение = ловушка 1; удобно для паддинга тестов).
- Декодирование: op 02..0B и 13..16 — F1; op 01, 0C..0F — F2;
  op 10..12 и 17 — F3; op 18 — F0.

## 6. Окно устройств

Окно — 4096 байт адресов `[memsize, memsize+4096)`, за пределами RAM.
Устройства подключаются как кирпичи: каждому — свой диапазон смещений;
новое устройство не требует новых инструкций.

v0 — одно устройство:

| Смещение | Устройство | Запись (stb) | Чтение (ldb) |
|---|---|---|---|
| 0 | Консоль, регистр данных | байт добавляется в выходной поток | 0 |

- Смещения 1..4095 — резерв: запись игнорируется, чтение = 0.
- Словный доступ (`ldq`/`stq`) к окну запрещён — ловушка 3/4:
  регистры устройств v0 байтовые.
- Консоль — упорядоченный байтовый поток; ядро выводит его
  в stdout (WriteFile) к моменту останова программы.

## 7. Ловушки и останов

Ловушка — аварийный останов с кодом; исполнение прекращается,
код возврата программы не определён (у ядра — свой диагностический
вывод, контракт E7.2):

| Код | Причина |
|---|---|
| 1 | недопустимая инструкция: опкод вне 01..18; rb > 15 (или rb != 0 у mov); ra != 0 у const; rd > 15 у jnz; rd != 0 у jmp/halt/call |
| 2 | выборка вне кода: pc >= codesize или pc+длина > codesize |
| 3 | чтение вне памяти: ldb/ldq по недопустимому адресу (п. 3.3) |
| 4 | запись вне памяти: stb/stq по недопустимому адресу (п. 3.3) |
| 5 | стек вызовов: call при глубине 1024 / ret при пустом (v1, п. 3.4) |
| 7 | деление на ноль: div/mod при значении rb = 0 (v1) |

Порядок проверок одной инструкции (однозначен — контракт диффтеста
ядро/оракул): (1) pc >= codesize -> ловушка 2; (2) опкод вне
01..18 -> ловушка 1; (3) pc+длина > codesize -> ловушка 2;
(4) поля-заполнители и номера регистров -> ловушка 1; (5) исполнение
-> ловушки 3/4/5/7 (у div/mod — значение rb = 0 даёт 7). Инструкция,
вызвавшая ловушку, НЕ считается выполненной (в счётчик шагов не входит).

**Нормальный останов** — только `halt`: код возврата = imm32 (u32).
Предел шагов (диагностический код 6, не ISA-ловушка) — у хозяина
исполнения: программа останавливается после N исполненных инструкций,
где N — предел шагов (защита от вечных циклов). Проверка выполняется
ДО выборки очередной инструкции: программа, чей сток кода совпал
с пределом, даёт ловушку 6, а не 2; останов `halt` предел не
встречает (исполнен до следующей проверки). Умолчание
N = 200 000 000; лимит параметром: оракул — `run(max_steps)`, ядро —
необязательный второй аргумент CLI `kernel.exe <файл.up> [N]`
(десятичные цифры, 0..2147483647; контракт — SPEC/13 п. 4).

## 8. Мнемоники (текстовая форма)

Единая мнемоника — контракт для ассемблеров/дизассемблеров
(инструмент — этап E7.3; в LAB — мини-ассемблер оракула):

```
const rD, число            mov rD, rA
add rD, rA, rB   sub rD, rA, rB   and rD, rA, rB   or rD, rA, rB
xor rD, rA, rB   shl rD, rA, rB   shr rD, rA, rB   lt rD, rA, rB
eq rD, rA, rB
mul rD, rA, rB   div rD, rA, rB   mod rD, rA, rB   sra rD, rA, rB
ldb rD, rA+смещ   ldq rD, rA+смещ        — чтение: приёмник первым
stb rA+смещ, rB   stq rA+смещ, rB        — запись: адрес первым
jmp цель          jnz rD, цель           — цель: метка или число
call цель         ret                    — v1; цель как у jmp
halt число
```

- Регистры — `r0`..`r15` (строчные). Смещение — знаковое; `+0`
  можно опускать. Числа — десятичные со знаком или `0x`-hex.
- `цель` перехода — беззнаковое смещение в коде (или метка
  ассемблера). `halt` — беззнаковый код возврата, метку НЕ принимает.
- Директивы ассемблера: `.mem` (memsize) и `.data <байты>` — секция
  данных .UP v2 (SPEC/13 п. 2.1; E7.4-1).

## 9. Рост ISA (правила срезов)

- Новая инструкция = новый опкод + строка в реестре п. 5 + карточка
  кирпича M3-UNIVM + семантика в оракуле + якорная кодировка
  (T-E7-26 расширяется). Занятые опкоды: 00 (резерв), 01..18.
- v1 (ВЫПОЛНЕНО в оракуле — E7.4-1, срез 1 «сначала истина
  семантики»): `mul`/`div`/`mod` (13..15), `sra` (16), `call`/`ret`
  (17/18) + стек вызовов (глубина 1024, ловушка 5) + деление на ноль
  (ловушка 7) + стековая конвенция sp = r13 (п. 3.4) + формат F0
  (1 байт, ret). Ядро и ассемблер подхватывают v1 срезами E7.4-2/3.
- Правило совместимости: кодировка и семантика выданных опкодов
  неизменны навсегда (как ID кирпичей, R5); расширение = только
  новые опкоды. Версия ISA фиксируется в .UP заголовке? — НЕТ:
  версия .UP (SPEC/13) — версия контейнера; набор опкодов программы
  определяется инструкциями в её коде, неизвестный опкод = ловушка 1.
- Слой L4 (библиотека) строится НАД ISA, не расширяя его произвольно.

## 10. Контракт оракула

`LAB/py/lab_vm.py` — эталонная семантика UNIVM v0/v1 (два независимых
свидетеля, как lab_l2 для SPEC/11); контейнер .UP — оракул
`LAB/py/lab_up.py` (выделен по лимиту 500 строк, E7.4-1):

- `assemble(текст) -> байты .UP` — мини-ассемблер (мнемоники п. 8,
  метки, директивы `.mem`/`.data`; синтаксис — докстрока файла);
- `parse_up(байты) -> (memsize, код, данные)` — разбор контейнера
  SPEC/13 v1/v2 (lab_up.py);
- `Machine.step()/run()` — исполнение: регистры, память, консоль,
  счётчик шагов, стек вызовов, ловушки — точно по этому SPEC;
- `run_up(байты)/run_asm(текст)` — прогон целиком.

Ядро E7.2/E7.4-2 обязано совпадать с оракулом на всех программах
корпуса (консоль, код возврата, счётчик шагов, код ловушки) —
расхождение находится и чинится по SPEC, а не «подгонкой» (правила
LAB/README). Якорные кодировки и ловушки закреплены в батарее
(TESTS/T-L3-UNIVM.md, секция 13, T-E7-01..08 + T-E7-26..31).
