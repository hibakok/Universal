# S01. Формат карточки метода

Паспорт файла: SPEC/01-METHOD-CARD.md | слой: все | роль: стандарт карточки кирпича.

## Зачем

Карточка — единица понимания. Прочитав карточку, исполнитель (человек или ИИ)
знает о методе всё необходимое для его использования и безопасного изменения,
не читая код.

## Формат

Карточка living в реестре `MAP/METHODS.md` и выглядит так:

```markdown
### K0-H001 — hex32_to_ascii8

| Поле | Значение |
|---|---|
| Слой | L0 |
| Ветвь | H — шестнадцатеричное представление |
| Файл | KERNEL/L0-SEED/seed.hex, строки RVA 0x1014–0x1041 |
| Функция | Превращает 32-битное число в 8 ASCII-цифр hex (старшая слева) |
| Вход | EAX = число; RSI = адрес поля 8 байт; R8 = таблица 16 цифр ASCII |
| Выход | поле [RSI..RSI+8) заполнено цифрами; EAX сохранён; RSI += 8 |
| Состоит из | — (атомарный) |
| Используется в | K0-P001 write_stdout |
| Тест | T-M0-02, T-M0-04 |
| Статус | готов |
```

## Правила заполнения

1. **Функция** — одна фраза в терминах результата, не реализации.
2. **Вход/Выход** — полный контракт: регистры, память, коды возврата,
   побочные эффекты (вроде «RSI += 8»). Всё, что меняется и видно снаружи.
3. **Состоит из** — ID кирпичей, которые вызываются/используются внутри.
   Для атомарных — прочерк.
4. **Используется в** — обратные ссылки; заполняются у соседей при
   добавлении зависимости (вручную до появления автоматического реестра).
5. **Статус**: `готов` / `в работе` / `план` / `x` (удалён; карточка
   сохраняется навсегда — ID не переиспользуются).
6. Карточка создаётся ДО кода (правило R3) со статусом `план`.

## Жизненный цикл

```
план -> в работе -> готов -> (изменение: карточка правится первой)
                  \-> x (удалён; строка остаётся в реестре)
```
