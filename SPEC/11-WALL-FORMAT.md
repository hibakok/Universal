# S11. Формат WALL v1/v2 (язык слоя L2 и контракт компилятора)

Паспорт файла: SPEC/11-WALL-FORMAT.md | слой: L2 | роль: спецификация языка
WALL v1/v2 и компиляции в BRICK v2.

## Назначение

**WALL** («стена») — компилируемый язык слоя L2: стены строятся из кирпичей
BRICK. Исходник `.wall` компилируется в текст BRICK v2 (`.b2`, SPEC/09);
дальше действует конвейер слоя L1:

```
корень.wall ──wall──> модуль.b2 ──enc──> .brick ──brick──> тело ──pegen──> EXE
              (E6.4b)          (SPEC/09)         (SPEC/08)        (SPEC/07)
```

С этапа E6.4b инструмент существует: **`KERNEL/L2-WALL/wall.exe`**
(M2-WALL, BRICK v2, 19 частей с разрезом по !include) — обязан
повторять выход оракула `LAB/py/lab_l2*.py` байт-в-байт (правило R8,
как enc в E6.2; проверяется секцией 10 батареи, T-E6-25..30 — на
программах v1). **WALL v2 (E6.4c):** оракул и SPEC расширены (массивы,
qword-индексация, `* / %`, break/continue, `&& / ||`, куча); инструмент
wall.exe v2 — этап E6.4c-3 (до него инструмент принимает только v1).
Самохостинг на самом языке (wall.wall) — этап E6.4d.

Контракт инструмента (E6.4b): `wall.exe <вход.wall> <выход.b2>`.
Коды возврата — как у enc/brick: 0 успех; 2 меньше двух аргументов;
3 `ERR=LONG NAME`; 4 `ERR=OPEN SRC`; 5 `ERR=READ SRC`;
6 `ERR=FORMAT AT=XXXX` (XXXX — hex-номер строки с 1); 7 `ERR=BIG SRC`;
8 `ERR=OPEN OUT`; 9 `ERR=WRITE OUT`.

## 0. Версии языка и заголовок выхода

- **v1** — подмножество v2 (E6.4a/b): всё, что не помечено «v2».
- **v2** (E6.4c) добавляет: массивы `var a[n]`, qword-индексацию
  `e[i]` / `e[i] = v` (цепочки допустимы), операторы `* / %`,
  `break`/`continue`, цепочки условий `&&` / `||`, `len(массив)`.
- Заголовок выхода: `; UNIVERSAL / WALL vN / …`, где **vN = v2, если
  программа использует хотя бы одну v2-конструкцию, иначе v1**.
  Программа v1 компилируется байт-в-байт как до E6.4c (обратная
  совместимость — инвариант; проверена якорями v1 и big_source).
- Всякий выход компилятора — корректный вход enc (инвариант T-E6-34).

## 1. Модель языка

- Всё — 64-битные знаковые целые. `str` — неизменяемые байты данных
  (литерал), в выражениях значение имени str — его адрес.
- Переменные: глобальные (`var` вне функций, нулевые ячейки) и локальные
  (`var` внутри функции, стековые). Рекурсия разрешена: кадры стековые.
- **v2: массивы** `var a[n]` — глобальные и локальные; n — десятичное
  число 1..4096. Элементы — qword. Значение имени массива в выражении —
  **адрес нулевого элемента** (как у str); `&a` — тот же адрес.
  Локальный массив занимает n последовательных слотов кадра, a[0] —
  самый глубокий: адрес a[i] = `rbp - 8*(p + n - i)`, p — первый слот.
  Глобальный — `DZ 8*n` в конце тела (порядок объявлений сохраняется).
  Проверок границ НЕТ (выход за массив — порча памяти; как в C).
- **v2: указатели.** Любое значение может быть адресом; `e[i]` читает
  qword по адресу `e + 8*i` (см. п. 2); HeapAlloc (ext) даёт адреса кучи.
- Функции: `func имя(параметры)` … `end`; `main` — ровно одна, без
  параметров; вход программы вызывает `main` (возврат из main без
  ExitProcess — ловушка int3).
- Объявления (`var`/`str`/`ext`) допустимы только ДО первой `func`.
- Сравнения (`== != < <= > >=`, знаковые) — только внутри условий
  `if`/`while` (v2: в цепочках `&&`/`||`); сравнение как значение — v3.
- `&имя` — адрес; `len(s)` — константа длины str (компиляции);
  **v2:** `len(a)` — размер массива (компиляции);
  `getb(база, индекс)` — чтение байта (выражение);
  `setb(база, индекс, значение)` — запись байта (только утверждение).
- **v2:** деление/остаток — усечение к нулю (как C); деление на 0 —
  аппаратное #DE (крах; проверок нет).

## 2. Грамматика v2 (v1 = без помеченных v2 строк)

```
программа  := строка*
строка     := пустая | комментарий | объявление | утверждение-или-функция
комментарий := ';' любой-текст (внутри '…' не считается)
объявление := 'var' имя ['[' число ']']        — [n] = массив (v2)
            | 'str' имя '=' 'литерал' | 'ext' имя
функция    := 'func' имя [ '(' [имя (',' имя)*] ')' ] утверждение* 'end'
утверждение:= 'var' имя ['[' число ']']                       (v2)
            | имя '=' выражение
            | имя ('[' выражение ']')+ '=' выражение          (v2: astore)
            | 'if' условие утверждение* ['else' утверждение*] 'end'
            | 'while' условие утверждение* 'end'
            | 'return' [выражение]
            | 'break' | 'continue'                            (v2, только в while)
            | 'setb' '(' выражение ',' выражение ',' выражение ')'
            | имя '(' [выражение (',' выражение)*] ')'
условие    := или                                           — v2: цепочки
или        := и ('||' и)*                                   (v2)
и          := сравнение ('&&' сравнение)*                   (v2)
сравнение  := выражение ('=='|'!='|'<'|'<='|'>'|'>=') выражение
выражение  := аддитив
аддитив    := конъюнкция (('+')('-')('|')('^') конъюнкция)*
конъюнкция := мультипликатив (('&')('<<')('>>') мультипликатив)*
мультипликатив := унарное (('*')('/')('%') унарное)*          (v2)
унарное    := '-' унарное | первичное
первичное  := число | имя | '&' имя | 'len' '(' имя ')'
            | 'getb' '(' выражение ',' выражение ')'
            | '(' выражение ')' | имя '(' аргументы ')'
постфикс   := первичное ('[' выражение ']')*                  (v2: индексация)
литерал    := "'" (символ | экран)* "'"
экран      := '\\' | '\'' | '\n' | '\r' | '\t' | '\0'
имя        := [a-z][a-z0-9_]* (≤63 байт, строчные; НЕ с '_');
              имя ext — [A-Za-z][A-Za-z0-9_]* (≤31 байт, регистр важен)
число      := десятичные цифры, 0..2147483647
```

Одно утверждение — одна строка. Отступы и пустые строки произвольны.
Приоритет (v2): унарный `-` > `* / %` > `& << >>` > `+ - | ^`; скобки
меняют порядок. `&&` сильнее `||`. Индексация — постфикс (сильнее
унарного минуса: `-a[i]` = `-(a[i])`). Адрес элемента массива без &:
`a + i * 8` (имя массива — значение-адрес). `!` в языке НЕТ: каждая
пара сравнений уже покрывает прямую и инверсную форму (`!(a<b)` ≡ `a>=b`).
Индексная запись неприменима к str напрямую (`s[0]` — ошибка; байты —
getb/setb; явная адресная арифметика `(&s + ...)` допустима).

## 3. Соглашения вызова (наши функции)

- Параметры (≤ 4): `rcx, rdx, r8, r9`; результат: `rax`.
- Каллер-сохраняемые: `rax rcx rdx r8 r9 r10 r11`; остальные — нетронуты.
- Кадр: `push rbp; mov rbp, rsp; sub rsp, <размер>`; выход:
  `mov rsp, rbp; pop rbp; ret`. Инвариант: внутри тела RSP ≡ 0 (mod 16);
  вход функции получает RSP ≡ 8 (mod 16) — как стандартный вызов Win64.
- **ext** (Win64): аргументы 1–4 в регистрах, 5-й — `[rsp+0x20]` (≤ 5
  аргументов); тень 0x20 байтов принадлежит вызываемому и покрыта
  зоной кадра (п. 5). Все ext — из kernel32.dll (v1/v2); куча —
  GetProcessHeap/HeapAlloc/HeapFree (E6.4c; в эмуляторе LAB —
  бамп-распределитель, HeapFree — no-op).

## 4. Разрешение имён

Пространство имён одно: глобальные `var`/`str`/`ext`/массивы + `func` +
локали и параметры текущей функции. Локаль не может совпадать с параметром,
другой локалью или глобальным именем. Локали объявляются до использования.
`имя` в выражении: локаль/параметр → значение; глобальная `var` → значение;
`str`/массив → адрес; `func`/`ext` как значение — ошибка. `&` —
локаль/параметр/var/str/массив; `len` — str или массив. `имя(...)` —
только func (аргументы строго по числу параметров) или ext (0..5).
Присваивание `a = e` — только в var/локаль (str неизменяема; массив
нельзя присвоить целиком — пишите `a[i] = e`). Цель `a[i] = e` (v2):
имя + цепочка индексов; str как корень — ошибка; значение базы может
быть любым выражением-адресом (p[i][j] — загрузка указателя и запись).

## 5. Раскладка кадра (канон, п. 5–8 обязательны для wall.exe)

Слоты нумеруются с вершины: слот i живёт в `[rbp - 8*(i+1)]` (hex-запись
смещения — минимальная, ЗАГЛАВНЫЕ цифры, как во всём BRICK). Порядок:

```
[параметры][локали в порядке объявления; массив — n слотов]
[T1..Tmaxd][C1..Cmaxc][S0 S1 S2][S5]
```

- **Базовые слоты** (v2): параметры по 1 слоту; локали в порядке
  объявления — скаляр 1 слот, массив n слотов (a[0] — самый глубокий:
  адрес a[i] = `rbp-8*(p+n-i)`, адрес a[0] = `rbp-8*(p+n)`).
- **T-слоты** (темпы выражений). `need(e)` — потребность выражения:
  первичное = 0; `neg` = need(операнда); `bin` (вкл. v2 `* / %`) и
  `getb` = 1 + max(need(операндов)); **v2: `index` = 1 +
  max(need(базы), need(индекса))**; `call` = max(need(аргументов), 0).
  maxd = максимум need по всем местам генерации (присваивание, return,
  аргументы, операнды setb и astore — база/индекс/значение ПОРОЗНЬ;
  для операндов условия — 1 + max(need) каждого сравнения).
- **C-слоты** (стейдинг аргументов вызовов): maxc = максимум по всем
  вызовам функции (включая вложенные в выражения): наши — число аргументов;
  ext — min(число, 4). Аргумент 5 ext-вызова идёт в **S5**.
- **S-слоты**: S0,S1,S2 — обязательно есть, если в функции есть `setb`
  **или v2-astore**; S5 — если есть ext-вызов с 5 аргументами.
- Размер кадра: `framesize = align16(8 * nslots) + 0x30`, где
  `nslots` — число слотов, `align16(x) = (x+15) & ~15`. Хвост 0x30 —
  защита зоны тени/5-го аргумента Win64 от наложения на слоты.

## 6. Область импортов (фиксированная, 0x200 байт в начале тела)

RVA тела = смещение + 0x1000. Тело начинается с области импортов —
одинаковой у всех программ WALL v1/v2 (обёртка PEG постоянна):

| Смещение | Размер | Содержимое |
|---|---|---|
| 0x000 | 0x28 | `:_idt` — DD-описатель (5 значений) + `DZ 14` |
| 0x028 | 0x48 | `:_iat` — 9 QWORD: метки `_iat_<ext>` для использованных, затем нули |
| 0x070 | 0x48 | `:_intt` — 9 QWORD: `$_hint_<ext>` использованных, затем нули |
| 0x0B8 | 14 | `:_dll` — "kernel32.dll\0" + `DZ 1` |
| 0x0C6 | 8×34 | слоты hint: `_hint_<ext>` = `DB 00 00 <имя> 00 <нули до 34>`; свободные — `DZ 22` |
| 0x1D6 | 0x2A | `DZ 2A` — выравнивание до 0x200 |

Без ext: описатель `DD 0 0 0 0 0`, IAT/INT — 9 нулей, затем
`DZ 148`. Все hints-записи лежат на чётных RVA по построению
(0x0C6 + 34·k — инвариант 7 SPEC/04). Далее `:_entry` (смещение 0x200).

**Обёртка PEG (константа для всех программ v1/v2):**

```
!module <имя>
!entry 1200
!idata 1000 28
!iat 1028 48
!stackcom 4000
!heapcom 4000
```

Отклонение от SPEC/04: точка входа 0x1200 (не 0x1000) — область импортов
фиксированной ёмкости предшествует коду; батарея проверяет это явно
(T-E6-22/T-E6-33). Глобальные `var` (скаляры) — `DZ 8`, массивы —
`DZ 8n` в конце тела (не DBZ): файловая длина стабильна, `!bss` не нужен.

## 7. Вход программы

```
:_entry
M sub rsp, 8 ; вход: выравнивание стека для вызова main
M call $main ; вход: вызов main
M int3 ; вход: возврат из main без ExitProcess — ловушка
```

## 8. Канон эмиттера (M-строки; wall.exe обязан повторять дословно)

Общий вид: `M мнемоника операнд1, операнд2 ; комментарий`. Разделитель
операндов — запятая и пробел; скобки памяти — без пробелов; числа —
ЗАГЛАВНЫЙ hex без ведущих нулей. Комментарий M-строки: **текст исходной
строки WALL** без комментария и краевых пробелов; у сгенерированных строк
входа/кадра/выхода — фиксированные пояснения («вход: …», «кадр <имя>»,
«выход <имя>»). Пролог:

```
:имя
M push rbp ; кадр имя
M mov rbp, rsp ; кадр имя
M sub rsp, <framesize hex> ; кадр имя
M mov [rbp-8], rcx ; кадр имя      (параметр 1; до 4: rbp-8/10/18/20)
```

Эпилог (`mov rsp, rbp` / `pop rbp` / `ret`, пояснение «выход <имя>»):
в каждом `return` и в конце функции — **кроме случая, когда последнее
утверждение тела — `return`** (тогда завершающего эпилога нет).

Утверждения и выражения (T = слот T_d, X = слот переменной):
базовые формы v1:

```
x = e          -> gen(e,1); M mov [X], r10
return e       -> gen(e,1); M mov rax, r10; эпилог
return         -> эпилог
if c … end     -> guard(c, _if<k>e); then; :_if<k>e
if c … else    -> guard(c, _if<k>); then; M jmp $_if<k>e; :_if<k>; else; :_if<k>e
while c … end  -> :_w<k>; guard(c, _w<k>e); тело; M jmp $_w<k>; :_w<k>e
```

`<k>` — СКВОЗНОЙ счётчик управляющих операторов программы (if и while
вместе, с 1). Инверсии: `==`→jne, `!=`→je, `<`→jge, `<=`→jg, `>`→jle,
`>=`→jl. Условие (каждое сравнение; операнды с глубины 2):

```
gen(левый,2); M mov [T1], r10; gen(правый,2); M mov r11, r10;
M mov r10, [T1]; M cmp r10, r11
```

**guard(c, Lfalse) — охрана условия (v2; цепочки && / ||):** условие
c = [дизъюнкт]… (по `||`), дизъюнкт = [сравнение]… (по `&&`), m ≥ 1:

```
для i = 1..m:
    lfail = _<pfx><k>d<i+1>  при i < m, иначе Lfalse
    для каждого сравнения дизъюнкта: (код сравнения — как выше)
        M j<инв> $lfail              # провал конъюнкта = провал дизъюнкта
    при i < m:  M jmp $<_pfx><k>t ; :_<pfx><k>d<i+1>
при m > 1:  :<_pfx><k>t               # успех любого дизъюнкта -> тело
```

pfx = `if`/`w`. Для m = 1 (одно сравнение или цепочка &&) лишних меток
нет — выход совпадает с v1 дословно. Семантика — short-circuit.

`gen(e, d)` — результат в r10 (глубина d задаёт индекс T-слота); формы v1:

```
число        -> M mov r10, <hex>
локаль/парам -> M mov r10, [rbp-…]
глобаль var  -> M mov r10, [rip+$имя]
str          -> M lea r10, [rip+$имя]        (адрес)
&локаль      -> M lea r10, [rbp-…];  &var/str -> M lea r10, [rip+$имя]
len(s)       -> M mov r10, <длина hex>
-e           -> gen(e,d); M neg r10
a + b        -> gen(a,d+1); M mov [Td], r10; gen(b,d+1); M mov r11, r10;
               M mov r10, [Td]; M add r10, r11     (also: sub/and/or/xor)
a << b       -> … как выше, но: M mov rcx, r11; M shl r10, cl   (>> = shr)
getb(a,i)    -> gen(a,d+1); M mov [Td], r10; gen(i,d+1); M mov r11, r10;
               M mov r10, [Td]; M movzx r10d, byte [r10+r11]
вызов f(x…)  -> для каждого аргумента: gen(xi,d); M mov [Ci], r10;
               затем M mov rcx, [C1] … M mov r9, [C4] (по числу);
               M call $f; [в выражении: M mov r10, rax]
ext E(x…)     -> стейдинг как выше (арг.5 -> S5);
               при 5 аргументах: M mov r10, [S5]; M mov [rsp+20], r10;
               M call [rip+$_iat_e]; [в выражении: M mov r10, rax]
setb(a,i,v)  -> gen(a,1); M mov [S0], r10; gen(i,1); M mov [S1], r10;
               gen(v,1); M mov [S2], r10; M mov r10, [S0];
               M mov r11, [S1]; M mov al, [S2]; M mov [r10+r11], al
```

Формы v2 (E6.4c):

```
имя массива  -> локальный: M lea r10, [rbp-<8*(p+n)>]   (адрес a[0])
                глобальный: M lea r10, [rip+$имя]
&a           -> тот же адрес (как для str)
len(a)       -> M mov r10, <n hex>
a * b        -> как bin: … M imul r10, r11
a / b        -> … M mov rax, r10; M cqo; M idiv r11; M mov r10, rax
a % b        -> … M mov rax, r10; M cqo; M idiv r11; M mov r10, rdx
e[i]         -> gen(e,d+1); M mov [Td], r10; gen(i,d+1); M shl r10, 3;
                M mov r11, r10; M mov r10, [Td]; M add r10, r11;
                M mov r10, [r10]
a[i] = v     -> gen(база,1); M mov [S0], r10; gen(i,1); M mov [S1], r10;
                gen(v,1); M mov [S2], r10; M mov r10, [S0];
                M mov r11, [S1]; M shl r11, 3; M add r10, r11;
                M mov r11, [S2]; M mov [r10], r11
break        -> M jmp $_w<k>e        (k — ближайший объемлющий while)
continue     -> M jmp $_w<k>         (условие перевычисляется)
```

Вызовы в позиции выражения дают C-слоты как и вызовы-утверждения
(учёт вложенных вызовов обязателен). Выход .b2: заголовок (2 строки
фиксированного вида + счётчики; версия — п. 0), область импортов п. 6,
секция `; --- код ---` (вход + функции в порядке исходника), секции
данных: `; --- данные: строки ---` (DB-строки по ≤16 байт),
`; --- данные: глобальные переменные (нулевые ячейки) ---`
(`:имя` + `DZ 8` скаляр / `DZ 8n` массив, в порядке объявлений).
Секции данных выводятся только при наличии. Пустая str — `DZ 0`.
Первичный литерал в M-строках всегда неотрицательный: унарный минус
даёт `M neg r10` (сворачивания констант нет).

## 9. Пределы v2

Исходник ≤ 128 КиБ; строка-литерал ≤ 512 байт; ≤ 8 ext (имя ≤ 31 байт);
имена ≤ 63 байт; ≤ 4 параметров; ext-вызов ≤ 5 аргументов; число
аргументов вызова func = числу параметров; **массив 1..4096 элементов
(локальный и глобальный)**; меток ≤ 500 (предел brick; цепочки || и
if/while добавляют метки: m>1 — ещё m, считая d-метки); тело ≤ 64 КиБ
(предел brick; v2-конструкции многострочны — следите по big_source2).
Числа: 0..2147483647.

## 10. Ошибки компиляции

Все ошибки — `WallError(сообщение, строка)`; строка — номер строки
исходника с 1 (разбиение строк как у enc: LF/CRLF/CR). Программные
ошибки (нет main, незакрытый блок) сообщают номер последней непустой
строки. v2-специфичные: `break`/`continue` вне while; размер массива —
не число или вне 1..4096; присваивание массиву целиком; индексирование
str (чтение и запись); `len` не str/массив. Контракт строк инструмента —
п. «Назначение».

## 11. Что v2 НЕ делает (зарезервировано для v3+)

- Локальные массивы с инициализаторами; двумерные массивы как тип
  (достижимы массивами указателей: `m[i][j]`);
- `!` и скобочные группы в условиях (`!(a<b)` ≡ `a>=b` — грамматика
  сравнений уже полна; группы — v3 с новыми метками);
- сравнение как значение (нужен setcc — нет в SPEC/05); сворачивание
  констант и оптимизации; автовыбор rel8;
- несколько DLL импорта; ext-имена вне kernel32;
- структуры/записи; строки как изменяемые буферы (есть массивы + setb).
