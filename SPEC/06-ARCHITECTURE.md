# S06. Целевая архитектура системы

Паспорт файла: SPEC/06-ARCHITECTURE.md | слой: все | роль: видение конечного состояния.

## Диаграмма слоёв (снизу вверх)

```
+----------------------------------------------------------+
| L6  ПРОЕКТЫ:  Minecraft-копия | AGI | любые программы     |
|                (.UP-файлы, внешние для ядра)              |
+----------------------------------------------------------+
| L5  МОСТЫ:    EXE -> ATOM (понимание чужого кода)         |
|               ATOM -> EXE (материализация своего)         |
+----------------------------------------------------------+
| L4  БИБЛИОТЕКА: математика, строки, память, окна, растр,  |
|                 ввод — переиспользуемые кирпичи           |
+----------------------------------------------------------+
| L3  UNIVM:     виртуальный процессор + память +           |
|                 устройства; ядро-загрузчик программ       |
+----------------------------------------------------------+
| L2  ЯЗЫК:      компилируемый язык высокого уровня         |
+----------------------------------------------------------+
| L1  BRICK:     символьная сборка (метки, имена, макро)    |
+----------------------------------------------------------+
| L0  МАШИНА:    ручной машинный код x86-64, ATOM, PE32+    |
+----------------------------------------------------------+
```

## Ядро и проекты (ключевое разделение)

- **Ядро** — самодостаточный EXE, собранный целиком из наших ATOM/BRICK
  исходников. Содержит UNIVM и инструментарий. Не знает ни одного проекта.
- **Проект** — файл программы (`.UP`), который ядро запускает по пути:
  `kernel.exe C:\проекты\minecraft.up`. Проект можно изменить, удалить,
  переместить — ядро не страдает.
- Взаимодействие — только через объявленные интерфейсы (в будущем —
  системные вызовы UNIVM; сейчас, на этапе L0, — карточки кирпичей).

## Виртуальная машина UNIVM (контур решения)

- Собственный ISA, спроектированный заново: не копия x86, а улучшаемая
  архитектура (широкие регистры, явные потоки, встроенная безопасность).
- Виртуальная оперативная память с управляемым отображением.
- Устройства: экран (растр), клавиатура/мышь, файловый ввод-вывод,
  таймер. Устройства подключаются как кирпичи.
- Программа не может выйти за пределы выделенной ей памяти и устройств —
  сбой проекта не роняет ядро.
- v1 — интерпретатор (простота и отладка), v2 — компиляция в машинный
  код нашими инструментами (скорость).

## Путь самодостаточности

```
ручные байты (сейчас)
  -> HEXGEN: ATOM-текст -> бинарник          (этап 3)
  -> PEGEN:  бинарник -> EXE                  (этап 4)
  -> BRICK:  метки и имена, самохостинг      (этап 5)
  -> язык L2, самохостинг                    (этап 6)
  -> UNIVM + внешние .UP-программы           (этап 7)
  -> библиотеки, мосты EXE<->ATOM            (этапы 8-9)
  -> проекты любого масштаба                 (этап 10+)
```

Каждая стрелка убирает одну ручную операцию. После этапа 5 система
полностью воспроизводит себя сама, стартуя только с текстовых исходников.

## Трансформация чужих EXE

Мост EXE -> ATOM (этап 9): для нашего подмножества x86-64 машина команд
описана в `SPEC/05-X86-SUBSET.md`; дизассемблер превращает байты чужой
программы в ATOM/BRICK, после чего программа становится частью нашего
мира — её можно читать, улучшать, исполнять на UNIVM.
