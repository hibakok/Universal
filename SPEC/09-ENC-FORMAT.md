# S09. Формат ENC v1 (BRICK v2: M-строки и канонические кодировки)

Паспорт файла: SPEC/09-ENC-FORMAT.md | слой: L1 | роль: спецификация кодировщика инструкций.

## Назначение

BRICK v2 = BRICK v1 + **M-строки**: инструкции записываются МНЕМОНИКАМИ,
а байты кодировки назначает инструмент, а не человек. Ручная кодировка
байтов в H-строках (последняя ручная работа по SPEC/08) прекращается.

Архитектурное решение: кодировщик — **нормализатор текста**, отдельный
инструмент `enc` (модуль M1-ENC):

```
исходник.b2 ──enc──> исходник.brick ──brick──> тело.bin ──pegen──> EXE
             (v2→v1)                (SPEC/08)            (SPEC/07)
```

`enc` НЕ считает адресов и НЕ разрешает меток: ссылки `$имя`/`$имя:1`
проходят сквозь него в слоты H-строк нетронутыми. Вся адресная
арифметика остаётся в brick.exe (проверен самохостингом E5) — риск
регресса существующего конвейера нулевой. enc переиспользуем как
кодогенератор транслятора L2 (этап E6.3).

## Грамматика BRICK v2

v2 = v1 (SPEC/08: метки, H/DB/DZ/DBZ/DD/DQ, комментарии) **плюс** M-строка:

```
M-строка := 'M' мнемоника [операнд (',' операнд)*] [';' пояснение]
операнд  := регистр | число | ссылка | память
регистр  := имя из таблицы регистров (ниже)
число    := ['-'] 1..8 ЗАГЛАВНЫХ hex-цифр (0-9A-F)
ссылка   := '$' имя | '$' имя ':' '1'
память   := '[' 'rip' '+' ссылка ']'
          | '[' база ']'
          | '[' база ('+'|'-') число ']'
          | '[' база '+' индекс ']'
          | '[' база '+' индекс ('+'|'-') число ']'
база,индекс := имя 64-битного регистра (без 'rip')
```

Правила: операнды разделяются запятыми (пробелы вокруг запятой
допускаются); внутри скобок пробелов нет; знак «−» перед числом в
скобках задаёт отрицательное смещение (`[rbp-28]`, `[rax+rcx-1]`);
пояснение после `;` проходит в выходную H-строку как есть. Числа —
как во всём BRICK: ЗАГЛАВНЫЙ hex, знак «−» допустим (значение
задаётся напрямую, например `-11` = −0x11). Строчная hex-цифра —
ошибка формата.

Не-M-строки (метки, H, DB, DZ, DBZ, DD, DQ, комментарии, пустые)
проходят в выход БЕЗ ИЗМЕНЕНИЙ — enc не проверяет их (это делает brick).

## Таблица регистров v1

| Размер | Имена | Коды |
|---|---|---|
| 64 | rax rcx rdx rbx rsp rbp rsi rdi r8..r15 | 0..15 |
| 32 | eax ecx edx ebx esp ebp esi edi r8d..r15d | 0..15 |
| 8 | al cl dl bl sil dil spl bpl r8b..r15b | 0..15 |

16-битные имена (ax, r8w) и ah/bh/ch/dh в v1 НЕ входят — ошибка формата.

## Ссылки и слоты

- `$имя` в операнде перехода/вызова или в `[rip+$имя]` → слот 4 байта
  в H-строке (значение считает brick, SPEC/08 п.1/3).
- `$имя:1` в операнде перехода → слот 1 байт (rel8).
- Слот всегда последний элемент кодировки — совпадает с правилом SPEC/08
  «слот в конце строки». **Следствие:** приёмник-память `[rip+$имя]` с
  операндом-числом (imm идёт ПОСЛЕ disp32) в v1 ЗАПРЕЩЁН — ошибка
  формата (пример: `mov dword [rip+$x],0` — C7 05 слот id). Такую
  инструкцию пишет H-строкой вручную (редкий случай табличных данных).
- `mov регистр, $имя` — ошибка формата: адрес метки берут `lea`,
  значение по метке — `mov регистр, [rip+$имя]`.

## Канонические кодировки (единственные для v1)

Каноническая форма — единственная детерминированная (R8): один вход —
один выход. Короткие опкоды (`25`=and eax,id, `3C`=cmp al,ib, `05`,
`3D`, `A8`…) в v1 НЕ используются: вместо них общие формы (`81 /x`,
`80 /x`). Исторические листинки E0–E5 сохраняют свои байты; их
M-эквиваленты дают те же байты только там, где листинг уже каноничен
(см. «Отклонения»).

### Семейство ALU: add, or, and, sub, xor, cmp

ext: add=0, or=1, and=4, sub=5, xor=6, cmp=7. База опкода: add=00,
or=08, and=20, sub=28, xor=30, cmp=38. Форма «r←m» = база+3, «r,r/m,r»
= база+1 (32/64 бит) или база+0 (8 бит).

| Форма M-строки | Кодировка | Условия |
|---|---|---|
| `op r64,r64` | `REX.W(база+1) /r` mod11 | размеры равны |
| `op r32,r32` | `(база+1) /r` mod11 | размеры равны |
| `op r8,r8` | `(база+0) /r` mod11 | размеры равны |
| `op r64,imm` | `REX.W 83 /ext ib` либо `81 /ext id` | imm влезает в знаковый байт → 83 |
| `op r32,imm` | `83 /ext ib` либо `81 /ext id` | то же |
| `op r8,imm` | `80 /ext ib` | imm −0x80..0xFF |
| `op r64,[m]` | `REX.W (база+3) /r` | r←m |
| `op r32,[m]` | `(база+3) /r` | r←m |
| `op r8,[m]` | `(база+2) /r` | r←m |
| `op [m],r64` | `REX.W (база+1) /r` | m←r |
| `op [m],r32` | `(база+1) /r` | m←r |
| `op [m],r8` | `(база+0) /r` | m←r |
| `op byte [m],imm` | `80 /ext ib` | imm 0..0xFF |
| `op dword [m],imm` | `83/81 /ext` | как reg,imm |
| `op qword [m],imm` | `REX.W 83/81 /ext` | как reg,imm |

В `83 /x ib` непосредственный — ЗНАКОВЫЙ байт: беззнаковое ≥ 0x80
требует формы `81 /x id` (урок E4 №2). Для 64-битных reg imm32
знакорасширяется: допустимы −0x80000000..0x7FFFFFFF; для 32-битных —
0..0xFFFFFFFF.

### MOV

| Форма | Кодировка |
|---|---|
| `mov r,r` (равные размеры 8/32/64) | `88 /r` (8) / `89 /r` (32) / `REX.W 89 /r` (64); reg — ИСТОЧНИК |
| `mov r8,imm` | `B0+rb ib` (0..0xFF) |
| `mov r32,imm` | `B8+rd id` (0..0xFFFFFFFF) |
| `mov r64,imm` | `REX.W C7 C0+rd id` (−0x80000000..0x7FFFFFFF) |
| `mov r8,[m]` / `mov r32,[m]` / `mov r64,[m]` | `8A /r` / `8B /r` / `REX.W 8B /r` |
| `mov [m],r8` / `[m],r32` / `[m],r64` | `88 /r` / `89 /r` / `REX.W 89 /r` |
| `mov byte [m],imm` | `C6 /0 ib` |
| `mov dword [m],imm` | `C7 /0 id` |
| `mov qword [m],imm` | `REX.W C7 /0 id` |

Формы памяти с imm требуют ключа размера (byte/dword/qword) —
размер памяти из числа не выводится. `[rip+$имя]` с imm — запрещено
(выше). 16-бит (word, `66`) в v1 нет.

### MOVZX (всегда 0F B6/B7, БЕЗ REX.W)

| Форма | Кодировка |
|---|---|
| `movzx r32, byte r8` | `0F B6 /r` mod11 |
| `movzx r32/r64, byte [m]` | `0F B6 /r` |
| `movzx r32/r64, word [m]` | `0F B7 /r` |

REX.W для movzx НЕ выдаётся никогда: 32-битная запись обнуляет старшие
32 бита, результат для r64 идентичен (так закодирован реестр SPEC/05,
например `41 0F B6 14 10` = movzx rdx,byte [r8+rdx]). Источник word —
только память (16-битных регистров в v1 нет). Приёмник r8 — ошибка.

### LEA, TEST, NEG, NOT, INC, DEC, сдвиги, прочее

| Форма | Кодировка |
|---|---|
| `lea r64,[m]` / `lea r32,[m]` | `REX.W 8D /r` / `8D /r` (m — любой, вкл. `[rip+$имя]`) |
| `test r,r` (8/32/64, равные) | `84 /r` / `85 /r` / `REX.W 85 /r` |
| `neg r32` / `neg r64` | `F7 /3` / `REX.W F7 /3` |
| `inc r32` / `inc r64` | `FF /0` / `REX.W FF /0` (dec = `/1`) |
| `shl/shr/sar/rol/ror r8,imm` | `C0 /x ib` (x: rol=0,ror=1,shl=4,shr=5,sar=7) |
| `shl/... r32,imm` / `r64,imm` | `C1 /x ib` / `REX.W C1 /x ib` |
| `shl/... r8,cl` / `r32,cl` / `r64,cl` | `D2 /x` / `D3 /x` / `REX.W D3 /x` |
| `push r64` / `pop r64` | `50+rd` / `58+rd` |
| `cdqe` / `ret` / `int3` | `48 98` / `C3` / `CC` |

Сдвиг на 1 всегда кодируется `C1 /x 01` (короткая D1-форма — v2).

### Переходы и вызовы

| Форма | Кодировка |
|---|---|
| `jmp $имя:1` / `jmp $имя` | `EB слот1` / `E9 слот4` |
| `jcc $имя:1` / `jcc $имя` | `7x слот1` / `0F 8x слот4` |
| `call $имя` | `E8 слот4` (суффикс `:1` у call — ошибка) |
| `call [rip+$имя]` | `FF 15 слот4` |

jcc: jz=je=4, jnz=jne=5, jb=2, jae=3, jbe=6, ja=7, js=8, jns=9,
jl=C, jge=D, jle=E, jg=F (мнемоника jne = синоним jnz, je = jz).
Автовыбор rel8/rel32 в v1 НЕТ: автор пишет `:1` для близких переходов
(как в v1) — enc адресов не знает. `jmp`/`jcc`/`call` с иными
операндами (регистр, число) — ошибка формата.

## REX, modrm, SIB (правила кодирования)

REX = `40 | W<<3 | R<<2 | X<<1 | B`, выдаётся только если хоть один
бит установлен:

- **W** — операнд 64 бит (кроме movzx и push/pop — см. выше);
- **R** — регистр в поле reg ≥ r8 (или sil..bpl/r8b.. в reg);
- **X** — индекс SIB ≥ r8;
- **B** — база/rm ≥ r8 (или 8-битный reg-приёмник ≥ spl).

modrm = `mod<<6 | reg<<3 | rm`; reg-поле: операнд-источник (89) или
приёмник (8B/03/8D) или /ext (83/81/C6/C7/FF). Память:

- `[rip+$имя]` → mod=00, rm=101, затем слот4. rip вне этой формы
  (база/индекс) — ошибка.
- Прочие: rm = база&7; если база rsp/r12 (код 4) ИЛИ есть индекс —
  rm=100 и далее SIB = `индекс&7<<3 | база&7` (scale фикс. ×1 в v1).
  Индекс rsp/r12 (код 4 = «нет индекса») — ошибка формата.
- disp: 0 → mod=00; не влезает в байт → mod=10, disp32; иначе mod=01.
  **Исключение:** база rbp/r13 (rm=101, код 5) при disp=0 получает
  mod=01 disp8=0 (иначе получилась бы rip-адресация); то же для
  SIB-базы 5. `[rbp]` ≡ `[rbp+0]` — обе допустимы, кодировка одна.

## Коды возврата и сообщения enc

`enc.exe <вход.b2> <выход.brick>`. Коды — как у brick (SPEC/08):
0 успех; 2 меньше двух аргументов (`U-L1-ENC CMDS: ENC <SRC.B2>
<OUT.BRICK>`); 3 `ERR=LONG NAME`; 4 `ERR=OPEN SRC`; 5 `ERR=READ SRC`;
6 `ERR=FORMAT AT=XXXX` (XXXX — hex-номер строки M-ошибки с 1);
7 `ERR=BIG SRC` (>128 КиБ); 8 `ERR=OPEN OUT`; 9 `ERR=WRITE OUT`.

## Пример

```
; вход .b2                          ; выход .brick (enc)
:entry                              :entry
M sub rsp, 38                       H 48 83 EC 38
M lea rbx,[rip+$base]               H 48 8D 1D $base
M mov rcx, -11                      H 48 C7 C1 F5 FF FF FF
M call [rip+$iat_gsh]               H FF 15 $iat_gsh
M movzx eax, byte [rdi]             H 0F B6 07
M test al, al                       H 84 C0
M jz $noargs:1                      H 74 $noargs:1
M inc rdi                           H 48 FF C7
M mov dword [r9+8], 4               H 41 C7 41 08 04 00 00 00
M cmp qword [r11+8], 0              H 49 83 7B 08 00
M jmp $sa_start                     H E9 $sa_start
M ret                               H C3
```

## Отклонения от исторических листингов (семантически идентичны)

Канонические формы отличаются байтами (не смыслом) от редких мест
листингов E0–E5: `and eax,FFFF` — было `25 …`, станет `81 E4 …`;
`xor ecx,ecx` — было `48 31 C9` (REX.W на 32-бит), станет `31 C9`;
`cmp al,22` — было `3C 22`, станет `80 F8 22`. Миграция старых
исходников на M-строки (E6.3) ведётся по-строчно с сверкой семантики
дизассемблером; исторические .hex/.brick не переписываются задним
числом.

## Что v1 НЕ делает (зарезервировано для v2)

- Автовыбор rel8/rel32 (нужно знание адресов — слой brick);
- короткие опкоды (05/25/3C/3D/A8, D1, jcxz), scale ×2/4/8, 16-битные
  операнды, movsx, movabs imm64, jmp/call по регистру;
  `not` (`F7 /2`) и `nop` (`90`) — вне реестра SPEC/05, введёт v2
  вместе с расширением декодера LAB;
- выражения в операндах (`[rbx+rsi*4+8]`, `$имя+4`);
- `mov [rip+$имя],imm` (слот не в конце — см. «Ссылки и слоты»).
